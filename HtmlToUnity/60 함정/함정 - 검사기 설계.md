# 함정 - 검사기 설계

검사가 통과했는데 화면이 틀렸거나 멀쩡한 게임을 결함으로 읽은 함정들이다. 뿌리는 대개 검사가 실제 진입 경로 · 재생 중 실효값 · 우리 화면을 재지 않았거나, 시간 · 시작 상태 · 대조군이 없어 검사기 결함과 게임 결함이 섞인 것이다. 검사기 · 채점기 · 하네스를 새로 만들 때, 검사 결과와 화면이 어긋날 때 편다.

## 재는 대상

### 요약

- 설정값이 아니라 우리 화면을 잰다.
- 원본만 재고 우리 화면은 안 잰 대조: 파일 값만 맞고 화면은 그대로니 두 화면의 같은 자리 단면을 숫자로 견준다.
- 런타임 코드가 덮어쓴 구운 설정: 에셋 검사에 안 잡히니 재생 중 값을 되읽어 구운 값과 대조한다.
- 설정 파일 값을 실효값으로 본 원인 추적: 파일 값과 실효값이 다르니 재생 중 실효값을 덤프해 나란히 둔다.

### 설계

#### 원본만 재고 우리 화면은 안 잰 대조
옛 번호: #168 · 파트: 미기재
- 증상: 원본 픽셀 · 소스 상수 · 스프라이트 · 프리팹 값을 다 맞췄는데 화면은 그대로다.
- 원인: 반투명 합성은 알파 · 색공간 · 블렌딩 · 늘리기가 함께 정해 화면에서만 드러나는데, 파일 값만 쟀다.
- 방향: 기본은 원본과 우리 화면의 같은 자리 한 줄 단면을 색이 바뀌는 구간으로 뽑아 경계 · 색 · 단계 수를 숫자로 나란히 두는 것이다. 캡처 눈대중이 아니라 수치화라 텍스트 덤프 방식과 부딪히지 않는다. 측정이 원본과 같다고 나와도 사람이 없애라고 한 것은 없앤다.
- 관련: [Fx](Fx.md)

#### 런타임 코드가 덮어쓴 구운 설정
옛 번호: #70 · 파트: Client · UI/UX
- 증상: 프리팹 검사는 통과하는데 재생 화면만 틀리다.
- 원인: 런타임 주입 코드가 구운 값을 덮어써, 에셋만 보는 검사에는 안 잡힌다.
- 방향: 기본은 재생 중 값을 되읽어 구운 값과 대조하는 것이다. 주입 코드가 있으면 자기 필드만 건드리는지도 같이 본다.
- 관련: [PrefabRule](PrefabRule.md)

#### 설정 파일 값을 실효값으로 본 원인 추적
옛 번호: #78 · 파트: Client · PD
- 증상: 설정 파일에 적힌 값을 근거로 없는 원인을 쫓는다.
- 원인: 런타임 코드가 값을 덮어써 파일 값과 실효값이 달랐다.
- 방향: 기본은 재생 중 실효값을 덤프해 파일 값과 나란히 두는 것이다. 다르면 덮어쓰는 코드 위치를 함께 적는다.

## 재는 단위

### 요약

- 식이나 요약이 아니라 결과물을 잰다.
- 순수 함수만 잰 골든 테스트: 계산식만 재면 그림이 조각나니 결과물 자체를 골든으로 삼는다.
- 요약 통계로 단정한 형상 판정: 평균은 다른 형상에서도 같으니 마스크를 덤프해 IoU 로 대조한다.
- 수치 검사만으로 닫은 연출: 모양은 개수로 안 잡히니 시작 · 진행 · 끝 재생 캡처를 확보한다.
- 기준보다 낮은 해상도로 찍은 판정용 캡처: 셀 수 없는 캡처로 통과를 적으니 기준 해상도 이상으로 찍는다.

### 설계

#### 순수 함수만 잰 골든 테스트
옛 번호: #162 · 파트: 미기재
- 증상: 골든 테스트는 전부 통과하는데 그려진 결과가 조각나 있다.
- 원인: 골든이 계산식만 재서 좌표계 반전 · 제자리 수정의 전파 순서 · 자르지 않는 인덱스 범위가 분모 밖에 있었다.
- 방향: 기본은 결과물(격자 · 그림) 자체를 골든으로 삼아 한 판을 전 칸 대조하고, 종류가 거의 다 나오는지 보는 것이다. 계산은 원본 좌표로 하고 뒤집기는 한 곳에 모아 주석으로 남기며, 원본의 다중 패스는 순서까지 옮긴다. 검사 통과인데 그림이 다르면 검사의 분모부터 의심한다.
- 관련: [Transfer_Programmer](Transfer_Programmer.md)

#### 요약 통계로 단정한 형상 판정
옛 번호: #117 · 파트: Fx · UIUX
- 증상: 찬 원을 링으로 읽는 식으로 형상을 잘못 판정한다.
- 원인: 반경 평균 같은 요약 통계는 서로 다른 형상에서 같은 값이 나온다.
- 방향: 기본은 마스크를 덤프해 보고, 구운 결과를 소스와 IoU 로 대조하는 것이다. 픽셀 중심은 +0.5 어긋나기 쉬우니 좌표부터 맞춘다.
- 관련: [Fx](Fx.md)

#### 수치 검사만으로 닫은 연출
옛 번호: #60 · 파트: 연출 · 아트 · Client
- 증상: 개수 · 수치 검사는 통과하는데 잔상이나 뭉친 꼬리가 남아 있다.
- 원인: 연출의 모양은 개수로 잡히지 않는다.
- 방향: 기본은 상태가 갈리는 시점의 재생 캡처 세 장(시작 · 진행 · 끝)을 확보하는 것이다. 배치에서는 렌더 텍스처로 저장한다. 캡처는 단면 · 마스크 수치로 바꿔 두면 회차끼리 비교할 수 있어 낫다.
- 관련: [Fx](Fx.md)

#### 기준보다 낮은 해상도로 찍은 판정용 캡처
옛 번호: #72 · 파트: 연출 · UI/UX
- 증상: 개수 · 선을 셀 수 없는 캡처를 보고 통과로 적는다.
- 원인: 캡처 해상도가 세야 할 단위보다 낮았다.
- 방향: 기본은 세는 판정을 기준 해상도 이상으로 찍는 것이다. 배치 재생은 기본 게임 뷰가 작으니 화면 크기를 지정해 둔다.
- 관련: [공통절차](공통절차.md)

## 진입 경로

### 요약

- 게임 초기화를 대신 해 주는 검사: 호출 사슬을 건너뛰니 게임 코드가 부르는 호출을 그대로 부른다.
- 게임 코드에 뚫은 하네스 전용 진입점: 치트가 제품에 남으니 기존 주입 지점으로 조종한다.
- 발동 경로를 안 태운 안전 장치 수정: 기능이 조용히 죽으니 참 · 거짓 두 경로를 모두 태운다.
- 게임 규칙 추가를 못 따라간 검사 봇: 봇이 스스로 죽으니 원본 실측 봇과 같은 규칙으로 맞춘다.

### 설계

#### 게임 초기화를 대신 해 주는 검사
옛 번호: #23 · 파트: Client · 전 파트
- 증상: 진입 경로가 끊겨도 검사는 통과한다.
- 원인: 검사가 창을 직접 열어 게임 코드의 호출 사슬을 건너뛰었다.
- 방향: 기본은 게임 코드가 부르는 호출을 그대로 불러 검사가 같은 경로를 지나게 하는 것이다.

#### 게임 코드에 뚫은 하네스 전용 진입점
옛 번호: #11 · 파트: Client · 전 파트
- 증상: 검증용 치트가 제품에 남고, 검증은 실제 경로를 안 지난다.
- 원인: 하네스 편의를 위해 게임 코드에 전용 진입점을 만들었다.
- 방향: 기본은 기존 주입 지점(RNG · 텍스트 · 틱 인자)으로 조종하고, 재는 도구는 프로젝트 밖에 두는 것이다. 주입 지점이 모자라면 검증 전용 진입점보다 설계상 주입 지점을 여는 편이 낫다.
- 관련: [PD](PD.md) · [Transfer_Programmer](Transfer_Programmer.md)

#### 발동 경로를 안 태운 안전 장치 수정
옛 번호: #77 · 파트: 전 파트 · PD
- 증상: 고친 안전 장치가 늘 거짓으로 판정해 기능이 조용히 죽어 있다.
- 원인: 미정의 변수 참조처럼 한쪽 분기가 깨져 있었는데 발동 경로를 실제로 태우지 않았다.
- 방향: 기본은 참 · 거짓 두 경로를 모두 실제로 태우는 것이다. 위쪽에 새로 추가한 함수라면 참조하는 변수가 그 시점에 정의됐는지도 본다.

#### 게임 규칙 추가를 못 따라간 검사 봇
옛 번호: #133 · 파트: Transfer_Programmer
- 증상: 규칙을 넣은 뒤 검사가 실패해 게임을 의심하게 된다.
- 원인: 검사 봇이 새 규칙(접촉 피해 등)을 몰라 스스로 죽었다.
- 방향: 기본은 봇을 원본 실측 봇과 같은 규칙으로 맞추고, 멈춤 창 같은 방해물을 치우게 하는 것이다. 실패 때는 정지 여부 · 거리 · 체력 같은 봇 상태를 찍어 봇 실패와 게임 실패를 가른다.

## 시간 · 시작 상태 · 외란

### 요약

- 초기화 완료 전에 화면을 바꾸는 검사: 구독 전에 전이를 거니 초기화 완료 신호 뒤에 건드린다.
- 프레임 수로 기다리는 자동 검사: 헤드리스에서 60프레임이 0.01초니 시간으로 기다린다.
- 저장된 진행 상태에 따라 갈리는 검사: 실행마다 점수가 다르니 검사가 시작 상태를 스스로 만든다.
- 사람 마우스에 흔들리는 재생 검사: 커서가 이벤트로 들어가니 이벤트 시스템을 끄고 `onClick` 을 직접 부른다.
- 편집 모드에서 실패한 UI 레이캐스트: 캔버스를 안 그려 모두 빠지니 입력 판정은 재생 검사에서만 한다.

### 설계

#### 초기화 완료 전에 화면을 바꾸는 검사
옛 번호: #178 · 파트: 미기재
- 증상: 멀쩡한 창이 안 열려 배선을 여러 번 뒤진다.
- 원인: 시뮬이 서자마자 전이를 걸어, 창 조종자가 구독하기 전이었다.
- 방향: 기본은 제품이 초기화 완료 신호를 내고 검사는 구독이 끝난 뒤(최소 한 박자 뒤) 건드리는 것이다. 실패가 나면 무엇이 틀렸나보다 언제 쟀나를 먼저 본다.

#### 프레임 수로 기다리는 자동 검사
옛 번호: #14 · 파트: 전 파트
- 증상: 화면 없는 재생에서 로직이 멈춘 듯 보인다.
- 원인: 헤드리스 재생은 60프레임이 0.01초 만에 지나가, 프레임 수 대기가 시간 대기가 되지 않는다.
- 방향: 기본은 시간으로 기다리고 경과 프레임 수를 로그에 남기는 것이다. 스텝 수 자체가 비교 대상이면 스텝 수로 맞추되 그렇게 했다고 적는다.

#### 저장된 진행 상태에 따라 갈리는 검사
옛 번호: #61 · 파트: Client · PD
- 증상: 같은 코드인데 실행마다 점수가 다르다.
- 원인: 검사가 저장된 진행 상태를 그대로 물려받았다.
- 방향: 기본은 검사가 시작 상태를 스스로 만드는 것이다. 못 만들면 결과에 「진행도 X 기준」을 함께 찍는다.

#### 사람 마우스에 흔들리는 재생 검사
옛 번호: #147 · 파트: 전 파트
- 증상: 커서 호버 · 클릭 때문에 첫 프레임이 실행마다 달라진다.
- 원인: 에디터 재생 중 사람이 쓰는 마우스가 이벤트 시스템으로 들어간다.
- 방향: 기본은 재생 검사에서 이벤트 시스템을 끄고 `onClick` 을 직접 부르는 것이다. 눌림 자체(레이캐스트)를 재는 검사라면 끄지 말고 합성 포인터로 쏜다.

#### 편집 모드에서 실패한 UI 레이캐스트
옛 번호: #13 · 파트: Client · UI/UX
- 증상: 게임에서는 눌리는 버튼이 검사에서는 안 눌린다고 나온다.
- 원인: 편집 모드는 캔버스를 그리지 않아 모든 그래픽이 레이캐스트에서 빠진다.
- 방향: 기본은 입력 판정을 재생 검사에서만 하고, 눌린다고 아는 대조군 버튼을 같이 쏘는 것이다. 대조군까지 실패하면 검사 환경부터 의심한다.
- 관련: [UIFramework](UIFramework.md)

## 검사기 사이 갈림

### 요약

- 같은 입력에 답이 갈리는 두 검사기: 숫자의 근거가 흔들리니 점수를 읽기 전에 갈림부터 닫는다.
- 판정 갈래를 한 점수로 합친 채점: 상계되어 개선을 되돌리니 갈래별로 따로 낸다.
- 기계 대조기 없이 둔 검산 축: 같은 사실이 조용히 갈라지니 허용 오차를 둔 대조기를 굽는 도구 끝에 붙인다.

### 설계

#### 같은 입력에 답이 갈리는 두 검사기
옛 번호: #106 · 파트: Client · PD
- 증상: 두 검사기가 같은 입력에 다른 답을 내 모든 숫자의 근거가 흔들린다.
- 원인: 초기화 · 스텝 수 · 주입 지점이 검사기마다 달랐는데 점수부터 읽었다.
- 방향: 기본은 점수를 읽기 전에 갈림부터 닫는 것이다. 초기화 · 스텝 수 · 주입 지점 경로를 나란히 찍어 비교하고, 못 닫으면 두 결과를 모두 보고한다.

#### 판정 갈래를 한 점수로 합친 채점
옛 번호: #54 · 파트: Client · PD
- 증상: 총점만 보고 실제 개선을 되돌린다.
- 원인: 구조 · 수치 판정과 결과 판정을 한 점수로 합쳐 서로 상계됐다.
- 방향: 기본은 갈래별(구조 · 수치 / 결과)로 따로 내고 상계하지 않는 것이다. 총점이 필요하면 갈래 점수 옆에 보조로만 둔다.

#### 기계 대조기 없이 둔 검산 축
옛 번호: #99 · 파트: Client · PD
- 증상: 두 곳에 적힌 같은 사실이 조용히 갈라진다.
- 원인: 검산용으로 둔 값을 맞대는 기계 대조기가 없었다.
- 방향: 기본은 같은 회차에 허용 오차를 둔 대조기를 굽는 도구 끝에 붙이는 것이다. 대조기를 못 붙이면 검산 축을 남기지 않는 편이 낫다.

## 대조의 순서와 분모

### 요약

- 값부터 맞댄 배치표 대조: 줄 자체가 다른 대상이니 개수 → bbox 합집합 → 개별 좌표 순으로 맞댄다.
- 미측정 목록에 안 잡히는 이관 공백: 등재 안 된 요소는 안 보이니 화면마다 원본 → 우리 전수 대조표를 만든다.

### 설계

#### 값부터 맞댄 배치표 대조
옛 번호: #114 · 파트: UIUX · Fx
- 증상: 좌표 차이를 쫓다 보니 줄 자체가 다른 대상이었다.
- 원인: 개수가 다른 두 표를 값부터 맞댔다.
- 방향: 기본은 개수 → bbox 합집합 → 개별 좌표 순으로 맞대는 것이다. 개수가 다르면 값 대조를 멈추고 대응부터 만든다.
- 관련: [UIUX](UIUX.md)

#### 미측정 목록에 안 잡히는 이관 공백
옛 번호: #120 · 파트: PD · UIUX
- 증상: 미측정을 전수 정리했는데 배경 장식 몇 개가 통째로 빠져 있었다. 시뮬만 옮긴 요소도 같은 식으로 빠진다. 이벤트는 내는데 그리는 코드가 없어 화면에 아무것도 안 나오고, 문서 어디에도 「없다」 고 적혀 있지 않았다.
- 원인: 미측정 목록은 이미 등재한 것만 담아, 등재조차 안 된 요소는 보이지 않는다.
- 방향: 기본은 마감 전 화면마다 원본 요소 → 우리 요소 전수 대조표를 만드는 것이다. 시뮬이 있는 게임은 **시뮬이 내는 알림(이벤트) → 그리는 뷰** 표도 같이 만든다. 읽는 곳이 없는 알림이 곧 공백이다.
- 관련: [UIUX](UIUX.md) 「전수 대조표」
