# 함정 - 설정 빌드

프로젝트 설정은 하나인데 게임은 여럿이고, 확정표의 결정이 설정 · 코드에 닿지 않아 에디터에서는 돌지만 빌드 · 재생에서 틀린 것이 나간 함정들이다. 착수해 확정표를 설정에 옮길 때, 다음 게임으로 넘어갈 때, 빌드 직전에 편다.

## 게임 여럿과 한 프로젝트

### 요약

- 확정표를 적용하지 않은 빌드: 마지막에 만진 게임이 그대로 나가니 빌드 진입점이 대상 게임의 확정표를 먼저 적용한다.
- 게임 하나 기준으로 박힌 프로젝트 전역 설정: 게임이 늘면 설정이 충돌하니 게임별 프로필을 두고 활성 하나만 적용한다.

### 설계

#### 확정표를 적용하지 않은 빌드
옛 번호: #125 · 파트: Transfer_Programmer · PD
- 증상: 빌드에 마지막으로 만진 게임의 방향 · 패키지 · 씬이 나간다.
- 원인: 프로젝트 설정은 하나인데 빌드가 대상 게임의 확정표를 적용하지 않았다.
- 방향: 기본은 게임별 빌드 진입점이 확정표 적용 → 씬 정리 → 엔진 실효값 확인 → 빌드 순서로 도는 것이다. 손 빌드에 대비해 빌드 전처리가 시작 씬으로 게임을 판별하고, 못 가리면 막지 않고 경고만 한다.
- 관련: [GameFramework - 프로젝트 설정](GameFramework%20-%20프로젝트%20설정.md) 「여러 게임의 빌드」 · [Transfer_Programmer](Transfer_Programmer.md)

#### 게임 하나 기준으로 박힌 프로젝트 전역 설정
옛 번호: #43 · 파트: PD · Client
- 증상: 같은 프로젝트에 게임이 늘자 설정끼리 충돌한다.
- 원인: 프로젝트 전역 설정을 첫 게임 값으로 직접 박았다.
- 방향: 기본은 게임별 프로필을 두고 활성 하나를 적용하는 것이다. 어느 프로필이 활성인지는 코드 · 커밋에서 읽히게 둔다.
- 관련: 「확정표를 적용하지 않은 빌드」 · [GameFramework](GameFramework.md)

## 확정표 반영

### 요약

- 프로젝트 설정에 반영 안 된 확정표: 에디터에서만 돌아 타깃 · 회전이 틀린 채 가니 착수 게이트가 반영 여부를 확인한다.
- 확정표에 행이 없는 하드코딩 게임 값: 코드에 박힌 값은 빈칸으로도 안 보이니 게임을 넘길 때 세어 행을 만든다.
- 어긋난 엔진 설정 짝 구성요소: 짝 중 한쪽만 바꾸면 재생에서만 죽으니 짝이 맞는지를 정적 검사로 둔다.

### 설계

#### 프로젝트 설정에 반영 안 된 확정표
옛 번호: #10 · 파트: PD
- 증상: 에디터에서는 돌아서 빌드 타깃 · 화면 회전이 틀린 채 진행된다.
- 원인: 확정표에 적은 결정을 프로젝트 설정에 옮겼는지 확인하는 단계가 없었다.
- 방향: 기본은 착수 게이트(G0) 증명에 설정 반영 여부를 넣고 도구가 확인하게 하는 것이다.
- 관련: [GameFramework - 프로젝트 설정](GameFramework%20-%20프로젝트%20설정.md) 「확정표 반영」 · [PD](PD.md) 「확정표」

#### 확정표에 행이 없는 하드코딩 게임 값
옛 번호: #42 · 파트: PD
- 증상: 코드에 박힌 값이 빈칸으로도 드러나지 않아 다음 게임에 그대로 남는다.
- 원인: 제품명 · 식별자 · 경로 접두어 같은 게임별 값이 확정표 행 없이 코드에만 있었다.
- 방향: 기본은 다음 게임으로 넘어갈 때 하드코딩된 게임별 값을 세어 확정표에 행을 만드는 것이다.
- 관련: 「프로젝트 설정에 반영 안 된 확정표」

#### 어긋난 엔진 설정 짝 구성요소
옛 번호: #12 · 파트: Client · PD
- 증상: 편집 모드에서는 문제가 없다가 재생에서만 죽는다.
- 원인: 입력 방식과 입력 모듈, 색공간과 그래픽 API 처럼 짝으로 맞아야 하는 설정 중 한쪽만 바꿨다.
- 방향: 기본은 「짝이 맞다」를 정적 검사로 두는 것이다. 설정 하나를 바꿀 때 딸린 구성요소 목록을 같이 본다.
- 관련: [GameFramework - 프로젝트 설정](GameFramework%20-%20프로젝트%20설정.md) 「딸린 구성요소」 · [Fx](Fx.md) 「색공간」
