# 함정 - 로직 데이터

원본이 기전(상태 · 물리 · PRNG)으로 만들던 값을 결과값으로 표나 뷰에 박거나, 표에 넣은 주소 · 컬럼을 읽는 코드가 없어 값은 맞는데 동작이 다르거나 표는 찼는데 화면에 안 나온 함정들이다. 시뮬 로직과 데이터 표를 옮길 때, 표는 채웠는데 화면에 안 나올 때 편다.

## 기전과 결과값

### 요약

- 뷰가 매 프레임 다시 잰 바라보는 방향: 유지 분기가 있는 값은 시뮬이 상태로 들고 뷰는 부호만 받는다.
- 물리가 정한 자리를 박은 레벨 데이터: 잔차 0 이면 유도값이니 표 대신 기전을 옮긴다.
- 시드 차이로 등재한 결정적 시작 화면: 원본을 n≥3회 열어 같은지 먼저 보고 PRNG 를 다시 구현한다.
- 성공 입력 구간을 안 옮긴 난이도: 입력 점 몇 개가 아니라 성공 구간을 구간 대 구간으로 대조한다.

### 규칙

- 소스는 규칙만 읽고 베끼지 않는다. #강제 [원칙 R11](원칙.md#R11)

### 설계

#### 뷰가 매 프레임 다시 잰 바라보는 방향
옛 번호: #172 · 파트: Transfer_Programmer · Client
- 증상: 붙어 있는 개체가 좌우로 떨고, 일부 개체는 반전이 아예 없다.
- 원인: 원본은 마지막 방향을 유지하는 상태다(차이 0 이면 유지, 거리 게이트 안에서만 갱신). 그런데 뷰가 매 프레임 위치를 비교해 계산했고, 호출부도 일부만 옮겼다.
- 방향: 유지 분기가 있는 값(반전·방향·마지막 입력)은 시뮬이 상태로 들고 뷰는 부호만 받는다. 원본 호출부를 전수로 뽑아 개수부터 맞추는 편이 낫다.
- 관련: [Client](Client.md)

#### 물리가 정한 자리를 박은 레벨 데이터
옛 번호: #102 · 파트: Client · Design
- 증상: 못 잰 레벨의 자리가 추정값으로 채워진다.
- 원인: 물리가 정하는 유도값을 레벨 데이터로 표에 박았다.
- 방향: 다른 값과 차가 일정하면(잔차 0) 유도값으로 보고, 표 대신 기전을 옮긴다. 파생 규칙은 교차 검산에 쓰는 편이 낫다.

#### 시드 차이로 등재한 결정적 시작 화면
옛 번호: #149 · 파트: Client · Fx · PD
- 증상: PRNG 만 달라 시작 화면부터 다른 게임이 된다.
- 원인: 원본이 결정적인지 확인하지 않고 차이를 시드 차이로 등재했다.
- 방향: 원본을 n≥3회 열어 같은지 먼저 본다. 같으면 PRNG 알고리즘을 소스에서 읽어 다시 구현하고 골든 벡터로 닫는다.
- 관련: 소스는 규칙만 읽고 베끼지 않는다 `#강제 [원칙 R11](원칙.md#R11)`

#### 성공 입력 구간을 안 옮긴 난이도
옛 번호: #73 · 파트: PD · Client · Design
- 증상: 배치는 같은데 체감 난이도가 다르다.
- 원인: 난이도는 성공 입력 구간의 폭·개수로 정해지는데, 입력 점 몇 개만 대조했다.
- 방향: 레벨마다 입력 전 구간을 스윕해 성공 구간을 구간 대 구간으로 대조하고, 그 결과를 합격 기준에 넣는 편이 낫다.

## 안 읽히는 데이터

### 요약

- 읽는 코드가 없는 표 주소 컬럼: 컬럼을 채운 것은 쓰인 것이 아니니 컬럼마다 읽는 곳을 한 줄 적는다.
- 어드레서블에 등록 안 된 자산 로드 주소: 로드가 조용히 null 이 되니 표 ↔ 주소 양방향 감사를 돌린다.
- private setter 때문에 기본값만 채워진 JSON 행: 역직렬화가 값을 못 넣으니 setter 를 `public` 으로 두고 행 수를 어설션한다.
- 한 장씩 await 한 시트 컷 로드: 첫 화면이 늦으니 `WhenAll` 로 묶어 읽는다.

### 설계

#### 읽는 코드가 없는 표 주소 컬럼
옛 번호: #131 · 파트: Transfer_Programmer · Transfer_Artist
- 증상: 아이콘 주소가 표에 있는데 화면에 아이콘이 안 나오고, 모든 검사가 통과한다.
- 원인: 컬럼을 채운 것을 쓰인 것으로 셌다. 그 주소를 넣는 코드가 없었다.
- 방향: 컬럼마다 읽는 곳을 한 줄 적는다. 주소·키뿐 아니라 문구·플래그 컬럼도 같다. 마감 캡처는 사람이 보는 편이 낫다.
- 관련: [원칙 R7](원칙.md#R7) · [DataFramework](DataFramework.md)

#### 어드레서블에 등록 안 된 자산 로드 주소
옛 번호: #129 · 파트: Transfer_Artist · Transfer_Programmer
- 증상: 로드가 조용히 null 이 되어 개체가 안 그려진다.
- 원인: 자산이 어드레서블에 등록되지 않아 로드 주소가 없었다.
- 방향: 등록 도구를 두고 표 ↔ 주소 양방향 감사를 돌린다. null 로드는 크게 기록하고, 시뮬 개체 수와 렌더러 수를 같이 찍어 어긋남을 드러내는 편이 낫다.
- 관련: [ResourceRule](ResourceRule.md)

#### private setter 때문에 기본값만 채워진 JSON 행
옛 번호: #7 · 파트: Design · Client
- 증상: 예외 없이 모든 행이 기본값이 된다.
- 원인: JSON 행 클래스의 setter 가 `private` 이라 역직렬화가 값을 넣지 못했다.
- 방향: 행 클래스 setter 는 `public` 으로 두고, 로드 뒤 행 수 어설션을 건다.
- 관련: [DataFramework](DataFramework.md)

#### 한 장씩 await 한 시트 컷 로드
옛 번호: #143 · 파트: Transfer_Programmer
- 증상: 첫 화면이 몇 초 늦게 뜬다.
- 원인: 시트 컷을 한 장씩 차례로 `await` 했다.
- 방향: 기본은 `WhenAll` 로 묶어 읽는 것이다. 초기화 단계별 시간 로그를 남기면 늦는 단계가 바로 보인다.

## 부호·순서 대응

### 요약

- 좌표계가 다른데 그대로 옮긴 부호 있는 값: 크기만 맞아 검사를 통과하니 두 부호 모두 정답지로 판정한다.
- 문서의 열거형 순서를 믿은 연출 인덱스: 문서 순서와 실제 인덱스가 다르니 재생 대조로 이름을 확정한다.

### 설계

#### 좌표계가 다른데 그대로 옮긴 부호 있는 값
옛 번호: #81 · 파트: Client · 아트
- 증상: 회전이나 y 가 반대로 도는데 크기는 맞아 검사를 통과한다.
- 원인: 원본과 Unity 의 좌표축 방향이 다른데 부호 있는 값을 그대로 옮겼다.
- 방향: 두 부호 모두 정답지로 판정한다. 변환은 한 곳에서 하고 주석에 적는 편이 낫다.

#### 문서의 열거형 순서를 믿은 연출 인덱스
옛 번호: #63 · 파트: 연출 · Client
- 증상: 비슷하지만 다른 연출이 나온다.
- 원인: 문서에 적힌 열거형 순서와 실제 인덱스가 달랐다.
- 방향: 재생 대조로 이름을 확정한다. 확정되지 않은 값은 옮기지 않는다.
