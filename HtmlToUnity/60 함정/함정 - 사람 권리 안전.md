# 함정 - 사람 권리 안전

권리 · 사람이 정한 것 · 되돌릴 수 없는 것에 관한 원칙이 왜 강제인지 보여 주는 사례집이다. 실제로 난 사고를 원칙별로 묶었고, 원칙 문장 자체는 [원칙](원칙.md) 에만 있다. 옛 번호는 재발방지 목록의 번호이고, 인용 `재발방지 #N` 을 여기서 찾는다.

## R11 원본 코드 복제

### 요약

- URL 원본 번들 소스를 연 김에 생기는 코드 복제: 소스를 손에 쥐면 옮겨 붙이고 싶어지니 값과 규칙만 읽는다.
- 원본을 보고 찍은 도트를 근거로 삼은 재제작: 「보고 그렸다」는 일치의 근거가 아니니 규격을 재서 다시 굽는다.

### 규칙

- 원본 에셋과 코드는 읽되 베끼지 않는다. #강제 [원칙 R11](원칙.md#R11)

### 설계

#### URL 원본 번들 소스를 연 김에 생기는 코드 복제
옛 번호: #127 · 파트: 전원 · PD
- 증상: URL 원본을 블랙박스로 단정해 관측으로 못 닫던 미측정이, 프레임 origin 스크립트를 읽자 한 번에 닫혔다. 소스를 손에 쥐면 코드째 옮기고 싶어진다.
- 원인: 원본 소스를 읽을 수 있는 것과 옮겨 붙여도 되는 것을 같은 일로 볼 여지가 있었다.
- 원칙이 막는 것: 원본 코드 복사로 인한 권리 침해. 소스는 앵커 값과 규칙을 읽는 데만 쓰고 코드는 다시 만든다.
- 관련: #강제 [원칙 R11](원칙.md#R11) · [공통절차](공통절차.md) · [분석로직](분석로직.md)

#### 원본을 보고 찍은 도트를 근거로 삼은 재제작
옛 번호: #152 · 파트: Transfer_Artist · PD
- 증상: 원본을 보고 손으로 찍은 도트를 완료로 뒀는데 실측 IoU 50.6%, 색 수 19 에서 7 로 줄었고 크기 · 주소 · 컷 수 채점기는 통과했다.
- 원인: 「원본을 보고 그렸다」를 일치의 근거로 삼았다. 이를 픽셀 일치로 바로잡으려 하면 원본 픽셀 배치를 옮겨 적는 쪽으로 기울기 쉽다.
- 원칙이 막는 것: 원본 픽셀 배치를 그대로 옮겨 적는 복제. 실루엣 · 팔레트 · 채움률 같은 규격을 재서 다시 굽고, 픽셀을 어디까지 맞출지는 사람이 정한다.
- 관련: #강제 [원칙 R11](원칙.md#R11) · [원칙 R12](원칙.md#R12) · [Transfer_Artist](Transfer_Artist.md)

## R12 사람 확정

### 요약

- 사람이 없애라 한 버튼 둘레 띠를 측정으로 되살린 일: 측정을 근거로 결정을 반박하지 말고 알린 뒤 결정을 따른다.
- 32px 이하 도트의 일치선을 담당자가 임의로 그은 판정: 일치 범위는 정책이니 32px 이하는 사람에게 묻고 확정표에 적는다.

### 규칙

- 사람 확정은 측정보다 위다. #강제 [원칙 R12](원칙.md#R12)

### 설계

#### 사람이 없애라 한 버튼 둘레 띠를 측정으로 되살린 일
옛 번호: #184 · 파트: Transfer_Artist · Fx · PD (원문 미기재)
- 증상: 시작 버튼 외곽선 바깥 반투명 띠를 사람이 없애라고 했는데, 원본 텍스처에 있다 · 원인은 딤이다를 들어 두 번 남겨 세 번 지적받았다.
- 원인: 원본 측정을 사람의 결정보다 위에 두고 결정을 근거로 반박했다.
- 원칙이 막는 것: 에이전트가 근거를 들어 사람의 결정을 뒤집는 일. 측정은 알리고 결정을 따르며, 의도된 차이 [사람 확정] 으로 등재한다.
- 관련: #강제 [원칙 R12](원칙.md#R12) · [원칙 R10](원칙.md#R10) · [Fx](Fx.md)

#### 32px 이하 도트의 일치선을 담당자가 임의로 그은 판정
옛 번호: #155 · 파트: Transfer_Artist · PD
- 증상: 16×16 에서 「형태만 맞추고 픽셀은 우리 것」이란 선을 지키는 한 사람 형태가 나오지 않았다.
- 원인: 작은 도트에서는 픽셀 배치가 곧 형태인데, 어디까지 맞출지라는 정책을 담당자가 스스로 정하고 완료를 선언했다.
- 원칙이 막는 것: 사람이 정할 정책(권리와 일치 범위의 경계)을 에이전트가 정하는 일. 32px 이하는 사람에게 묻고 확정표에 적는다.
- 관련: #강제 [원칙 R12](원칙.md#R12) · [원칙 R11](원칙.md#R11) · [Transfer_Artist](Transfer_Artist.md)

## R13 게임별 결정

### 요약

- 화면 방향 · 해상도를 다음 게임에 이월한 착수: 게임별 결정을 저장소 규약으로 보지 말고 착수마다 묻는다.

### 규칙

- 게임마다 달라지는 결정은 게임마다 묻는다. #강제 [원칙 R13](원칙.md#R13)

### 설계

#### 화면 방향 · 해상도를 다음 게임에 이월한 착수
옛 번호: #37 · 파트: PD
- 증상: 앞 게임의 화면 방향 · 해상도를 다음 게임 착수에 그대로 썼다.
- 원인: 게임별 결정을 저장소 규약으로 착각했다.
- 원칙이 막는 것: 사람이 게임마다 정할 값이 묻지도 않고 굳는 일. 착수마다 묻고, 이월은 PD 「이월되는 것」 표에 있는 것만 한다.
- 관련: #강제 [원칙 R13](원칙.md#R13) · [PD](PD.md) · [GameFramework](GameFramework.md)

## R18 git 범위

### 요약

- 시키지 않은 브랜치 이동으로 사라진 작업 트리 파일: 깃 조작은 작업 정리가 아니니 사람이 말한 범위만 한다.

### 규칙

- git 은 시킨 범위만 한다. #강제 [원칙 R18](원칙.md#R18)

### 설계

#### 시키지 않은 브랜치 이동으로 사라진 작업 트리 파일
옛 번호: #26 · 파트: 전 파트
- 증상: 사람이 말하지 않은 깃 조작(브랜치 이동 등) 뒤 작업 트리 파일이 사라졌다.
- 원인: 커밋 · 브랜치 · 푸시를 작업 정리의 일부로 보고 에이전트가 판단해 했다.
- 원칙이 막는 것: 되돌릴 수 없는 작업 유실. 커밋 · 브랜치 · 푸시는 사람이 말한 범위만 한다.
- 관련: #강제 [원칙 R18](원칙.md#R18)

## R19 프로세스 종료

### 요약

- 프로세스 이름으로 죽여 날아간 다른 프로젝트 작업: 이름이 같다고 우리 것이 아니니 명령줄 경로로 우리 PID 만 고른다.

### 규칙

- 프로세스는 이 프로젝트 PID 로만 끈다. #강제 [원칙 R19](원칙.md#R19)

### 설계

#### 프로세스 이름으로 죽여 날아간 다른 프로젝트 작업
옛 번호: #75 · 파트: 전 파트 · PD
- 증상: 에디터를 프로세스 이름으로 죽이자 같은 엔진으로 열린 다른 프로젝트 작업이 날아갔다.
- 원인: 이름이 같으면 우리 프로세스라고 보았다.
- 원칙이 막는 것: 우리 것이 아닌 작업의 비가역 유실. 명령줄 프로젝트 경로로 우리 PID 만 고르고, 락파일이 아니라 살아 있는 프로세스로 판정하며, 못 가리면 멈춘다.
- 관련: #강제 [원칙 R19](원칙.md#R19) · [공통절차](공통절차.md)

## R20 에디터 종료

### 요약

- 다리 경로에서 에디터를 무조건 종료한 검사기: 배치용 종료 호출이 사람 에디터를 끄니 다리 실행에서는 부르지 않는다.

### 규칙

- 사람의 에디터를 저장 없이 끄지 않는다. #강제 [원칙 R20](원칙.md#R20)

### 설계

#### 다리 경로에서 에디터를 무조건 종료한 검사기
옛 번호: #140 · 파트: Transfer_Programmer · PD
- 증상: 에디터 다리로 돌린 검사기가 `EditorApplication.Exit` 를 불러 에디터가 저장 없이 꺼지고 복구 대화상자가 떴다.
- 원인: 배치 실행용 종료 호출을 사람이 쓰는 에디터 경로에서도 그대로 불렀다.
- 원칙이 막는 것: 저장 안 된 사람 작업의 유실과 복구 대화상자. 다리 실행이면 재생은 `ExitPlaymode` 만, 편집은 아무것도 안 부르고, 꺼야 하면 저장 후 종료한다.
- 관련: #강제 [원칙 R20](원칙.md#R20) · [Transfer_Programmer](Transfer_Programmer.md) · [공통절차](공통절차.md)
