# 함정 - 판정 보고

판정(무엇이 맞은 결과인가)과 보고(완료라고 말해도 되는가) 원칙이 왜 강제인지 보여 주는 사례집이다. 실제로 난 사고를 원칙별로 묶었고, 원칙 문장 자체는 [원칙](원칙.md) 에만 있다. 옛 번호는 재발방지 목록의 번호이고, 인용 `재발방지 #N` 을 여기서 찾는다.

## R1 원본 이상 거동

### 요약

- 원본 버그를 고쳐서 옮긴 이관: 「더 나은 쪽」을 스스로 고르지 말고 의도된 차이로 등재해 사람이 확정한다.

### 규칙

- 원본 이상 거동도 옮길 사양이다. #강제 [원칙 R1](원칙.md#R1)

### 설계

#### 원본 버그를 고쳐서 옮긴 이관
옛 번호: #3 · 파트: Client · Design
- 증상: 원본에서 재현되는 이상 거동을 우리 쪽에서 고쳐 옮겨, 원본과 플레이가 달라졌다.
- 원인: 이상 거동을 결함으로 보고 담당자가 「더 나은 쪽」을 스스로 골랐다.
- 원칙이 막는 것: 원본이 정답이라는 파리티 정의가 에이전트 판단으로 바뀌는 일. 고치려면 의도된 차이로 등재하고 사람이 확정한다.
- 관련: #강제 [원칙 R1](원칙.md#R1) · [원칙 R10](원칙.md#R10) · [원칙 R12](원칙.md#R12) · [PD - 대원칙](PD%20-%20대원칙.md) 「원본 이상」

## R3 관측 하한

### 요약

- 관측 하한을 확정값으로 적은 기록: 관측 최솟값을 등호로 적지 말고 `≥ N [관측 하한]` 으로 적는다.
- 라이브 원본을 열지 않고 낸 재현 안 됨 답변: 우리 자료만으로 판정하지 말고 원본 같은 자리를 먼저 해 본다.

### 규칙

- 원본이 진실이고 관측은 하한이다. #강제 [원칙 R3](원칙.md#R3)

### 설계

#### 관측 하한을 확정값으로 적은 기록
옛 번호: #134 · 파트: Client · Design
- 증상: 관측으로 본 피격 6회 · 무적 0.95초를 확정값으로 적었는데 소스는 7회 · 1.0초였다.
- 원인: 관측에서 본 최솟값을 값 자체로 읽고 등호로 적었다.
- 원칙이 막는 것: 추정이 확정처럼 굳어 이후 판정이 틀린 기준을 쓰는 일. 관측은 `≥ N [관측 하한]`, 등호는 소스 직독 · 후킹만 쓴다.
- 관련: #강제 [원칙 R3](원칙.md#R3) · [분석로직](분석로직.md)

#### 라이브 원본을 열지 않고 낸 재현 안 됨 답변
옛 번호: #173 · 파트: Client · PD (원문 미기재)
- 증상: 「움직일 때 깜빡인다」는 지적에 소스 읽기와 우리 빌드 실측만으로 재현 안 됨이라 보고했는데, 원본을 해 보면 원래 동작이었다.
- 원인: 판정자인 원본을 건너뛰고 우리 쪽 자료만으로 사양인지 결함인지를 정했다.
- 원칙이 막는 것: 원본을 안 본 결론이 판정으로 통하는 일. 증상 보고를 받으면 원본 같은 자리를 먼저 해 보고 사양 · 결함을 가른다.
- 관련: #강제 [원칙 R3](원칙.md#R3) · [원칙 R1](원칙.md#R1) · [공통절차 - 원본에서 값 캐기](공통절차%20-%20원본에서%20값%20캐기.md) 「여는 순서」

## R4 못 캔 값

### 요약

- 정답지 빈 구간을 없는 값으로 채운 골든: 표 모양을 채우지 말고 부존재를 증명하거나 미측정으로 둔다.
- 못 본 것을 관찰로 부재 증명한 기록: 「없다」는 목록 열거로만 닫고, 못 읽으면 미측정으로 둔다.
- 조건부로만 나오는 요소를 없다고 적은 분석: 관찰 조건 밖을 일반화하지 말고 「그 조건에서 안 나온다」로 적는다.

### 규칙

- 못 캔 값을 지어내지 않는다. #강제 [원칙 R4](원칙.md#R4)

### 설계

#### 정답지 빈 구간을 없는 값으로 채운 골든
옛 번호: #47 · 파트: PD · Client
- 증상: 원리적으로 존재하지 않는 구간에 값을 만들어 넣어 거짓 정답지가 됐다.
- 원인: 정답지 표의 모양(칸이 다 차야 한다)을 채우는 것을 목표로 삼았다.
- 원칙이 막는 것: 지어낸 값이 골든이 되어 이후 모든 채점을 오염시키는 일. 부존재를 증명하거나 미측정으로 둔다.
- 관련: #강제 [원칙 R4](원칙.md#R4) · [원칙 R6](원칙.md#R6)

#### 못 본 것을 관찰로 부재 증명한 기록
옛 번호: #57 · 파트: 전 파트
- 증상: 「없다」고 적은 사실이 실제로는 못 본 것이었고, 둘이 구분되지 않았다.
- 원인: 부정 사실을 관찰 몇 번으로 닫았다.
- 원칙이 막는 것: 못 본 것이 없는 것으로 기록되어 거짓 사실이 되는 일. 「없다」는 목록 열거로만 닫고, 못 읽으면 미측정으로 둔다.
- 관련: #강제 [원칙 R4](원칙.md#R4) · [원칙 R6](원칙.md#R6)

#### 조건부로만 나오는 요소를 없다고 적은 분석
옛 번호: #130 · 파트: 전원
- 증상: 조건부 업그레이드 4종 · 체력바 · 거리 표시를 원본에 없는 것으로 적어 놓쳤다.
- 원인: 관찰한 조건에서 안 나온 것을 원본 전체에 없는 것으로 일반화했다.
- 원칙이 막는 것: 관측 범위 밖의 요소가 분석에서 통째로 빠지는 일. 「그 조건에서 안 나온다」로 적고, 개수는 원본 정의로 확인하며 관측 개수는 하한이다.
- 관련: #강제 [원칙 R4](원칙.md#R4) · [원칙 R3](원칙.md#R3)

## R5 점수 맞추기

### 요약

- 관측값과 유도값이 섞인 정답지: 컬럼마다 관측/유도를 표시하고 관측이 이긴다.
- 모형 예측값이 섞인 정답지: 순환 채점이 되니 컬럼마다 실측/유도/예측을 표시하고 예측은 뺀다.
- 미측정 파라미터를 골든에 맞춘 채점: 역산이 통과가 되니 추정임을 표시하고 바꾸려면 먼저 잰다.
- 표본 의존 검사를 허용치로 덮은 마감: 허용치를 낮추지 말고 관측 합집합을 쓰거나 누락을 별도 줄로 찍는다.
- 효과가 없다는 점수로 되돌린 실측값: 점수를 원본 위에 두지 말고 되돌리는 근거는 새 실측만 쓴다.

### 규칙

- 점수에 맞추지 않는다. #강제 [원칙 R5](원칙.md#R5)

### 설계

#### 관측값과 유도값이 섞인 정답지
옛 번호: #44 · 파트: Client · PD
- 증상: 유도값에 맞추다 보니 관측값과 갈렸다.
- 원인: 정답지 컬럼에 관측한 값과 식으로 유도한 값이 표시 없이 섞였다.
- 원칙이 막는 것: 무엇이 원본에서 온 값인지 흐려져 채점 기준이 유도식으로 바뀌는 일. 컬럼마다 관측/유도를 표시하고 관측이 이긴다.
- 관련: #강제 [원칙 R5](원칙.md#R5) · [원칙 R3](원칙.md#R3)

#### 모형 예측값이 섞인 정답지
옛 번호: #66 · 파트: Client · PD
- 증상: 채점이 원본과의 일치가 아니라 우리 모형과의 일치를 쟀다.
- 원인: 정답지에 모형이 예측한 값이 실측처럼 들어갔다.
- 원칙이 막는 것: 우리 모형이 우리 모형을 확인하는 순환 채점. 컬럼마다 실측/유도/예측을 표시하고 예측은 뺀다.
- 관련: #강제 [원칙 R5](원칙.md#R5)

#### 미측정 파라미터를 골든에 맞춘 채점
옛 번호: #48 · 파트: Client · PD
- 증상: 채점이 우리가 맞춘 값을 확인하게 되어 가짜 근거가 생겼다.
- 원인: 재지 못한 파라미터를 골든이 통과하는 값으로 골랐다.
- 원칙이 막는 것: 통과가 원본 일치가 아니라 역산의 결과가 되는 일. 추정임을 표시하고, 실패는 재측정 대기로 두며, 바꾸려면 먼저 잰다.
- 관련: #강제 [원칙 R5](원칙.md#R5) · [원칙 R6](원칙.md#R6)

#### 표본 의존 검사를 허용치로 덮은 마감
옛 번호: #121 · 파트: Client · PD
- 증상: 지터로 표본을 놓치면 실패해 회귀와 구분되지 않는 검사를 둔 채 마감했다.
- 원인: 흔들리는 검사를 고치는 대신 허용치를 낮춰 통과시키려는 길이 열려 있었다.
- 원칙이 막는 것: 허용 오차가 원본이 아니라 통과를 기준으로 정해지는 일. 관측 합집합을 쓰거나 누락을 별도 줄로 찍고, 마감 전 두 번 돌려 비교한다.
- 관련: #강제 [원칙 R5](원칙.md#R5)

#### 효과가 없다는 점수로 되돌린 실측값
옛 번호: #82 · 파트: Client · PD
- 증상: 원본에서 잰 값을 넣었는데 점수가 안 올라 되돌렸다.
- 원인: 점수를 원본보다 위의 판정자로 두었다.
- 원칙이 막는 것: 점수가 값을 고르게 되는 일. 실측값은 넣고 A/B 점수를 적으며, 되돌리는 근거는 새 실측뿐이다.
- 관련: #강제 [원칙 R5](원칙.md#R5)

## R7 최소 단위 증명

### 요약

- 자작 지표 만점으로 낸 그림 완료 보고: 대리 지표로 「같음」을 선언하지 말고 최소 단위(그림은 픽셀)로 잰다.
- 만든 것을 옮긴 것으로 센 이관율 분자: 「화면에 나옴을 무엇이 증명하나」가 비면 분자에 넣지 않는다.
- 검사 분모를 지금 보이는 화면에 맡긴 검사기: 분모는 전수로 잡고 최소 개수를 박는다.

### 규칙

- 증명은 결과물의 최소 단위로 한다. #강제 [원칙 R7](원칙.md#R7)

### 설계

#### 자작 지표 만점으로 낸 그림 완료 보고
옛 번호: #154 · 파트: 전원 · PD
- 증상: 실루엣 IoU · 팔레트 거리 만점으로 완료라 했는데 실제 픽셀 일치는 13~34% 였다.
- 원인: 내가 만든 대리 지표가 안을 무엇으로 칠했는지는 보지 않았다.
- 원칙이 막는 것: 대리 지표로 「같음」을 선언해 판정 기준이 바뀌는 일. 같은지는 최소 단위(그림은 픽셀)로 재고, 보고 전에 원본과 나란히 본다.
- 관련: #강제 [원칙 R7](원칙.md#R7) · [원칙 R23](원칙.md#R23) · [Transfer_Artist](Transfer_Artist.md)

#### 만든 것을 옮긴 것으로 센 이관율 분자
옛 번호: #159 · 파트: 전원 · PD (원문 미기재)
- 증상: 한 회차에 버튼 먹통 · 뷰가 시트 한 장만 읽음 · 문구 읽는 곳이 없어 UI 누락 · 지표 만점인데 픽셀 불일치가 동시에 났고 모든 검사가 통과했다.
- 원인: 산출물만 세고, 그것을 읽는 소비 지점(코드 · 화면)은 세지 않았다.
- 원칙이 막는 것: 화면에 나오지 않는 것이 이관율 분자에 들어가 수치가 거짓이 되는 일. 「화면에 나옴을 무엇이 증명하나」가 비면 분자에 넣지 않는다.
- 관련: #강제 [원칙 R7](원칙.md#R7) · [원칙 R8](원칙.md#R8) · [PD](PD.md)

#### 검사 분모를 지금 보이는 화면에 맡긴 검사기
옛 번호: #163 · 파트: Transfer_Programmer · PD (원문 미기재)
- 증상: 문구 검사가 UI 가 붙기 전 1개만 보고, 버튼 검사가 씬에 떠 있는 5개만 세고(모달은 열릴 때 생성) 둘 다 「0개 실패」로 통과했다.
- 원인: 세는 검사의 분모를 프리팹 · 표 전수가 아니라 그 순간 존재하는 오브젝트로 잡았다.
- 원칙이 막는 것: 분모가 작거나 0 이라 통과하는 판정 결함. 분모는 전수로 잡고 최소 개수를 박는다.
- 관련: #강제 [원칙 R7](원칙.md#R7) · [Transfer_Programmer](Transfer_Programmer.md)

## R8 전수 분모

### 요약

- 이관율 100% 뒤에 드러난 시스템 통째 누락: 분모를 우리 산출물에서 뽑지 말고 원본 소스 정의로 센다.
- UI 연출이 빠진 이관율 분모: 창별 UI 연출 표를 두고 빈칸 0 을 학습 완료 조건으로 건다.
- 갈래별 연출 문구를 한 벌로 뭉뚱그린 표: 갈래별 행을 가진 표로 두고 분모는 소스의 갈래 수로 센다.
- 개체만 세고 행동은 안 센 분모: 분기와 타이머 필드를 전수로 적고 갈래마다 화면 증명을 둔다.

### 규칙

- 100% 선언은 원본 전수 분모 위에서만 한다. #강제 [원칙 R8](원칙.md#R8)

### 설계

#### 이관율 100% 뒤에 드러난 시스템 통째 누락
옛 번호: #174 · 파트: Client · PD (원문 미기재)
- 증상: 과제 4종에서 액티브 스킬 4종으로 이어지는 시스템 코드가 없었는데, 문구 키와 아트가 있어 자산 · 문구 · 프리팹 감사가 통과했다.
- 원인: 분모를 원본 소스의 시스템 정의가 아니라 우리 산출물 목록에서 뽑았다.
- 원칙이 막는 것: 분모를 좁혀 얻은 100% 선언. 분모는 원본 소스 정의(시스템 · 갈래 · 행동)를 전수로 센다.
- 관련: #강제 [원칙 R8](원칙.md#R8) · [원칙 R7](원칙.md#R7) · [SkillSystem](SkillSystem.md)

#### UI 연출이 빠진 이관율 분모
옛 번호: #138 · 파트: Fx · UIUX · PD
- 증상: 버튼 펄스 · 호버 · 디머 누락을 100% 선언 뒤 사람이 지적했다.
- 원인: UI 움직임을 이관율 대조 대상에서 뺐다.
- 원칙이 막는 것: 보이는 연출이 분모 밖에 있어 누락이 100% 에 가려지는 일. 창별 UI 연출 표를 두고 빈칸 0 을 학습 완료 조건으로 건다.
- 관련: #강제 [원칙 R8](원칙.md#R8) · [UIUX](UIUX.md) · [Fx](Fx.md)

#### 갈래별 연출 문구를 한 벌로 뭉뚱그린 표
옛 번호: #146 · 파트: Design · Fx
- 증상: 여섯 갈래 문구가 전부 달랐는데 한 벌로 옮겼고 한 갈래는 빠졌다.
- 원인: 연출 값을 갈래 없이 하나로 두어 분모가 1 로 줄었다.
- 원칙이 막는 것: 갈래 누락이 분모에서 사라지는 일. 갈래별 행을 가진 표로 두고 이관율 분모는 소스의 갈래 수로 센다.
- 관련: #강제 [원칙 R8](원칙.md#R8) · [Design](Design.md)

#### 개체만 세고 행동은 안 센 분모
옛 번호: #160 · 파트: Client · PD (원문 미기재)
- 증상: 동료 개체는 이관율에 있었지만 `update` 갈래 다섯 중 둘만 옮겼다(공격 · 추종 · 지연 뒤 단계 열기 · 반응 말풍선 · 진행 링 누락).
- 원인: 분모가 명사(개체)뿐이고 동사(행동 분기 · 타이머 필드)가 없었다.
- 원칙이 막는 것: 개체가 있다는 것으로 개체가 산다는 것까지 통과시키는 일. 소스 클래스의 분기와 타이머 필드를 전수로 적고 갈래마다 화면 증명을 둔다.
- 관련: #강제 [원칙 R8](원칙.md#R8) · [Client](Client.md)

## R23 완료 조건

### 요약

- 「일단 여기까지」로 닫은 회차: 완료 조건은 미측정 0 · 재측정 대기 0 · 임시 도구 0 이다.
- 검사 통과만 보고 지운 측정 도구: 검사 통과와 미측정 · 재측정 대기 0 을 둘 다 확인한다.
- 남은 일이 있는데 쓴 완료 보고: 조건이 전부 참일 때만 완료라 쓰고, 아니면 남은 목록을 낸다.

### 규칙

- 완료는 조건이 전부 참일 때만 말한다. #강제 [원칙 R23](원칙.md#R23)

### 설계

#### 「일단 여기까지」로 닫은 회차
옛 번호: #30 · 파트: 전 파트
- 증상: 남은 목록이 회차마다 길어졌다.
- 원인: 완료를 상황마다 고를 수 있는 말로 썼다.
- 원칙이 막는 것: 「끝남」의 뜻이 사라지는 일. 완료 조건은 미측정 0 · 재측정 대기 0 · 임시 도구 0 이다.
- 관련: #강제 [원칙 R23](원칙.md#R23) · [PD](PD.md)

#### 검사 통과만 보고 지운 측정 도구
옛 번호: #21 · 파트: PD
- 증상: 미측정이 남아 있어 지운 채점기를 다시 만들었다.
- 원인: 전 검사 통과를 완료로 읽고 미측정 · 재측정 대기 수를 확인하지 않았다.
- 원칙이 막는 것: 조건 하나만 참인데 도구를 치워 되돌리는 비용을 치르는 일. 검사 통과와 미측정 · 재측정 대기 0 을 둘 다 확인한다.
- 관련: #강제 [원칙 R23](원칙.md#R23) · [원칙 R6](원칙.md#R6) · [Transfer_Programmer](Transfer_Programmer.md)

#### 남은 일이 있는데 쓴 완료 보고
옛 번호: #137 · 파트: PD
- 증상: 완료라고 적은 뒤 다음 회차가 남은 셋을 잊었다.
- 원인: 완료 조건 일부가 거짓인데 완료라는 말을 썼다.
- 원칙이 막는 것: 거짓 완료 보고로 남은 일이 기록에서 사라지는 일. 조건이 전부 참일 때만 완료라 쓰고, 아니면 남은 목록을 낸다.
- 관련: #강제 [원칙 R23](원칙.md#R23) · [PD - 작업 분해표](PD%20-%20작업%20분해표.md) 「완료 선언」
