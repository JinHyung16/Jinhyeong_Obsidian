# 장르 - 서바이버

자동 공격으로 적 무리를 버티는 게임에서 더 볼 것과 Unity 구조 차이다.

## 알아보는 신호

### 요약

- 주인공은 이동만 하고 공격은 자동으로 나간다.
- 몰려오는 적 무리를 버티며 강화 카드로 큰다.
- 월드가 화면보다 넓고 카메라가 주인공을 따라간다.

### 설계

| 신호 | 무엇이 보이나 |
|---|---|
| 입력 | 입력이 이동뿐인데 적이 죽는다. 공격 입력 0 으로 처치 수가 오르는지 보고 가른다 |
| 적 | 적이 화면 밖에서 계속 들어오고 동시 개체 수가 시간에 따라 불어난다 |
| 강화 | 처치 보상을 주워 게이지가 차면 게임이 서고 강화 카드를 고른다 |
| 월드 | 월드가 화면보다 넓다. 카메라가 주인공을 따라가고 지형이 끝없이 이어진다 |

## 더 볼 질문

### 요약

- [분석로직 - 학습 판정](분석로직%20-%20학습%20판정.md) 「시스템 축 점검표」에 더해 묻는다.
- 스폰 · 적 속성 · 접촉 피해 · 강화 · 부활 · 퀘스트 · 동료 · 스킬 · 바이옴을 따로 묻는다.
- 답은 원본 코드에서 잰다.

### 설계

| 주제 | 질문 |
|---|---|
| 스폰 | 스폰 자리는 화면 밖 어디인가? 화면 밖에 오래 머문 적을 다시 배치하나? |
| 적 속성 | 적의 체력 · 크기 · 비용은 태어난 웨이브로 굳나? 해금 순간 바로 나오는 종류가 있나? |
| 적 이동 | 개체마다 속도가 흩어지나? 적끼리 밀어내나, 겹치나? 넉백 감쇠는 프레임 단위인가? |
| 접촉 피해 | 접촉 피해를 조절하는 것은 첫 겹침 대기인가, 공격 간격인가, 무적인가? |
| 강화 | 게이지 초과분이 넘어가나? 카드 선택은 두 단계인가? 정지 창이 뜨면 무엇이 서나? |
| 부활 | 죽고 나서 잠깐 더 도나? 부활은 몇 번이고 무엇을 되돌리나(체력 · 주변 적 · 난이도)? |
| 퀘스트 | 퀘스트 목표 자리는 시작 자리 기준인가, 켜진 순간 기준인가? 첫 퀘스트는 언제 켜지나? |
| 동료 | 동료 · NPC 는 따라다니는 것 말고 무엇을 하나(공격 · 말풍선 · 진행 링 · 다음 단계 열기)? |
| 과제 | 과제 완료와 퀘스트 체인 클리어는 다른 사건인가? 완료 창은 어디에 붙고 한 판에 몇 번 뜨나? |
| 액티브 스킬 | 액티브 스킬이 세계 시간 배율을 바꾸나? 정지 스킬은 애니 · 공격까지 멈추나? |
| 바이옴 | 바이옴은 판마다 하나인가? 바이옴끼리 시드 · 적 · 웨이브를 나눠 쓰나? 지형 오브젝트가 길을 막나? |

## Unity 구조 차이

### 요약

- 전투는 순수 C# 시뮬레이션이다.
- 적 · 투사체 · 보상은 배열 개체와 활성 플래그로 둔다. 개체당 컴포넌트는 0 이다.
- 절차 지형은 Tilemap 으로 카메라 둘레 창만 칠한다.
- 난수는 시드 난수 한 곳에서만 꺼낸다.

### 규칙

- 강화 축이 단순해 [SkillSystem](SkillSystem.md) 조합에서 벗어나면 사람과 교차 확인한다.

### 설계

| 자리 | 기본과 이유 |
|---|---|
| 시뮬 | 기본은 전투를 순수 C# 시뮬레이션으로 둔다. 유니티 타입 · 물리 없이 원본 좌표계 · 시간 단위 식을 그대로 계산한다. 이유: 원본 식 대조와 헤드리스 하네스가 쉽다. 스텝 안 호출 순서는 원본 메인 루프를 따르고, 시간 배율 스킬은 스텝 입구의 배율 하나로 받는다 ([Client](Client.md) 「충돌 반지름」). 물리 엔진 전투면 [장르 - 물리 퍼즐](장르%20-%20물리%20퍼즐.md) 노트를 본다 |
| 개체 | 기본은 적 · 투사체 · 보상 · 지형 오브젝트를 배열 개체와 활성 플래그로 둔다. 개체당 컴포넌트 · Animator 는 0 이고 애니 프레임도 데이터다. 뷰는 배열을 읽어 풀링 렌더러를 맞추기만 한다. 이유: 개체 수가 불어난다 ([SKILL - 잘못 옮긴 것](SKILL%20-%20잘못%20옮긴%20것.md) 「재생 계층」). 수가 적은 보스 · NPC 는 컴포넌트를 고려한다 |
| 매니저 | 매니저는 표를 시뮬 구조체로 옮기고 스텝만 부른다. 입력은 배선이 꽂는다. 정지 게이트는 플래그 하나이고 뒷받침 게임의 기본값은 정지다. 푸는 자리를 먼저 본다(함정: [검사 분모를 지금 보이는 화면에 맡긴 검사기](함정%20-%20판정%20보고.md#검사%20분모를%20지금%20보이는%20화면에%20맡긴%20검사기)) |
| 공격 수단 | 공격 수단이 2종 이상이면 기본은 [SkillSystem](SkillSystem.md) 조합으로 만들고 같은 중앙 틱에서 돌린다. 이유: 강화가 겹쳐도 한 규칙으로 쌓인다. 강화 축이 단순하면 직접 구현도 선택지다 |
| 유지 분기 값 | 방향처럼 유지 분기가 있는 값은 시뮬 상태로 두고, 뷰는 부호만 받는다. 이유: 뷰가 매 프레임 재면 떤다 |
| 난수 | 난수는 시드 난수 한 곳에서만 꺼낸다 ([GameFramework](GameFramework.md) 「무작위」). 지형 PRNG 는 원본 알고리즘을 이식한다 |
| 절차 지형 | 기본은 Tilemap(한 칸 = 1 유닛)이다. 카메라 둘레 창만 칠하고, 중심 칸이 바뀔 때만 다시 칠한다. 이유: 지형이 끝없다. 시드 · 노이즈 정의와 타일 역할 열거는 한 곳에 두고 시뮬(통행) · 굽기 · 뷰가 같이 읽는다. 원본 지형이 자유 배치면 스프라이트 풀을 고려한다 |
| 바이옴 | 바이옴이 여럿이면 기본은 바이옴 표를 따로 두고, 타일 시트는 합집합으로 굽고, 뷰가 지금 바이옴을 비교해 갈아 끼운다. 시트가 커지면 바이옴별 시트를 고려한다 |
| 카메라 · 포인터 | 카메라 추적식과 가장자리 목표 포인터의 각도 · 거리는 시뮬이 내고, 카메라와 HUD 는 따라가기만 한다. 이유: 골든으로 대조된다 |
| 로드 | 개체 시트는 묶음으로 읽고 세트를 먼저 띄운다. 뜨는 문구 · 입자는 풀링한다 |

## 함정

### 요약

- 관측으로 규칙을 지어내는 사고가 가장 많다.
- 시뮬은 옮겼는데 뷰가 안 읽어 화면에서 사라지는 사고가 그다음이다.
- 검사가 멈춘 시뮬을 재면 전부 통과한다.
- 옛 번호(`#N`)는 그대로 둔 항목 번호다.

### 규칙

- #강제 [원칙 R3](원칙.md#R3) 관측은 규칙이 아니고 하한이다.
- #강제 [원칙 R8](원칙.md#R8) 문구 · 아트 존재는 이관율 분자가 아니다.
- #강제 [원칙 R9](원칙.md#R9) 시드 차이 등재에는 원본도 갈린다는 실측이 붙는다.

### 설계

| 사고 | 근거 |
|---|---|
| 관측으로 규칙을 지어낸다. 상수는 맞는데 스폰 · 조준 · 강화 누적 · 카메라가 틀린다. 충돌 상자가 만든 간격을 적끼리 밀어내기로 만든다 | [상수가 맞아 규칙도 맞다고 봄](함정%20-%20측정%20추론.md#상수가%20맞아%20규칙도%20맞다고%20봄) |
| 관측 하한을 체력 · 무적 값으로 적는다 | #134 |
| 가중치 0 카드를 없다고 적는다 | #130 |
| 첫 화면의 지형 오브젝트를 장식으로 넘겨 시스템째 놓친다 | #120 · #130 |
| 과제 · 스킬 시스템이 통째로 없는데 문구 · 아트가 있어 감사를 통과한다 | #174 |
| 동료의 행동 갈래를 안 세서 동료가 안 싸운다 | #160 |
| 「한 발에 죽는다」 같은 가정으로 동시 개체 수가 모자라도 화면 대조로는 안 잡힌다. 개체 수 추이를 골든으로 둔다 | |
| 웨이브별 크기 열을 뷰가 안 읽는다 | #131 |
| 방향을 매 프레임 다시 재서 붙은 적이 떤다 | #172 |
| 지형 난수를 시드 차이로 등재한다 | #149 |
| 골든이 순수 함수만 재고, 타일 종류가 줄어도 정상으로 보인다 | #162 · #151 |
| 아트 주소가 없어 시뮬에는 적이 있는데 화면에는 0 이다 | #129 |
| 컷을 한 장씩 await 해 늦게 뜬다 | #143 |
| 레벨업 정지 창이나 죽은 봇 때문에 검사가 멈춘 시뮬을 잰다 | #163 · #133 |
| 움직이는 목표 포인터를 한 프레임 좌표로 고정한다 | #145 |
