# 장르 - 영토 점령 전략

큰 격자 지도를 칸 단위로 칠해 넓히는 게임에서 더 볼 것과 Unity 구조 차이다.

## 알아보는 신호

### 요약

- 큰 격자 지도를 여러 나라가 칸 단위로 칠해 가며 넓힌다.
- 시뮬이 고정 틱으로 돌고 화면 프레임과 따로다.
- 봇 · AI 나라가 수백 개 동시에 돌고 시드 난수로 결정적이다.

### 설계

| 신호 | 무엇이 보이나 |
|---|---|
| 지도 | 큰 격자 지도(수백만 칸)를 여러 나라가 칸 단위로 칠해 가며 넓힌다. 승리는 땅 비율이다 |
| 틱 | 시뮬이 고정 틱(수십~수백 ms)으로 돌고, 화면 프레임과 따로다. 멀티 대비로 명령(intent) → 실행(execution) 구조가 보인다 |
| 워커 | 원본 코드가 워커(Web Worker)에서 돌고, 메인 스레드는 틱마다 「바뀐 칸 · 플레이어 · 유닛」 갱신만 받는다 |
| 결정성 | 봇 · AI 나라가 수백 개 동시에 돈다. 시드 난수로 결정적이다. 틱 해시를 보내는 코드가 있으면 거의 확실하다 |
| 그리기 | 영토 · 국경 그리기가 GPU 텍스처(칸 값 → 팔레트)다 |

## 더 볼 질문

### 요약

- 결정성이 있으면 원본 번들을 node 로 돌려 틱 해시 정답지를 만든다.
- 순서가 결과를 바꾸는 자료구조와 수 표현을 먼저 찾는다.
- 팀 모드와 AI 모드 분기는 인원 많은 팀 판에서만 드러난다.

### 설계

| 질문 | 왜 |
|---|---|
| 시뮬이 결정적인가. 틱 해시 · 시드 난수 · 정수(BigInt) 병력이 있나 | 있으면 원본 번들을 node 로 돌려 틱 해시 정답지를 만들 수 있다 ([공통절차 - 원본 관측 도구](공통절차%20-%20원본%20관측%20도구.md) 「node 틱 정답지」). 눈 대조보다 훨씬 강하다 |
| 실행(execution)의 생애. 추가 → init → tick 이 같은 틱인가 다음 틱인가. 스폰 단계에도 도나 | 한 틱 어긋나면 해시가 첫 판에서 갈린다 |
| 순서가 결과를 바꾸는 자료구조. 삽입 순서 Set · 스왑 삭제 배열 · 힙 · 안정 정렬 | JS Set 순회 순서 · Float32 우선순위 힙 · `sort` 안정성이 그대로 결과다. C# 기본 컬렉션으로 바꾸면 틀린다 |
| 수 표현. Float32 · double · BigInt 가 어디서 섞이나. `Math.round` 와 칸 0 을 거짓으로 보는 자리는 어디인가 | 반올림 규칙(`floor(x+0.5)`)과 「칸 0 = 없음」 버그가 원본 동작이다 |
| 지도는 몇 벌인가. 본 지도 · 작은 지도(길찾기용) · 해안 비트 | 작은 지도를 만드는 규칙이 원본 파일 그대로인지, 코드가 줄이는지 확인한다 |
| 길찾기 종류. 물길 · 철도 · 포물선 · 격자 직선 · 캐시 | 종류마다 따로 대조한다. 캐시가 있으면 호출 순서도 결과다 |
| AI 는 몇 층인가. 봇 · 나라(성격 · 난이도) · 공유 상태 | 나라끼리 공유 상태가 있으면 한 판에 하나다 |
| 칸 다시 칠하기 박자. 틱마다 전부인가, 우선순위 줄에서 일부씩인가 | 화면이 원본처럼 「번지는」 느낌이 여기서 나온다 |
| HUD 는 DOM 인가 · px 고정인가 | 캔버스 배율 결정([표현 - DOM CSS UI](표현%20-%20DOM%20CSS%20UI.md))으로 이어진다 |
| 범위 밖(멀티 · 계정 · 순위표 · 광고)이 싱글 흐름 어디에 끼어 있나 | 싱글 시작이 광고 콜백 뒤인 것처럼 흐름에 박혀 있으면 끊는 자리를 정한다 |
| 팀 모드가 있나. 팀 나누기 규칙(균형 · 해시 · 섞기 시드) · 봇 팀 · 승자가 플레이어인가 팀 이름인가 | 팀 배정 순서가 틀리면 첫 틱부터 갈린다. 승자 자료형이 다르면 판 끝 화면 배선이 갈린다 |
| AI 의 모드 분기. `gameMode` · `isFFA` 를 번들 전체에서 전수로 찾았나 | 팀원이 둘 이상일 때만 도는 분기(팀원 돕기 · 팀 집계)는 2팀 판에서는 안 드러나고 인원 많은 팀 판에서만 수백 틱 뒤에 갈린다. 팀 구성마다 시나리오를 따로 둔다 |

## Unity 구조 차이

### 요약

- 시뮬은 엔진 참조가 없는 순수 C# 이고 매니저가 고정 틱으로 돌린다.
- 칸마다 GameObject 를 두지 않는다. 사각형 하나와 텍스처 셋으로 그린다.
- 검증은 node 원본 틱 해시 정답지가 중심이다.

### 규칙

- 원본 코드를 스크래치에서 돌려도 프로젝트에는 넣지 않는다 ([원칙 R11](원칙.md#R11)).

### 설계

| 자리 | 공통 규약 | 이 장르 |
|---|---|---|
| 시뮬 | 매니저가 프레임마다 | 순수 C# 시뮬(엔진 참조 없음). 매니저는 시간을 모아 고정 틱으로 돌리고, 밀린 틱은 한 프레임 시간 한도 안에서만 몰아 돈다 |
| 명령 | 창 event → 매니저 호출 | 창 · 입력은 명령 객체를 매니저에 싣고, 다음 틱에 실행으로 바뀐다. 멀티가 범위 밖이어도 이 구조를 지킨다. 원본 순서가 여기서 정해진다 |
| 칸 | 칸마다 GameObject | 없다. 사각형 하나 + 텍스처 셋(지형 · 칸 값 · 팔레트) + 셰이더. 국경 판정은 CPU 가 칸 값 비트로 넣는다 |
| 유닛 · 이름 | 프리팹 인스턴스 | 유닛 갱신 이벤트를 모아 프레임에 한 번 반영. 이름 자리는 틱마다 일부 플레이어만 다시 계산 |
| 검증 | 재생 캡처 대조 | ① node 원본 틱 해시 정답지. 시나리오 여럿(스폰만 · 사람만 · 봇만 · 전체 짧게 · 전체 길게) ② 길찾기 · 색 · 난수 따로 대조 ③ 재생 흐름 검사 |
| 데이터 | 표 → 컨테이너 | 설정 · 난이도 · 성격 · 지형 · 유닛 · 핵 표를 한 설정 객체로 모아 시뮬에 넘긴다. 시뮬은 GameRoot 를 모른다 |

- 긴 시나리오(수천 틱)까지 해시를 대조한다. 짧은 시나리오는 배 · 핵 · 기차 같은 늦게 등장하는 실행을 안 지난다.

## 함정

### 요약

- 원본이 안 넘기는 값을 「당연히 쓰일 것」으로 채우면 시작부터 갈린다.
- 원본 설명 창과 설정 창이 화면 구성의 근거다.
- 시뮬만 옮기고 그리는 뷰를 안 세면 화면에 없는 것이 생긴다.

### 설계

- 원본이 플레이어 정보에 넘기지 않는 값(예: 나라 강도)을 「당연히 쓰일 것」으로 채우면 시작 병력부터 갈린다. 해시 대조가 잡는다.
- 스폰 단계에 한 번 꺼진 HUD 묶음을 `activeSelf` 로 다시 읽어 켜면 영영 안 켜진다. 켜짐 의도는 따로 든다.
- 같은 타입을 두 에이전트가 따로 만들면(길찾기 결과 구조체 등) 합칠 때 이름 · 필드가 어긋난다. 병렬 작업 전에 인터페이스 파일을 먼저 못 박는다.
- 빌더가 굽는 시점에 코드로 만든 스프라이트(런타임 Texture2D)를 이미지에 넣으면 프리팹에 저장되지 않아 빈 칸이 된다. 도형 아이콘은 창이 열릴 때 넣는다.
- HUD 가 HTML 인 원본은 「창을 열기 전 · 연 뒤」 요소 목록을 비교하면 새로 생긴 요소만 뽑힌다 (자리 · 글자 크기 · 색 · 테두리). 원형 메뉴처럼 SVG 로 그린 것은 SVG 속 조각(id · fill · cursor)을 따로 뜯는다. 판 끝 창은 규칙 「게임 시간」 을 최소로 켜서 띄운다.
- 원본 설명 창의 조작 설명과 입력 소스가 다를 수 있다 (Ctrl+클릭). 입력은 소스 핸들러(포인터 업 · 휠 · 보조 키)를 기준으로 옮기고 설명 창은 그 결과에 맞춘다.
- 플레이어 이름이 시뮬 박자에 들어갈 수 있다 (이름 해시로 주기 검사 틱을 정하는 식). 이름을 저작권 때문에 새로 지으면 원본 실행에도 같은 새 이름을 끼워 정답지를 만든다. 안 그러면 일부 시나리오만 수백 틱 뒤에 갈려 엉뚱한 곳을 뒤진다.
- 원본 「설명」 창(도움말 탭들)이 **화면 구성의 근거** 다. 조각 · 버튼 목록을 상태 하나(중립 상대)만 재면 빠진다. 동맹일 때만 뜨는 조각(기부 · 배신)처럼 상태가 바뀌면 메뉴가 늘어난다. 설명 창 탭을 전부 떠서 목록으로 삼는다.
- 설정 창은 항목이 많다(이 게임 11개). 「기능이 있는 것만」 옮기면 창이 원본과 딴판이 된다. 항목을 먼저 표로 옮기고, 기능이 없는 항목은 값만 저장하고 의도된 차이로 적는다.
- 이모지로 말하는 게임은 글꼴에 이모지가 없으면 두부가 된다. 이모지 글꼴을 받지 않기로 했으면 코드로 그린 표식으로 바꾸고, 그 대응표를 한곳에 둔다.
- 튜토리얼 오버레이(비추기 · 조준경 · 브리핑)는 HTML 요소의 **상자** 를 따라간다. 유니티에선 HUD · 원형 메뉴 창이 **비출 자리의 네 귀퉁이** 를 알려 주는 함수를 두고, 튜토리얼 창은 그 상자를 캔버스 좌표로 바꿔 쓴다. 원형 메뉴처럼 SVG 조각이면 부채꼴 둘레로 상자를 잰다.
- 목표를 건너뛰는 튜토리얼 검사는 **스폰 단계가 끝난 뒤** 에 돌린다. 스폰 단계엔 조작 판이 숨고 건설 조각이 꺼져 브리핑 · 건설 안내가 안 뜬다.
- 시뮬이 내는 알림(유닛 · 철도 · 정복 · 금 · 이모지)마다 **그리는 뷰** 가 있는지 목록으로 확인한다. 시뮬만 옮기면 화면에 없는 것이 생긴다. 철도가 그 예였다(이벤트는 있는데 그리는 코드가 없었다).
- 설정 스위치를 화면 기능으로 옮기기 전에, 원본 **그리기 코드가 그 설정을 읽는지** 를 찾는다. 안 읽으면 값만 저장하는 설정이다. 읽는 곳을 못 찾았는데 그림을 지어내면 원본에 없는 화면이 된다.
- 작은 지도(길찾기 · 축소 판)를 만드는 규칙을 못 찾았으면, node 정답지에도 그 임시 지도가 들어간다. 그 대조는 작은 지도를 쓰는 길(배 길 · 축소 판 · 튜토리얼)을 증명하지 못한다. 같은 지형을 공개한 원본(예: 원작 저장소의 축소 지도 파일)이 있으면 그것을 양쪽에 쓰고, 차이를 「의도된 차이」 로 적는다.
