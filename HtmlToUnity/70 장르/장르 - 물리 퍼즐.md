# 장르 - 물리 퍼즐

한 발을 쏘아 물리로 푸는 레벨제 퍼즐에서 더 볼 것과 Unity 구조 차이다.

## 알아보는 신호

### 요약

- 홀드로 힘을 모아 한 발을 쏜다.
- 충돌 · 튕김을 거쳐 목표에 넣으면 다음 레벨로 간다.
- 한 판의 결과를 물리 시뮬레이션이 정한다.

### 설계

| 신호 | 무엇이 보이나 |
|---|---|
| 입력 | 입력이 조준 · 홀드 · 릴리즈뿐이고 한 판의 결과를 물리 시뮬레이션이 정한다 |
| 바디 | 런타임 인스턴스에 물리 바디가 있고 반발 · 마찰 · 밀도 · 감쇠 · 충돌 도형이 속성으로 보인다 |
| 레벨 | 레벨마다 바뀌는 것은 배치와 조준이고, 성공/실패가 홀드 한 축의 구간으로 갈린다 |

## 더 볼 질문

### 요약

- 엔진 · 스텝 · 계수 · 홀드 · 발사 · 조준 · 충돌 쌍 · 골 판정 · 배치 · 비결정을 따로 묻는다.
- 월드 스케일과 스텝이 반발 임계를 가른다.
- 답은 원본 인스턴스 속성과 코드에서 잰다.

### 설계

| 주제 | 질문 |
|---|---|
| 엔진 | 원본 물리 엔진 계열은 무엇이고 월드 스케일(1 미터 = 몇 px)은 얼마인가 |
| 스텝 | 스텝은 프레임당 몇 번이고 dt 는 가변인가. 상한 클램프 · 따라잡기가 있나. 솔버 반복은 엔진 기본값인가 |
| 계수 | 반발 · 마찰 혼합 규칙, 반발이 죽는 속도 임계, 잠듦 허용은 어디서 정해지나. 게임이 바꿀 통로가 있나 |
| 홀드 | 홀드는 무엇으로 힘이 되나. 경과 시간의 식인가 틱마다 누적되는 변수인가. 누적이면 도달 가능한 값이 이산 격자인가. 상한 · 최소 발사 조건은 무엇인가 |
| 발사 | 발사가 위치 · 속도 말고 무엇을 주나(각속도). 발사점은 상수인가 홀드의 함수인가. 발사 액션은 그 틱 스텝 앞인가 뒤인가 |
| 조준 | 조준은 레벨 데이터인가 포인터 입력인가 |
| 충돌 쌍 | 생성되지 않는 충돌 쌍이 있나. 그림 인스턴스와 충돌 인스턴스가 따로인가 |
| 골 판정 | 목표 판정은 물리 도형인가 별도 감지 영역인가. 플래그를 무엇이 켜고 무엇이 리셋하나 |
| 배치 | 배치 중 물리가 정한 자리(떨어져 정착한 개체)가 있나. 바디 원점은 bbox 어디인가 |
| 비결정 | 원본이 같은 입력에 갈리는 구간(모서리 스침 · 저속 정착 · 긴 반발 사슬)은 어디이고 빈도는 얼마인가 |

## Unity 구조 차이

### 요약

- 같은 계열이면 Unity 2D 물리에 읽은 파라미터를 1:1 로 넣는다.
- 스케일 · 부호 환산은 로드 지점 한 함수만 지난다.
- 스텝은 고정, 프레임당 하나, 하위스텝 끔이다.
- 채점은 재생 경로에서 시행마다 물리 월드를 새로 만들어 한다.

### 규칙

- 피팅 곡선 표는 관측 메움이라 두지 않는 쪽이다([원칙 R4](원칙.md#R4)).

### 설계

| 자리 | 기본과 이유 |
|---|---|
| 엔진 | 기본은 같은 계열이면 Unity 2D 물리에 읽은 파라미터를 1:1 로 넣는다. 이유: 반사 벡터로 튕기는 자체 적분기는 마찰×회전 관성을 원리적으로 못 낸다([Client](Client.md) 「물리 엔진」). 원본이 자체 적분기면 그 이식을 고려한다 |
| 스케일 · 부호 | 기본은 월드 단위를 원본 엔진 미터에 맞추고, 데이터는 원본 px 로 두어 로드 지점 한 함수에서 환산한다. 회전 · y 부호도 그 함수를 지난다. 이유: 반발 임계가 미터 기준이다 |
| 스텝 | 기본은 원본 평균 dt 와 같은 rate 의 고정 스텝, 프레임당 한 스텝, 하위스텝 끔이다. 원본 가변 dt 흔들림과 입력 프레임 양자화는 재현 대상이 아니다. 우리가 더 결정적인 것은 결함이 아니다. 원본 따라잡기 · 다중 스텝이 거동을 만들면 그 구조를 고려한다 |
| 설정 감사 | 솔버 반복 · 반발 임계 · 잠듦 상수 · 스텝을 한 곳에서 세우고 엔진에서 되읽어 대조한다. 기본값과 같아도 적는다. 이유: 설정 파일 값은 실효값이 아닐 수 있다 |
| 파워 | 기본은 홀드→힘을 원본 기전(누적 · 클램프)으로, 힘→속도를 질량에서 계산한다. 이유: 누적이면 도달 값이 이산 격자다 |
| 레벨 데이터 | 레벨이 갖는 값만 행으로 둔다. 콜라이더 크기는 프리팹이, 목표 부품 · 감지기 오프셋은 전역 설정이, 정착 자리는 유도 함수가 든다. 배치 좌표는 원본 그대로 둔다(격자로 재구성하면 원본의 어긋남 · 겹침이 사라진다). 원본이 격자 데이터면 격자로 든다. 콜라이더 크기와 격자 피치는 따로다 |
| 충돌 배제 | 기본은 쌍 단위다. 이유: 레이어 매트릭스는 저장소 전역이고 쌍보다 넓다 (함정: [게임 하나 기준으로 박힌 프로젝트 전역 설정](함정%20-%20설정%20빌드.md#게임%20하나%20기준으로%20박힌%20프로젝트%20전역%20설정)). 전용 레이어가 있으면 레이어도 선택지다 |
| 골 판정 | 기본은 물리 바디가 아닌 영역 겹침으로 시뮬 코드에 두고 원본 플래그 수명을 그대로 옮긴다. 이유: 켜고 리셋하는 순서가 틱 안에 있다. 원본이 물리 도형으로 판정하면 그쪽을 고려한다 |
| 정답지 | [Transfer_Programmer](Transfer_Programmer.md) 「정답지와 채점기」의 항목은 발사 프레임 · 첫 반발 전 궤적 · 접촉점(위치 · 법선 · 속도 · 각속도) · 레벨별 성공 창이다. 입력 축은 원본 내부 힘 변수, 극값은 보간 꼭짓점, 첫 반발 뒤 좌표는 접촉 정답지로만 본다 |
| 밸런싱 | 레벨마다 입력 전 구간을 격자로 훑어 성공 창을 원본과 격자점마다 대조한다. 비교 축은 갈린 격자점 수다 ([Client](Client.md) 「난이도가 같다」) |
| 채점 | 기본은 재생 경로에서, 시행마다 물리 월드를 새로 만들어, 검증용 진입점 없이 실제 홀드 경로로 한다. 이유: 월드 재사용은 스침 샷을 가르고, 진입점은 실제 경로를 안 지난다. 재사용은 초기화를 대조로 증명했을 때만 고려한다 |

## 함정

### 요약

- 원본 엔진 값을 안 읽고 손계산 · 역산 · 인상으로 메우는 사고가 가장 많다.
- 검사기 쪽 사고(월드 재사용 · 기록 시점 · 부분 구간)가 그다음이다.
- 옛 번호(`#N`)는 그대로 둔 항목 번호다.

### 규칙

- #강제 [원칙 R4](원칙.md#R4) 솔버 값은 인상이 아니라 원본 실측에서만 온다.
- #강제 [원칙 R9](원칙.md#R9) 비결정으로 빼는 구간에는 충분한 원본 시행 근거와 뺀 건수가 붙는다.

### 설계

| 사고 | 근거 |
|---|---|
| 원본 엔진을 안 보고 손계산 모델로 옮겨 다중 반발 뒤 갈렸다 | [물리 엔진 원본을 손계산 모델로 옮긴 함정](함정%20-%20물리%20엔진.md#물리%20엔진%20원본을%20손계산%20모델로%20옮긴%20함정) |
| 월드 스케일을 원본과 다르게 잡아 반발 임계가 어긋났다 | #50 |
| 물리 계수·골인 규칙을 쏴서 역산했다. 인스턴스 속성·이벤트 시트에 원문이 있었다 | #45 · #56 |
| 공칭 홀드를 입력 축으로 써 레벨마다 파워가 다르다는 가짜 결론이 났다 | #46 |
| 발사점을 한 홀드에서만 재 상수로 옮겼는데 홀드의 함수였다 | #76 |
| 발사 각속도를 원본 부호 그대로 넣어 반대로 돌았다 | #81 |
| 설정 파일의 스텝 값을 실효값으로 믿었다 | #78 |
| 효과가 안 보인다고 실측 솔버 값을 되돌리려 했다 | #82 · #48 |
| 닿은 접촉만 세서 발사대 쌍이 생성되지 않는 것을 못 봤다 | #91 · #92 |
| 물리가 정착시킨 자리를 레벨 데이터로 박았다 | #102 |
| 적은 시행으로 원본 비결정을 등재해 한 방향 계통 오차를 덮었다 | #83 · #90 · #69 |
| 극값을 프레임 샘플 최대로 재 위상을 비결정으로 읽었다 | #89 |
| 검사기가 월드를 재사용해 스침 샷만 같은 입력에 답이 갈렸다 | #109 · #106 |
| 접촉 시각을 스텝 전에 적어 물리 결함으로 읽었다 | #110 |
| 틱 안 호출 순서를 시계열로 추측했다 | #107 |
| 누적 입력이 못 내는 격자 사이 값을 정답지로 골랐다 | #112 |
| 부분 구간만 훑고 레벨 난이도를 결론냈다 | #74 · #73 |
| 클리어를 이벤트 도착 시각으로 귀속해 원본 이상을 오보했다 | #40 · #85 |
