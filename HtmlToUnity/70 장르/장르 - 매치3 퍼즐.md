# 장르 - 매치3 퍼즐

격자 칸을 교환해 지우는 퍼즐에서 더 볼 것과 Unity 구조 차이다.

## 알아보는 신호

### 요약

- 격자 칸을 교환해 같은 종류 연속을 지운다.
- 빈 칸을 낙하 · 보충으로 메우며 연쇄가 이어진다.
- 상태가 칸 배열 하나이고 인덱스 산술이 보이면 이 장르다.

### 설계

| 신호 | 무엇이 보이나 |
|---|---|
| 상태 | 상태가 칸 배열 하나이고 `i % width` · `i + width` 같은 인덱스 산술이 보인다 |
| 판정 함수 | 가로 · 세로 연속 판정 함수가 길이별로 있고, 주기 함수 하나가 판정 → 낙하 → 보충을 부른다 |
| 입력과 표식 | 입력이 인접 두 칸 교환이고 빈 칸 표식(빈 문자열 · `-1` · `null`)이 있다 |

## 더 볼 질문

### 요약

- 판정 · 제거 · 연쇄 · 낙하 · 점수 · 인접 · 교환 · 난수 · 모드 · 연출을 따로 묻는다.
- 경계 거동과 호출 순서가 답의 핵심이다.
- 답은 원본 코드에서 잰다.

### 설계

| 주제 | 질문 |
|---|---|
| 판정 | 판정 함수의 호출 순서는? 루프 상한 · 건너뛰기 조건은 폭에서 어떻게 파생되고, 어긋나는 상한이 있나? |
| 제거 | 찾자마자 지우나, 다 찾고 한꺼번에 지우나? 이미 비운 칸을 거르는 가드는 어느 칸 기준인가? |
| 겹친 매치 | 판정 길이보다 긴 연속, 한 칸을 공유하는 L · T 모양은 몇 점이고 무엇이 남나? |
| 연쇄 | 한 주기에 연쇄가 끝까지 도나, 한 단계만 도나? 판정과 낙하가 같은 주기에 붙어 있나? |
| 낙하 | 낙하 루프의 순회 방향은? 한 호출에 한 칸인가, 빈 칸 끝까지인가, 열 압축인가? 보충은 어느 행에서 낙하 전인가 후인가? |
| 점수 | 점수는 매치 단위인가 칸 단위인가? 표시는 판정 안에서 갱신되나? |
| 인접 | 인접 판정은 인덱스 차이인가 좌표인가? 행 경계 가드가 있나? 무매치 교환을 되돌리나? |
| 교환 순서 | 먼저 바꾸고 되돌리나, 검사하고 바꾸나? 인덱스 `0` 이 falsy 로 걸리나? 무효 교환 뒤 드래그 상태가 남나? |
| 난수 | 초기 보드의 매치를 재추첨하나? 초기 보드와 보충은 어떤 난수를 쓰나? |
| 모드 | 모드마다 무엇이 다르고, 종료 때 루프 · 입력 · 판을 각각 어떻게 두나? |
| 연출 | 제거 · 낙하 · 교환에 애니메이션이 있나, 값만 즉시 바뀌나? |

## Unity 구조 차이

### 요약

- 보드는 순수 데이터 매니저가 들고 뷰는 표기만 한다.
- 원본 배열 차원 · 순회 방향 · 호출 순서를 그대로 둔다.
- 칸은 시작 때 전부 만들고 풀링하지 않는다.
- 난수는 주입식 하나로 실제 경로를 지난다.

### 규칙

- #강제 [원칙 R10](원칙.md#R10) 원본에 없는 트윈은 의도된 차이로 등재한 것만 들어간다.

### 설계

| 자리 | 기본과 이유 |
|---|---|
| 보드 | 기본은 보드를 순수 데이터 매니저가 들고 칸 값을 종류 인덱스와 빈 칸 상수로 둔다. 원본 표현(이미지 문자열 비교)은 버리고 절차만 옮긴다. 이유: 하네스로 대조된다. 빈 문자열 표식이 거동을 만들면 그 거동은 살린다 |
| 배열 차원 | 원본이 1차원 배열이면 기본은 1차원으로 든다. 이유: 인덱스 산술과 경계 거동이 같이 온다 ([UIFramework](UIFramework.md) 「고정 격자」). 2차원이면 행 경계 거동을 회귀 벡터에 넣는다 |
| 판정 · 낙하 | 원본 함수당 메서드 하나로, 호출 순서 · 순회 방향 · 제자리 수정을 그대로 둔다. 상한은 폭에서 파생식으로 계산하고 원본 값은 주석에 둔다 ([Client](Client.md) 「순회 방향」 · 「먼저 처리한 것이 뒤 판정을 막는다」) |
| 주기 | 기본은 중앙 틱 하나, 한 프레임에 한 틱이다(밀린 틱 몰아 돌리기 없음). 이유: 연쇄 단계가 보인다. 원본 타이머가 몰아 돌면 PD 확정에 올린다. 모드 · 타이머는 별도 매니저가 보드 시작 · 정지만 부른다 |
| 뷰 | 뷰는 표기만 한다. 보드 변경 이벤트에 창이 전 칸 그림을 다시 넣고 칸은 인덱스만 든다. 기본은 칸을 시작 때 전부 만들고 풀링은 없다 ([PrefabRule](PrefabRule.md)). 이유: 고정 격자다. 판 크기가 모드마다 바뀌면 풀링을 고려한다 |
| 재생 | 기본은 칸별 재생 컴포넌트 없이, 원본에 낙하 · 제거 애니메이션이 없으면 값을 즉시 바꾼다 ([SKILL - 잘못 옮긴 것](SKILL%20-%20잘못%20옮긴%20것.md) 「재생 계층」). 이유: 칸 수가 많다. 원본에 칸 단위 연출이 있으면 칸별 재생을 고려한다 |
| 끌어 놓기 | 기본은 드래그 시작 · 드롭 · 드래그 끝 핸들러로 접고, 원본 실행 순서 · 인덱스 인접 판정 · 입력 잠금 해제 시점까지 옮긴다 ([UIFramework](UIFramework.md) 「입력」). 이유: 무효 교환 뒤 거동이 순서에서 나온다. 원본이 두 번 눌러 고르면 그 구조를 고려한다 |
| 난수 | 초기 보드와 보충은 주입식 RNG 하나를 쓴다 ([Client](Client.md) 「수치 계층」). 이유: 검증용 진입점 없이 실제 경로로 대조된다 |

## 함정

### 요약

- 경계 거동을 「바로잡아」 옮기는 사고가 가장 많다.
- 원작 기억으로 없는 규칙을 채우는 사고가 그다음이다.
- 검사기가 실제 경로를 안 지나면 전부 통과한다.

### 규칙

- #강제 [원칙 R1](원칙.md#R1) PD 확정 전까지 재현이 기본이다.
- #강제 [원칙 R3](원칙.md#R3) 교환 취소 · 재추첨은 원본 코드에 있을 때만 옮긴다.

### 설계

| 사고 | 함정 노트 |
|---|---|
| 모자란 상한 · `0` falsy · 경계 가드 누락을 고쳐서 옮긴다 | [원본 버그를 고쳐서 옮긴 이관](함정%20-%20판정%20보고.md#원본%20버그를%20고쳐서%20옮긴%20이관) |
| 겹친 매치 · 긴 연속 · 연속 빈 칸을 교과서대로 짜 합산 점수 · 열 압축이 된다. 겹치는 입력을 벡터에 안 넣으면 안 잡힌다 ([PD](PD.md) 「「이상」과 「직관과 다른 것」을 가른다」) | [순수 함수만 잰 골든 테스트](함정%20-%20검사기%20설계.md#순수%20함수만%20잰%20골든%20테스트) |
| 상한을 파생 조건식으로 「바로잡아」 원본 경계 거동이 사라진다 | [기전 대신 파생 규칙을 조건식으로 옮김](함정%20-%20측정%20추론.md#기전%20대신%20파생%20규칙을%20조건식으로%20옮김) |
| 「검사 후 교환」으로 뒤집어 화면은 같은데 경계 칸 거동이 사라진다 | |
| 원작 기억(매치 없는 교환 취소 · 초기 매치 재추첨)으로 없는 규칙을 채운다 | |
| 자동 진행 · 무작위 보충이 섞인 판에서 델타를 잰다. 매치 없는 기저 보드에 패턴을 심고 보충 칸은 빼고 한 틱 전체 결과로 대조하면 잡힌다 | [자동 진행이 섞인 판에서 델타를 잼](함정%20-%20측정%20추론.md#자동%20진행이%20섞인%20판에서%20델타를%20잼) |
| 검증용 치트 API 를 보드에 뚫는다. 주입 RNG · 틱 인자로 세운다 | [게임 코드에 뚫은 하네스 전용 진입점](함정%20-%20검사기%20설계.md#게임%20코드에%20뚫은%20하네스%20전용%20진입점) |
| 헤드리스 재생에서 프레임 수로 기다려 틱이 안 돈다고 읽는다 | [프레임 수로 기다리는 자동 검사](함정%20-%20검사기%20설계.md#프레임%20수로%20기다리는%20자동%20검사) |
| 「끌어도 안 움직인다」를 입력으로 뒤졌는데 판이 화면 밖이었다 | [폭 하나로만 맞춘 기준 해상도](함정%20-%20UI%20흐름.md#폭%20하나로만%20맞춘%20기준%20해상도) |
