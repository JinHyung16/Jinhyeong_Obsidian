# 표현 - 도트

원본 그림이 픽셀 아트일 때 공통 규칙에 더해 잴 것과 달라지는 자리다.

## 알아보는 신호

### 요약

- 원본 그림이 스프라이트 · 시트 · 타일셋 · 9슬라이스 UI 로 된 픽셀 아트다.
- 작은 텍스처를 크게 그리고 서브렉트로 컷을 돌린다.
- 전역 서체가 픽셀 서체다.

### 설계

| 신호 | 무엇이 보이나 |
|---|---|
| 아틀라스 | 네트워크 로그에 아틀라스(json + png)와 여러 컷을 가로로 이어붙인 시트형 프레임이 있다 |
| 서브렉트 | 런타임이 텍스처 서브렉트(`texture.frame`)를 바꿔 컷을 돌린다 |
| 확대 | 작은 텍스처를 크게 그린다. 덤프에서 그린 크기가 컷 × 배율이면 정수배 확대, 아니면 9슬라이스 생성자 호출이다 |
| 타일셋 | 지형이 메시 한 장이어도 정점 · UV 가 일정 격자에 놓이면 타일셋이다 |
| 서체 | 전역 서체가 픽셀 서체다(대개 고정폭) |

## 더 볼 질문

### 요약

- 해상도 · 배율 · 시트 규격 · 피벗 · 9슬라이스 인셋 · 알파 · 틴트 · 타일 분기 · 서체를 따로 묻는다.
- 맞추는 단(존재 · 규격 · 형태·색 · 픽셀 배치)을 먼저 정한다.
- 답은 원본 파일과 호출부에서 잰다.

### 규칙

- #강제 [원칙 R12](원칙.md#R12) 맞추는 단은 사람이 정한다.

### 설계

| 주제 | 질문 |
|---|---|
| 해상도 | 논리 해상도의 어느 축이 고정인가. 화면 배율은 얼마이고 개체마다 표시 배율이 다른가 |
| 시트 갈래 | 아틀라스가 애니메이션으로 선언한 그룹과 런타임이 서브렉트로 자르는 시트는 각각 몇 개인가 |
| 시트 규격 | 시트마다 한 컷 크기 · 열×행 · 실제로 도는 칸은 무엇인가. 행이 상태(대기 · 이동)를 가르나 |
| 재생 속도 | 시트마다 fps · loop 는 무엇인가. 소스 `animationSpeed` 와 서브렉트가 바뀌는 간격이 같은가 |
| 트림 · 피벗 | 트림이 있나. 피벗(앵커)은 컷마다 어디인가 |
| 9슬라이스 | 9슬라이스 인셋은 호출부 인자로 얼마인가. 같은 텍스처가 자리마다 다른가. 늘리는 방식은 폭 키우기인가 자르기인가 |
| 알파 | 알파가 불투명/투명 둘뿐인가, 반투명 단계(그림자 · 글로우)가 있나 |
| 착색 | 흰색으로 굽고 틴트로 칠하나, 원색 그대로인가. 좌우 방향은 배율 부호인가 별도 그림인가 |
| 타일 | 타일셋에서 실제로 쓰는 칸은 무엇인가. 자동 타일링 분기(`tileId` 상수)는 몇 갈래이고 변종은 무슨 규칙으로 고르나. 패스 순서는 무엇인가 |
| 서체 | 서체는 고정폭인가. 확보할 수 있나. 테두리가 있나 |
| 맞추는 단 | 존재 · 규격 · 형태·색 · 픽셀 배치 중 어느 단까지 맞추나([공통절차 - 원본에서 값 캐기](공통절차%20-%20원본에서%20값%20캐기.md) 「자산 단계」) |

## Unity 구조 차이

### 요약

- 임포트는 코드로 Point · 무압축 · mip 끔 · Clamp 를 건다.
- PPU 는 월드와 UI 두 갈래다.
- 시트 재생은 개체당 Animator 대신 프레임 인덱스와 중앙 틱이다.
- 재제작은 규격 실측 → 규격 JSON → 빌더 굽기 → 채점기 순서다.

### 규칙

- #강제 [원칙 R11](원칙.md#R11) 원본 파일을 뽑아 넣는 대신 규격을 재서 굽는다.
- #강제 [원칙 R12](원칙.md#R12) 사람이 정한 예외(원본에 있지만 걷을 것)는 원본에 있다는 측정보다 위다.

### 설계

| 자리 | 기본과 이유 |
|---|---|
| 임포트 | 기본은 생성기가 코드로 `FilterMode.Point` · 무압축 · mip 끔 · NPOT 스케일 끔 · Clamp 를 건다. [ResourceRule](ResourceRule.md) 공통 규격(플랫폼 압축 · 4의 배수)과 갈린다. 블록 압축은 도트를 번지게 한다. 확정표에 용량 제약이 있으면 정수배 확대 비교로 번짐을 보고 압축을 고려한다 |
| PPU | 기본 두 갈래다. 월드는 타일 한 칸이 1 유닛이 되게 한 상수로 두고 환산은 한 곳만 지난다. UI 는 캔버스 기준 PPU 와 같게 둔다. 개체별 표시 배율은 프리팹에 둔다 |
| 격자 자르기 | 컷 크기 · 열 · 행 · 피벗은 데이터 표에서 읽는다. 기본은 격자 수를 임포트된 텍스처 크기가 아닌 표나 PNG 헤더에서 뽑는다(임포트 크기는 NPOT 반올림 뒤일 수 있다). 원본 행 순서와 텍스처 y 뒤집기는 한 곳에서 한다. 임포트 설정이 먹은 것을 되읽었으면 텍스처 크기도 쓸 수 있다 |
| 9슬라이스 UI | `Image.Sliced` + 표의 인셋을 Sprite Border 로 넣는다. `pixelsPerUnitMultiplier` 를 화면 배율의 역수로 넣어 그려지는 테두리가 인셋 × 화면 배율이 되게 한다. 폭이 자라는 채움 바도 기본은 Sliced 다(Filled 는 끝을 자른다). 원본이 자르는 방식이면 Filled 를 고려한다. 9슬라이스가 아닌 것은 정수배 Simple 로 둔다 |
| 시트 재생 | 기본은 개체당 Animator 대신 프레임 인덱스를 개체 데이터에 두고 중앙 틱이 진행한다. 스프라이트 세트는 인덱스 → 스프라이트 표이고 도는 칸만 묶음으로 읽는다. 이유: 원본도 서브렉트 인덱스로 컷을 돌리고 개체 수가 많다. 수가 적은 단일 캐릭터 · UI 연출은 Animator 를 고려한다 |
| 타일 | 타일은 Tilemap 에 칠한다. 제품은 역할만 알고 역할 ↔ 원본 `tileId` 대응은 검사가 든다. 이유: 역할 순서가 한 곳에 있어야 변종이 안 뒤바뀐다 |
| 재제작 순서 | 기본은 규격 실측 → 에디터 전용 규격 JSON → 빌더가 굽기 → 채점기다. 손으로 그리는 대신 이 순서를 탄다([Transfer_Artist](Transfer_Artist.md) 「아트 재제작」). 이유: 작은 도트는 픽셀 배치가 곧 형태다. 규격에 알파 축을 따로 두고 알파 포함 픽셀 일치로 채점한다 |
| 측정 입력 | 기본은 원본 이미지 파일 바이트다. 이유: 브라우저 캔버스(`getImageData`)는 저알파 색을 왜곡한다. 캔버스밖에 없으면 알파 오차 한계를 같이 적는다 |
| 색공간 | Linear 프로젝트에서 반투명 오버레이는 알파를 역산한다. 밝은 것은 내리고 어두운 것(딤 · 그림자)은 올린다. 역산은 헬퍼 한 곳, 호출부에는 원본 값([Fx](Fx.md) 「색공간」) |
| 사람이 정한 예외 | 기본은 그 예외를 굽는 입력 데이터나 프리팹([PrefabRule](PrefabRule.md))에 반영하고 회귀 검사가 지킨다. 이유: 다시 구워도 살아남는다 |

## 뒷받침

### 요약

- 뒷받침 1건이다.
- 전체가 「가설」이다. 이관 1건에서 뽑았다.

### 규칙

- 방향 노트다. 판단 대상이 아닌 것은 [원칙](원칙.md) 에만 있다.

### 설계

| 게임 | 원본 형태 | 아트 처리 |
|---|---|---|
| Undead Slayer | URL 제공형 | 원본 에셋 추출 금지, 규격 실측 후 재제작 |
