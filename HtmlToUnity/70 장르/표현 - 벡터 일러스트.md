# 표현 - 벡터 일러스트

원본 그림이 매끄러운 벡터 · 일러스트일 때 더 재고 다르게 옮길 것이다.

## 알아보는 신호

### 요약

- 확대해도 계단이 없고 곡선 가장자리가 안티에일리어싱이다.
- 외곽선 두께가 요소 크기와 무관하게 거의 일정하다.
- 그림이 엔진 텍스처인 경우와 그리기 호출인 경우가 둘 다 여기다.

### 설계

| 신호 | 무엇이 보이나 |
|---|---|
| 해상도 | 논리 해상도를 임의 캔버스 크기로 매끄럽게 늘린다. 확대해도 계단이 없고 곡선 가장자리가 안티에일리어싱이다 |
| 외곽선 | 외곽선 두께가 요소 크기와 무관하게 거의 일정하다 |
| 형태 | 둥근 모서리 · 그라디언트 음영 · 하이라이트가 있다 |
| 그리는 수단 | 그림이 엔진 텍스처이거나 그리기 호출(`stroke` · `createLinearGradient` · `shadowBlur`)이다. 둘 다 여기다 |

## 더 볼 질문

### 요약

- 해상도 비 · 그리는 수단 · 착색 기전 · 겹 수 · 외곽선 · 글로우 · 반투명 · 배경 · 서체를 따로 묻는다.
- 인스턴스 색은 유추하지 말고 직접 읽는다.
- 대조용 캡처는 정착 상태여야 한다.

### 설계

| 주제 | 질문 |
|---|---|
| 해상도 | 논리 해상도와 표시 캔버스의 비는 얼마인가. 기기 픽셀 비(DPR)를 따르나 |
| 그리는 수단 | 요소마다 텍스처인가 그리기 호출인가. 텍스처면 소스 크기와 표시 배율은 얼마인가 |
| 착색 | 색이 텍스처에 구워져 있나, 흰 마스크 + 인스턴스 틴트인가. 인스턴스 색을 직접 읽었나 |
| 겹 | 한 요소가 몇 겹인가(바탕 · 라인 아트 · 하이라이트). 색이 바뀌는 변종이 겹 분리를 요구하나 |
| 외곽선 | 외곽선은 절대 픽셀인가 크기 비례인가. 그 인자를 렌더러가 실제로 쓰나 |
| 글로우 | 글로우 · 가산 합성이 정말 있나. 발광처럼 보이는 것은 무엇인가(플래시 판 · 빛줄기 오브젝트). 그라디언트 방향과 정지점은 무엇인가 |
| 반투명 | 반투명이 어느 자리에서 무엇 위로 겹치나 |
| 배경 | 배경 층마다 원근 배율이 있나. 타일은 어느 원점에서 어느 방향으로 채우나. 같은 텍스처를 쓰는 다른 화면의 배치도 같나 |
| 서체 | 서체를 확보할 수 있나. 대소문자 변환 · 문구별 글자 외곽선 두께는 무엇인가 |
| 캡처 | 대조용 원본 캡처가 정착 상태인가(페이드 · 색 트윈 중이 아닌가) |

## Unity 구조 차이

### 요약

- 임포트 기본 필터는 Bilinear 이고 밉맵은 끈다.
- 잰 기하로 굽는 에디터 도구를 두고 IoU 로 대조한다.
- 그리기 호출 원본은 재구현하지 말고 페인터로 베이크한다.
- 게이트는 재생 정착 뒤 같은 해상도 픽셀 대조다.

### 규칙

- #강제 [원칙 R11](원칙.md#R11) 원본 파일을 뽑는 대신 잰 기하로 굽는다.
- #강제 [원칙 R10](원칙.md#R10) 서체 확보 불가면 대체를 의도된 차이로 등재한다.
- #강제 [원칙 R12](원칙.md#R12) 대체 서체는 사람이 정한다.

### 설계

| 자리 | 기본과 이유 |
|---|---|
| 임포트 | 기본 필터는 Bilinear 다(Point 는 늘릴 때 계단). 밉맵은 끈다(원본은 밉맵 없이 그려 켜면 축소 때 더 흐리다). 압축 · 크기 배수는 확정표다. 타일 · 9-slice · 늘리는 판은 Full Rect, 나머지는 Tight. 설정은 임포트 코드로 건다 |
| 굽기 | 기본은 잰 기하로 굽는 에디터 도구를 두고, 곡선은 슈퍼샘플, 구운 결과는 소스 마스크와 IoU 로 대조한다([Transfer_Artist](Transfer_Artist.md)). 외곽선이 절대 픽셀이면 절대 두께 상수 하나, 크기 비례면 그 비례로 굽는다(렌더러가 인자를 실제로 쓰는지도 본다) |
| 그리기 호출 원본 | 원본이 그리기 호출이면 기본은 캔버스 API 를 줄 단위로 받는 페인터로 베이크한다([Fx](Fx.md) 「절차 이펙트 베이크」 · 「선 굵기는 절대 픽셀이다」). 이유: 재구현하면 형상이 갈린다. 색 · 길이가 런타임에 크게 바뀌면 런타임 메시 · 셰이더를 고려한다 |
| 착색 | 틴트 기전이면 흰색으로, 테마를 안 따르면 색까지 굽는다. 색이 바뀌는 겹은 따로 둔다(합치면 변종마다 다시 굽는다, [ResourceRule - 리소스 굽기](ResourceRule%20-%20리소스%20굽기.md) 「절차 생성」) |
| 글로우 | `shadowBlur` 가 있으면 수식으로 적분해 굽고, 없으면 가산을 끈다([Fx](Fx.md) 「글로우」 · 「합성 모드」). 발광처럼 보이는 것은 플래시 판 · 빛줄기 같은 원본 오브젝트로 옮긴다 |
| 색공간 | Linear 에서는 반투명이 겹치는 자리만 뜬다. 원본 값은 코드에 두고 보정은 한 곳에서 한다([Fx](Fx.md) 「색공간」) |
| 배경 | 층 원근은 환산식으로 옮긴다. 화면마다 배치가 다르면 기본은 배치 클래스를 나눈다. 차이가 값뿐이면 데이터 표 하나를 고려한다. 타일 줄 위상은 원본 원점에 맞춘다 |
| 서체 | 대체 서체는 자폭 · 상자 맞추기 · 대소문자 변환을 옮기고, 글자 외곽선은 재질 에셋으로 문다([UIUX](UIUX.md) 「폰트」). 이유: 인스턴스 재질은 저장 때 사라진다 |
| 게이트 | 렌더 A/B 는 기본으로 재생 정착 뒤 같은 해상도로 찍어 원본 정착 캡처와 픽셀 대조한다. 기준 캡처는 원본만 보고 고른다([원칙 R5](원칙.md#R5)). 빼는 영역은 사유 · 면적째 찍는다([원칙 R9](원칙.md#R9)). 재제작이면 일치율은 읽는 숫자, 판정은 확정표 합격 기준이다 |

## 함정

### 요약

- 합성 화면 캡처와 요약 통계로 색 · 형상을 메우는 사고가 가장 많다.
- 브라우저 캔버스로 원본 픽셀을 읽으면 저알파가 왜곡된다.
- 사건 때만 쓰는 FX 자산과 화면별 배경 장식이 잘 빠진다.

### 규칙

- #강제 [원칙 R4](원칙.md#R4) 합성 캡처 · 요약 통계로 메운 자산색 · FX 형상은 값이 아니다.
