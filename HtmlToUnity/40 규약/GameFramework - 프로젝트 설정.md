# GameFramework - 프로젝트 설정

상위: [GameFramework](GameFramework.md)

확정표의 답을 프로젝트 설정에 넣고 검사로 지킨다.

## 확정표 반영

### 요약

- 확정표의 답이 프로젝트 설정에 안 들어가면 확정하지 않은 것과 같다.
- 에디터에서는 잘 돌아 아무도 모른다.
- 판정은 확정표의 각 행이 프로젝트 설정 어디에 들어갔는지 말할 수 있나다. 못 하면 반영 안 된 것이다.

### 규칙

- #강제 [원칙 R16](원칙.md#R16) 사람이 인스펙터를 돌아다니게 시키지 않는다 (`SKILL.md` 목적 3).
- 기본은 반영도 코드로 하는 것이다. 이유: 되풀이할 수 있고 검증에 넣을 수 있다.
- 반영 여부를 검증에 넣는 것이 기본이다. 이유: 다음 회차에 누가 되돌려도 잡힌다.
- 값의 출처는 그 게임의 확정표다. 이유: 설정 코드에 따로 적은 값은 확정과 갈라져도 에디터에서는 잘 돌아 아무도 모른다.

### 설계

| 확정표 | 반영 위치 | 안 하면 |
|---|---|---|
| 타깃 플랫폼 | 빌드 타깃 전환 | 텍스처 압축·셰이더 변형·스크립팅 백엔드가 다른 플랫폼 것이다 |
| 화면 방향 | 기본 방향 + 자동 회전 항목 전부 | 기기를 돌리면 원본에 없는 레이아웃이 나온다 |
| 화면 비율 | Canvas Reference + 플레이어 기본 해상도 | Game 뷰 비율이 달라 눈대중이 처음부터 어긋난다 |
| 색공간 | 색공간 설정 + 그래픽 API 목록 | Linear 는 구형 API 로 못 쓴다. 자동 선택이면 기기마다 색이 갈린다 |
| 리소스 해상도 정책 | 텍스처 압축 포맷 | 「4의 배수로 굽는다」의 근거(압축 블록)를 잃는다 |
| 데이터·아트 로드 단위 | 번들/라벨 설정 | 로드 경로가 런타임에만 드러난다 |

## 여러 게임의 빌드

### 요약

- 저장소에 게임이 여럿이면 빌드 직전에 그 게임 것을 적용한다.
- 프로젝트 설정은 하나다. 빌드가 확정표 적용을 안 부르면 마지막에 만진 게임의 방향 · 패키지 이름 · 제품명 · 시작 씬이 그대로 나간다.
- 에디터에서는 잘 돈다.
- 기본은 두 겹이다. 이유: ① 만 있으면 사람이 Build 버튼으로 구운 경로가 빠진다.

### 규칙

- #강제 [원칙 R23](원칙.md#R23) 씬이 없거나 둘 이상이면 굽지 않고 멈춘다. 씬 없이 구우면 빈 결과물이 「성공」으로 나온다.
- #강제 [원칙 R23](원칙.md#R23) 전처리가 게임을 못 가리면 고치지 말고 경고만 한다. 임의로 정하는 것이 더 위험하다.

### 설계

| 겹 | 무엇 |
|---|---|
| ① 게임별 빌드 진입점 | 확정표 적용 → 씬을 그 게임 것만 → 되물어 확인 → 빌드 |
| ② 빌드 전처리 | 사람이 Build 버튼을 누르면 시작 씬 경로로 게임을 알아내 같은 것을 적용한다 |

씬을 안 바꾸면 다른 게임 씬이 함께 들어가고 첫 씬이 바뀌면 엉뚱한 게임이 뜬다.

## 엔진 기본값

### 요약

- 원본에 없는 것이 기본값으로 켜져 있는 자리를 같이 본다.
- 엔진 기본값 중 원본에 대응물이 없는데 켜진 것(대표: 시작 스플래시)은 원본에 없는 화면을 한 겹 붙인다.
- 엔진이 그려서 플로우 diff 에도 안 걸린다.

### 규칙

- #강제 [원칙 R10](원칙.md#R10) 이런 엔진 기본 화면은 원본과의 차이로 본다. 남기려면 의도된 차이로 등재한다.

## 딸린 구성요소

### 요약

- 엔진 설정에는 딸린 구성요소가 있다. 짝이 어긋나면 재생에서만 터진다.
- 일부 프로젝트 설정은 씬·프리팹의 특정 컴포넌트와 짝이다.
- 어긋나도 컴파일·씬 열기·「컴포넌트가 있다」 검사가 통과하고, 재생 순간 예외로 죽는다.
- 기본은 짝을 정적 검사로 끌어내리고, 재생 검사(`PLAYMODE=1 Tools/unity-batch.sh`)는 그 뒤의 겹으로 두는 것이다.

### 규칙

- #강제 [원칙 R7](원칙.md#R7) 이 자리의 검사는 「있다」가 아니라 「짝이 맞다」로 통과를 판정한다.

### 설계

| 엔진 설정 | 딸린 구성요소 | 어긋나면 |
|---|---|---|
| 입력 처리 방식 | 이벤트 시스템의 입력 모듈 종류 | 재생 즉시 예외. 입력이 통째로 안 온다 |
| 색공간 | 그래픽 API 목록 | 구형 API 가 섞이면 기기마다 색이 갈린다 |
| 렌더 파이프라인 | 머티리얼·셰이더 | 분홍색으로 뜬다 |

정적 검사로 끌어내리는 이유는 짝이 설정 값과 씬 내용을 나란히 읽으면 재생 없이 판정되기 때문이다.

| 약한 검사 | 짝을 보는 검사 |
|---|---|
| 「입력 모듈이 있다」 | 「입력 처리 설정이 A 면 모듈이 A 용이고 B 용이 없다」 |
| 「그래픽 API 가 지정돼 있다」 | 「색공간이 Linear 면 구형 API 가 목록에 없다」 |

사례: 새 입력 시스템 프로젝트에 구형 입력 모듈 씬을 구웠고, 「모듈이 있다」로 본 검사 60항이 전부 통과했다.
