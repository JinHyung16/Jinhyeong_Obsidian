# PrefabRule

프리팹을 만들기 전에 UI 인지 게임오브젝트인지 먼저 가른다.

## 노트 자리

### 요약

- 방향 노트다. 기본값과 이유를 준다.
- 판단 대상이 아닌 것은 [원칙](원칙.md) 에만 있다.
- 상위는 [PD](PD.md) 다. 사용자는 [Transfer_Artist](Transfer_Artist.md) 다.
- 함정 목록은 [PrefabRule - 함정](PrefabRule%20-%20함정.md) 에 있다.

## UI 와 게임오브젝트

### 요약

- 프리팹은 UI 와 게임오브젝트 두 갈래다.
- 먼저 가르는 것이 기본이다. 이유: 폴더·규칙·어휘가 다르다.
- 갈래마다 Layer · 좌표 · 폴더 · 어휘 · 코드 위치가 갈린다.

### 규칙

- `Window` / `Popup` / `Panel` / `View` 는 UI 프레임워크 어휘로 남긴다. 월드는 `~Visual` 이 기본이다. 이유: 이름만 보고 갈린다.
- 프리팹 에셋은 접미 없이 오브젝트 이름 그대로 둔다 (`Enemy.prefab`).

### 설계

| | UI 프리팹 | 게임오브젝트 프리팹 |
|---|---|---|
| 무엇 | 창·패널·버튼·리스트 칸 | 적·탄환·미사일·유닛·이펙트 |
| Layer | `UI` | 기본(또는 전용 레이어) |
| 좌표 | `RectTransform` / 앵커 | `Transform` / 월드 좌표 |
| 폴더 | `Assets/<게임명>/Resources/UI/` | `Assets/<게임명>/` 아래 (로드는 `CLAUDE.md` 「로드 규칙」) |
| 어휘 | `Window` `Popup` `Panel` `Component` | `~Visual` (`EnemyVisual` `BulletVisual`) |
| 코드 위치 | `Assets/<게임명>/Scripts/UI/` · 공용 `Assets/Scripts/UI/` (`JinHyung.UI`) | `Assets/<게임명>/Scripts/View/` (`JinHyung.<게임>`) |

## 폴더

### 요약

- UI 프리팹은 게임 폴더의 `Resources/UI/` 아래에 모은다.
- 핵심은 UI 와 월드를 가르는 것이다.
- 하위 폴더 이름은 프로젝트가 정한다.

### 설계

```
Assets/<게임명>/Resources/UI/
├─ Windows/      전체 화면
├─ Popup/        버튼으로 여는 창 (80% 이하)
├─ Panel/        창 안 구획
├─ Components/   재사용 최소 단위
├─ Common/       기성 공용 프리팹 (버튼·텍스트·게이지·딤)
└─ Graph/        노드 그래프 위젯류
```

경로와 로드 방식은 `CLAUDE.md` 폴더·로드 규칙을 따른다.

## 풀링

### 요약

- 많이 생성될 것은 풀링이 기본이다. UI 는 `PrefabAuto`, 월드는 전용 풀이다.
- 고정 격자는 풀링이 필요 없다 ([UIFramework](UIFramework.md) 「고정 격자」).

### 규칙

- 풀 반환 규약(`Dead = true` 등)을 정한다. 생성 지점마다 반환 지점을 짝지어 확인한다. 이유: 짝이 없으면 풀이 의미가 없다.
- 리스트에서 뺄 때 `RemoveAt` 반복(O(n²)) 대신 단일 패스 압축을 쓴다.

## Canvas 설정

### 요약

- Canvas 네 항목은 프로젝트당 한 번 정한다.
- Reference Resolution 은 PD 착수 질문 3번의 답으로 채운다 (PD 「질문 문안」).
- 크기·배치는 앵커와 레이아웃으로 잡는다. 픽셀을 환산해 박지 않는다.
- `renderMode` 는 상황마다 다르다. 프리팹에 저장된 값을 믿지 않는다.

### 규칙

- 한 번 정하고 절대 바꾸지 않는다. 이유: 도중에 바꾸면 잡은 배치가 전부 흔들린다.
- 다른 값이 낫다면 착수 확정 때 근거와 함께 고른다.
- 원본 CSS 값은 비율과 의도를 읽는 참고 자료다. 옮겨 적을 수치가 아니다.
- 중첩 Canvas 가 켜질 때마다 루트를 보고 `renderMode` · `worldCamera` · `sortingLayerID` 를 맞추는 것이 기본이다. 이유: 프리팹에 박으면 한쪽이 깨진다.

### 설계

| 항목 | 값 |
|---|---|
| Render Mode | ScreenSpace - Camera |
| UI Scale Mode | Scale With Screen Size |
| Reference Resolution | X 1080 · Y 1920 (Portrait 기본). Landscape 기본은 1920×1080 |
| Screen Match Mode | Expand |

위 네 값은 기본값이다.

기본은 원본 논리 해상도 × Canvas Reference 배율로 좌표를 박는 대신, 환산을 팩토리 `Px()` 한 곳으로 모으는 것이다 (UIUX 「환산 상수는 한 곳에서만」).
크기·배치는 앵커 · 레이아웃 그룹 · `LayoutElement` · `ContentSizeFitter` · `AspectRatioFitter` 로 잡는 것이 기본이다. 이유: 화면 비율이 바뀌어도 앵커가 따라간다.

| 언제 | renderMode | worldCamera |
|---|---|---|
| 에디터에서 프리팹을 열었을 때 | 프리팹에 저장된 값 | 없을 수 있다 |
| 런타임(실기) | `ScreenSpaceCamera` | UI 카메라 |

- 프리팹 인스펙터의 중첩 Canvas 값이 런타임과 달라도 정상이다.
- 판정은 재생 중 `Canvas.renderMode` 를 읽어서 하는 것이 기본이다 (`PLAYMODE=1 Tools/unity-batch.sh`). 이유: 편집 값은 런타임과 달라 측정이 아니다.

## 계층

### 요약

- 계층은 Window → Panel 두 단계까지만이다.
- 정본은 [UIUX - 레이아웃](UIUX%20-%20레이아웃.md) 「계층」이다.
- 프리팹 쪽 기본은 원본 DOM 의 구획을 따라 자르는 것이다. 원본 flex 컨테이너 하나가 패널 하나다 (UIFramework 「3계층」).

### 규칙

- #강제 [원칙 R2](원칙.md#R2) 따르는 것은 구획이다. DOM 계층 깊이를 1:1 로 옮기는 것이 아니다.

### 설계

구획을 따라 자르는 이유는 구획이 원본과 짝지어져 대조가 쉽기 때문이다.

## 앵커 패턴

### 요약

- 용도별 기본 앵커·피벗 표가 있다.
- 회전하는 rect 와 부모 변에 붙는 아이콘은 헬퍼에 맡기지 않는다.

### 규칙

- 회전시킬 rect 는 앵커·피벗을 직접 잡는 편이 낫다. 상단 피벗 헬퍼는 그 축으로 돌아 엉뚱한 데 간다.
- 부모 변에 붙이는 아이콘은 앵커까지 옮긴다. 기본 앵커(0.5,0.5) 헬퍼에 위치만 주면 가운데 기준으로 앉는다.

### 설계

| 용도 | anchorMin/Max | pivot | 비고 |
|---|---|---|---|
| 전체 배경 | (0,0)~(1,1) | (0.5,0.5) | sizeDelta 0 |
| 상단 고정 바 | (0,1)~(1,1) | (0.5,1) | `sizeDelta.y`=높이, `sizeDelta.x`=음수(좌우 인셋) |
| 세로 스택 블록 | (0,1)~(1,1) | (0.5,1) | `anchoredPosition.y` = -y |
| 고정폭 블록 | (0,1) 점앵커 | (0.5,1) | 절대 sizeDelta |
| 하단 버튼 바 | (0,0)~(1,0) | (0.5,0) | |
| 중앙 카드 | (0.5,0.5) | (0.5,0.5) | 팝업 기본 |

## 조립 단위

### 요약

- 큰 프리팹 안에 다 넣지 않는다.
- 기본은 작은 단위를 재사용 가능하게 모듈화해 조립하는 것이다.
- 이유: 같은 표기가 여러 곳에 쓰일 때 고칠 곳이 하나다.

### 설계

- 기성 Common 프리팹이 있으면 그것이 첫 순서다.
- 그다음 순서와 사례는 [UIFramework - Component](UIFramework%20-%20Component.md#설계%20순서) 가 정본이다.

## 프리팹 생성 방식

### 요약

- 생성 방식은 확정표 10-b 가 가른다. 이 문서가 정하지 않는다.
- 누가 이 프리팹을 이어서 고치는가가 정한다.
- 기본값은 프리팹이 주인이다 [사람 확정].

### 규칙

- #강제 [원칙 R14](원칙.md#R14) 적용: 기본값이 「프리팹이 주인」으로 바뀐 뒤 새로 착수하는 게임부터다. 이미 「빌더가 주인」으로 만든 게임은 그대로 둔다 [사람 확정. 소급 안 함].
- #강제 [원칙 R22](원칙.md#R22) 두 방식을 섞지 않는다. 「프리팹이 주인」인데 빌더를 다시 돌려 통째로 구우면 사람의 작업이 조용히 사라진다.
- #강제 [원칙 R22](원칙.md#R22) 초안 빌더는 저장 전에 `AssetDatabase.LoadAssetAtPath` 로 있는지 보고, 있으면 건너뛰고 로그만 남긴다. 통째로 다시 굽는 것은 사람이 명시할 때만 하고 원장에 적는다.
- #강제 [원칙 R16](원칙.md#R16) 은 AI 가 에디터 API 로 프리팹을 고쳐서 지킨다.

### 설계

| 확정표 10-b | 빌더가 하는 일 | 이후 고칠 곳 |
|---|---|---|
| 프리팹이 주인 (기본값) | 첫 초안을 굽는다. 프리팹이 이미 있으면 건너뛴다 | 프리팹. 사람은 에디터에서, AI 는 에디터 API 로 연다 |
| 빌더가 주인 | 매번 통째로 다시 굽는다 | 빌더 코드. 손으로 고친 것은 다음 굽기에 사라진다 |

기본값의 이유는 결과물을 이어서 다듬는 것이 목적이기 때문이다. 빌더가 주인이면 디테일 수정이 전부 코드 수정이 된다.
「빌더가 주인」이 낫다고 보면(이어서 다듬을 일이 없는 결과물 등) 착수 확정 때 근거를 보여 교차 확인하고 10-b 에 남긴다 ([원칙](원칙.md) 「쓰는 법」).

프리팹이 주인일 때의 기본값이다.

- 초안 이후 수정은 기존 프리팹을 열어 고치는 것이 기본이다 (`PrefabUtility.LoadPrefabContents` → 수정 → `SaveAsPrefabAsset` → `UnloadPrefabContents`). 여러 개를 한꺼번에 고칠 때도 새로 굽는 대신 이 방식의 일괄 스크립트를 쓴다.
- 보이는 조정값(위치·크기·색·알파·연출 속도·타이밍)은 `[SerializeField]` 필드로 두는 것이 기본이다. 기본값은 원본 값이고 출처를 `[Tooltip]` 이나 주석으로 남긴다. 이유: 코드 상수면 디테일 수정이 코드 수정이 된다.
- 런타임이 바꾸는 것은 데이터·상태로 갈리는 값뿐인 것이 기본이다. 이유: 상수로 덮으면 프리팹 수정이 먹지 않는다.
- 런타임 계층 조립은 `new GameObject` + `AddComponent` 대신 `Instantiate` 가 기본이다. 이유: 계층이 프리팹에 있어야 열어서 고칠 수 있다.
- 코드로 Mesh 를 묶어 그리는 드로잉은 기본 선택지가 아니다. 필요하다고 보면 스스로 가기 전에 근거를 보여 사람의 지시를 받는다.

## 배치 상수

### 요약

- 원본의 배치 상수는 프리팹으로 온다. 시트로 보내지 않는다.
- 원본 캔버스 좌표를 시트 컬럼으로 옮기고 코드가 꽂으면 프리팹이 배치의 진실 소스라는 전제가 깨진다.
- 그러면 배치가 두 곳으로 갈린다.

### 규칙

- 정규화 −1~1 좌표는 앵커 그 자체다. `x = -0.4` 는 `anchorMin.x = anchorMax.x = 0.3` 이다 (`(1 + x) / 2`). 해상도가 바뀌어도 앵커가 따라가므로 데이터일 이유가 없다.
- 개체별 장식 개수가 다르면(1~N) 1:N 시트보다 개체별 프리팹이 낫다.
- 시트에 남는 것은 그 개체가 어느 프리팹을 쓰는가다 (`~Path` 한 컬럼).
- 컬럼명에 좌표·오프셋·크기가 들어가면 프리팹 자리인지 먼저 묻는다.
- 환산 배율 필드(「프리팹 값 × 배율」) 대신 값 자체를 최종 단위(픽셀/초)로 바꿔 넣는다. 이유: 배율 필드가 있으면 프리팹에 보이는 값이 실제 값이 아니다.

### 설계

사례: 개체 12종의 장식 좌표를 1:N 시트 3개·99행으로 옮겨 `Instantiate` + 좌표 주입을 했고, 거동 컴포넌트를 걷으며 환산 배율(≈0.49)을 필드로 되살렸다.

## 완료 체크리스트

### 요약

- 기본 구조 기준 점검이다.
- 다른 선택은 확정표대로 본다.

### 규칙

- [ ] UI/게임오브젝트 구분이 맞고 UI 프리팹의 Layer 가 `UI` 다
- [ ] UI 프리팹이 `Assets/<게임명>/Resources/UI/` 아래에 있고 월드 프리팹이 섞이지 않는다 (하위 폴더 이름은 프로젝트 확정값)
- [ ] Canvas 4항목이 규격값이다 (ScreenSpace-Camera / Scale With Screen Size / Reference / Expand)
- [ ] 계층이 Window → Panel 두 단계 안이고 창 루트에 낱개 위젯이 없다
- [ ] 절대 y·환산 픽셀이 아니라 앵커와 레이아웃 그룹으로 잡혔고 접힘/펼침 두 상태가 같이 맞는다
- [ ] 코드가 `sizeDelta` · `anchoredPosition` 을 계산해 넣는 자리가 없다
- [ ] `[SerializeField]` 참조에 빈 슬롯이 없다
- [ ] #강제 [원칙 R22](원칙.md#R22) 10-b 가 「프리팹이 주인」이면 빌더를 다시 돌려도 기존 프리팹이 바뀌지 않는다
- [ ] 보이는 조정값이 프리팹 필드에 있다. 코드 상수로 박힌 위치·크기·색·연출 수치가 0 이다 (PD 「속 품질」)
- [ ] 재생 중 `RaycastAll` 로 눌러야 하는 것의 첫 결과가 자기 자신이다 (`PLAYMODE=1`)
