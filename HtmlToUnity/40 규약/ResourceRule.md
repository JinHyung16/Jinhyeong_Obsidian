# ResourceRule

HTML5 게임의 리소스는 파일로 존재하는 것과 코드(CSS·canvas)로 그리는 것 두 갈래다.

## 노트 자리

### 요약

- 방향 노트다. 기본값과 이유를 준다.
- 판단 대상이 아닌 것은 [원칙](원칙.md) 에만 있다.
- 상위는 [PD](PD.md) 다. 사용자는 [Transfer_Artist](Transfer_Artist.md) 다.
- 굽는 법은 [ResourceRule - 리소스 굽기](ResourceRule%20-%20리소스%20굽기.md) 에 있다.

## 폴더

### 요약

- 아트는 게임 폴더의 `Art/` 아래에 모은다. 없으면 만든다.
- 하위 폴더 이름은 예시다. 기존 폴더의 대소문자를 따른다.
- 로드 방식은 `CLAUDE.md` 「로드 규칙」이다. UI 프리팹·구운 폰트는 Resources, 그 밖의 아트는 Addressables 다.

### 규칙

- 기본은 경로를 빌더·로더 상단에 `const` 로 모으는 것이다. 이유: 인라인 문자열로 흩어지면 폴더를 옮길 때 고칠 곳을 다 못 찾는다.
- 기본은 폴더만 어드레서블에 등록하고, 개별 파일 주소는 DB(시트)에서 가져오는 것이다. 이유: 코드에 파일명을 박으면 아트가 늘 때마다 코드를 고친다.

### 설계

```
Assets/<게임명>/Art/        (없으면 만든다)
├─ UI/                     Icons/  Frames/  Bars/  Cards/  …
├─ Game/                   BG/<theme>/ (레이어 분리) · Enemies/ · Weapons/ · Fx/ · Audio/ …
├─ Atlas/                  스프라이트 아틀라스 (아이콘 계열)
└─ Materials/  Shaders/
```

## 리소스 목록

### 요약

- 착수 때 두 목록을 먼저 만든다 (`06_리소스.md`).
- 학습 단계 산출물이다 (PD 「산출물 목록」).
- 이 목록이 없으면 무엇이 빠졌는지 모른다.
- 코드로 그리는 것을 못 세면 이관은 미완으로 끝난다.

### 규칙

- 기본은 제작해야 하는 리소스를 발견한 그 자리에서 굽는 것이다. 이유: 단색 박스는 미완성이고, 미루면 빠진 줄 모른 채 완료 보고로 흘러간다.

### 설계

| # | 목록 | 만드는 법 |
|---|---|---|
| ① | 존재하는 리소스 | 원본이 리소스를 호출하는 폴더(`assets/` 등)를 훑는다. 파일명·크기·사용처 |
| ② | 제작해야 하는 리소스 | 화면에 나오는데 파일이 없는 것(CSS·canvas 로 그림). Client 지식 담당자의 도움으로 원본 draw/CSS 를 짚는다 |

```bash
# ① 원본이 실제로 부르는 파일 전수
grep -oE "(assets|img|res)/[A-Za-z0-9_./-]+\.(png|jpg|webp|mp4|webm|mp3|ogg)" 원본.html scripts/**/*.js | sort -u
# ② 코드로 그리는 것 — 그리기 호출 전수
grep -n "fillRect\|arc(\|drawImage\|createLinearGradient\|shadowBlur" 원본.html | wc -l
# ② CSS 로 그리는 것 — 배경·그라디언트·테두리
grep -n "background:linear-gradient\|box-shadow\|border-radius\|clip-path" 원본.html
```

## 해상도 정책

### 요약

- PD 착수 질문 7번의 답으로 갈린다.
- 픽셀 대조가 우선이고 메모리 여유가 있으면 원본 크기다.
- 모바일 출시가 목표면 리사이즈가 낫다. 리사이즈가 기본 권장이다.

### 규칙

- 원본 크기 그대로 가면 원본 픽셀 크기를 유지한다. 픽셀 대조가 쉬운 대신 모바일 메모리가 커진다.
- 모바일 타깃이면 텍스처 변이 4의 배수여야 압축이 걸린다. 아니면 압축이 풀려 용량이 튄다.
- 기본은 생성기가 임포트 설정까지 거는 것이다. 이유: PNG 만 쓰고 끝내면 기본 임포트(압축·mip·PPU)가 걸려 흐려지거나 크기가 어긋난다.

### 설계

리사이즈할 때의 권장 크기다.

| 종류 | 권장 크기 |
|---|---|
| BG | 512 ~ 1024 |
| Icon | 64 ~ 512 |
| FX | 64 ~ 256 |
| 폰트 | 임시 생성해 사용 (「폰트」) |

공통 임포트 규격이다.

| 항목 | 값 |
|---|---|
| Pivot | Center |
| Pixels Per Unit | 100 |
| Max Size / 압축 | 플랫폼별로 명시 (모바일 압축 포맷) |
| Mip | UI 는 끈다 |

## 리소스 굽기

### 요약

- 없는 리소스는 만들어서 채운다.
- 절차 생성 · 반투명 · 블러 · PPU · 생성기 실패는 [ResourceRule - 리소스 굽기](ResourceRule%20-%20리소스%20굽기.md) 에 있다.
- 절차 이펙트는 재구현하지 않고 원본에서 베이크한다. 정본은 [Fx](Fx.md) 「절차 이펙트 베이크」다.

## 폰트

### 요약

- 기본은 폰트 하나에 폴백 없이 가는 것이다.
- 이유: 폴백이 조용히 메우면 없는 글리프가 드러나지 않는다.
- 폰트에 없는 글자는 cmap 을 재서 스프라이트로 채운다.
- 원본의 기호는 아이콘 칸 · 글자 흐름 · 장식 셋 중 하나로 갈린다.

### 규칙

- 개발 중에는 영어·한국어·특수문자가 되게 Dynamic(1024² 등)으로 임시로 구워 쓸 수 있다. Dynamic 을 쓰는 동안은 커밋 전에 아틀라스를 비운다. 이유: 에디터에서 쌓인 글리프가 diff 를 부풀린다.
- 결과물에 들어가는 폰트 에셋은 굽는다. 구운 에셋은 Resources, 원본 TTF 는 `Editor/` 에 둔다 (`CLAUDE.md` 「로드 규칙」).
- 원본 문구와 폰트에 있는 글자는 그대로 쓴다. 이유: 고쳐 적거나 치환하는 것 자체가 원본과의 차이다.
- 폰트에 없는 글자만 스프라이트로 그린다. 없는지는 TTF cmap 을 파싱해 확인한다.
- 원본에 기호가 보이면 자리를 먼저 판정하고 cmap 을 재는 것이 기본 순서다.

### 설계

브라우저는 아무 글리프나 그리지만 Unity 는 폰트 cmap 에 있는 것만 그린다. 없으면 두부로 뜬다.

| 그 기호가 있는 자리 | 처리 |
|---|---|
| 아이콘 칸. 노드·슬롯·버튼의 그림 자리 | 아틀라스 아이콘. 데이터에 `IconCode` 를 넣는다 |
| 글자 흐름 안. 문장에 섞인 기호 | cmap 에 있으면 텍스트 그대로, 없으면 `TMP_SpriteAsset` 에 등록 |
| 장식 | 프리팹에 이미지로 물린다 |

원본이 텍스트로 그렸어도 아이콘 칸을 기호로 때운 것이면 이미지가 맞다.

사례: 스킬 수백 개의 아이콘 칸 기호 글리프가 전부 폰트에 없어 아틀라스 아이콘으로 매핑했다.

```bash
# 판정 전에 반드시 잰다
python - <<'EOF'
# TTF cmap(format 12) 파싱 → 원본에서 뽑은 코드포인트 전수를 대조
EOF
```

## 정적 아트와 데이터 종속 아트

### 요약

- 둘을 섞지 않는다.
- 정적 장식은 프리팹에 직접 물린다.
- 데이터 종속 아트는 런타임에 주입한다.
- 배경은 대개 데이터 종속이다.

### 규칙

- 프리팹 값은 로드 실패 폴백으로만 쓰는 것이 기본이다. 원본이 `bgIdFor(모드, 구역)` 로 고르면 프리팹에 구운 1구역 배경이 5구역에도 나온다.
- 등급별 프레임처럼 후보가 유한한 것은 `Sprite[]` 에 전부 물리고 런타임에 인덱스로 고르는 편이 낫다 (정적 취급).
- 월드 오브젝트 프리팹에 스프라이트를 박지 않는다. 프리팹은 계층·`SpriteRenderer`·정렬 순서·머티리얼까지만 담고 스프라이트는 각 Visual 이 주입한다.
- 지연 로드 아트는 다시 물어야 한다. 로드 완료 이벤트를 구독하거나, 표시 시점에 다시 조회한다.

### 설계

| 구분 | 예 | 처리 |
|---|---|---|
| 정적 장식 | 패널 테두리, 탭 아이콘, 인트로 이미지 | 프리팹에 직접 물린다 |
| 데이터 종속 | 초상·유닛·아이템 아이콘·구역별 배경 | 프리팹 대신 런타임 `SetData/SetXxx` 로 주입 |

어드레서블이 카테고리 단위로 로드/해제하는 아트를 `Resources` 프리팹이 물면 생명주기를 우회하고 빌드에 중복 편입된다.
첫 화면 뒤에 로드되는 아트를 창이 열릴 때 한 번만 물면 null 이라 평생 폴백 도형으로 남는다. 구독은 로드 즉시 바뀌고, 재조회는 구독 해제를 챙길 일이 없다.

## 어드레서블 감사

### 요약

- 어드레서블 등록은 양방향으로 감사한다.
- 동기화 도구는 「파일 → 주소」만 보장한다.
- 코드·데이터가 요구하는 주소가 실제로 있는지도 본다.
- 기본은 파일을 만드는 생성기가 등록까지 하는 것이다. 이유: 사람이 기억해서 등록하면 빠진다.

### 규칙

- #강제 [원칙 R23](원칙.md#R23) 동기화 도구의 「제거 0 · 건너뜀 0」은 통과가 아니다. 통과는 감사 3종이 0건일 때다.
- 기본은 감사 3종을 도구로 만들어 두고 화면 완료 전에 돌리는 것이다.

### 설계

| 항목 | 잡는 것 |
|---|---|
| 코드·데이터에 박힌 주소 리터럴 전수 → 등록 여부 | 이름이 어긋난 것 |
| 아트 파일명의 공백 · 복사본 접미 | 「이름 1.png」 |
| 등록됐는데 파일이 없는 고아 | 지운 뒤 남은 것 |

사례: 영상 파일명이 `Intro_start 1.mp4` 로 어긋나 시네마틱이 `InvalidKeyException` 으로 죽었는데 동기화 도구는 「제거 0 · 건너뜀 0」이었다.

주의: 감사기는 폴더 엔트리와 폴더 접두어를 오탐한다. 파일 존재 검사에 디렉터리 예외를 넣고, 폴더 접두어는 재생 중 로딩으로 확인한다 (`PLAYMODE=1 Tools/unity-batch.sh`).

## 캡처 확인

### 요약

- 아트를 물리기 전에 캡처의 그 영역을 실제로 확인한다.
- 기본은 붙이기 전에 크롭해서 그 그림이 정말 거기 있는지 보는 것이다.
- 이유: 그럴듯한 파일명은 다른 그림을 통과시킨다.

### 설계

크롭·픽셀 샘플링은 python + PIL 로 한다 (`cap.getpixel((x, y))`).

사례: `XXX_button.png`(금색 장식 프레임)를 행 배경으로 깔았으나 캡처는 평면 남색 패널 + 좌측 시안 바였다.
