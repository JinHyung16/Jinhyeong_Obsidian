# UI/UX 파트

방향 노트다. 기본값과 이유를 준다.

## 역할

### 요약

- 담당은 프리팹 · 레이아웃 · 좌표계 · 폰트/글리프 · 컴포넌트 재사용 · 입력 판정이다.
- 지식 담당자다. 이관에 직접 참여하지 않고 [Transfer_Artist](Transfer_Artist.md) 가 100% 이관할 정확한 정보를 낸다.
- 상위는 [PD](PD.md) 다.
- 판단 대상이 아닌 것은 [원칙](원칙.md) 에만 있다.

### 규칙

- #강제 [원칙 R3](원칙.md#R3) 판정 근거는 원본 코드 → 규약 문서 → 캡처 순이다. 캡처에서 읽어낸 것은 사양이 아니다.
- #강제 [원칙 R12](원칙.md#R12) 사람이 확정한 결정은 실측보다 위다. 실측은 보고한다 (함정: [사람이 없애라 한 버튼 둘레 띠를 측정으로 되살린 일](함정%20-%20사람%20권리%20안전.md#사람이%20없애라%20한%20버튼%20둘레%20띠를%20측정으로%20되살린%20일)).
- #강제 [원칙 R17](원칙.md#R17) 이 역할은 프리팹·아트를 만들지 않는다.
- 이 역할로 들어갈 때 역할 선언을 출력한다 (PD 「역할 기동 규약」).
- 이전 역할의 결론은 md 에 적힌 것을 기준으로 받는다.

### 설계

- 기본 방향은 원본 DOM 의 블록 구성과 흐름(무엇이 묶이고 어떤 순서로 쌓이나)을 읽어 Window / Panel / LayoutGroup 으로 다시 짜는 것이다.
- DOM 계층을 1:1 로 옮기지 않는다 ([원칙 R2](원칙.md#R2)).
- 절대 y 를 박는 대신 흐름을 레이아웃 그룹으로 옮기는 것이 기본이다. 이유: 흐름을 옮기면 블록 높이만 실측해도 접힘/펼침이 맞는다 ([레이아웃](UIUX%20-%20레이아웃.md) 「계층」).

```
[역할 전환] 지금부터 나는 UI/UX(지식 담당)다.
  할 수 있는 것 : 원본 읽기·실행 · 04_UIUX규칙.md / 06_리소스.md 작성
  하지 않는 것  : 프리팹·아트 생성 (그건 Transfer_Artist 가 한다)
```

- 표 오른쪽 칸의 기본값은 확정값이 무엇이든 출발점으로 쓴다.

### 규칙

## 학습 산출물

### 요약

- 학습 단계에서 내가 채우는 파일은 둘이다.
- 착수 전에 원장 3단계를 밟는다.

### 설계

| 파일 | 내가 채우는 것 |
|---|---|
| `04_UIUX규칙.md` | 좌표계 · `:root` 색 · 타이포 · 공통 컴포넌트 · 화면별 영역 표 |
| `06_리소스.md` | 존재하는 리소스 / CSS 로 그리는 것(제작 필요) 두 목록 (FX 와 공동) |

- 착수 전 3단계: 원장 `HtmlToUnity_작업내역_<게임명>.md`(착수 시 생성) 확인 → 최신화 → 확인 (PD 「담당자는 착수 전에 반드시 3단계를 밟는다」).
- 새로 안 것은 「학습 내용」, 틀렸던 것은 「오염된 내용」에 적는다 (PD 「오염된 내용의 정의」).

## 좌표계

### 요약

- 환산 상수는 한 곳에서만 쓴다.
- 캔버스는 아래가 +y, UGUI 는 위가 +y 다.
- 부모 크기의 분수로 정의된 배치는 분수로 옮긴다.
- 원본 좌표값이 「위치」인지 「순서」인지 먼저 가른다.
- 자세한 것은 [좌표계](UIUX%20-%20좌표계.md) 에 있다.

## 레이아웃

### 요약

- 계층은 Window → Panel 두 단계까지만 간다.
- 원본의 좌표 계산은 옮기는 게 아니라 버리는 것이다.
- CSS 레이아웃 프리미티브는 Unity 와 1:1이 아니다.
- CSS 수치는 계산과 캡처 검증 2단계로 넣는다.
- 자세한 것은 [레이아웃](UIUX%20-%20레이아웃.md) 에 있다.

## 카드 장식

### 요약

- 장식과 내용물을 한 필드에 겸하지 않는다.
- CSS 클래스 하나가 만드는 요소를 낱개로 옮기면 반드시 하나가 빠진다.
- 캡처에 절대 안 찍히는 것이 둘 있다. `animation` 과 `:hover` 다.
- 원본의 표기 분기 개수를 세고 그대로 옮긴다.
- 자세한 것은 [카드 장식](UIUX%20-%20카드%20장식.md) 에 있다.

## 폰트

### 요약

- 「원본 폰트를 가져오면 된다」가 아니다. 원본 CSS 폰트가 모든 글리프를 그리지 않는다.
- 주폰트는 가장 넓은 글리프 집합이 가져간다.
- 기본은 폰트 하나 · 폴백 0 이다.
- 자세한 것은 [폰트](UIUX%20-%20폰트.md) 에 있다.

## 프리팹 생성

### 요약

- 새로 그리기 전에 기존 컴포넌트 재사용부터 찾는다.
- 빌더 코드가 첫 초안을 굽고, 이후 수정은 기존 프리팹을 연다.
- 구운 뒤 임포트 설정을 안 걸면 굽는 의미가 없다.
- 자세한 것은 [프리팹 생성](UIUX%20-%20프리팹%20생성.md) 에 있다.

## 전수 대조표

### 요약

- 화면 하나를 전수 대조표로 연다.
- 정적 캡처 점수로는 「배치는 맞는데 알맹이가 빠진」 상태를 못 잡는다.
- 빈 칸이 작업 목록이다.

### 설계

- 기본 순서는 그 화면을 만드는 원본 함수의 요소를 전부 표로 편 다음 코드를 고치는 것이다.
- 형식·절차는 [PD](PD.md) 「화면 하나를 「전수 대조표」로 여는 법」 이 정본이다.
- UI/UX 는 DOM 과 캔버스를 둘 다 훑고, `draw*` 호출 트리는 끝까지 편다.

## 판정 항목

### 요약

- 전수 대조표에서 확인할 항목이다.
- 이 표가 유일본이다. [Transfer_Artist](Transfer_Artist.md) 도 이 표를 쓴다.

### 설계

| 확인할 것 | 사례 |
|---|---|
| 엔티티마다 모양이 다른가 | 탄환·미사일·드론·적을 전부 점으로 찍었다 |
| 표기 크기가 원본 수치인가 | 임의 반지름으로 2~3배 작았다 |
| 지연 로드 아트를 다시 묻는가 | 한 번만 물어 평생 폴백 도형이었다 |
| 데이터가 바뀌면 그 자리에서 갈리는가 | 구역을 바꿔도 배경이 그대로였다 |
| 눌러야 하는 것이 다 버튼인가 | 탭 가능한 썸네일이 그림뿐이었다 |
| 전면 히트 영역에 가려지지 않는가 | 전체 히트 영역이 위 버튼을 먹었다 |
| 애니메이션 위상·속도가 원본 값인가 | 드리프트 11px/s, 원본은 1.1 |
| 상태가 바뀌면 같이 바뀌는 것까지 옮겼나 | 펼침에서 숨길 형제 요소가 남았다 |
| 분수 배치를 픽셀로 박지 않았나 | 펼침 상태에서 어긋났다 |

## 글자 테두리

### 요약

- 글자의 테두리·그림자는 「스타일」이 아니라 「재질」이다.
- 세계 위 글자는 테두리가 없으면 안 읽힌다.
- 문구 스타일을 뜰 때 크기·색과 같은 급으로 테두리 색·두께를 적는다.

### 규칙

- #강제 [원칙 R7](원칙.md#R7) 테두리는 구운 파일이나 재생 화면에서 값이 들어갔는지 되읽어 판정한다. 호출이 있다는 것은 증거가 아니다.

### 설계

| 원본이 주는 것 | 우리 쪽 | 환산 |
|---|---|---|
| `stroke.width` (픽셀) | 텍스트 엔진 테두리 (대개 글자 크기 대비 0~1) | `두께 ÷ 글자크기` |
| `stroke.color` | 테두리 색 | 그대로 |
| 테두리가 없는 문구 | 테두리 0 | 전수로 갈라 적는다. 전부 두르면 원본과 다르다 |

- 기본은 테두리를 재질 에셋으로 만들어 공유 슬롯에 물리는 것이다. 같은 (색·두께)는 한 벌만 만든다. 이유: 인스턴스 재질은 어느 에셋에도 안 붙어 프리팹 저장 때 버려진다.
- 사례: 굽는 코드에 호출이 있었지만 모든 문구에 테두리가 없었다 (함정: [인스턴스 재질에 쓴 문구 테두리 설정](함정%20-%20아트%20굽기.md#인스턴스%20재질에%20쓴%20문구%20테두리%20설정)).

## 상자 맞추기

### 요약

- 「상자에 맞추기」는 배율만이 아니다. 원본이 크기를 고르는 경우가 있다.
- 원본은 흔히 문구를 상자에 줄여 넣는다(`배율 = min(상자폭/글자폭, 상자높이/글자높이, 1)`).
- 크기만 옮기면 서체를 갈 때 넘친다.
- 기본은 원본 방식대로 옮기는 것이다.

### 설계

함정: [상자 맞추기 없이 고정한 글자 크기](함정%20-%20UI%20흐름.md#상자%20맞추기%20없이%20고정한%20글자%20크기)(맞추기 규칙 자체를 옮긴다)에는 두 갈래가 있다.

| 원본이 하는 것 | 옮기는 법 |
|---|---|
| 렌더 크기를 재서 배율로 줄인다 | 배율 = `min(상자/렌더, 1)`. 키우지 않는다 |
| 글자 크기를 한 단씩 내려 처음 드는 크기를 쓴다 | 상한부터 하한까지 1 씩 내리며 본다. 하한으로도 안 들 때만 배율 |

둘째 갈래를 「고정 크기 + 배율」로 뭉개면 짧은 문구가 상한 크기로 뜨지 못한다.
사례: 뭉개서 한 문구가 원본의 절반 크기로 굳었다.

| 옮길 것 | 어디서 오나 |
|---|---|
| 글자 크기 | 덤프의 `font` |
| 상자 | 소스. 호출 인자라 덤프에 없다 |
| 줄이기만(키우지 않음) | 소스 식 그대로 |

기본은 맞추기를 자리 잡은 뒤에 다시 재는 것이다. 이유: 한 번 재고 캐시하면 자리 잡기 전 값이 남고, 그때 재면 0 이 나온다. 그 0 은 잰 값으로 쓰지 않는다.

## 렌더링 함정

### 요약

- 실제로 걸렸던 렌더링 함정이다.
- 9-slice 와 중첩 Canvas 가 특히 조용히 틀어진다.
- 비율이 안 맞는 rect 에서 스틸(contain)과 영상(cover)이 갈린다.

### 설계

- 한 GameObject 에 Graphic 하나. TMP 오브젝트에 `AddComponent<Image>()` 는 null → NRE.
- `Image.type = Filled` 는 sprite 가 없으면 무시된다.
- `Image.Type.Tiled` 는 원본 픽셀 크기로 가로·세로 양쪽 반복한다.
- 9-slice 보더는 원본 픽셀 크기로 그려진다. 좌우 합이 배치 크기를 넘으면 가운데가 사라지니 가장 작은 사용처 기준으로 잡는다. 원본 `background-size:100% 100%` 는 9-slice 가 아니라 통짜 스트레치다.
- 세로로 크게 눌리는 장식 아트는 뭉개진다. 캡처 색 단색 판을 깔고 아트는 테두리로만 쓰는 쪽이 낫다.
- 원본 카드·버튼은 거의 전부 `border-radius` 가 있다. 채움과 테두리를 같은 반경으로 맞추고 Source Image 는 채워 둔다.
  사례: 9-slice 프리미티브가 있는데도 색만 채워 `border-radius` 220곳의 Image 390개가 각졌다.
- 9-slice 는 스트레치 존이 심판이다. 기본은 보더를 장식 두께에 딱 맞추는 대신, 4방향 모두 장식이 끝난 균일(투명) 지점 너머까지 잡는 것이다. 스트레치 존(중앙·엣지 띠 4개)에는 완전 투명 또는 완전 균일 픽셀만 남긴다.
  이유: 경계 안티앨리어스·압축 노이즈 한 줄이 엣지 띠에 걸리면 배치 폭 전체로 늘어 베일이 된다.
  사례: 라인 두께 3px 에 맞춰 잘라 카드 전체가 흰 베일로 덮였고, 투명 지점 7px 까지 늘려 해결했다.
  검증: 보더 기준 5개 존의 알파 `std > 2` 또는 스트레치 축 인접 차 `> 8` 이면 오염이다(스크립트로).
- 중첩 Canvas 는 세트로: `overrideSorting` + `sortingOrder` + `GraphicRaycaster` + 루트와 같은 `renderMode`/`worldCamera`. `worldCamera` 가 비면 WorldSpace 에서 하위가 안 그려진다. 기본은 형제 순서이고, 형제 순서로 안 될 때만 중첩 Canvas 를 쓰는 쪽이 낫다.
- 중첩 Canvas order 는 프리팹에 굽는 대신 런타임에 루트 기준으로 맞추는 것이 기본이다. 이유: 루트 `sortingOrder` 는 창이 열릴 때 들어오므로 `OnEnable` 한 번만 읽으면 뒤 히트 영역에 먹힌다.
- 투명 히트 판은 `raycastTarget` 을 명시적으로 켠다.
- 원본 `clip()`/`overflow:hidden` 이면 마스크를 넣는다.
- 원본 그리기 순서를 계층 순서로 옮긴다. 원본은 SVG 선을 먼저, 노드 `div` 를 나중에 그린다. Unity 는 형제 순서라 풀링으로 뒤집히니 전용 부모를 `SetAsFirstSibling` 으로 고정한다.
- 선이 붙는 점은 셀 중심이 아니라 아이콘 원 중심이다(원본 `y = node.y*YS + 42`). 픽셀 대신 아이콘 rect 기준 비율로 뽑는다.

**스틸과 영상이 겹치는 rect**

| | 맞추는 방식 | 비율이 다르면 |
|---|---|---|
| `Image.preserveAspect` | contain | 레터박스 |
| `VideoPlayer` 기본 (`aspectRatio`) | cover | 넘치는 쪽이 잘린다 |

사례: rect 0.6555, 소스 0.6806 이라 스틸과 영상 크기가 달랐다.
기본은 fit 모드가 아니라 컨테이너 rect 를 소스 비율에 맞추는 것이다. 원본 CSS 크기(예: 882×1296)가 소스 비율이다.

## 화면 층

### 요약

- 화면 층(앞뒤)은 덤프의 부모·형제 순서로 정한다. 그림으로 못 읽는다.
- 이유: 반투명 디머 아래 밝은 UI 는 「덮였다」와 「위에 있다」가 눈으로 안 갈린다.

### 설계

- 사례: 시작 화면 대역을 스크린샷으로 정해 원본과 반대로 뒀다 (함정: [스크린샷으로 정한 화면 층](함정%20-%20UI%20흐름.md#스크린샷으로%20정한%20화면%20층)).
- 주의: 대역을 옮기면 그리기 순서와 입력 순서가 같이 바뀐다. 옮긴 뒤 버튼이 눌리는지 잰다.

## 9슬라이스 두께

### 요약

- 9슬라이스는 인셋 값이 아니라 그려지는 두께로 검사한다.
- 인셋은 스프라이트 px 다.
- 캔버스가 원본을 키우면 가운데만 늘고 모서리는 남아, 테두리가 `1/배율` 두께가 되고 곡률이 조인다.

### 설계

```
그려지는 두께 = 인셋 ÷ (스프라이트 PPU × 배수) × 캔버스 기준 PPU
목표          = 인셋 × 화면 배율
따라서 배수   = 1 / 화면 배율
```

기본은 「소스와 같은 인셋」이 아니라 화면에 몇 px 로 나오는지를 재는 것이다 (함정: [화면 배율만큼 얇아진 9슬라이스 테두리](함정%20-%20아트%20굽기.md#화면%20배율만큼%20얇아진%209슬라이스%20테두리)).

## 차오르는 바

### 요약

- 차오르는 바는 자르는 것이 아니라 폭이 자라는 것일 수 있다.
- 원본이 9슬라이스 판의 폭을 바꾸면 양끝 둥근 마감이 남는다.
- 자르면 차오르는 동안 끝이 잘린다.

### 설계

기본은 원본이 자르는지 늘리는지 소스에서 확인하고 같은 쪽을 쓰는 것이다.

## 완료 체크리스트

### 요약

- UI/UX 파트를 닫기 전에 아래를 확인한다.
- 못 잰 것은 지우지 말고 사유와 함께 남긴다.

### 규칙

- [ ] #강제 [원칙 R6](원칙.md#R6) 못 잰 항목은 `미측정(사유)` 로 적고 재측정 대기에 등록했다
- [ ] #강제 [원칙 R17](원칙.md#R17) 내 권한 밖 파일을 건드리지 않았다 (PD 「역할 기동 규약」 권한표)

### 설계

1. 원본 함수를 전수 대조표로 펴고 빈 칸이 0인가 (「전수 대조표」)
2. 장식과 데이터 종속 아트가 다른 필드인가 ([카드 장식](UIUX%20-%20카드%20장식.md) 「장식과 내용물」)
3. 등급색 같은 공통 강조가 배경이 아니라 테두리에 걸리나 ([카드 장식](UIUX%20-%20카드%20장식.md) 「장식과 내용물」)
4. 레이아웃 그룹 아래 낱개 아이콘에 `LayoutElement` 가 있나 ([레이아웃](UIUX%20-%20레이아웃.md) 「레이아웃 함정」)
5. 폰트가 못 그리는 글리프를 텍스트로 넣지 않았나 ([폰트](UIUX%20-%20폰트.md))
6. 치환 Helper 를 모든 표시 경로가 타나 ([폰트](UIUX%20-%20폰트.md) 「치환 경로」)
7. 분수 배치를 픽셀로 박지 않았나 ([좌표계](UIUX%20-%20좌표계.md) 「분수 배치」)
8. 재생에서 눌러야 할 것이 실제로 눌리나 (`RaycastAll` 첫 결과가 자기 자신 · `PLAYMODE=1 Tools/unity-batch.sh`, 에디터 다리)
9. 지연 로드 아트를 다시 묻는가
10. 상태 전이(접힘↔펼침, 정지↔재개)를 실제로 눌러 확인했나
11. CSS 레이아웃을 대응표로 옮겼나 ([레이아웃](UIUX%20-%20레이아웃.md) 「CSS 대응표」)
12. 수치를 CSS 계산 → 캡처 검증 2단계로 넣었나 ([레이아웃](UIUX%20-%20레이아웃.md) 「CSS 수치 검증」)
13. 스틸과 영상이 겹치는 rect 비율을 소스에 맞췄나 (「렌더링 함정」)
14. 재사용한 공용 창이 원본에서도 같은 구조인가 ([프리팹 생성](UIUX%20-%20프리팹%20생성.md) 「재사용 단서」)
15. 새로 구운 절차 도형의 알파 프로파일을 찍어 봤나 ([프리팹 생성](UIUX%20-%20프리팹%20생성.md) 「알파 프로파일」)
16. 팩토리 헬퍼를 고쳤으면 호출부 인자 조합을 전부 구워 봤나 ([프리팹 생성](UIUX%20-%20프리팹%20생성.md) 「팩토리 헬퍼」)
