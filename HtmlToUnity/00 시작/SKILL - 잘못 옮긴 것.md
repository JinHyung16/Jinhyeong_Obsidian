# SKILL - 잘못 옮긴 것

상위: [SKILL](SKILL.md)

## 엉뚱한 곳에 옮긴 값

### 요약

- 다 옮겼는데 자리가 틀린 것은 화면이 정상이라 파리티 검증에 안 걸린다.
- 원본 JS 의 배치 좌표 · 프레임 번호 · 트림 박스 · 프레임 개수를 전부 시트로 옮기면 프리팹 · AnimationClip · 스프라이트 임포터 · 앵커의 몫을 표가 덮는다.
- 가르는 질문은 「이 값을 누가 눈으로 맞추나」다.

### 규칙

- 아트가 눈으로 맞추면 프리팹 · 클립이다.
- 기획이 표로 정하면 시트다.
- 아무도 눈으로 안 맞추는 것(좌표계 단위 기준 등)만 코드다.
- 원본이 JS 상수였다는 사실은 자리를 정하는 근거가 아니다.

### 설계

| 증상 | 규칙 |
|---|---|
| 시트에 좌표 · 오프셋 · 크기 컬럼이 있다 | [PrefabRule](PrefabRule.md) 「배치 상수」. 정규화 −1~1 좌표는 앵커다 |
| 시트에 프레임 접두어 · 개수 · fps · loop 가 있다 | [DataFramework](DataFramework.md) 「시트로 옮길 값」. 재생 계층이 가질 값이다 |
| 개수 컬럼이 실제 파일 수와 같다 | 합격이 아니라 중복이다. 같은 문서 |
| 같은 거동 값이 프리팹과 시트 양쪽에 있다 | 같은 문서. 화면마다 읽는 쪽이 갈린다 |
| 판별 어휘가 `string` 컬럼이다 | 같은 문서. enum 이다. 전환 전 세이브 키인지 확인한다 |
| 조회 실패에 폴백을 깔았다 | 없으면 오류다. 폴백은 어서트를 무력화하므로 조회 실패는 터뜨린다 |
| 아트 주소를 코드가 조립한다 (`"<폴더>/" + code`) | 1장이면 `~Path` 컬럼과 `Validate` 존재 검사 |
| 연출 상수가 코드 `const` 로 남아 있다 (크기 배율 · fps · 알파 · 오프셋) | 아래 「코드에 남은 상수」 |
| 원본과 크기 · 속도가 어긋나는 것을 뷰에서 보정했다 | 같은 절. 단위 문제를 뷰로 덮으면 판정과 그림이 갈린다 |

## 코드에 남은 상수

### 요약

- 코드에 남은 상수는 화면 · 시트 검사 · 프리팹 검사를 전부 통과한다.
- 기획과 아트가 만질 수 없게 된다.
- 그래서 착수할 때 한 번 세는 것이 기본이다.

### 규칙

- 이관한 파일에서 숫자 상수를 전부 뽑아 행선지를 적는다.
- 코드에 남기는 값은 「튜너블이 아니다」를 주석으로 못박는다.
- 그 값을 바꾸고 싶어질 사람이 있으면 코드 자리가 아니다.

### 설계

```bash
# 경로·언어는 프로젝트마다 다르다. 「세어서 표로 만든다」가 규칙이다
grep -rn "const .*= *[0-9]" <이관한 코드 폴더> | grep -v "<단위 기준 파일>"
```

| 남아 있는 상수 | 가야 할 곳 |
|---|---|
| 크기 · 오프셋 배율, 색 · 알파 | 프리팹 (`[SerializeField]`) |
| 프레임 fps · 재생 길이 · loop | 재생 계층. 아래 「재생 계층」 |
| 밸런스 · 확률 · 문구 · 쿨다운 | 시트 |
| 좌표계 단위 기준 · 원본 알고리즘의 고정 계수 | 코드 |

## 재생 계층

### 요약

- 프레임 값(fps · loop · 프레임 목록)은 시트도 코드 `const` 도 아니다.
- 무엇이 재생하느냐는 동시에 몇 개가 도느냐가 정한다.
- 「애니메이션이니까 AnimationClip」은 근거가 아니다.

### 규칙

- 다수 풀링 개체의 기본은 중앙 틱이다.
- 단발 · 소수거나 여러 트랙 동기가 필요하면 AnimationClip 또는 Timeline 이다.
- 이 기본에서 벗어나면 근거를 사람과 교차 확인한다 ([원칙](원칙.md) 「쓰는 법」).

### 설계

| 언제 | 재생 계층 |
|---|---|
| 동시 수십~수백 개 (풀링되는 전투 개체 · 이펙트 · 투사체) | 중앙 틱. 프레임 인덱스를 데이터에 두고 렌더러가 배열을 한 번에 진행시킨다 |
| 단발 · 소수, 이벤트 · 커브를 여러 트랙으로 동기 | AnimationClip / Timeline |

- 개체당 재생 컴포넌트(Animator 포함)는 비용이 개체 수에 비례한다.
- 중앙 틱은 `frame += dt * fps` 한 줄이다. 프레임 인덱스가 개체 데이터라 풀 반환 때 같이 초기화된다.
- fps · 배율 · 알파는 에디터에서 눈으로 다루는 자산으로 간다. 1순위는 에셋(ScriptableObject)이고, 밸런스로 갈리는 값만 시트다.
- 경량 런타임과 에디터 저작은 배타적이지 않다. 중앙 틱이 에셋을 읽으면 런타임 비용 0 에 인스펙터 프리뷰가 된다.

## 착수 전 세 가지 세기

### 규칙

- 새 표의 행 수가 상위 표와 같은지 센다. 같으면 컬럼으로 접는다.
- 같은 값이 프리팹에도 있는지 센다.
- 개수 컬럼이 파일 개수와 같은지 센다.
