# 지도

HTML5 · 웹 게임을 Unity 로 옮기는 방법을 모은 지식 책의 목차다.

## 이 볼트

### 요약

- 작업 기록이 아니라 찾아 읽는 책이다.
- 방법만 둔다. 한 게임의 값은 그 게임의 작업 기록에 둔다.

### 규칙

| 이 볼트에 둔다 | 두지 않는다 |
|---|---|
| 공통 Unity 구조 · 장르별 구조 차이 · 절차 · 게이트 · 원칙 · 함정 사전 | 게임별 작업 원장 · 회차 기록 · 한 게임의 실측 수치 |

### 설계

- 노트 형태는 [노트 형식](노트%20형식.md) 이 정한다.
- 흐름 그림은 [이관 흐름](이관%20흐름.canvas) 이다.

## 강제와 방향

### 요약

- 강제는 [원칙](원칙.md) 한 노트뿐이다.
- 나머지는 방향이라 에이전트가 고른다.

### 규칙

| 성격 | 어디 | 읽는 법 |
|---|---|---|
| 강제 | [원칙](원칙.md) R1~R23 | 판단 대상이 아니다. 다른 노트에서는 `#강제` 줄과 원칙 링크로만 나온다 |
| 방향 | 나머지 전부 | 기본값과 이유, 다른 선택이 나은 조건. 기본값을 벗어나면 사람과 교차 확인한다 |

### 설계

모든 노트의 `성격` 속성으로 구분한다.

## 읽는 순서

### 설계

| 단계 | 여는 노트 |
|---|---|
| 0. 판단 대상이 아닌 것 | `00 시작/` [원칙](원칙.md) |
| 1. 이관인지 판정 · 뼈대 | `00 시작/` [SKILL](SKILL.md) |
| 2. 착수 질문 · 확정표 · 분해 · 게이트 | `10 PD/` [PD](PD.md) |
| 3. 원본 형태 · 장르 판정 | [PD - 원본 형태](PD%20-%20원본%20형태.md) 「원본 형태 판정」 다음에 `70 장르/` [장르 지도](장르%20지도.md) |
| 4. 학습 (지식 4) | `20 지식/` [Design](Design.md) · [Client](Client.md) · [Fx](Fx.md) · [UIUX](UIUX.md) 와 해당 장르 노트 |
| 5. 이관 (단위마다 3패스) | `30 이관/` [Transfer_Programmer](Transfer_Programmer.md) · [Transfer_Artist](Transfer_Artist.md) |
| 6. 이관 중 규약 | `40 규약/` [DataFramework](DataFramework.md) · [GameFramework](GameFramework.md) · [UIFramework](UIFramework.md) · [PrefabRule](PrefabRule.md) · [ResourceRule](ResourceRule.md) · [SkillSystem](SkillSystem.md) |
| 재거나 산출물 규격이 필요할 때 | `50 공통/` [공통절차](공통절차.md) · [분석로직](분석로직.md) |
| 착수 전에 · 막혔을 때 | `60 함정/` [함정 색인](함정%20색인.md) |

## 폴더

### 설계

| 폴더 | 무엇 |
|---|---|
| `00 시작` | 진입 · 이 지도 · 원칙 · 노트 형식 · 흐름 캔버스 |
| `10 PD` | 확정 · 배분 · 게이트 · QA |
| `20 지식` | 원본을 읽어 사실을 넘기는 역할 4 |
| `30 이관` | 사실을 합쳐 Unity 로 옮기는 역할 2 |
| `40 규약` | Unity 쪽 공통 구조 |
| `50 공통` | 측정 절차 · 산출물 규격 |
| `60 함정` | 반복된 함정을 주제별로 모은 사전과 색인 |
| `70 장르` | 장르 · 표현 방식별로 더 볼 것과 구조 차이 |

## 속성

### 규칙

- 모든 노트에 `분류` · `성격` 속성과 `htmltounity` 태그를 둔다.
- `성격` 은 강제 또는 방향이다.

### 설계

Bases 와 그래프에서 이 값으로 묶어 본다. 강제가 걸린 자리는 태그 창의 `#강제` 로 모아 본다.

## 고칠 때

### 규칙

- 사실은 한 노트에만 둔다. 다른 노트는 링크한다.
- 노트 이름은 볼트 전체에서 유일하게 둔다. 링크가 이름으로 풀린다.
- 게임 고유명사와 한 게임의 실측 수치를 규칙으로 적지 않는다 ([SKILL - 글쓰기 규약](SKILL%20-%20글쓰기%20규약.md#금칙)). 장르 노트의 뒷받침 게임 표기만 예외다.
- 노트를 쪼개면 이 지도와 상위 노트의 링크를 같이 고친다.
- 프로젝트에 사본을 만들지 않는다. 프로젝트에는 발화용 스텁 스킬만 둔다 ([SKILL - 프로젝트에 붙이기](SKILL%20-%20프로젝트에%20붙이기.md)).

### 설계

고친 뒤 옵시디언에서 미해결 링크가 0 인지 본다. 그래프 뷰의 「미해결 파일 표시」 또는 백링크 창이다.
