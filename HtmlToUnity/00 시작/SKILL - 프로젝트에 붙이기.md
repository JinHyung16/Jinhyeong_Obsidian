# SKILL - 프로젝트에 붙이기

상위: [SKILL](SKILL.md)

## 스텁과 진입 파일

### 요약

- 문서 원본은 옵시디언 볼트 `HtmlToUnity/` 하나다.
- 프로젝트에는 사본을 두지 않고 볼트를 가리킨다.
- 사본이 생기면 두 곳이 갈린다.

### 규칙

1. 프로젝트 `.claude/skills/htmltounity/SKILL.md` 에 스텁을 둔다. 스텁에는 [SKILL](SKILL.md) 의 프론트매터(`name` · `description`)와 볼트 경로만 둔다.
2. 진입 파일(`CLAUDE.md` · `AGENTS.md`)에는 볼트 경로와 「이관이면 스킬을 연다」만 둔다.
3. 그 프로젝트 진입 파일에 「도구 제약」 표를 채운다.

### 설계

- Claude Code 는 스킬을 `.claude/skills/` 에서만 찾는다. 발화는 `description` 이 한다.
- 볼트는 무엇을 하는가만 적는다. 어떤 도구로 하는가는 프로젝트의 도구 제약 표가 가진다.
- 사례: 진입 파일의 「이관 작업일 때만 다른 문서를 연다」는 한 세션 내내 발화하지 않았다. 스텁의 `description` 이 작업 문구와 매칭되어 이를 막는다.

## 진입 파일에 두지 않는 것

### 요약

- 진입 파일은 매번 읽힌다.
- 이관할 때만 필요한 규칙은 진입 파일에 두지 않는다.

### 규칙

- 가르는 질문은 「이관이 아닌 작업에서도 이 규칙이 필요한가」다.
- 먼저 정본으로 옮기고, 정본에 그 내용이 실제로 있는지 확인한 뒤에 뺀다.
- 뺀 뒤 진입 파일이 가리키는 절 제목이 실재하는지 기계로 확인한다.

### 설계

| 답 | 자리 |
|---|---|
| 필요하다 (폴더 · 네이밍 · 로그 · 커밋 · 로드 방식 · 엔진 러너 명령) | 진입 파일 |
| 이관할 때만 필요하다 (색공간 역산 · 검증 산출물 자리 · 원본을 여는 도구의 한계 · 확정값 자리) | 이 세트의 해당 문서. 진입 파일에는 어느 문서인지 한 줄만 |
