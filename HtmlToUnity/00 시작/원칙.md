# 원칙

판단 대상이 아닌 것만 모았다. 나머지 노트는 방향이다.

## 쓰는 법

### 요약

- 이 노트의 R1~R23 만 강제다.
- 어기면 결과물이 틀리거나, 되돌릴 수 없거나, 권리를 침해하거나, 사람이 정한 것을 뒤집거나, 보고가 거짓이 된다.
- 다른 노트는 기본값과 이유를 주는 방향이다.

### 규칙

- 강제가 걸리는 자리는 `#강제` 태그와 `[원칙 R7](원칙.md#R7)` 링크로 표시한다.
- 원칙 문장은 이 노트에만 둔다.
- 방향 노트의 기본값에서 벗어날 때는 선택지와 근거를 사람에게 보여 교차 확인한다. 고른 결과와 이유는 확정표에 남긴다.
- 강제끼리 부딪히거나 강제 때문에 품질이 분명히 떨어지면 스스로 풀지 않고 사람에게 묻는다.

### 설계

| 성격 | 어디 | 누가 고르나 |
|---|---|---|
| 강제 | 이 노트 | 고르지 않는다 |
| 방향 | 나머지 노트 | 에이전트가 원본 · 장르 · 규모를 보고 고른다 |

## 판정

### 요약

- 무엇이 맞은 결과인지 정한다.
- 기준은 원본이고, 증명은 결과물에서 되읽은 값이다.
- 못 잰 것은 통과가 아니다.

### 규칙

#### R1

겉(보이는 것 · 플레이 감각)은 원본이 기준이다. 값 · 분기 · 순서 · 원본의 이상 거동까지 같게 한다. 다르면 유니티가 틀린 것이다.
원본의 이상 거동을 고치려면 의도된 차이로 등재하고 사람이 확정한다(R10 · R12).
이유: 「돌아간다」와 「원본과 같다」는 다르다. 판정 기준이 흔들리면 모든 숫자가 무의미해진다.

#### R2

원본 엔진 · 프레임워크와 Unity 의 차이를 먼저 이해하고, 구조는 Unity 에 맞게 다시 설계한다. 값과 규칙은 원본에서 가져온다. 원본의 구조(DOM 계층 · 캔버스 호출 순서 · 전역 루프 · 원본 엔진 API)를 1:1 로 옮기지 않는다.
이유: 겉을 맞추려고 원본 구조를 흉내 내면 속이 다듬을 수 없는 코드가 된다. 어떤 Unity 구조가 맞는지는 방향 노트가 제시하고 에이전트가 고른다.

#### R3

원본이 진실 소스다. 요약 · 기획서 · 캡처 · 장르 지식 · 기억보다 원본 코드와 원본 실측이 이긴다.
값에는 근거 등급([소스] · [실측] · 미측정)을 붙인다. 관측으로 본 최솟값 · 개수는 값이 아니라 하한으로 적는다.

#### R4

지어내지 않는다. 못 캔 값을 공식 · 그림 · 관측으로 메우지 않고 미측정으로 둔다. 관측에서 지어낸 규칙은 값이 맞아도 틀린 것으로 본다.

#### R5

점수에 맞추지 않는다. 정답지 · 파라미터 · 허용 오차를 통과하게 고르지 않는다. 정답지는 원본에서 온 값이어야 한다. 정답지를 고치는 근거는 새 실측뿐이다.

#### R6

미측정은 통과가 아니다. 못 잰 것과 도달하지 못한 경로는 `미측정(사유)` 로 적고 달성률은 0 이다. 판정 칸에는 숫자 또는 미측정만 적는다.

#### R7

증명은 결과물로 한다. 「있다 · 호출했다 · 식이 맞다 · 표에 행이 있다」는 증명이 아니다. 화면이나 산출물의 최소 단위에서 되읽은 것만 센다. 세는 검사는 최소 개수를 박아 분모 0 으로 통과하지 않게 한다.

#### R8

100% 는 조건이 갖춰졌을 때만 선언한다. 분모는 원본 전수(이관율 대조표)다. 의도된 차이 밖의 차이는 전부 미흡이다. 원본이 URL 로만 오면 「관측 범위 내 동일 + 미측정 목록」까지만 말한다. 선언은 QA 통과 뒤다.

#### R9

채점에서 뺀 것은 드러낸다. 비결정 구간 등은 원본에서도 갈린다는 실측 근거로만 뺀다. 뺀 건수를 항상 따로 보고한다.

#### R10

원본과 다르게 한 것은 의도된 차이로 등재해야 차이로 인정된다. 등재 없는 변경은 결함이다.

## 권리

### 규칙

#### R11

원본 에셋 · 코드를 추출하거나 복사하지 않는다. 런타임 · 번들에서 읽을 수 있어도 마찬가지다. 규칙과 규격만 읽고 다시 만든다. 원본 픽셀 배치를 어디까지 맞출지는 사람이 정한다.

## 사람이 정한 것

### 요약

- 사람의 확정이 측정과 판단보다 위다.
- 확정표가 비면 착수하지 않는다.
- 역할 권한을 섞지 않는다.

### 규칙

#### R12

사람이 확정한 것은 에이전트의 판단이나 측정보다 위다. 측정이 확정과 다르면 알리고 확정을 따른다.

#### R13

확정표가 비면 착수하지 않는다. 게임마다 달라지는 결정(방향 · 해상도 · 범위)은 게임마다 사람에게 묻는다. 이관 의사가 확정되지 않았으면 확정표 · 원장 · Unity 산출물을 만들지 않는다.

#### R14

새로 생긴 규칙은 앞으로 착수하는 게임부터 적용한다. 끝난 게임은 사람이 시킬 때만 고친다.

#### R15

프로젝트 진입 파일(`CLAUDE.md` 등)이 이 볼트와 어긋나면 프로젝트 쪽이 우선한다.

#### R16

사람에게 엔진 조작(메뉴 · 인스펙터 · 설치 · 에디터 재시작)을 요구하지 않는다. 사람에게 남기는 것은 원본을 건네기와 마지막에 열어 보기뿐이다. 도구로 할 수 없는 일을 만나면 멈추고 무엇이 막혔는지 알린다.

#### R17

역할 권한을 지킨다. 지식 역할은 Unity 산출물을 만들지 않는다. PD 는 직접 만들지 않는다. 배선 패스는 프리팹을 직접 고치지 않고 프리팹 담당에게 되돌린다. 권한표 정본은 [PD - 실행 단계](PD%20-%20실행%20단계.md) 「역할 기동 규약」.
이유: 한 에이전트가 여러 역할을 맡을 때 앞 역할의 결론이 다음 판단을 오염시키는 것을 막는다.

## 되돌릴 수 없는 것

### 요약

- 사람의 작업과 기계 상태를 건드리는 일은 시킨 범위만 한다.
- 지우거나 덮어쓰기 전에 되돌릴 수 있는지 본다.

### 규칙

#### R18

git 커밋 · 브랜치 · 푸시는 사람이 시킨 범위만 한다.

#### R19

프로세스는 이 프로젝트의 PID 로만 끈다. 말없이, 또는 이름으로 죽이지 않는다. 가려낼 수 없으면 멈춘다.

#### R20

사람이 쓰는 에디터를 저장 없이 끄지 않는다. 꺼야 하면 알리고 저장 후 정상 종료한다. 검사기는 재생 종료까지만 한다.

#### R21

사용자 데이터를 지킨다. 검증 하네스에는 세이브에 닿는 경로가 없어야 한다. 상태를 조작하는 측정은 전에 백업하고 끝나면 복원한다. 원본 폴더는 건드리지 않는다.

#### R22

사람이 손본 결과물을 덮어쓰지 않는다. 프리팹이 주인이면 통째로 다시 굽는 것은 사람이 명시할 때만 하고 원장에 적는다. 원본(SSOT)이 따로 있는 생성물은 원본에서만 고친다.

## 보고

### 규칙

#### R23

완료는 조건이 전부 참일 때만 말한다. 아니면 남은 목록을 낸다. 기록은 덮어쓰지 않고 정정을 남긴다. 실패를 조용히 넘기지 않는다(굽기 실패는 비0 종료 · 산출물 미갱신, 생성 실패는 경고).
