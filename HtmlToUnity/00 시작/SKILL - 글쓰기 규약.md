# SKILL - 글쓰기 규약

상위: [SKILL](SKILL.md)

노트 형태는 [노트 형식](노트%20형식.md) 이 정한다. 이 노트는 무엇을 적고 무엇을 안 적는지를 정한다.

## 표기 마커

### 요약

- 예시 없는 규칙은 적용이 안 되므로 예시는 남긴다.
- 사실로 오독되지 않게 마커를 단다.

### 규칙

- 사고는 한 줄 `사례: … (함정: [항목](함정%20-%20주제.md#항목))` 로 적는다.
- 사고 밖의 실측 수치는 `[예시]` 를 달거나 재는 방법으로 바꾼다.
- 표시 없는 수치는 다음 회차에 원본 사양처럼 인용된다.

### 설계

| 마커 | 뜻 | 읽는 쪽이 할 일 |
|---|---|---|
| `[예시]` · `예:` | 이렇게 생기면 된다는 모양. 값은 프로젝트마다 다르다 | 모양만 베끼고 값은 갈아끼운다 |
| `[사고]` · `사례:` | 실제로 났던 실패. 재발 조건이 남아 있다 | 같은 자리를 먼저 확인한다 |
| 마커 없음 | 이 세트의 기본값. 강제는 `#강제` 줄이 [원칙](원칙.md) 을 가리킨다 | 기본으로 따르고, 더 나은 선택이면 근거를 남긴다 |

- 사고 한 줄 안의 수치는 그 프로젝트의 실측이지 사양이 아니다.
- 코드 블록 · 경로 · 클래스명(`Assets/Scripts/UI/` · `GameRoot.Instance.XxxDataContainer`)은 전부 `[예시]` 취급이다. 프로젝트에 규약이 있으면 그쪽이 우선한다.

## 말투

### 요약

- 사람에게 하는 보고와 새로 쓰는 문서에 적용한다.
- 적용 범위는 2026-09-15 부터다 [사람 확정].
- 이유: 한자어 · 문서 용어가 겹치면 사람이 뜻을 되짚느라 핵심을 놓친다.

### 규칙

- 결론을 먼저 쓴다. 한 문장에 한 가지만 쓴다.
- 일상어를 쓴다. 문서 용어를 꼭 써야 하면 처음 한 번 괄호로 풀어 준다. 예: 원장(작업 기록 파일).
- 끝나지 않았으면 보고 마지막에 「남은 작업」 목록을 붙인다.
- 「완료」는 남은 것이 0 일 때만 쓴다 ([원칙 R23](원칙.md#R23)).

### 설계

| 피할 말 | 쓸 말 |
|---|---|
| 원장 | 작업 기록 |
| 확정표 | 결정 목록 |
| 착수 | 시작 |
| 실측 | 직접 잰 값 |
| 미측정 | 아직 안 잼 |
| 정본 | 기준 문서 |
| 산출물 | 만든 파일 |
| 골격 | 빈 틀 |
| 회차 | N번째 작업 |
| 게이트 · 판정 | 통과 조건 · 결과 |
| 의도된 차이 | 일부러 다르게 한 것 |
| 등재 · 소관 | 적어 둠 · 담당 |
| 앵커 | 찾을 글자 |
| 상류 · 파생 | 원래 프로젝트 · ~에서 나온 |

기존 노트의 용어와 파일 이름은 링크가 걸려 있어 그대로 둔다. 보고에서 그 이름을 가리킬 때만 쉬운 말을 앞에 쓴다.

## 금칙

### 요약

- 특정 타이틀의 고유명사와 실측치는 이 문서 세트의 수명을 깎는다.
- 역할 이름과 재는 방법으로 적는다.

### 설계

| 피할 것 | 대신 |
|---|---|
| 게임 고유명사 (유닛명 · 화면명 · 스킬명) | 역할 이름 (`선택 카드` · `유닛` · `상점 창`) |
| 특정 프로젝트의 실측치 (`노드 564개`) | 재는 방법. 수치는 그 프로젝트의 원장에 |
| 그 프로젝트에서만 있던 도구 경로 | 도구가 무엇을 재는지 |
| 「이 저장소는 …」 | `[예시]` 로 표시한다 |
| 한 게임의 실측 수치를 장르 사양으로 적기 | 장르 노트에는 구조 · 질문 · Unity 패턴만 둔다. 규격은 [장르 지도](장르%20지도.md) 「노트 규격」 |

- `사례:` 한 줄 안의 수치와 장르 노트의 뒷받침 게임 이름은 허용하는 자리다.
- 프로젝트 사정에 맞춰 이 문서들을 고치고 싶어지면, 그건 대개 원장에 적을 회고다.
