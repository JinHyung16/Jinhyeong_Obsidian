# SKILL

HTML5 게임을 Unity 로 옮기는 문서 세트의 본문이다. 방향 노트라 기본값과 이유를 준다.

## 목적

### 요약

- 특정 타이틀에 매이지 않는 범용 문서 세트다.
- 목적은 넷이다.
- 겉은 원본이 심판이고, 속은 우리 기준이 심판이다.

### 규칙

1. HTML5 게임을 Unity 로 100% 옮긴다. 화면 · 그래픽 · 시스템 · 콘텐츠 전부다.
2. 옮긴 빌드가 원본과 똑같이 플레이된다. 완료 조건은 「돌아간다」가 아니라 「원본과 같다」다.
3. 옮기는 과정이 사람의 유니티 조작을 요구하지 않는다.
4. 결과물을 이어서 다듬을 수 있다. 디테일을 올릴 때 프리팹 · 데이터만 조금 고친다.

#강제 [원칙 R1](원칙.md#R1) 목적 2. 다르면 유니티가 틀린 것이다.
#강제 [원칙 R2](원칙.md#R2) 목적 4. 원본 구조를 옮기지 않는다.

### 설계

| 어디 | 기준 |
|---|---|
| 겉 (보이는 것 · 플레이 감각) | 원본처럼 보이고 원본처럼 논다 |
| 속 (코드 · 프리팹 · 데이터 구조) | 원본 구조를 따라 하지 않는다. 이어서 다듬기 쉬운 Unity 구조로 짠다 ([PD - 대원칙](PD%20-%20대원칙.md) 「속 품질」) |

- 읽는 순서는 [지도](지도.md) → [원칙](원칙.md) → 이 노트 → [PD](PD.md) 다.
- 노트 형태는 [노트 형식](노트%20형식.md) 이 정한다.
- [원칙](원칙.md) 만 강제다. 나머지는 기본값이라 원본 · 장르 · 규모를 보고 고르고, 벗어나면 사람과 교차 확인해 확정표에 남긴다.

## 뼈대

### 요약

- 입력 형태별로 갈리는 것은 윗단 분석뿐이다.
- 모든 입력이 같은 허리 산출물로 모인다.
- 허리 아래는 입력 형태를 모른다.

### 규칙

- 트렁크 문서는 입력 형태와 무관하게 쓴다. 「URL형이면 이렇게」 같은 분기를 넣지 않는다.
- 형태 차이가 들어가는 자리는 둘뿐이다. 윗단 가지(진실을 어떻게 캐나)와 합격 기준(완전성을 어디까지 증명하나)이다.
- 트렁크가 원본으로 되돌아갈 때는 허리의 「접속 · 재현 방법」을 쓴다.

### 설계

```
[코드 제공형]   [URL 제공형]   [미래의 형태]      가지: 입력 형태별 분석 (PD 「원본 형태 판정」)
      └──────────────┴──────────────┘
                     ▼
   확정표 · 00_원본정보 · HtmlToUnityLogic 골격 전부    허리: 표준 산출물 계약
                     ▼
   지식 4 → 작업 분해표 → 단위별(①②③+검사) → 게이트 → QA    트렁크
                     ▼
                Unity 빌드
```

- 분기를 넣으면 새 형태가 생길 때마다 문서 전부를 고친다.
- 담당자 실행 컨텍스트(병렬 · 격리)는 [PD](PD.md) 「PD 역할」.

## 사람 조작 없이

### 요약

- 의뢰인은 대개 유니티 사용자가 아니다.
- 메뉴 · 인스펙터 조작을 요구하면 절차가 거기서 멈춘다.
- 사람에게 남기는 것은 원본 건네기와 마지막에 열어 보기뿐이다.

### 규칙

#강제 [원칙 R16](원칙.md#R16) 이 카테고리 전체.

### 설계

| 하지 않는다 | 한다 |
|---|---|
| 「`Tools > …` 메뉴를 눌러 주세요」 | 러너로 직접 실행한다 |
| 「인스펙터에서 라벨을 지정해 주세요」 | 에디터 API 로 코드가 지정한다 |
| 「프리팹을 만들어 주세요」 | 빌더가 첫 초안을 굽고 이후 수정은 에디터 API 로 프리팹을 고친다 |
| 「패키지를 설치해 주세요」 | `Packages/manifest.json` 을 직접 고친다 |

결과물은 프로 수준이어야 한다. 의뢰인이 검수할 수 없으므로 기준은 우리가 지킨다.

## 에디터 러너

### 요약

- MCP 에디터 제어 없이도 셸로 에디터 코드를 실행한다.
- 기본은 에디터 다리다. 에디터가 열려 있으면 끄지 않고 작업을 넘긴다.
- 배치모드는 에디터가 꺼져 있을 때의 폴백이다.

### 규칙

- 대상은 인자 없는 `static` 메서드다.
- 재생 검사기는 시작할 때 `Application.runInBackground = true` 를 켠다 (함정: [포커스 없는 에디터 재생의 throttle](함정%20-%20도구%20러너.md#포커스%20없는%20에디터%20재생의%20throttle)).
- 에디터를 끄는 것은 배치가 필수일 때로 좁힌다.

#강제 [원칙 R20](원칙.md#R20) 꺼야 하면 러너가 저장 후 정상 종료시킨다 (`CLOSE_EDITOR=1`).

### 설계

```bash
Tools/unity-batch.sh <정적 메서드 전체 이름>              # 열린 에디터면 다리, 꺼져 있으면 배치모드
PLAYMODE=1 Tools/unity-batch.sh <정적 메서드 전체 이름>   # 재생 검사

# 배치모드(폴백)가 부르는 모양
<Unity실행파일> -batchmode -quit -nographics -silent-crashes \
  -projectPath <프로젝트> -executeMethod <Namespace.Class.Method> -logFile <로그>
```

- 메뉴 · 에디터 툴 실행, 에셋 임포트, 설정 에셋 생성, 프리팹 굽기가 된다. 테스트는 `-runTests` 다.
- 배치모드는 에디터가 그 프로젝트를 열어 두면 실패한다. 한 프로젝트를 두 인스턴스가 못 연다.
- 다리 정본은 [공통절차 - 에디터 실행](공통절차%20-%20에디터%20실행.md) 「에디터 다리」.

## 분해

### 요약

- 학습이 끝나면 분해한다.
- 이관은 분해표 순서대로만 돈다.
- 분해 없이 게임 전체에 패스를 반복하면 뒤에서 나온 결함이 앞으로 되돌아간다.

### 규칙

- 단위는 학습 산출물에서 기계적으로 뽑는다. 시스템 문서 한 장 · 화면 하나 · 테이블 묶음 · 연출 덩어리 · 리소스군이다.
- 기본 순서는 의존 → 한 판 돌아가는 최소 경로 → 못 잰 것이 많은 것 → 작은 것이다.
- 3패스는 한 단위 안에서 돈다. 게임 전체에 ①을 다 하고 ②를 다 하지 않는다.
- 이관은 게이트 `G0-b` 통과 뒤에 시작한다.

### 설계

```
학습 산출물 → 작업 분해표(단위 · 선행 · 순서 · 완료 조건) → 단위마다 ①→②→③→검사 → 완료
```

규격은 [분석로직 - 원장 기입 규칙](분석로직%20-%20원장%20기입%20규칙.md) 「작업 분해표」, 절차와 순서 규칙은 [PD](PD.md) 가 정본이다.

## 한 요청에 한 게임

### 요약

- 사람이 이관을 시켰으면 분해표 전 단위를 멈춤 없이 돈다.
- 단위 하나 끝날 때마다 보고하고 기다리지 않는다.
- 이유: 단위마다 멈추면 사람이 매번 「계속해」를 말해야 한다.

### 규칙

| 만나면 | 하는 것 |
|---|---|
| 결정이 필요한데 원칙 안에 기본값이 있다 | 기본값으로 진행하고 작업 기록과 결정 목록에 적는다. 마지막 보고에 모아 알린다 |
| 도구로 못 하는 일 ([R16](원칙.md#R16)) · 허락이 필요한 일 | 그 항목만 막힘으로 두고 나머지 단위를 계속한다 |
| 학습 부족 | 그 단위 시작 직전에 채우고 이어 간다 |

- 중간 보고는 사람이 물을 때만 한다.
- 마지막 보고는 결론 다음에 남은 작업 순서다.

## 언제 여나

### 요약

- 이 스킬이 열렸으면 이관 작업이다.
- 사람은 「이관」이라는 말을 쓰지 않는다. 판정 기준은 어휘가 아니다.
- 애매하면 한 줄로 묻고 Y/N 을 받는다.

### 규칙

| 언제 | 무엇부터 |
|---|---|
| 게임만 주고 「분석해줘」. 이관 의사 미확정 | [PD - 진입](PD%20-%20진입.md) 「사전 분석 모드」. 원본만 재서 기록하고 끝에 이관 여부를 묻는다 |
| 새로 이관 | [PD](PD.md). 착수 질문의 답을 받기 전에 아무것도 만들지 않는다 |
| 원본과 같은지 검증 | 같은 문서. PD 를 QA · 게이트 역할로 연다 |
| 아직 안 옮긴 것을 옮긴다 | 해당 파트 문서만 ([UIUX](UIUX.md) · [ResourceRule](ResourceRule.md) · [Transfer_Programmer](Transfer_Programmer.md)) |

#강제 [원칙 R13](원칙.md#R13) 「새로 이관」 행. 착수 질문의 답 전에는 아무것도 만들지 않는다.
#강제 [원칙 R15](원칙.md#R15) 프로젝트 규칙과 어긋나면 `CLAUDE.md` 가 우선한다.

### 설계

- 어휘는 환원 · 옮겨 · 만들어 · 유니티 버전 · 포팅 · 바꿔 · 돌아가게 · 컨버팅 · 마이그레이션 중 무엇이든 된다. 「HTML5 · 웹 게임」과 「Unity」가 한 문장에 있으면 이 스킬이다.
- 애매하면 만들기 전에 한 번 묻는다. 「HTML5 게임을 Unity 로 제작(이관)하는 것을 원하십니까? Y / N」
- Y 면 [PD](PD.md) 착수 질문부터 간다. N 이면 스킬을 닫고 프로젝트 진입 파일로 돌아간다.
- 신규인지 이어가기인지는 원장이 가른다. `.claude/HtmlToUnity_작업내역_<게임명>.md` 가 없으면 신규다.
- 있으면 확정표의 빈 행과 「미확인」 행만 다시 묻고, 최신 회차 다음에 미흡 목록, 그다음 최하위 미통과 게이트로 간다 ([PD - 진입](PD%20-%20진입.md) 「첫 턴 프로토콜」).

## 구성

### 요약

- 문서는 오케스트레이터 · 지식 · 이관 · 규약 · 공통 · 함정 · 장르로 나뉜다.
- 프로젝트마다 새로 만드는 것은 셋뿐이다.
- 나머지 문서는 그대로 쓴다.

### 설계

```
PD            오케스트레이터. 확정 · 배분 · 게이트 · 최종 QA
├── 지식 (이관에 직접 참여하지 않는다. 정보를 제공한다)
│    ├── Design    기획. 상수 · 테이블 · 문구 · 밸런스
│    ├── Client    클라. 시뮬 루프 · 계산 · 수치 정밀도
│    ├── Fx        연출. 렌더 패리티 · 합성 · 색공간
│    └── UIUX      UI/UX. 레이아웃 · 좌표계 · 폰트 · 글리프
├── 이관 (지식을 합쳐 실제로 옮긴다. 분해표의 단위마다 3패스)
│    ├── Transfer_Programmer   ① 코드 · 데이터   ③ 배선
│    └── Transfer_Artist       ② 프리팹 · 연출
├── 규약        DataFramework · GameFramework · UIFramework · PrefabRule · ResourceRule · SkillSystem
├── 공통절차    전 파트가 매번 쓰는 것. 측정 · 캡처 · 감사 · 원본에서 답 찾는 법
├── 원칙        판단 대상이 아닌 것 R1~R23. 유일한 강제
├── 함정 사전   반복된 함정을 주제별로 모은 사전 (함정 색인)
├── 분석로직    프로젝트마다 새로 만드는 문서의 생성 규격
└── 장르        장르 · 표현 방식별로 더 볼 것과 Unity 구조 차이 (장르 지도)
```

| 프로젝트마다 새로 만드는 것 | 담당 |
|---|---|
| 확정표 (착수 질문 전부의 답) | PD |
| `.claude/HtmlToUnity_작업내역_<게임명>.md` | PD |
| `<원본폴더>/HtmlToUnityLogic/` 골격 전부 | 지식 4 |

- 실측으로 남기는 기본은 장면 그래프 덤프다. 캡처는 세션 안에서 한 번 보는 것까지라 캡처 폴더는 없다 ([공통절차 - 캡처와 덤프](공통절차%20-%20캡처와%20덤프.md) 「캡처 사용 범위」).
- 규격만 들고 다니고 실물은 프로젝트를 보고 만든다. 빈 템플릿을 들고 다니면 채우지 않은 칸이 「해당 없음」으로 읽힌다.

## 원본을 여는 규칙

### 요약

- 이관이 끝난 뒤에도 로직 · 수치 · 연출의 진실 소스는 원본 HTML5 다.
- 무엇이 이상하냐에 따라 먼저 여는 것이 갈린다.

### 규칙

| 증상 | 먼저 여는 것 |
|---|---|
| 화면이 이상하다 | 프리팹. 원본보다 프리팹이 먼저다 |
| 수치 · 확률 · 상태 전이가 이상하다 | 원본 |
| 원본에 있는데 우리에게 없다 | 아래 「옮기다 만 것」 |

#강제 [원칙 R1](원칙.md#R1) 수치 · 확률 · 상태 전이가 원본과 다르면 프리팹을 고쳐 덮지 않고 원본에 맞춘다.

## URL 원본

### 요약

- 링크만 받아도 절차는 같다.
- 심판이 원본 코드에서 라이브 원본으로 바뀔 뿐이다.
- 웹 게임은 코드가 브라우저로 내려온다.

### 규칙

1. 게임명을 묻는다. 폴더명과 원장명이 게임명에서 나온다.
2. `<원본폴더>` 역할의 폴더를 만든다. 위치는 저장소 진입 파일의 규약이다.
3. 모든 확정값에 근거 등급을 단다.

#강제 [원칙 R11](원칙.md#R11) 번들은 규칙과 규격을 읽는 데까지다. 에셋 · 코드를 추출하거나 복사하지 않는다.
#강제 [원칙 R3](원칙.md#R3) 등급은 [소스] · [실측] · 미측정 셋뿐이다. 장르 지식으로 채우지 않는다.

### 설계

- 번들 소스를 받아 읽는 것이 관측보다 먼저다 ([PD - 원본 형태](PD%20-%20원본%20형태.md) 「번들 소스」).
- 절차 정본은 [PD - 원본 형태](PD%20-%20원본%20형태.md) 「원본 형태 판정」이다.
- 실측 심화 기법은 [공통절차 - 원본에서 값 캐기](공통절차%20-%20원본에서%20값%20캐기.md)이다.

## 옮기다 만 것

### 요약

- 원본에 있는데 우리에게 없는 것이다.
- 고치기 전에 해당 규칙을 먼저 편다.

### 설계

| 증상 | 규칙 |
|---|---|
| 원본에 있는 필드가 우리 데이터에 없다 | [Transfer_Programmer](Transfer_Programmer.md). 안 옮긴 필드는 어떤 검증에도 안 걸린다. 원본 필드 전수표부터 만든다 |
| 원본의 기호가 두부로 뜨거나 안 보인다 | [ResourceRule](ResourceRule.md) 「폰트」. 자리를 가른 뒤 cmap 을 잰다 |
| 좌표가 원본과 어긋난다 | [UIUX - 좌표계](UIUX%20-%20좌표계.md) 「위치와 순서」 |

반대편은 [SKILL - 잘못 옮긴 것](SKILL%20-%20잘못%20옮긴%20것.md) 이다. 다 옮겼는데 자리가 틀린 것은 화면이 정상이라 검증에 안 걸린다.

## 찌꺼기 지우기

### 요약

- 한 덩어리 작업이 끝날 때마다 문서를 지금 사실로 맞춘다.
- 남은 찌꺼기는 같은 회차에 지운다.
- 이유: 찌꺼기는 다음 회차가 아직 할 일로 잘못 읽는다.

### 규칙

| 찌꺼기 | 어떻게 |
|---|---|
| 틀린 정보 (코드 · 소스 · 검사 결과와 어긋나는 주장, 추측을 사실처럼 적은 것, 지금 코드와 다른 설명, 엉뚱한 링크) | 지운다. 확인 못 한 것은 「미확인」으로 표시하거나 뺀다. 노트가 링크로 이어져 있어 틀린 노트 하나가 다른 판단까지 흐린다 |
| 문서의 끝난 줄 (그어 둔 대기 줄, 「아직 없음」 이었다가 만든 것, 옛 수치) | 지운다. 무엇이 틀렸었는지가 쓸모 있으면 회고 한 줄로 옮긴다 |
| 같은 사실을 두 곳에 적은 것 | 정본 한 곳만 남기고 나머지는 링크로 |
| 검증 산출물 (`out/` 의 지난 로그, 회차용 검사기, 진단용 출력) | 회차 끝에 지운다. 게임 하네스와 회귀 검사는 이관 끝까지 남긴다 |
| 코드 · 에셋 (안 쓰게 된 필드, 옛 방식과 새 방식이 같이 남은 것, 스테이징 폴더, 임시 그림) | 읽는 곳이 없으면 지운다 |
| 스크래치 파일 | 다시 쓸 도구만 남기고 일회용 출력은 지운다 |
