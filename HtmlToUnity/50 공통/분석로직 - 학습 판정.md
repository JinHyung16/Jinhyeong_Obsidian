# 분석로직 - 학습 판정

상위: [분석로직](분석로직.md)

## 시스템 축 점검표

### 요약

- 장르를 모른 채 질문으로 시스템을 센다.
- 기본은 아래 질문에 전부 답하는 것이다. 이유: 화면에 보이는 시스템만 세면 기전이 안 보이는 축이 빠진다.
- 답은 `[소스]` · `[실측]` · `미측정` 중 하나다. R3 을 증명하는 기본 방법이다.
- 「해당 없음」도 근거를 적는다. 이 표에 값은 적지 않는다.

### 설계

| 축 | 질문 | 관측으로 못 가르는 이유 |
|---|---|---|
| 개체 생성 | 시간 · 예산/포인트 · 확률 · 저작 배치 중 무엇? 종류마다 따로 도나? 우선순위는? | 「초당 몇 마리」를 내는 기전이 여럿이다 |
| 난이도의 시간축 | 경과 시간 · 레벨 · 웨이브 · 처치 수 중 무엇? 첫 판 온보딩 감산이 있나? | 레벨과 시간이 같이 오른다 |
| 성장 목표 | 표인가 식인가? | 앞 몇 개는 표로 보인다 |
| 강화 적용 | 두 번 먹으면 덧셈인가 곱셈인가? 상한은? | 한 번으로는 못 가른다. 두 번 먹는다 |
| 후보 풀 | 정의는 몇 개? 조건부 가중치 0 항목이 있나? 비복원 추출인가? | 0 인 항목은 안 보인다. 관측 개수는 하한 |
| 보상 값 | 고정값인가 개체 속성에서 파생되나? | 첫 종류만 보면 고정으로 보인다 |
| 대상 선택 | 유지하나 매번 다시 고르나? 후보는 화면 안인가 전체인가? | 갈리는 순간만 최근접과 다르다 |
| 피격·무적 | 체력은? 무적·쿨다운은? | 마지막 타격은 가린다. 관측 최솟값은 하한 |
| 카메라 | 즉시 · 지수 추적 · 리드 · 데드존 중 무엇? 오프셋은? | 「따라온다」는 다 같아 보인다 |
| 접촉 판정 | 원인가 상자인가? 크기는 그림과 같은가? | 그림 크기로 짜도 맞는 것 같다 |
| 목표·퀘스트 | 한 판을 끝내는 것은 시간 · 목표 수 · 연쇄 과제 중 무엇? 다음 단계는 무엇이 여나? | 끝까지 가야 보인다. 소스가 없으면 미측정 등재 |
| 월드·지형 | 저작인가 절차 생성인가? 시드는? 단위(타일 크기)는? 영역 종류(바닥·풀밭·길)의 문턱과 가장자리 규칙은? | 노드 종류(메시 한 장)로는 틀린다. 버퍼를 열고 문턱 식을 읽는다 |
| 월드 오브젝트 | 지형이 놓는 것(나무·모닥불·상자)과 상호작용(막힘·충전·터짐·회복), 배치 규칙(청크·문턱·개수)은? | 배경 장식으로 보여 전수표에서 빠진다 |
| 공격·스킬 | 공격 수단은 몇 종? 종마다 발동 · 대상 · 발사 · 타격 · 소멸 · 상태이상 중첩 · 강화 적용 키는? 2종 이상이면 `SkillSystem.md` 로 간다 | 화면에선 「쏜다」로 뭉친다. 궤도·연쇄·지연 폭발처럼 한 번에 안 보이는 갈래가 있다 |
| 끝난 뒤 | 클리어 뒤에도 도는 것(반복 조우 · 무한 모드)이 있나? | 클리어해 봐야 보인다 |

- 「해당 없음」이 아닌 축마다 `02_시스템_*.md` 한 장이 선다.
- G0-b(분해표)에서 `미측정` 인 축은 「학습 부족」 표로 떨어지고 단위 착수 전에 채운다.
- 사례: 축 여덟 개를 관측으로 지어내 상수는 2% 안에 맞고 기전은 하나도 안 맞았다 (함정: [상수가 맞아 규칙도 맞다고 봄](함정%20-%20측정%20추론.md#상수가%20맞아%20규칙도%20맞다고%20봄)).

## 장르 노트

### 요약

- 장르 노트에는 구조와 질문만 둔다.
- 시스템 축 점검표를 채우며 원본의 장르와 표현 방식을 판정하고 [장르 지도](장르%20지도.md) 에서 해당 노트를 연다.
- 노트가 없으면 공통 노트만으로 간다.

### 설계

- 장르 노트에는 기본으로 더 볼 질문 · Unity 구조 차이 · 함정만 둔다.
- 한 게임의 실측 수치는 원장에 둔다.
- 뒷받침 게임이 하나뿐인 내용은 「가설」로 표시한다.
- 이관이 끝나면 그 게임에서 새로 필요했던 질문과 구조를 장르 노트로 올린다 ([장르 지도](장르%20지도.md) 「노트 규격」).

## URL 제공형

### 요약

- 블랙박스가 아니라 이름이 지워진 코드부터 의심한다.
- 골격의 자리와 이름은 그대로다 (PD 「원본 형태 판정」).
- 「원본 위치」에 적는 것만 번들 소스 수신 여부로 갈린다.

### 규칙

#강제 [원칙 R23](원칙.md#R23) 「못 받았다」는 번들 소스 수신을 시도한 뒤에만 적는다.
#강제 [원칙 R4](원칙.md#R4) 관측으로 지은 규칙은 값이 맞아도 틀린 것으로 본다 (함정: [URL 원본 번들 소스를 연 김에 생기는 코드 복제](함정%20-%20사람%20권리%20안전.md#URL%20원본%20번들%20소스를%20연%20김에%20생기는%20코드%20복제) · [상수가 맞아 규칙도 맞다고 봄](함정%20-%20측정%20추론.md#상수가%20맞아%20규칙도%20맞다고%20봄)).
#강제 [원칙 R3](원칙.md#R3) 관측 개수는 하한이다.

### 설계

| 소스 | 「원본 위치」 컬럼 | `99_원본지도.md` |
|---|---|---|
| 받았다 ([PD - 원본 형태](PD%20-%20원본%20형태.md) 「번들 소스」) | `[소스] <청크 파일>:<앵커>`. 줄번호 대신 앵커(근처 문자열·관측값) | 소스 지도 |
| 못 받았다 (막힌 근거를 `00_원본정보` 에) | `[실측]` + 재현 방법 (URL · 진입 경로 · 입력 시퀀스 · 캡처 파일명) | 실측 세션 지도 |

````markdown
## 소스 지도 (번들 소스를 받았을 때)
| 청크 파일 (해시 포함) | 들어 있는 것 | 앵커 (검색어) | 복원한 이름 대응 | 회차 |

## 실측 세션 지도
| 회차 | 확인한 것 (화면·거동) | 입력 시퀀스 | 캡처 | 남은 미측정 |

## 화면 요소 소속표 (게임 / 플랫폼)
| 요소 | 소속 | 근거 |
````

- 「모든 수치에 원본 위치 인용」은 `[소스]` 앵커 또는 `[실측]` + 재현 방법으로 충족한다.
- 전수 항목(버튼·행 수·연출)은 소스가 있으면 소스 정의로 세는 것이 기본이다 (함정: [조건부로만 나오는 요소를 없다고 적은 분석](함정%20-%20판정%20보고.md#조건부로만%20나오는%20요소를%20없다고%20적은%20분석)).
- 소스가 없으면 관측 범위에 한하고, 못 본 범위가 있다는 사실을 미측정으로 적는다. 합격 기준도 이로 갈린다 (PD 확정표 12).

## 학습 단계 완료 판정

### 요약

- 학습 단계가 끝났는지 이 목록으로 본다.
- 아래가 기본 체크리스트다.

### 설계

- [ ] 골격 전부가 있고 `HtmlToUnityLogic/*.md` 를 `미작성` 으로 grep 해 0건이다 (README 상태표보다 grep 이 확실하다)
- [ ] 모든 수치에 원본 위치 인용이 있고, 확인 못 한 것은 「미확인」이다
- [ ] `00` 에 한 판이 끝나는 조건이 `[소스]`/`[실측]` 근거로 있다 (없으면 분해표 마지막 단위를 못 세운다)
- [ ] `01` 버튼 전수가 화면 전부를 덮는다
- [ ] `03` 모든 테이블에 행 수가 있다
- [ ] `05` 전수표에 눈대중 값이 없고, 「UI 연출」 표에 창마다 한 줄·빈칸 0 이다 (없는 연출은 「없음 [근거]」)
- [ ] `06` 에 두 목록이 있고, 아트를 실측했다면 몇 단까지 떴는지 있다 ([공통절차 - 원본에서 값 캐기 「자산 단계」](공통절차%20-%20원본에서%20값%20캐기.md#자산%20단계)). 단이 미정이면 확정표에 물을 것이 남았다
- [ ] 시스템 축 점검표 빈칸 0
- [ ] URL 제공형이면 번들 소스 수신 시도 결과가 `00_원본정보.md` 에 있다 (받았으면 `99` 에 소스 지도)
- [ ] `frames/` 에 화면(창)마다 열린 프레임 덤프가 있고 `paths.md` 경로마다 사건 순서가 있다. 이미지만 있는 화면은 미측정이다
- [ ] `paths.md` 상태 전수표에 상태마다 도달 여부가 있다 ([공통절차 - 원본에서 값 캐기 「도달 설계」](공통절차%20-%20원본에서%20값%20캐기.md#도달%20설계))
