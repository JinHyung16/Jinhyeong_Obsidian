# 공통절차 - 에디터 실행

상위: [공통절차](공통절차.md)

## 사람 요청 금지

### 요약

- 사람에게 엔진 조작을 요구하지 않는다.
- 이관을 의뢰한 사람은 코딩도 엔진도 모를 수 있다.
- 비개발자 의뢰가 품질을 낮출 이유가 되지 않는다. 기준은 우리가 지킨다.

### 규칙

#강제 [원칙 R16](원칙.md#R16) 사람에게 남기는 것은 ① 원본을 건네주기 ② 마지막에 열어서 보기, 둘뿐이다.

### 설계

아래는 R16 을 지키는 기본 경로다.

| 사람에게 떠넘기던 요청 | 도구가 하는 기본 경로 |
|---|---|
| 「메뉴에서 이걸 눌러 주세요」 | 러너로 직접 실행 |
| 「인스펙터에서 지정해 주세요」 | 에디터 API 로 코드가 지정 |
| 「프리팹을 만들어 주세요」 | 빌더가 초안을 굽고, 이후엔 에디터 API 로 프리팹을 고친다 (확정표 10-b) |
| 「패키지를 설치해 주세요」 | 매니페스트를 직접 고친다 |

## 에디터 다리

### 요약

- 에디터가 열려 있으면 끄지 말고 다리로 시킨다.
- 에디터 작업의 기본 경로는 다리다.
- 이 저장소는 `Tools/unity-batch.sh` 가 열린 에디터에 시키고, 재생 검사도 `PLAYMODE=1` 로 다리를 탄다.
- 배치모드가 필요한 이유는 같은 프로젝트를 두 인스턴스가 못 연다는 것뿐이다. 에디터가 꺼져 있거나 `BRIDGE=0` 이면 배치가 낫다.

### 규칙

#강제 [원칙 R20](원칙.md#R20) 다리로 돌 때 검사기는 에디터를 끄지 않고 재생 종료까지만 한다.

### 설계

다리의 모양이다. 에디터 안에 지켜보는 스크립트를 상주시킨다.

1. 셸이 요청 파일을 쓴다(`{"id":…, "method":…}`).
2. 에디터가 틱마다 보다가 에셋을 새로고침한다(포커스 없이는 자동 새로고침이 안 온다).
3. 컴파일·임포트가 끝날 때까지 기다린다. 도메인 리로드 뒤에도 요청 파일이 남아 이어받는다.
4. 메서드를 실행하고 콘솔 로그를 잡아 응답 파일로 쓴다. 판정은 로그다.

- 요청·응답 파일의 기본 자리는 `Temp/` 밖이다(함정: [유니티 Temp 폴더에 둔 측정 파일](함정%20-%20도구%20러너.md#유니티%20Temp%20폴더에%20둔%20측정%20파일)).
- 재생 검사기는 `SessionState "JinHyung.EditorBridge.Driving"` 이 참이면 `Exit` 대신 `ExitPlaymode` 로 끝낸다(함정: [다리 경로에서 에디터를 무조건 종료한 검사기](함정%20-%20사람%20권리%20안전.md#다리%20경로에서%20에디터를%20무조건%20종료한%20검사기)).
- 검사기는 시작할 때 `Application.runInBackground = true` 를 켠다. 안 켜면 포커스 없는 재생이 throttle 되어 「다리는 느리다」로 오판한다(함정: [포커스 없는 에디터 재생의 throttle](함정%20-%20도구%20러너.md#포커스%20없는%20에디터%20재생의%20throttle)).
- 다리 스크립트의 첫 활성화만 재시작이 필요하다.

## 배치모드

### 요약

- 에디터 툴은 배치모드로 직접 실행한다. 사람에게 메뉴를 누르라고 하지 않는다.
- 배치는 에디터가 꺼져 있거나 `BRIDGE=0` · `BRIDGE_PLAY=0` 일 때의 예외 경로다([에디터 종료](공통절차%20-%20에디터%20실행.md#에디터%20종료)).
- 근거 절은 [사람 요청 금지](공통절차%20-%20에디터%20실행.md#사람%20요청%20금지) 다. [SKILL](SKILL.md) 「사람 조작 없이」도 같이 본다.

### 규칙

#강제 [원칙 R16](원칙.md#R16) 메뉴 실행은 사람이 아니라 도구가 한다.
#강제 [원칙 R20](원칙.md#R20) 살아 있는 에디터를 끌 때는 미저장 소실을 알리고 승인 뒤 저장 후 정상 종료한다.

### 설계

```bash
# 인자 없는 static 메서드를 헤드리스로 실행하고 로그를 파일로 받는다
<Unity실행파일> -batchmode -quit -nographics -silent-crashes \
  -projectPath <프로젝트> -executeMethod <Namespace.Class.Method> -logFile <로그>
```

기본 순서는 닫고 · 돌리고 · 여는 것이다.

1. 에디터 프로세스가 살아 있는지 본다.
2. 살아 있으면 저장 안 된 작업이 날아갈 수 있다고 알리고 승인을 받는다.
2-b. 재부팅 문구를 남긴다([재부팅 문구](공통절차%20-%20에디터%20실행.md#재부팅%20문구)).
3. 정상 종료를 요청하고 프로세스가 실제로 사라질 때까지 기다린다(저장 확인 대화상자가 막을 수 있다).
4. 잔재 락파일이 남았으면 지운다.
5. 배치모드로 실행하고 로그를 파일로 받는다.
6. 다시 연다. 열기 전에도 같은 문구를 남긴다.

- 판정은 종료 코드가 아니라 로그로 한다. 이유: 컴파일 에러에도 0이 나올 수 있다. 로그에서 `error CS` · `Exception` · 성공 문구를 같이 본다.
- 배치는 임포트를 동반해 느리다. 백그라운드로 돌리고 로그를 읽는 것이 기본이다.
- 배치 로그는 다음 실행이 지운다. 임시 폴더의 로그는 다음 배치 시작 때 지워진다. 기본은 각 단계 출력을 실행 직후 갈무리하는 것이고, 여러 단계면 로그를 임시 폴더 밖에 쓴다.
- 「성공 표시」와 「실패 표시」의 모양이 다르면 요약이 잘린다. 성공 표식으로 결과를 잘라 내면 실패가 안 보인다. 줄 수를 자르면 마지막 요약(N/N)이 먼저 잘린다. 기본은 요약 줄을 따로 한 번 더 찍는 것이다.

비동기 에디터 API 는 `-quit` 전에 안 끝난다. 요청만 거는 API(패키지 임포트 등)는 배치 종료와 함께 작업이 날아가도 성공 로그는 찍힌다.

- 기본 확인은 「요청했다」가 아니라 생겼는지를 같은 메서드 안에서 파일로 보는 것이다.
- 동기 API 나 직접 처리가 있으면 그쪽이 낫다. 없으면 한 배치에서 요청하고 다음 배치에서 결과를 쓴다.
- 패키지 파일은 대개 gzip tar(`<guid>/pathname` · `<guid>/asset`)다. 직접 풀어 쓰는 것이 가장 결정적이다.

## 재생 검사

### 요약

- 입력 판정은 재생 안에서만 잰다. 편집 모드 레이캐스트는 원리적으로 빈다.
- 편집 모드에서는 캔버스가 안 그려져 그리기 깊이가 `-1` 로 남고 레이캐스터가 전부 건너뛴다. `-nographics` 를 빼도 같다.
- 아래가 R7 을 증명하는 기본 방법이다.

### 설계

- 대조군(사람이 눌러서 되는 모드 버튼 등)을 같이 쏜다. 그것도 안 맞으면 검사 환경 문제다.
- 재생 모드에서 실제 포인터 이벤트를 흘린다. 기본은 다리(`PLAYMODE=1`)다.
- 진단을 같이 찍는다: `raycastTarget` · 깊이 · `cull` · 부모 캔버스.
- 기본은 매니저를 직접 부르지 않고 레이캐스트 결과에 이벤트를 흘리는 것이다. 이유: 그래야 배선 끊김과 가로막힘이 걸린다.

배치로 재생에 들어갈 때(`BRIDGE_PLAY=0`):

1. `-quit` 을 뺀다(진입 메서드 종료와 함께 꺼져 재생이 시작되지 않는다).
2. `-nographics` 도 뺀다.
3. 진입 메서드는 씬을 열고 재생을 요청만 한다(안에서 기다리면 재생이 시작되지 않는다).
4. 재생 시작 훅에서 검사기를 심는다. 도메인 리로드를 넘는 저장소에 표시를 남긴다.
5. 검사기가 스스로 끝내고, 바깥에도 시간 제한을 건다.

자동 검사에서 프레임 수로 기다리지 않는다. 화면 없는 재생은 초당 수천 프레임이 돌아 「60프레임 대기」가 0.01초 수준이다. 기본은 틱 · 타이머 · 연출을 시간으로 기다리고, 실제 경과 프레임 수를 같이 찍는 것이다.

## 에디터 종료

### 요약

- 에디터를 끄는 것은 예외다.
- 기본은 끄지 않는 것이다. 빌드처럼 배치가 필수일 때만 끈다.

### 규칙

#강제 [원칙 R20](원칙.md#R20) 사람이 쓰는 에디터는 알리고 저장 후 정상 종료로만 끄고, 검사기는 재생 종료까지만 한다.

### 설계

| 언제 | 경로 |
|---|---|
| 에디터가 열려 있다 (보통) | 다리 |
| 재생 검사 | 다리 (`PLAYMODE=1`), 검사기는 `ExitPlaymode` 까지만 |
| 에디터가 꺼져 있다 · `BRIDGE=0` · `BRIDGE_PLAY=0` | 배치 |

- 끌 때의 기본 절차는 러너가 ① 저장 후 정상 종료를 시키고 ② 응답이 없을 때만 강제 종료하고 ③ 열기 전에 복구 백업을 치워 「_recovery backup scene?」에 No 를 대신 누르는 것이다. 이유: 강제 종료(`taskkill`)하면 복구 대화상자를 사람이 눌러야 한다.
- 주의: 다리로 돌 때 검사기가 에디터 프로세스를 끄면 이 전부가 무너진다(함정: [다리 경로에서 에디터를 무조건 종료한 검사기](함정%20-%20사람%20권리%20안전.md#다리%20경로에서%20에디터를%20무조건%20종료한%20검사기)).

## 재부팅 문구

### 요약

- 예외로 재부팅할 때는 항상 같은 문구를 남긴다.
- 문구: `유니티를 재부팅 중입니다. 기다려주세요.` (`Tools/unity-batch.sh` 가 찍는 문구)
- 이유: 사람은 화면이 사라진 것만 보고 「멈췄나」로 읽는다.
- 기본은 러너가 닫는 경로와 여는 경로에서 대신 찍는 것이다.

### 규칙

#강제 [원칙 R19](원칙.md#R19) 에디터 프로세스는 이 프로젝트 PID 로만, 말하고 끈다.

### 설계

| 언제 | 무엇 |
|---|---|
| 닫기 전 | 문구 + 저장 안 된 작업이 사라진다는 경고 |
| 다시 열 때 | 문구 |
| 여러 단계를 이어 돌릴 때 | 마지막 단계에서만 연다 (중간에 열면 락에 막힌다) |

- 이름으로 죽이면 같은 엔진으로 연 다른 프로젝트가 함께 죽는다(함정: [프로세스 이름으로 죽여 날아간 다른 프로젝트 작업](함정%20-%20사람%20권리%20안전.md#프로세스%20이름으로%20죽여%20날아간%20다른%20프로젝트%20작업)).
