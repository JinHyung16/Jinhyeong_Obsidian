# 분석로직 - 원장 기입 규칙

상위: [분석로직](분석로직.md)

## 작업 분해표

### 요약

- 학습이 끝나면 만든다. 이관은 이 순서대로만 돈다.
- 학습 산출물에서 기계적으로 뽑는 것이 기본이다. `02` 한 장 = 한 시스템, `01` 의 화면, `03` 의 테이블 묶음, `05` 의 연출 덩어리, `06` 의 리소스군이다.
- 문서에 없는 단위를 만들어야 하면 분석이 덜 된 것이라, 학습으로 돌아가는 편이 낫다.

### 설계

| # | 단위 | 무엇을 만드나 | 근거 문서 | 선행 | 완료 조건 (검사·항수) | 상태 |
|---|---|---|---|---|---|---|

- 기본은 완료 조건을 채운 뒤에 그 단위를 시작하는 것이다. 이유: 완료 조건이 비면 끝났는지 판정할 수 없다 (R7 · R23 을 지키는 기본 방법).
- 상태는 기본으로 `대기` · `진행` · `완료 N/N` 셋을 쓴다.
- 순서 규칙(의존 → 최소 경로 → 불확실 → 크기)은 [PD - 작업 분해표](PD%20-%20작업%20분해표.md) 「순서 규칙」이 정본이다.
- 한 단위는 패스 ①②③ + 검사까지 완주하고 다음으로 가는 것이 기본이다 (`PD.md`).
- 끝난 단위를 다시 열었으면 그 단위의 완료 조건을 고쳐 이 표에 반영한다.

## 이관율 대조표

### 요약

- 「원본에 있는 것 중 몇 개가 우리 화면에 나오나」를 센다.
- 분모는 확정표 범위다. 의도된 차이 밖의 차이는 결함이다.

### 규칙

#강제 [원칙 R8](원칙.md#R8) 100% 는 이 표로만 선언하고, 표에 없는 차이는 전부 미흡이다.
#강제 [원칙 R13](원칙.md#R13) 분모의 이관 범위와 의도된 차이는 확정표(사람 결정)가 정한다.
#강제 [원칙 R7](원칙.md#R7) 증명 칸이 비면 분자에 넣지 않는다.

### 설계

| 규칙 | 내용 |
|---|---|
| 분모 | 확정표 이관 범위(모드·월드·「한 판」)의 원본 요소 전수. 갈래: 화면 · 시스템 축 · 무기/행동 · 진행 체인 · 월드 개체 · HUD · 연출 · UI 연출(펄스·호버·디머·트윈) · 지형 · 아트(재제작이면 「퀄리티 동일」 판정 행). 갈래 하나가 빠지면 0건인 채 100% 가 나온다 |
| 원본 개수 | 소스 정의로 센다. 소스가 없으면 관측 + 「관측 범위」 명시 |
| 의도된 차이 | 다르게 두기로 한 것 전부(재제작 아트 · 사운드 · 플랫폼 요소 · 광고 · 이관 밖 화면). 근거 칸에 확정표 행 또는 판정 절 |
| 증명 | 「화면에 나옴/동작함」을 보인 근거(재생 검사 이름 · 사건 프레임 덤프의 줄 · A/B 개체 수). 빈 칸의 처리는 R7 |
| 판정 | 표 밖 차이의 처리는 R8. 표가 없으면 100% 를 말할 수 없다 (PD 「QA 체크 순서」 9) |

## 만든 것과 옮긴 것

### 요약

- 「우리에게 있다」로 세지 않는다. 그 사이에 네 겹의 틈이 있다.
- 「만들었나」로 세면 안 쓰이는 것도 100% 가 된다.
- 아래 넷이 한 회차에 모든 검사를 통과했다 (함정: [만든 것을 옮긴 것으로 센 이관율 분자](함정%20-%20판정%20보고.md#만든%20것을%20옮긴%20것으로%20센%20이관율%20분자)).

### 규칙

#강제 [원칙 R7](원칙.md#R7) 「프리팹에 있다」·「표에 행이 있다」·「파일을 구웠다」는 증명이 아니다.

### 설계

| 만든 것 | 빠진 것 | 화면에서는 |
|---|---|---|
| 버튼 컴포넌트를 붙였다 | 포인터를 받게 안 켰다 | 눌러도 반응 없음 |
| 상태별 시트를 구웠다 | 뷰가 한 장만 읽는다 | 상태가 바뀌어도 그림이 같다 |
| 문구를 표에 넣었다 | 읽는 곳이 없다 | 그 UI 가 없다 |
| 형태·색 지표가 만점 | 지표가 그림을 안 잰다 | 다른 그림이다 |

## 개체마다 행동이 분모

### 요약

- 분모를 명사로만 채우지 않는다.
- 기본은 개체가 있나가 아니라 원본처럼 하나를 갈래마다 세는 것이다.
- 개체를 옮길 때 소스 클래스를 통째로 읽고 둘을 수로 적는다.
- 갈래가 다섯이면 분모가 다섯이다.

### 설계

| 무엇 | 어떻게 |
|---|---|
| 매 프레임 갈래 | `update()` 분기 이름 전수 (`updateFollow`·`updateAttack`·…). 우리 코드 갈래 수와 맞춘다 |
| 타이머·상수 필드 | `…IntervalMs`·`…DurationMs`·`…Offset`·`…Multiplier`·`…Radius` 전수. 표에 없는 상수는 이관 안 된 규칙이다 |

- 사례: 증명까지 있던 동료 개체가 싸우지 않았다. 원본 갈래 다섯 중 둘만 옮겼다.

## 골든 분모

### 요약

- 골든의 분모는 결과물이다. 「식이 맞다」는 「그림이 맞다」가 아니다.
- 절차가 있는 것(여러 패스 · 캐시 제자리 수정 · 좌표 변환)은 중간값이 맞아도 결과가 갈린다.
- 사례: 지형 골든 19/19 통과인데 화면이 달랐다. `f(x,y)` 값만 쟀다.

### 규칙

#강제 [원칙 R7](원칙.md#R7) 「식이 맞다」로 통과 판정하지 않고 결과물로 대조한다.

### 설계

| 골든 밖에 있던 것 | 값으로 안 잡히는 이유 |
|---|---|
| 좌표계 (엔진 y 위 ↔ 원본 y 아래) | 넣는 좌표가 뒤집혔다 |
| 패스 전파 (캐시를 제자리에서 고친다) | 이웃을 읽는 시점이 다르다 |
| 인덱스 범위 (원본은 안 자른다) | 가장자리가 다르다 |

- 기본은 결과물을 골든으로 만드는 것이다. 지형이면 타일 격자를 창 한 판 전 칸 대조하고, 타일 종류가 거의 다 나오는 창을 고른다.
- 검사는 통과했는데 그림이 다르면 검사의 분모를 의심한다.

## 세는 검사

### 요약

- 세는 검사는 개수를 못 박는다.
- 「0개 실패」는 분모가 0 이어도 통과한다.

### 규칙

#강제 [원칙 R7](원칙.md#R7) 세는 검사는 최소 개수를 박아 분모 0 으로 통과하지 않게 한다.

### 설계

- 기본 형태는 `Check(n >= 최소)` 다.
- 지금 화면이 아니라 만들어 둔 것 전부(프리팹·표)를 세는 것이 기본이다. 이유: 모달과 풀은 게으르게 만들어져 화면에 없다.
- 화면을 봐야 하면 창들이 다 붙어 가라앉기를 기다린다.

## 리스트업

### 요약

- 항목은 화면과 시스템 단위로 자른다.
- 완료 정의는 분모가 있는 문장으로 적는다.

### 규칙

#강제 [원칙 R8](원칙.md#R8) 100% 는 PD QA 통과 뒤에만 붙인다.
#강제 [원칙 R6](원칙.md#R6) 미측정은 0% 로 계산한다.

### 설계

| 규칙 | 내용 |
|---|---|
| 항목 단위 | 화면·시스템 단위로 자르는 것이 기본이다. 덩어리는 달성률이 안 움직인다 |
| 완료 정의 | 분모가 있는 문장 (예: 「9요소 중 6개 이식」·「정답지 230행 중 통과 수」·「팝업 9곳」) |
| 달성률 | 완료 정의에서 역산한다. 분모를 못 적으면 전수 대조표(UIUX 「화면 하나를 전수 대조표로 연다」)부터 만든다 |
| 회차 | 손댄 횟수. 3회차인데 60% 면 접근을 재검토한다 (PD 「회차 카운터를 원장에 남긴다」) |
| 100% | R8 |
| 미측정 | R6 |

## 학습 내용

### 요약

- 한 줄에 한 사실이 기본이다.
- 근거 열이 빈 줄은 기본으로 적지 않는다. 이유: 근거 없는 줄은 다음 회차에 사실로 인용된다.

### 규칙

#강제 [원칙 R23](원칙.md#R23) 이전 줄을 지우지 않고 새 줄에 「전 회차 정정」이라 적는다.

## 오염된 내용

### 요약

- 갈래를 반드시 적는다.
- 기본 갈래는 아래 다섯이다.

### 규칙

#강제 [원칙 R23](원칙.md#R23) 오염은 고치기 전에 먼저 적는다. 조용히 고치면 재발한다.

### 설계

| 갈래 | 무엇 |
|---|---|
| 캡처를 사양으로 삼음 | 픽셀로 읽은 것을 사양으로 적었다 |
| 문서·라인 번호를 믿음 | 인용 라인이 현재 빌드와 어긋났다 |
| 애니메이션 프레임을 정색으로 오인 | 점멸·페이드 중 한 프레임을 정색으로 봤다 |
| 이름이 비슷해 다른 물건을 가져옴 | 그럴듯한 이름의 다른 용도 것을 썼다 |
| 추측을 결론으로 적음 | 「대략」이 다음 회차에 원본 수치로 인용됐다 |

## 패스 수행 내용

### 요약

- 패스 ①②③ 의 수행 내용이다.
- 한 항목을 끝낼 때마다 적는 것이 기본이다.

### 설계

- 판정 열에 분모 있는 숫자를 적는다. 예를 들어 「팝업 9/9」·「정답지 120/230」·「A/B 개체 수 통과」다.
- 미착수는 회차를 `. ` 로 두고 남긴다.
- 패스 ③은 배선 대상 6종(UI · 게임 플로우 · 연출 파라미터 · 게임오브젝트 · 데이터 종속 아트 · 지연 로드 아트) 중 무엇인지 적는다 (PD 「패스 ③이 하는 일」).

## 회고록

### 요약

- 세 칸이 다 차야 끝난다.
- 세 번째 칸은 기본으로 도구 · 체크리스트 · 게이트 중 하나로 끝난다.
- 이유: 「주의하겠다」는 대책이 아니다.

### 설계

```
무엇을 놓쳤나 | 왜 안 보였나 | 무엇으로 막나
```

- 도구의 예는 양방향 에셋 감사기다.
- 체크리스트의 예는 담당자 md 완료 체크리스트에 한 줄 넣는 것이다.
- 게이트의 예는 플로우 diff 를 프리팹 대조보다 먼저 두는 것이다.

## 재측정 대기

### 요약

- 미측정을 통과로 넘기지 않는 장치다.
- PD 는 QA(PD 「QA 체크 순서」 8번)에서 이 표를 미흡 목록에 자동 편입한다.
- 대기 회차 규칙은 [분석로직 - 원장 스키마 「갱신 시점」](분석로직%20-%20원장%20스키마.md#갱신%20시점).

### 규칙

#강제 [원칙 R6](원칙.md#R6) 판정 칸에는 숫자 또는 `미측정(사유)` 만 적는다. 빈칸·「됨」·「확인함」은 판정이 아니다.

### 설계

기본 절차는 아래다.

1. 판정 칸에 숫자를 못 넣으면 `미측정(사유)` 로 적는다.
2. 사유를 3갈래 중 하나로 적는다.
3. 달성률에 0% 로 계산한다.
4. 즉시 재측정 대기 표에 한 줄 올리고, 다음 회차에 신규 작업보다 먼저 처리한다. 실측값이 오면 표에서 지우고 패스 표 판정을 숫자로 덮는다.

| 갈래 | 무엇 | 해소하려면 |
|---|---|---|
| ① 도구 없음 | 브라우저·Unity 제어·이미지 비교 등이 없다 | 사람에게 도구 또는 대체 자료(캡처·로그·DOM 덤프) 요청 |
| ② 상태를 못 맞춤 | 진행도·재화·선택 상태가 다르다 | 치트/디버그 명령을 이식해 한 줄로 같은 상태를 만든다 ([공통절차 - 측정 준비 「A/B 측정」](공통절차%20-%20측정%20준비.md#A/B%20측정)) |
| ③ 하네스 없음 | 채점기·프리뷰·감사기가 없다 | 하네스 제작을 리스트업에 올린다 (PD 「재는 도구를 먼저 만든다」) |

## PD QA 미흡 목록

### 요약

- 기본은 무엇이 · 어디가 · 기대 · 실측 네 칸으로 적는 것이다.
- 「어색하다」는 QA 결과가 아니다.
- 이 목록이 다음 회차 리스트업이 된다. 해당 항목 달성률을 내리고 회차를 +1 한다.
