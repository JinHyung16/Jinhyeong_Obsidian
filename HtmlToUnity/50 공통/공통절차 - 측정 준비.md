# 공통절차 - 측정 준비

상위: [공통절차](공통절차.md)

## 세이브 백업

### 요약

- 상태를 조작하는 측정은 실제 세이브를 덮는다.
- 기본 순서는 백업 → 측정 → 복원이다.

### 규칙

#강제 [원칙 R21](원칙.md#R21) 상태를 조작하는 측정은 세이브를 백업하고 끝나면 복원한다.

### 설계

- Play Mode 중 자동 저장이 돌아 상태 조작이 실제 세이브를 덮는다.

## 폰트 로드 대기

### 요약

- 웹폰트 원본의 첫 페인트는 폴백 폰트다.
- 글자가 크기를 정하는 요소는 로드 전후 값이 다르다. `width:auto` 컨테이너 · 버튼 · 라벨이 그렇다.
- 기본은 로드 뒤에 두 번 재는 것이다.

### 설계

```js
await document.fonts.ready;          // 이 줄 없이 잰 값은 사양이 아니다
el.getBoundingClientRect();
```

- 두 번 재서 다르면 나중 값이 사양이다. 먼저 잰 값은 오염으로 원장에 적는다([분석로직 - 원장 기입 규칙 「오염된 내용」](분석로직%20-%20원장%20기입%20규칙.md#오염된%20내용), 함정: [웹폰트 로드 전에 잰 DOM 크기](함정%20-%20원본%20관측.md#웹폰트%20로드%20전에%20잰%20DOM%20크기)).
- 웹폰트가 없는 원본이면 이 대기 없이 재도 된다. 글자가 크기를 정하지 않는 요소도 그렇다.

## 기능 부재 증명

### 요약

- 기본은 개수가 아니라 매칭된 줄을 출력해 확인하는 것이다.
- 경계 없는 패턴은 이름이 비슷한 다른 식별자에 걸린다.

### 설계

```bash
grep -c "play" 원본.js                          # 하지 않는다: display · scoreDisplay 가 걸린다
grep -nE "new Audio|<audio|\.play\(\)" 원본.js   # 한다: 경계가 있는 패턴 + 줄을 눈으로 본다
```

- 함정: [부분 일치 grep 으로 내린 기능 부재 판정](함정%20-%20원본%20관측.md#부분%20일치%20grep%20으로%20내린%20기능%20부재%20판정).

## A/B 측정

### 요약

- 기본은 스크린샷이 아니라 개체 수로 대조하는 것이다.
- 캔버스는 픽셀로 셀 수 없다. 상태가 다르면 결함을 가를 수 없다.
- 순서는 ① 상태 맞추기 → ② 개체 세기 → ③ 판정 표다.

### 설계

① 상태를 맞춘다. 원본의 치트/디버그 명령을 이식해 같은 한 줄로 양쪽을 올린다. 그 상태를 기준 캡처의 상태로 못박는다. 아래 중 하나라도 다르면 그 구간 점수는 의미가 없다.

| 맞출 것 | 안 맞추면 |
|---|---|
| 진행도 (스킬·유닛·등급·장비·동료) | 계산이 수십 % 어긋난다 |
| 보유 재화 | 자릿수가 달라 상단바 구간이 깎인다 |
| 스크롤 위치 · 선택 대상 · 활성 탭 | 다른 화면을 비교한다 |
| 배경이 영상인가 | 그 구간은 40~60%가 정상이다 |

점수가 낮으면 결함을 찾기 전에 이 표부터 채우는 것이 빠르다.

② 픽셀이 아니라 개체를 센다. 원본은 JS 전역 상태에서 센다. 유니티는 리플렉션으로 private 리스트를 같은 항목·같은 이름으로 센다. 종류 분포까지 센다. 총량이 비슷해도 `Elite:5` 가 살아 있으면 무언가 안 죽는다.

③ 판정 표를 만든다. 실시간 시뮬은 2~3회 샘플링해 같은 대인지 본다.

| 항목 | 원본 | 고치기 전 | 고친 후 |
|---|---|---|---|
| 살아있는 적 (예시) | 1 / 6 / 2 | 11 / 28 | 2~4 |

## 기저 상태

### 요약

- 기본은 재려는 변화 외의 변화가 0인 판을 먼저 설계하는 것이다.
- 다른 변화가 섞이면 델타의 출처를 가를 수 없다.

### 설계

| 원본에 있는 것 | 기저 상태 설계 |
|---|---|
| 자동 진행 (자동 매치·전투·낙하) | 자동 진행이 원천적으로 불가능한 배치를 만든다 (예: 값이 `(열 + 2×행) % 3` 인 판) |
| 무작위 생성 | 생성이 안 일어나는 상태로 두거나 생성 자리를 대조에서 제외한다 |
| 타이머 | 타이머 없는 모드나 정지 상태에서 잰다 |

- 깔고 방치해 변화가 0인지로 기저 상태를 먼저 증명한다. 그 위에 원본이 안 쓰는 값을 심어 델타의 출처를 확정한다.
- 제외할 자리는 벡터에 `RANDOM` 으로 미리 적어 둔다. 이유: 안 적으면 다음 회차가 「값이 틀렸다」로 읽는다.

## 원본 결정성

### 요약

- 정답지 · A/B · 창 대조는 「같은 입력 → 같은 결과」를 전제한다.
- 재기 전에 이 원본이 같은 답을 내는지부터 잰다.
- 웹 원본은 프레임 간격이 고정이 아니어서 갈린다.

### 규칙

#강제 [원칙 R9](원칙.md#R9) 비결정 입력은 원본에서도 갈린다는 실측으로만 빼고, 뺀 건수를 리포트에 따로 찍는다.

### 설계

1. 대표 입력을 n≥3 회 돌린다(2회로는 못 가른다).
2. 갈리면 첫 갈림 지점을 본다. 그곳이 비결정의 씨앗이다.
3. 갈리는 입력은 「비결정」으로 분류해 정답지에서 뺀다. 행은 지우지 않고 남긴다.
4. 제외 건수를 리포트에 찍는다.

- 연쇄가 길수록 증폭되니 짧게 결판나는 입력을 고르는 것이 기본이다.
- 빈도를 같이 잰다. 원본 10회 중 9회 성공에 우리 0회면 비결정이 아니라 우리 결함이다.

## 프레임 정지

### 요약

- 교전 중 프레임을 얼려서 본다. 게임 코드는 고치지 않는다.
- 도구 왕복(10~30초)이 전투보다 길면 기본은 에디터 쪽 `EditorApplication.update` 훅으로 조건에서 얼리는 것이다.
- 왕복이 전투보다 짧으면 얼릴 필요가 없다.

### 설계

```csharp
EditorApplication.CallbackFunction hook = null;
hook = () => {
  var ctx = GameManager.Instance?.Combat?.Context;
  if (ctx == null || GameManager.Instance.Combat.IsRunning == false) return;
  ctx.Player.Hp = ctx.Player.MaxHp;        // 조사 중 격침 방지
  if (/* 보고 싶은 조건 */) {
    EditorApplication.isPaused = true;
    EditorApplication.update -= hook;      // 한 번만 잡고 스스로 제거
  }
};
EditorApplication.update += hook;
```

- `Time.timeScale` 낮추기는 안 통한다. 출격 전이가 안 걸린다.
- 일시정지는 원격 도구의 틱으로 풀린다. 결과는 파일로 덤프한다.
- 원본에 「선택창이 뜨면 시뮬 정지」가 있으면 그 모달 상태가 곧 정지 프레임이라 훅보다 낫다. 캡처와 측정을 여기서 한다.

## 하네스 초기화

### 요약

- 하네스가 초기화를 대신할 때는 게임과 같은 호출로 한다.
- 기본은 게임 코드가 부르는 그 한 줄을 그대로 부르는 것이다. 화면 전환 함수 등이다.

### 설계

- 창이나 컴포넌트를 직접 만지면 진입 경로가 끊겨도 통과한다.
- 그 한 줄을 모르면 초기화 코드의 마지막 줄을 본다.

## 영향 없음 등재

### 요약

- 「영향이 없다」도 실측으로 확증하고 등재한다.
- 「이 순서로 넣으면 변화 0」을 벡터로 등재한다.

### 설계

- 안 보이는 상태도 그대로 옮기는 것이 기본이다.
- 이유: 지우면 원본과 상태 기계가 갈려 나중에 어긋난 곳을 못 찾는다.
