# 공통절차 - 캡처와 덤프

상위: [공통절차](공통절차.md)

## 캡처 사용 범위

### 요약

- 캡처는 쌓지 않는다. 남기는 것은 덤프다.
- 기본은 캡처를 세션 안에서 눈으로 한 번 보는 데까지만 쓰고 저장소에 쌓지 않는 것이다.
- 캡처는 눈으로 맞춘 값을 근거 없이 사양으로 만든다.
- 덤프는 값마다 개체와 열이 남아 다음 회차가 다시 재서 숫자로 대조한다.

### 규칙

#강제 [원칙 R3](원칙.md#R3) 캡처에서 읽은 값은 사양이 아니다. 근거는 원본 코드와 원본 실측(덤프)이다.

### 설계

- 판정 순서는 ①원본 코드 → ②규약 문서 → ③덤프다. 캡처는 그 뒤 마지막 눈 확인 한 장이고 스크래치패드에 둔다.
- 그림으로 원리적으로 안 읽히는 것은 덤프와 소스로 본다. 겹침 · 늘리는 방식(9슬라이스 vs 확대) · 「0인가 못 읽었나」가 그렇다.
- 함정: [스크린샷을 분석 입력으로 삼는 함정](함정%20-%20원본%20관측%20-%20상태%20직독.md#스크린샷을%20분석%20입력으로%20삼는%20함정) · [덤프에 원리적으로 없는 값을 공식으로 메운 함정](함정%20-%20원본%20관측.md#덤프에%20원리적으로%20없는%20값을%20공식으로%20메운%20함정) · [스크린샷으로 정한 화면 층](함정%20-%20UI%20흐름.md#스크린샷으로%20정한%20화면%20층).

## 캡처 기록 규격

### 요약

- 그래도 캡처를 남겨야 한다면 상태를 같이 적는다.
- 상태가 없는 그림은 A/B 에 못 쓴다.

### 설계

| 컬럼 | 무엇 / 비었을 때 |
|---|---|
| 파일명 | 공백·복사본 접미를 피한다 (「이름 1.png」). 주소가 깨진다 |
| 화면 | 원본의 어느 화면인가 |
| 상태 | 진행도 · 보유 재화 · 선택 대상 · 활성 탭. 비면 A/B 불가. 「상태 미기록」으로 적고 재촬영 대상에 남긴다 ([A/B 측정](공통절차%20-%20측정%20준비.md#A/B%20측정)) |
| 애니메이션 | 끝 상태를 강제했나. 비면 한 프레임을 정색으로 오인한다 (오염 3갈래) |
| 근거 | 그리는 원본 코드 위치. 비면 캡처가 유일 근거 = 오염 |
| 회차 | 어느 빌드의 캡처인가 |

- 애니메이션 화면은 끝 상태를 강제하고 찍는다. t=0 이면 「기능이 없다」로 오판한다.
- 커밋 여부는 프로젝트가 정한다. 커밋하면 `_대장.md` 가 회차를 갖는다.

## 화면 캡처 타이밍

### 요약

- 화면 캡처는 비동기다.
- `ScreenCapture.CaptureScreenshot` 은 프레임 끝에 기록되어 같은 호출 안에서는 파일이 없다.

### 설계

- 그 사이 Play Mode 가 리셋될 수 있다. 기본은 모달로 시뮬을 얼린 뒤 찍는 것이다([프레임 정지](공통절차%20-%20측정%20준비.md#프레임%20정지)).

## 장면 그래프 덤프

### 요약

- 원본 실측은 장면 그래프 덤프로 한다. 스크린샷을 남기지 않는다.
- 캡처의 기본 용도는 원본을 여는 길이 되는지 확인하는 데까지다([캡처 사용 범위](공통절차%20-%20캡처와%20덤프.md#캡처%20사용%20범위)).
- 이 덤프가 R3 을 증명하는 기본 방법이다.

### 규칙

#강제 [원칙 R4](원칙.md#R4) 덤프에서도 소스에서도 못 캔 값은 못 캤다고 적고 공식으로 메우지 않는다.

### 설계

- 덤프 모양: 개체마다 한 줄, 열은 `id parent depth name x y sx sy alpha visible tint frame font text cx cy w h`.
- `frame` · `sx/sy` · `w/h` 는 셋 같이 읽는다([분석로직 - 사건 프레임 덤프 「덤프 열 읽기」](분석로직%20-%20사건%20프레임%20덤프.md#덤프%20열%20읽기)).
- 덤프에 없는 생성자 인자는 소스에서 캔다. 9슬라이스 인셋 등이다(함정: [덤프에 원리적으로 없는 값을 공식으로 메운 함정](함정%20-%20원본%20관측.md#덤프에%20원리적으로%20없는%20값을%20공식으로%20메운%20함정)).

## 요소 대조

### 요약

- 요소 대조는 요소가 실제로 칠하는 자리만 센다.
- 배경 배치가 달라, 통째로 겹치면 투명한 자리로 새어든 배경이 점수를 먹는다.

### 설계

| 요소 종류 | 재는 법 |
|---|---|
| 불투명한 그림 | 원본 알파에서 심만 남긴 마스크로 센다. 가장자리 몇 px 는 깎는다 |
| 반투명한 면 | 뒷배경이 같은 색인 자리에서 앞색을 대조하거나 실효 알파를 역산한다 |
| 모서리·모양 | 반지름을 잰다 |
| 크기가 의도된 차이인 요소 | 색만 본다. 크기 차이는 확정표 등재로 갈음한다 |

- 알파 역산의 정본은 `Fx.md` 「색공간」이다. 어두운 덮개는 역산 방향이 반대다(함정: [어두운 오버레이 알파 역산 방향 착오](함정%20-%20아트%20굽기.md#어두운%20오버레이%20알파%20역산%20방향%20착오)).
- 원본 PNG 와 우리 PNG 를 먼저 대조하면 자산 문제와 렌더 문제가 갈린다.

## 지표 선정

### 요약

- 대조 항목은 원본이 가진 최소 단위에서 고른다.
- 윤곽 · 색 목록 · 개수처럼 잴 수 있는 것은 부분 지표로 이름 붙인다.

### 규칙

#강제 [원칙 R7](원칙.md#R7) 주 지표는 결과물의 최소 단위(그림이면 픽셀, 글이면 글리프, 배치면 좌표)이고, 부분 지표 하나로 통과 판정하지 않는다.

### 설계

- 지표를 만들 때 「이 값이 100% 인데도 원본과 다를 수 있는 경우는?」을 한 줄 적는 것이 기본이다. 못 적으면 판정 지표가 아니라 부분 지표로 둔다.
- 「완료」라고 말하기 전에 원본과 나란히 한 번 본다. 눈으로 다른데 100% 면 지표를 고친다.
- 사례: 실루엣 IoU 와 팔레트 거리 만점으로 완료 보고했는데 픽셀로 재니 13~34% 였다.

## 점수 검증

### 요약

- 점수를 믿기 전에 환경과 기준부터 의심한다.
- 이상해 보이는 값은 원본에서 같은 상태를 만들어 같은 값이 나오는지 확인한 뒤 판단한다.

### 규칙

#강제 [원칙 R1](원칙.md#R1) 직관과 반대인 값도 원본과 같으면 맞다.
#강제 [원칙 R3](원칙.md#R3) 캡처에서 읽어낸 것은 사양이 아니다(판정 순서는 [캡처 사용 범위](공통절차%20-%20캡처와%20덤프.md#캡처%20사용%20범위)).

### 설계

- 헤드리스 캡처는 색 프로파일로 원본 PNG 보다 밝을 수 있다. 점수가 낮으면 원본 에셋과 직접 대조하는 것이 먼저다.
- 기준 캡처가 렌더 전 상태일 수 있다. 원본 코드가 실제로 그리는 것을 만들어 빈 자리에 넣는다.
- 글자 · 숫자 · 라벨은 기본으로 DOM/JS 문자열에서 확인한다.

## 채록 위생

### 요약

- 이것 때문에 회차가 날아간다.
- 아래가 회차 유실을 막는 기본값이다.

### 규칙

#강제 [원칙 R3](원칙.md#R3) 관측 최솟값은 값이 아니라 하한 `≥ N [관측 하한]` 이다.

### 설계

| 규칙 | 이유·방법 |
|---|---|
| 얕은 덤퍼 + 관심 개체만 + 중간 저장 | 무필터 전 프레임 채록은 메모리 한계로 죽어 회차가 유실된다 |
| 앵커는 시각(ms)이 아니라 프레임 수 | 프레임 수는 안 흔들린다 |
| 극값은 보간 꼭짓점으로 | 프레임 샘플 최대값에는 샘플링 위상이 섞인다 |
| 같은 입력을 n≥3 회 | [원본 결정성](공통절차%20-%20측정%20준비.md#원본%20결정성) |
| 원본지도의 함정은 프로브 공통 조각으로 굳힌다 | 가시성 판정(부모 사슬의 visible·alpha)을 한 함수로 두고 모든 프로브가 지난다 (함정: [가시성 필터를 빠뜨린 새 프로브](함정%20-%20원본%20관측.md#가시성%20필터를%20빠뜨린%20새%20프로브)) |
| 시계열 대조 전에 둘의 0시를 맞춘다 | 원본은 심은 순간, 우리는 전투 시작부터 센다. 사건 프레임 시각만큼 민다 |
| 파일 이름에 사건 라벨을 그대로 쓰지 않는다 | `?` · `:` 로 윈도 파일 쓰기가 터진다. 라벨은 파일 첫 줄에 두고, 이름에서는 윈도가 못 받는 문자를 바꾼다 |
| 양쪽 덤프가 같은 항목을 뜨는지 먼저 맞춘다 | 열 이름·단위·기준점(중심/앵커)을 표로 못 박고 양쪽 덤퍼가 지난다. 한쪽에만 있는 열은 영원히 대조되지 않는다 |
| 우리 쪽 덤프는 원본 화면비에서 뜬다 | 배치 재생 기본 게임 뷰는 4:3 이다. 재생 전에 해상도를 못 박고 첫 줄에 화면 크기와 논리 폭을 찍는다 |
| 경계 상자는 네 귀 전부로 | 돌아간 것을 대각 두 귀로 재면 폭이 반이 된다 |
| 덤프는 마우스 없는 상태를 잰다 | 이벤트 시스템을 끄고 뜨기 직전에 호버를 내린다 (함정: [사람 마우스에 흔들리는 재생 검사](함정%20-%20검사기%20설계.md#사람%20마우스에%20흔들리는%20재생%20검사)) |
| 판마다 다른 것과 틀린 것을 갈라 적는다 | 씨앗·진행으로 자리가 바뀌는 개체(나무·적·보석·팝업)는 크기와 존재만, 난이도 곡선은 시계열로 본다 |
| 관측 최솟값은 소스·후킹으로 닫는다 | 하한 표기(R3)로 두고 소스·후킹으로 값을 닫는다 (함정: [관측 하한을 확정값으로 적은 기록](함정%20-%20판정%20보고.md#관측%20하한을%20확정값으로%20적은%20기록)) |
