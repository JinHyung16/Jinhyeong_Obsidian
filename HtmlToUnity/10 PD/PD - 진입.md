# 진입

상위: [PD](PD.md)

## 첫 턴 프로토콜

### 요약

- 이관 요청을 받으면 이 문서 세트를 먼저 연다. 시작 문서는 [PD](PD.md) 하나로 둔다.
- 첫 턴에 원장(`HtmlToUnity_작업내역_<게임명>.md`)이 있나부터 본다.
- 원장 유무와 이관 의사에 따라 사전 분석 · 신규 착수 · 재개로 갈린다.
- 신규 착수는 아래 9단계를 1번부터 밟는다.

### 규칙

#강제 [원칙 R13](원칙.md#R13) 착수 질문의 답으로 확정표가 차기 전에는 아무것도 만들지 않는다.

### 설계

```
원장(HtmlToUnity_작업내역_<게임명>.md)이 있나?
├─ 없다 + 「분석만 해줘」·이관 의사 미확정 → 사전 분석 모드 (아래 절).
│         끝에 이관 Y 를 받으면 그때 신규 착수로 내려온다.
├─ 없다 → 신규 착수. 아래 절차를 1번부터.
├─ 있다 → 확정표부터 검증한다. 빈 행·「미확인」 행만 다시 묻는다.
│         그다음 원장의 미흡 목록에서 최하위 미통과 게이트로 간다.
└─ 검증·누락 보충 요청 → 원장 최신 회차 → 해당 게이트의 통과 증명을 다시 잰다.
```

신규 착수 절차. 아래 순서가 기본이다.

```
1. 전제 도구를 점검한다 — 못 하는 단계가 있으면 만들기 전에 알린다
   (브라우저가 없으면 해상도 실측(3-d)을 사람에게 요청하고, 못 받으면 확정표에 미측정(① 도구 없음))
2. 원본 HTML5 위치를 확인한다 (모르면 묻는다) — 원본 형태를 가른다 (「원본 형태 판정」)
3. 「착수 질문」 전부를 묻는다                      ← 답을 다 받기 전에 다음으로 안 간다
4. 답을 「확정표」에 채우고 각 담당자 md 의 [Unity 프로젝트 세팅] 절로 복사한다
5. HtmlToUnity_작업내역_<게임명>.md 를 만든다                ← 분석로직 「HtmlToUnity_작업내역_<게임명>.md」
6. <원본폴더>/HtmlToUnityLogic/ 골격 껍데기를 만든다 ← 분석로직 「HtmlToUnityLogic/」
7. 템플릿 프로젝트면 잔재를 걷는다                  ← GameFramework 「신규 프로젝트를 청소한다」
8. 확정값을 프로젝트 설정에 반영한다                ← GameFramework 「확정표를 프로젝트 설정에 반영한다」
9. 학습 단계를 연다
```

- 2번의 판정 기준은 [PD - 원본 형태](PD%20-%20원본%20형태.md).
- 3번의 질문 목록은 [PD - 착수 질문](PD%20-%20착수%20질문.md), 4번의 표는 [PD - 확정표](PD%20-%20확정표.md).
- 프로젝트마다 새로 만드는 것은 셋뿐이다. 확정표 · `HtmlToUnity_작업내역_<게임명>.md` · `HtmlToUnityLogic/` 골격 전부다. 확정표의 행 수는 문장에 적지 않고 표를 센다.
- 기본은 빈 템플릿 파일 대신 규격만 들고 다니는 것이다. 실물은 그 프로젝트를 보고 만든다. 이유는 [분석로직](분석로직.md) 「만드는 문서」.
- 다른 문서를 프로젝트 사정에 맞춰 고치고 싶어지면 그것은 대개 원장에 적을 회고다.

## 사전 분석 모드

### 요약

- 게임만 주고 「분석해줘」라고 하면 이관 의사 미확정이다.
- 착수 질문은 아직 던지지 않는 것이 기본이다. 이유: 이관 여부가 먼저 정해져야 질문의 답이 쓰인다.
- 한다: 원본 형태 판정 · 원본 폴더 준비 · `00_원본정보.md` · 실측(조작·구조·메커니즘·미측정 목록).
- 산출물은 md 뿐이다.

### 규칙

#강제 [원칙 R13](원칙.md#R13) 이관 의사 확정 전에는 확정표·원장, `HtmlToUnityLogic/` 골격, Unity 쪽 산출물을 만들지 않는다.

### 설계

- 끝나면 결과를 보고하고 「이 게임을 Unity 로 제작(이관)할까요? Y / N」을 묻는다.
- Y 면 첫 턴 프로토콜 1번부터 가고 산출물은 이월한다.
- N 이면 멈추고 산출물은 남긴다.

## 문서 로딩 규칙

### 요약

- 단계마다 여는 문서만 연다.
- 착수 전에 기본으로 읽는 것은 [함정 색인](함정%20색인.md) 전체와 원장의 오염된 내용 · 회고록이다.

### 설계

| 단계 | 여는 문서 |
|---|---|
| 착수 확정 | [PD - 착수 질문](PD%20-%20착수%20질문.md) + [장르 지도](장르%20지도.md) 「장르 판정」 |
| 원장 · 학습 산출물 생성 | 분석로직 |
| 학습 (지식 담당자) | 자기 파트 문서 1개 + 분석로직 「HtmlToUnityLogic/」 + 공통절차 「원본 코드에서 답 찾는 법」 + 해당 장르 노트(있으면) |
| 패스 ① 코드 / 데이터 | Transfer_Programmer + DataFramework + GameFramework (+ SkillSystem. 원본 공격 수단이 2종 이상이면) |
| 패스 ② 프리팹 / 연출 | Transfer_Artist + PrefabRule + ResourceRule + UIFramework |
| 패스 ③ 배선 | Transfer_Programmer 「패스 ③」 + UIFramework |
| 재거나 캡처할 때 | 공통절차 (PD 문서는 열 필요가 없다) |
| 검증 (PD QA) | [PD - 검증 단계](PD%20-%20검증%20단계.md) · [PD - 게이트](PD%20-%20게이트.md) + 공통절차 |
