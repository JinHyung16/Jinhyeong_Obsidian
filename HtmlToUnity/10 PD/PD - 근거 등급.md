# 근거 등급

상위: [PD](PD.md)

## 근거 등급

### 요약

- 값마다 네 등급 중 하나를 적는다.
- 이유: 등급이 없으면 가설이 실측처럼 인용된다.
- ①이 오면 ①이 정본이다. 실측 169.3 이고 저작값이 170 이면 170 이다. 실측치는 식의 확인 근거로 남긴다.
- 값의 등급과 규칙의 등급은 따로 매긴다.

### 규칙

#강제 [원칙 R3](원칙.md#R3) 값마다 아래 등급 중 하나를 붙인다.

### 설계

| 등급 | 무엇 | 표기 |
|---|---|---|
| ① 소스 직독 | 원본 코드의 저작 상수·식 | `[소스]` · 표에서는 표본 수 `-1` |
| ② 실측 | 원본을 돌려 잰 값 (n ≥ 3) | `[실측 n=…]` |
| ③ 관측 | 한두 번 본 것 | `[관측]`. 실측으로 올리기 전까지는 값이 아니라 단서다 |
| ④ 미측정 / 가설 | 안 쟀거나 추론한 것 | `[미측정]`. 달성률 0% |

함정: [상수가 맞아 규칙도 맞다고 봄](함정%20-%20측정%20추론.md#상수가%20맞아%20규칙도%20맞다고%20봄).

## 미측정

### 요약

- 미측정은 통과가 아니다.
- 숫자를 못 넣은 칸은 `미측정(사유)` 이고 달성률은 0% 다.
- 아래 장치는 R6 을 운영하는 기본 방법이다.
- 기입 규격은 [분석로직 「섹션별 기입 규칙」](분석로직.md).

### 규칙

#강제 [원칙 R6](원칙.md#R6) 숫자를 못 넣은 칸은 `미측정(사유)` 이고 달성률은 0% 다. 빈칸·「됨」은 판정이 아니다.

### 설계

| 장치 | 규칙 |
|---|---|
| 어휘 | 숫자 또는 `미측정(사유)` (R6) |
| 사유 3갈래 | ① 도구 없음 ② 상태를 못 맞춤(A/B 정합 실패) ③ 하네스 없음. 해소법이 달라 갈래를 나눠 적는 것이 기본이다 |
| 달성률 | 미측정은 0% (R6) |
| 재측정 대기 | 원장 재측정 대기 표에 남기고 다음 회차에 신규 작업보다 먼저 처리하는 것이 기본이다 |
| 에스컬레이션 | 대기 회차 3 이상이면 PD 가 사람에게 도구·데이터를 요청한다 (기본 임계 3) |
| 소스 우선 | 미측정 3건 이상이면 관측 회차보다 번들 소스 수신([PD - 원본 형태](PD%20-%20원본%20형태.md) 「번들 소스」)을 먼저 하는 것이 기본이다. 이유: 그 절의 사례처럼 관측만으로는 규칙이 안 닫힌다 |

## 전제 도구

### 요약

- 없으면 못 하는 단계를 먼저 알린다.
- 착수 시 실제로 찔러 보고 확정표 13번에 적는다.
- 아래 「대체 판정」 열은 도구가 없을 때의 기본 대안이다.

### 규칙

#강제 [원칙 R20](원칙.md#R20) 열린 에디터를 껐다 켜지 않는다. 닫았으면 사람이 볼 상태로 되돌린다.

### 설계

| 도구 | 없으면 | 대체 판정 |
|---|---|---|
| 브라우저 (원본 실행 · DOM · 콘솔) | 순서·타이밍·게이트 조건이 안 잡힌다 | 코드 정독 + 사람에게 캡처·영상·DOM 덤프 요청. 돌려 봐야 아는 것은 미측정 |
| Unity 에디터 제어 | 대화형 조작이 안 된다 | 에디터가 열려 있으면 에디터 다리로 시키는 것이 기본이다. 재생 검사도 다리로 한다 (예시: `Tools/unity-batch.sh` · `PLAYMODE=1`). 에디터가 꺼져 있을 때만 배치모드(`-batchmode -executeMethod`) (공통절차 「에디터가 열려 있으면」 · 「에디터 툴은 배치모드로 직접 실행한다」). 둘 다 없으면 사람에게 한 묶음으로 요청 |
| 파일 검색 · grep | 원본 인용이 성립하지 않는다 | 대체가 없다. 착수 전에 먼저 확보한다 |
| 이미지 비교 | 「글자 제외 95%」를 못 잰다 | 요소 수 대조 (원본 N개 중 M개). 점수는 미측정 |
| 셸 (빌드 · ffmpeg 등) | 컴파일 판정(공통절차 「컴파일·툴 실행 순서」 ⓪-b)·영상 스틸 불가 | 사람에게 빌드 로그 요청. 「에디터가 안 먹는다」 판별식은 미측정 |

## 전제 능력

### 요약

- 특정 라이브러리를 강요하지 않는다. 능력만 규정한다.
- 아래 둘의 충족 방법을 확정표 14번에 적는다. 기본은 이미 쓰던 것이다.

### 설계

| 필요한 능력 | 용도 | 못 채우면 |
|---|---|---|
| JSON 역직렬화. 최상위 배열 · 임의 키 맵 · `null` 구분 · 중첩 제네릭 | 데이터 컨테이너 · 정답지 파싱 | 데이터 로드·수치 판정이 막힌다. `JsonUtility` 는 넷 다 안 된다 |
| 아트 로드/해제 단위 (번들 시스템 등) | 카테고리 단위 로드 · 양방향 감사(공통절차 「에셋 등록은 양방향으로 감사한다」) | 전부 `Resources` 로 물어 빌드가 부푼다 |

- 선택지와 접점 격리는 [DataFramework 「전제」](DataFramework.md). 기본은 라이브러리 이름이 나오는 파일을 한두 개로 격리하는 것이다. 넘으면 접점 설계부터 다시 본다.
- 확인은 `dotnet build` 가 기본이다. 이유: 에디터 콘솔은 변경을 아직 안 집어갔을 수 있다 (공통절차 「컴파일·툴 실행 순서」 ⓪-b).
