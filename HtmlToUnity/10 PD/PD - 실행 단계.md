# 실행 단계

상위: [PD](PD.md)

## 역할 기동 규약

### 요약

- 한 AI 가 7개 역할을 순차로 연기하므로 역할 이탈이 가장 흔한 실패다.
- 전환할 때마다 선언문을 사용자에게 보이게 출력한다.
- 역할을 바꾸면 기억을 이어가지 않는다. 이전 역할의 결론은 md 에 적힌 것만 근거로 삼는다.
- 서브에이전트를 쓸 수 있으면 권한표를 도구 화이트리스트로 걸어 이탈을 원천 차단한다.

### 규칙

#강제 [원칙 R17](원칙.md#R17) 아래 권한표가 역할 권한의 정본이다. 이 표 밖을 건드리면 이탈이다.

### 설계

전환 선언문 틀과 예시다.

```
[역할 전환] 지금부터 나는 <역할>다.
  할 수 있는 것 : <산출물>
  하지 않는 것  : <권한 밖>
```

```
[역할 전환] 지금부터 나는 Client(지식 담당)다.
  할 수 있는 것 : 원본 읽기 · 01_게임플로우.md / 99_원본지도.md 작성
  하지 않는 것  : Unity 코드·프리팹 수정 (그건 Transfer_Programmer 가 한다)
```

| 역할 | 만드는 것 | 손대지 않는 것 |
|---|---|---|
| PD | 확정표 · 원장 껍데기 · QA 미흡 목록 | 코드 · 프리팹 · 아트 전부 |
| Design / Client / FX / UI/UX (지식) | `HtmlToUnityLogic/` 문서만 | Assets 아래 전부 |
| Transfer_Programmer ① | 데이터·Manager·Management·Window 스크립트 · 검증 하네스·정답지 덤프·채점기 (G1·G2 를 열기 전에) | 프리팹 · 아트 파일 · 빌더 스크립트 |
| Transfer_Artist ② | 프리팹 · 리소스 · 연출 (굽는 방식은 확정표 10-b) | 게임 로직 · 데이터 컨테이너 · 배선 |
| Transfer_Programmer ③ | 배선 (등록 · 호출 · 파라미터 주입) | 프리팹 수정. Artist 에게 되돌린다 |

- 이전 역할의 결론은 md 에 적힌 것만 근거로 삼는 것이 기본이다. 필요하면 원본을 다시 연다. 이유: 방금 본 Unity 코드가 「원본도 이렇겠지」로 판단을 오염시킨다.
- 선언문 출력과 기억 비이어감은 환경과 무관하게 기본으로 두고, 권한표는 R17 이다.

## 패스 순서

### 요약

- 순서는 고정이다.
- 지식 담당자 갱신은 Design → Client → FX → UI/UX 다.
- 이관 담당자 수행은 Transfer_Programmer ① → Transfer_Artist ② → Transfer_Programmer ③ 이다.
- Design 이 먼저다. 데이터가 없으면 배선할 대상이 없다.

### 규칙

#강제 [원칙 R3](원칙.md#R3) 최종 판정은 지식 담당자 요약이 아니라 원본 코드다.

#강제 [원칙 R17](원칙.md#R17) ③에서 프리팹을 다시 뜯어야 하면 Artist 에게 되돌린다.

### 설계

```
지식 담당자 갱신 :  Design → Client → FX → UI/UX

이관 담당자 수행 :  Transfer_Programmer ①  코드 / 데이터 이관
                    Transfer_Artist     ②  프리팹 / 연출 생성
                    Transfer_Programmer ③  게임 플로우에 따라 배선
                                            (UI · 연출 · 게임오브젝트)
```

| 패스 | 담당 | 다음으로 가는 조건 | 이유 |
|---|---|---|---|
| ① | Programmer | 데이터 조회·로직·화면 전이가 돈다. 주입 API(`SetData`)가 선언돼 있다 | 주입 API 가 있어야 프리팹을 구울 의미가 있다 |
| ② | Artist | 프리팹·리소스·연출이 존재하고 정적 상태로 원본과 같아 보인다 | 배선할 실물이 있어야 ③이 가능하다 |
| ③ | Programmer | 게임 플로우 위에서 실제로 돈다 | 어디에 물리는지는 실물이 나온 뒤 정해진다 |

- 이관 담당자는 `HtmlToUnityLogic/` 을 근거로 작업한다.
- 확정표 10-b 가 「프리팹이 주인」(기본)이면 Artist 가 프리팹을 직접 고치고 빌더를 다시 돌리지 않는다 (R22). 「빌더가 주인」이면 빌더를 고쳐 다시 굽는다.

## 패스 ③

### 요약

- 패스 ③은 「만들어졌다」와 「돈다」 사이를 잇는다.
- ③의 완료 판정은 Play Mode 다.
- 기본은 에디터 다리로 돌리는 것이다 (예시: `PLAYMODE=1`).
- 주의: 편집 모드 레이캐스트는 원리적으로 비므로 「안 맞았다」를 결함으로 읽지 않는다.

### 규칙

#강제 [원칙 R16](원칙.md#R16) 재생 검사를 사람에게 넘기지 않는다.

#강제 [원칙 R20](원칙.md#R20) 재생 검사 때문에 열린 에디터를 껐다 켜지 않는다.

### 설계

| 배선 대상 | 하는 일 | 빠지면 |
|---|---|---|
| UI 배선 | Management 등록 · 버튼 → event → Manager 연결 · `SetData` 호출 | 창이 안 열리거나 값이 비었다 |
| 게임 플로우 배선 | `GameFlow` 전이표대로 열고 닫기 · 원본에 없는 창 차단 | 없어야 할 창이 뜬다 ([PD - 게이트](PD%20-%20게이트.md) 「플로우 diff」) |
| 연출 배선 | 런타임 파라미터(속도·위상·색·상태) 주입 · 상태 전이와 동기 | 프리팹 기본값으로만 돈다 |
| 게임오브젝트 배선 | 프리팹 로드 경로 · 풀 등록 · 스프라이트 런타임 주입 · 정렬 기준값 | 폴백 도형으로 남거나 풀에서 샌다 |
| 데이터 종속 아트 | 배경·초상·아이콘을 데이터로 조회 | 1번 값이 전 구역에 나온다 |
| 지연 로드 아트 | 로드 완료 후 다시 조회 | 평생 폴백 |

검사기는 시작할 때 `Application.runInBackground = true` 를 켠다 (함정: [포커스 없는 에디터 재생의 throttle](함정%20-%20도구%20러너.md#포커스%20없는%20에디터%20재생의%20throttle)). 절차는 [공통절차 - 에디터 실행](공통절차%20-%20에디터%20실행.md) 「에디터 다리」 · 「입력 판정은 재생 안에서만 잰다」.

## 유니티는 스스로 돌린다

### 요약

- 도메인 리로드·재생·정지는 담당자가 직접 실행하고 멈춘다. 사람에게 묻지 않는다.
- 에디터가 열려 있으면 다리로 시킨다.
- 재생 멈춤은 파괴적 행위가 아니다.
- 이관 작업은 재생을 멈춘 뒤에 하는 것이 기본이다. 이유: 재생 중에 하면 컴파일 보류·프리팹 미반영·세이브 훼손이 섞인다.

### 설계

```
[재생 멈춤]      ← 작업 착수 전 무조건 (공통절차 「컴파일·툴 실행 순서」 ⓪)
dotnet build …                    ← 컴파일 판정은 여기서 (공통절차 「컴파일·툴 실행 순서」 ⓪-b)
[에셋 새로고침] → 컴파일 완료 확인 → [에디터 코드 실행] → [콘솔 읽기]
[재생 시작] → 거동 확인 → [재생 멈춤]
```

## 원장 갱신과 PD 콜

### 요약

- 이관 담당자는 한 항목을 끝낼 때마다 원장을 갱신한다. 이유: 몰아서 적다가 문맥이 날아가면 복구할 수 없다.
- 콜은 패스 ③까지 끝난 뒤가 기본이다.
- 콜을 받은 PD 는 [PD - 검증 단계](PD%20-%20검증%20단계.md) QA 를 돌린다.

### 규칙

#강제 [원칙 R8](원칙.md#R8) 100% 는 PD QA 뒤에 붙는다. 담당자가 스스로 선언하지 않는다.
