# 인수인계 계약

상위: [PD](PD.md)

## 인수인계 계약

### 요약

- 파트 사이에서 무엇을 넘기고 무엇을 증명하는지의 계약이다.
- 아래 경계별 「받는 쪽이 증명할 것」과 「점검」은 기본 증명 방법이다.

### 규칙

#강제 [원칙 R3](원칙.md#R3) 모든 파트가 원본을 직접 읽는다. 전달받은 요약은 판정 근거가 아니다.

#강제 [원칙 R7](원칙.md#R7) 받는 쪽은 넘겨받은 것이 결과물에 도달했음을 증명한다.

### 설계

```
원본(심판)
   │
   ├─ 기획 ──[테이블 + 문구 + 파생규칙]──▶ 클라
   │                                        │
   │                                        ├─[계산 결과 스냅샷 + 표기 계약]──▶ UI/UX
   │                                        │
   │                                        └─[엔티티 상태 + 그리기 파라미터]──▶ 연출
   │
   └─ (모든 파트가 원본을 직접 읽는다. 전달받은 요약을 믿지 않는다)
```

## 지식 → 이관

### 요약

- md 는 컴파일되지 않아 가장 조용히 새는 경계다.
- 점검은 문서 항목 수 대비 이관 수를 분수로 적는 것이다. 이것이 [PD - 작업 원장](PD%20-%20작업%20원장.md) 「리스트업」 달성률의 분모다.

### 설계

| 넘기는 것 | 받는 쪽이 증명할 것 |
|---|---|
| `HtmlToUnityLogic/` 골격 전부 | 항목이 코드·프리팹에 1:1로 도달했다. 안 쓰인 항목은 미이관 |
| 원본 라인 인용 | 직접 열어 grep 으로 재확정했다 (공통절차 「문서의 라인 번호를 믿지 마라」) |
| 「제작 필요 리소스」 목록(`06_리소스.md`) | 전 항목을 굽고 어드레서블 등록까지 했다 (공통절차 「에셋 등록은 양방향으로 감사한다」) |
| 「오염된 내용」 목록 | 다시 밟지 않았다. 대책이 도구로 남아 있다 |

## 기획 → 클라

### 요약

- 테이블과 계산식과 폴백 계수를 넘긴다.
- 점검은 새 테이블마다 `AllValues.Count` 를 찍는 것이다.

### 설계

| 넘기는 것 | 받는 쪽이 증명할 것 |
|---|---|
| 테이블 (스키마 + 행 수) | 컨테이너가 존재하고 조회가 성공한다 |
| 원본 계산식 인용 (라인 번호 포함) | 같은 입력에 같은 출력. 정답지 또는 A/B |
| 폴백 계수 (원본 `\|\|` 뒤의 값) | 코드 상수로 두고 원본 행을 주석에 인용 |

## 클라 → UI/UX

### 요약

- 표기용 스냅샷 구조체와 필드의 의미를 넘긴다.
- 점검은 원본 UI 함수(예: `augCardHTML`) 하나를 「원본 / 우리 / 출처」 3열 요소표로 펴는 것이다 (「전수 대조표」).

### 설계

| 넘기는 것 | 받는 쪽이 증명할 것 |
|---|---|
| 표기용 스냅샷 구조체 (`XxxEntry`) | 모든 필드가 화면에 도달한다. 안 쓰는 필드는 계약 오류 |
| 필드의 의미(내부 코드인가 표기명인가) | 화면에 내부 코드가 뜨지 않는다 |
| 파생 표기 필요 여부 | 표시 직전 변환을 태웠다 |

## 클라 → 연출

### 요약

- 엔티티 상태와 그리기 파라미터와 시각을 넘긴다.
- 점검은 원본 draw 함수의 `lineWidth` / `shadowBlur` / `globalAlpha` / `globalCompositeOperation` 을 전부 grep 해 표로 만드는 것이다.

### 설계

| 넘기는 것 | 받는 쪽이 증명할 것 |
|---|---|
| 엔티티 상태 (위치·속도·반지름·종류) | 원본 반지름을 그대로 쓴다 |
| 원본 그리기 파라미터 (선 굵기·blur·색·알파) | 상수로 두고 원본 행을 인용 |
| 프레임 단위 시각(`t`)·`dt` | `t`/`dt` 를 받는 원본 함수는 반드시 움직인다 |

## UI/UX ↔ 연출

### 요약

- 분담은 텍스트·레이아웃·입력이 UI, 그림 자체가 연출이다.
- 아이콘 프레임(장식)과 글리프(데이터 종속)는 별개 필드로 나누는 것이 기본이다. 이유: 한 필드가 겸하면 런타임 주입이 테두리를 덮는다 ([PD](PD.md) 「파트 경계 사고」 UI → 연출).
- 절차 생성 아이콘·이펙트 텍스처는 연출이 굽고 UI는 경로만 참조하는 것이 기본이다.

## 전수 대조표

### 요약

- 화면 하나를 전수 대조표로 여는 법이다. 모든 파트 공통이다.
- 기본은 원본에서 그 화면을 그리는 함수의 요소를 빠짐없이 표로 나열한 뒤에 코드를 고치는 것이다.
- 이유: 아래 사례처럼 화면상 그럴듯해도 요소가 빈다.
- 사례: 선택 카드 9개 요소 중 6개가 비었는데 화면상으론 그럴듯했다.

### 설계

| 요소 | 원본 | 우리 | 출처 | 상태 |
|---|---|---|---|---|
| 상단 띠 | 계통 사전으로 변환한 표기명 | 내부 코드가 그대로 뜸 | 클라가 분류값을 넘김 | 실패 |
| 태그 | 등급 사전 + 접미어 (`고급 등급 무기`) | `고급` | 등급명만 넘김 | 실패 |
| 설명 | `descLvResolve(augDescT(k), L[k])` | (없음) | 트리 노드 설명 미조회 + 파생 미적용 | 실패 |
| 효과표 | `augEffectHTML(k)` 최대 6줄 | (빈 박스) | 미이식 | 실패 |
| … | | | | |
