# 작업 분해표

상위: [PD](PD.md)

## 분해 단위

### 요약

- 학습이 끝나면 작업 분해표를 만든다. 이관은 그 순서대로만 돈다.
- 기본은 단위를 학습 산출물에서 기계적으로 뽑는 것이다.
- 이유: 분해 없이 돌면 뒤 결함이 앞으로 되돌아가고 진행이 안 보인다.
- 문서에 없는 단위가 필요하면 분석이 덜 된 것이다. 학습으로 돌아가는 것이 기본이다.

### 설계

| 단위가 나오는 자리 | 한 단위 |
|---|---|
| `02_시스템_<이름>.md` | 문서 한 장 |
| `01_게임플로우.md` 의 화면 전이 그래프 | 화면 하나 |
| `03_데이터.md` 의 테이블 전수 | 테이블 묶음 |
| `05_연출.md` 의 연출 목록 | 연출 덩어리 (클리어 연출 · 피격 연출 …) |
| `06_리소스.md` 의 두 목록 | 리소스군 (배경 · UI · 이펙트) |

## 분해표

### 요약

- 분해표는 원장에 만든다. 규격은 `분석로직.md` 다.
- 빈칸이 있는 단위는 빈칸부터 채우고 시작하는 것이 기본이다.
- 완료 조건에 숫자가 없으면 판정이 안 되므로 숫자부터 박는다 (R6).

### 설계

| # | 단위 | 무엇을 만드나 | 근거 문서 | 선행 | 완료 조건 (검사·항수) | 상태 |
|---|---|---|---|---|---|---|
| 1 | 데이터 적재 | 테이블 N개 → 컨테이너 | `03` | | 행 수 어설션 N/N | |
| 2 | <핵심 시스템> | 계산·판정 | `02_<이름>` | 1 | 정답지 N/N | |
| 3 | <화면> | Window/Panel | `01`·`04` | 1 | 전수 대조표 빈칸 0 | |
| … | | | | | | |

## 순서 규칙

### 요약

- 네 개를 위에서부터 적용한다.
- 2 와 3 이 부딪히면 3 이 이긴다.

### 설계

1. 의존이 먼저. 데이터 → 로직 → 화면 → 연출 → 배선.
2. 한 판이 돌아가는 최소 경로(입력 → 판정 → 결과)가 먼저. 장식·연출은 뒤.
3. 그 안에서 못 잰 것이 많은 단위가 먼저. 이유: 불확실을 미루면 마지막에 터진다.
4. 같은 순위면 작은 것부터.

## 3패스

### 요약

- 3패스는 한 단위 안에서 도는 순서다.
- 기본은 단위마다 ①②③ 을 도는 것이다.
- 게임 전체에 ①을 다 하고 ②로 넘어가면 뒤 결함이 앞으로 되돌아간다.

### 설계

```
단위 1 : ① 코드·데이터 → ② 프리팹·연출 → ③ 배선 → 검사 → 완료
단위 2 : ① → ② → ③ → 검사 → 완료
…
```

- 한 단위는 검사까지 끝내고 다음으로 간다.
- 끝난 단위를 다시 열어야 하면 그 단위의 완료 조건을 고쳐 분해표에 반영한다.
- 공용 토대(프레임워크 최소 세트 · 로더 · 확정표 반영)는 단위가 아니라 0번 전제로 먼저 세운다.

## 보고 문장

### 요약

- 단위마다 시작과 완료를 말한다.
- 제목은 게임을 아는 사람이 알아듣는 말로 쓰는 것이 기본이다.
- 패스 번호·파일명은 듣는 사람이 읽지 못한다.

### 설계

```
<단위 이름> 작업 들어갑니다.      ← 무엇을 · 왜 (한 줄)
<단위 이름> 완료 — <검사> N/N.    ← 무엇이 바뀌었나 · 숫자 (한 줄)
```

| 피할 것 | 기본 |
|---|---|
| 「패스 ①-g 완료. 정답지 459 → 461」 | 「발사 물리 완료 — 정답지 461/465」 |
| 여러 단위를 한 보고에 섞기 | 단위마다 시작·완료를 따로 |
| 「됐습니다」 | 어느 검사가 몇 항 통과했나 |

## 완료 선언

### 요약

- 완료는 마지막에 한 번, 조건이 다 찼을 때만 말한다.
- 하나라도 비면 남은 것의 목록을 낸다. 「거의 완료」는 없다.

### 규칙

#강제 [원칙 R23](원칙.md#R23) 「이관 완료」는 아래가 전부 참일 때만 말한다. 하나라도 비면 남은 것의 목록을 낸다(「거의 완료」 없음).

### 설계

| 조건 | 확인 위치 |
|---|---|
| 재측정 대기 표가 비어 있다 (해소 또는 이관 밖 판정) | 원장 |
| PD QA 미흡 목록이 비어 있다 | 원장 |
| 이관율 대조표 분모가 확정표 범위와 같고 「의도된 차이」 밖 차이가 0 | 원장 (분석로직 「이관율 대조표」) |
| 검사 전부가 마지막 코드로 다시 돌아 N/N | 검사 로그 |
| 빌드가 그 게임 확정표로 구워졌다 | [GameFramework - 프로젝트 설정](GameFramework%20-%20프로젝트%20설정.md) 「여러 게임의 빌드」 |
| 재는 도구 정리. 회차용 검사기는 각 회차 끝에, 게임별 하네스·회귀 검사는 이관이 끝날 때 지운다(`out/` 은 회차마다 비운다) · 게임 전용 도구가 공용 자리에 없다 | [Transfer_Programmer - 검증 도구](Transfer_Programmer%20-%20검증%20도구.md) 「재는 도구 정리」 |
| 볼트 노트를 고쳤으면 미해결 링크 0 | [지도](지도.md) 「고칠 때」 |
| 사람이 열어서 볼 상태로 되돌려 놓았다 (닫았던 에디터 재실행 등) | [PD - 근거 등급](PD%20-%20근거%20등급.md) 「전제 도구」 |
