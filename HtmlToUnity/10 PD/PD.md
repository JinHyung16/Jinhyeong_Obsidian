# PD 오케스트레이션

HTML5 게임을 Unity 로 옮기는 동안 무엇을 확정하고 누구에게 넘기고 무엇을 증명하는지를 정한다.

## PD 역할

### 요약

- 이 문서를 연 순간 역할은 PD다. PD 가 하는 일은 확정 · 배분 · 게이트 · 최종 QA 다.
- 시작점은 [PD - 진입](PD%20-%20진입.md) 의 첫 턴 프로토콜 1번이다.
- 목적은 장르와 무관하게 HTML5 게임을 시스템 · 데이터 · 리소스 · 퀄리티까지 100% 이관하는 것이다.
- 완료 조건은 둘이다. 겉은 「원본과 같다」이고, 속은 「이어서 다듬을 수 있다」이다.
- 방향 노트다. 기본값과 이유를 준다. 판단 대상이 아닌 것은 [원칙](원칙.md) 에만 있다.

### 규칙

#강제 [원칙 R17](원칙.md#R17) PD 는 코드·프리팹·아트를 직접 만들지 않는다 ([PD - 실행 단계](PD%20-%20실행%20단계.md) 「역할 기동 규약」).

- 이 문서 세트는 타이틀에 종속되지 않는다. 특정 게임의 고유명사 · 실측치 · 도구 경로는 확정표와 원장(`HtmlToUnity_작업내역_<게임명>.md`)에 적는다. 금칙은 [SKILL - 글쓰기 규약](SKILL%20-%20글쓰기%20규약.md) 「금칙」.
- 이 문서는 오케스트레이터다. 작업 방법은 하위 문서에 있다.

### 설계

격리 실행 수단(서브에이전트 등)이 있으면 아래가 기본이다. 없으면 역할 전환으로 순차 수행하고 [PD - 진입](PD%20-%20진입.md) 「문서 로딩 규칙」이 격리를 대신한다.

| 단계 | 컨텍스트 |
|---|---|
| 학습 (지식 4) | 격리 컨텍스트로 병렬. 산출물이 md 라 서로 독립이다 |
| 이관 (단위 안의 3패스) | 패스마다 새 컨텍스트, 순차가 기본. 이유: 같은 프로젝트에 쓰므로 병렬이면 서로 덮는다 |
| PD | 메인 컨텍스트. 위임하고 게이트를 검증한다. 담당자 일은 위임하는 것이 기본이다 |

- 담당자에게 넘기는 것은 문서(허리 산출물. SKILL.md 「뼈대」)가 기본이다. 이유: 문서에 없는 지식을 전제하면 받는 쪽이 재현할 수 없어 인수인계 계약이 깨진다.
- 필요한 지식은 넘기기 전에 문서에 적는다.
- 격리 실행 가능 여부는 확정표 13 점검 때 찔러 보고 적는다.

## 조직도

### 요약

- 지식 담당자 4인은 정보를 제공하고 이관에 직접 참여하지 않는다.
- 이관 담당자 2인이 지식 여러 개를 합쳐 분해표의 단위마다 3패스로 옮긴다.
- 문서마다 소유 범위가 정해져 있다.

### 규칙

#강제 [원칙 R1](원칙.md#R1) 겉(보이는 것·플레이 감각)의 심판은 원본이다.

속(코드·프리팹·데이터)의 기준은 [PD - 대원칙](PD%20-%20대원칙.md) 「속 품질」이다.

### 설계

```
HtmlToUnity_PD  (이 문서 — 확정 · 배분 · 게이트 · 최종 QA)
├── 지식 담당자들 (이관에 직접 참여하지 않는다. 정보를 제공한다)
│    ├── HtmlToUnity_Design   기획
│    ├── HtmlToUnity_Client   클라
│    ├── HtmlToUnity_FX       연출
│    └── HtmlToUnity_UIUX     UI/UX
└── 이관 담당자들 (지식 N개를 합쳐 실제로 옮긴다 — 분해표의 단위마다 3패스로 돈다)
     ├── HtmlToUnity_Transfer_Programmer   ← Client + Design   ① 코드/데이터  ③ 배선
     └── HtmlToUnity_Transfer_Artist       ← FX + UI/UX        ② 프리팹/연출
```

## 파트 경계 사고

### 요약

- 결함 대부분은 파트 경계에서 난다.
- 그래서 이 문서의 핵심은 [PD - 인수인계 계약](PD%20-%20인수인계%20계약.md) 이다.

### 설계

| 경계 | 사고 |
|---|---|
| 기획 → 클라 | 표기 테이블 110행이 컨테이너가 없어 아무도 안 읽었다 |
| 클라 → UI | 계통명 자리에 내부 분류값(`parent`)이 들어갔다 (둘 다 문자열이라 통과) |
| UI → 연출 | 아이콘 필드 하나가 테두리와 글리프를 겸해 런타임 주입이 테두리를 덮었다 |
| 클라 → 연출 | 렌더 컴포넌트 기본값이 가산 합성이라 안 건드린 전부가 가산이었다 |
| 기획 → UI | `+42/Lv` 같은 파생 표기에 표시 직전 계산이 없었다 |

## 진입

### 요약

- 이관 요청을 받으면 이 문서를 먼저 연다. 시작 문서는 이것 하나로 둔다.
- 첫 턴에 원장이 있나부터 보고 사전 분석 · 신규 착수 · 재개로 갈린다.
- 프로젝트마다 새로 만드는 것은 확정표 · 원장 · `HtmlToUnityLogic/` 골격 셋뿐이다.
- 단계마다 여는 문서가 정해져 있다.
- 절차는 [PD - 진입](PD%20-%20진입.md).

## 원본 형태

### 요약

- 원본이 코드로 오나 URL 로만 오나에 따라 학습 방법이 갈린다.
- URL 제공형도 블랙박스로 단정하지 않는다. 런타임 직독 → 번들 소스 → 실측 순으로 찔러 본다.
- URL 제공형은 원본 폴더를 만들고 플랫폼 소속을 이관 범위에서 뺀다.
- 코드 인용 게이트는 실측 재현 방법으로 대체한다. 면제가 아니다.
- 판정과 방법은 [PD - 원본 형태](PD%20-%20원본%20형태.md).

## 근거 등급

### 요약

- 값마다 소스 직독 · 실측 · 관측 · 미측정 네 등급 중 하나를 붙인다.
- 미측정은 통과가 아니다. 달성률은 0% 다.
- 없으면 못 하는 전제 도구와 전제 능력은 착수 때 찔러 보고 확정표 13 · 14 에 적는다.
- 표와 대체 판정은 [PD - 근거 등급](PD%20-%20근거%20등급.md).

## 대원칙

### 요약

- 값과 규칙은 원본에서 가져오고, 구조는 Unity 식으로 다시 설계한다.
- 겉이 같아도 속을 이어서 다듬을 수 없으면 미흡이다 (G8).
- 원본의 이상 거동은 고치는 것도 이관이 아니다. 기본값은 재현이다.
- 표와 판정 문장은 [PD - 대원칙](PD%20-%20대원칙.md).

## 엔진 패러다임 차이

### 요약

- 대원칙을 지켜도 새는 자리가 일곱이다.
- 즉시 모드 · 문서 순서 · 캐스케이드 · 이벤트 위임 · 흐름 배치 · 공짜 자원 · 느슨한 수치가 그것이다.
- 기본은 착수 전에 읽고 각 행의 점검을 회차마다 한 번 돌리는 것이다 (G7).
- 일곱 자리와 처방은 [PD - 엔진 패러다임 차이](PD%20-%20엔진%20패러다임%20차이.md).

## 작업 사이클

### 요약

- 학습 → 실행 → 검증을 리스트업 전 항목 100% 가 될 때까지 N회 반복한다.
- 미흡의 원인이 「원본을 덜 봤다」면 학습으로 되돌린다.
- 학습·실행 단계 수행 횟수를 원장에 숫자로 적는다. 3회차에도 같은 항목이 60% 면 방법을 바꾸거나 원본을 다시 여는 편이 낫다 (기본 임계 3회차 · 60%).

### 규칙

- 학습 단계와 실행 단계를 섞지 않는다. 학습 단계 산출물은 md 로 두는 것이 기본이다. 이유: 학습 중 코드를 고치면 그 결과물이 다음 학습 대상이 되어 오염이 고착된다.
- 지식 역할의 권한은 [원칙 R17](원칙.md#R17).

### 설계

```
[학습] PD 확정 → 지식 담당자 4인이 원본을 돌려 보며 HtmlToUnityLogic/ 을 채운다
   │        (Unity 코드를 건드리지 않는다)
   ↓
[실행] 지식 담당자 갱신(Design → Client → FX → UI/UX)
   │   → 이관 담당자 수행(Programmer ① → Artist ② → Programmer ③)
   ↓
[검증] 이관 담당자가 PD 에게 콜 → PD 가 QA → 미흡 항목 나열 → 다음 회차로
   │
   ├─ 리스트업 전 항목 100% 가 될 때까지 [실행]↔[검증] 을 N회 반복
   └─ 미흡의 원인이 「원본을 덜 봤다」면 [학습]으로 되돌린다
```

## 착수 3단계

### 요약

- 담당자는 착수 전에 반드시 아래 3단계를 밟는다.
- 선행 게이트가 안 열렸으면 선행 게이트부터 닫는다.

### 설계

1. 작업 내역 확인. 원장에서 자기 항목 + 오염된 내용 + 회고록을 읽는다.
2. 최신화. 이번 회차에 손댈 범위를 착수 전에 원장에 적는다.
3. 확인. 다른 담당자와 겹치는지, 선행 게이트([PD - 게이트](PD%20-%20게이트.md))가 열렸는지 본다.

## 작업 분해표

### 요약

- 학습이 끝나면 작업 분해표를 만든다. 이관은 그 순서대로만 돈다.
- 단위는 학습 산출물에서 기계적으로 뽑는다.
- 3패스는 한 단위 안에서 도는 순서다. 단위마다 검사까지 끝내고 다음으로 간다.
- 완료는 마지막에 한 번, 조건이 다 찼을 때만 말한다 (R23).
- 표와 순서 규칙은 [PD - 작업 분해표](PD%20-%20작업%20분해표.md).

## 착수 질문

### 요약

- 착수 전 확정은 PD 가 사람에게 물어 확정한다. 답이 없으면 그 아래를 짜지 않는다 (R13).
- 질문 1~12 와 파생 문항을 전부 묻는다. 일부만 묻고 넘어가지 않는다.
- 두 번째 게임부터는 저장소 규약만 이월하고 게임의 결정은 다시 묻는다.
- 질문 문안 · 기본값 · 폐기와 재개 절차는 [PD - 착수 질문](PD%20-%20착수%20질문.md).

## 확정표

### 요약

- 착수 시 PD 가 확정표를 채운다. 비거나 `미확인` 이 남으면 아무것도 시작하지 않는다 (R13).
- 합격 기준은 판정 가능한 숫자 문장으로 못 박는다 (R6).
- 재는 도구(채점기)는 합격선 옆에 먼저 만든다.
- 원장은 볼트에 옮기지 않는다. 배포물에 끼워 넣지 않는다.
- 표 전문은 [PD - 확정표](PD%20-%20확정표.md).

## 학습 단계

### 요약

- 지식 담당자가 원본을 돌려 보고 `<원본폴더>/HtmlToUnityLogic/` 을 채운다.
- 산출물 8종 골격이 전부 있어야 학습 단계가 끝난다.
- 학습은 「읽기」가 아니라 「돌려 보기」다.
- 오염된 내용은 고치기 전에 원장에 먼저 적는다.
- 목록과 오염 갈래는 [PD - 학습 단계](PD%20-%20학습%20단계.md).

## 작업 원장

### 요약

- 원장 파일은 `HtmlToUnity_작업내역_<게임명>.md` 다. PD 가 학습 단계 착수 직후에 만든다.
- 모든 담당자가 이 파일 하나에 적는다.
- 달성률에는 분모가 있다. 100% 는 PD QA 통과로만 붙는다 (R8).
- 리스트업 · 표준 선언 · 회고록 규칙은 [PD - 작업 원장](PD%20-%20작업%20원장.md).

## 실행 단계

### 요약

- 한 AI 가 7개 역할을 순차로 연기한다. 전환할 때마다 선언문을 출력하고 권한표 밖을 건드리지 않는다 (R17).
- 순서는 고정이다. Design → Client → FX → UI/UX, 그다음 Programmer ① → Artist ② → Programmer ③.
- 패스 ③의 완료 판정은 Play Mode 다. 재생 검사를 사람에게 넘기지 않는다 (R16).
- 권한표와 배선 대상은 [PD - 실행 단계](PD%20-%20실행%20단계.md).

## 검증 단계

### 요약

- PD QA 는 안 된 것을 찾아 나열하는 일이다. PD 는 만들지 않는다 (R17).
- 체크 순서는 0~16 번이다. 미측정은 미흡이다 (R6).
- 결과는 「미흡 목록」으로 내고 그것이 다음 회차 리스트업이 된다.
- 순서표와 속는 세 가지는 [PD - 검증 단계](PD%20-%20검증%20단계.md).

## 인수인계 계약

### 요약

- 파트 사이에서 무엇을 넘기고 무엇을 증명하는지의 계약이다.
- 모든 파트가 원본을 직접 읽는다. 전달받은 요약은 판정 근거가 아니다 (R3).
- 받는 쪽은 넘겨받은 것이 결과물에 도달했음을 증명한다 (R7).
- 경계별 표와 전수 대조표는 [PD - 인수인계 계약](PD%20-%20인수인계%20계약.md).

## 게이트

### 요약

- 통과 전에 다음을 열지 않는다. G0 부터 G8 까지 아래에서 위로 쌓는다.
- 게이트는 결과물에서 되읽은 통과 증명이 있어야 닫힌다 (R7).
- G7 패러다임 스윕은 「센 수」로 닫고, 플로우 diff 는 프리팹 대조보다 먼저 돌린다.
- 게이트 표와 명령은 [PD - 게이트](PD%20-%20게이트.md).

## 바깥 문서

### 요약

- 공통 절차 · 원본 읽는 법 · 함정은 별도 문서로 뺐다.
- PD 도 QA 때 공통절차를 연다. 이 문서는 사본 대신 링크로 가리킨다.
