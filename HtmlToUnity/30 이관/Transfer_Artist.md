# 이관 담당 · 프리팹/리소스

지식을 만들지 않고, FX 와 UI/UX 의 지식을 합쳐 프리팹 구성과 연출을 옮긴다.

## 역할

### 요약

- 이 역할의 이름은 HtmlToUnity_Transfer_Artist 다. 한 단위 안의 ②다.
- 목표는 퀄리티까지 100% 다.
- 상위는 [PD](PD.md). 지식 출처는 [FX](Fx.md) + [UI/UX](UIUX.md).
- 규약은 [PrefabRule](PrefabRule.md) · [ResourceRule](ResourceRule.md) · [UIFramework](UIFramework.md). 원장은 `HtmlToUnity_작업내역_<게임명>.md` 이고 착수 시 PD 가 만든다.
- 방향 노트다. 기본값과 이유를 준다. 판단 대상이 아닌 것은 [원칙](원칙.md) 에만 있다.

### 규칙

#강제 [원칙 R17](원칙.md#R17) 아래 선언문의 「하지 않는 것」과 「Programmer 는 프리팹을 만지지 않는다」가 이 자리의 권한 경계다.

### 설계

```
작업 분해표의 단위 하나 :
  ① 코드 / 데이터 이관      ← Transfer_Programmer
  ② 프리팹 / 연출 생성      ← 나
  ③ 게임 플로우에 따라 배선  ← Transfer_Programmer
  → 그 단위의 완료 조건 검사 → 완료 → 다음 단위
```

- 기본은 분해표에서 내 차례인 단위만 만드는 것이다. 이유: 다른 단위의 것을 같이 만들면 그 단위의 ①이 정할 주입 API 없이 모양을 짐작하게 된다 (함정: [분석과 이관 사이에 작업 분해표가 없음](함정%20-%20문서%20운영.md#분석과%20이관%20사이에%20작업%20분해표가%20없음)).
- ①이 끝난 뒤에 착수하는 것이 기본이다. 이유: 주입 API(`SetData`) 시그니처와 넘어올 필드의 의미가 있어야 프리팹 모양이 정해진다.
- 배선은 ③이 한다. 나는 실물과 주입받을 자리까지 만든다. ② 시점에 눌러도 반응이 없는 것은 정상이지만 자리는 다 있어야 한다.
- ③에서 온 프리팹 수정 요청은 내가 받는다. 확정표 10-b 가 「프리팹이 주인」(기본)이면 기존 프리팹을 열어 고치고, 「빌더가 주인」이면 빌더를 고쳐 다시 굽는다.
- 이전 역할의 결론은 md 에 적힌 것을 이어받는 것이 기본이다. 이유: 기억으로 이어가면 앞 역할의 결론이 기록 없이 다음 판단에 섞인다.

역할 선언. 이 역할로 들어갈 때 다음을 출력한다 ([PD - 실행 단계](PD%20-%20실행%20단계.md) 「역할 기동 규약」).

```
[역할 전환] 지금부터 나는 Transfer_Artist(패스 ②)다.
  할 수 있는 것 : 프리팹 · 리소스 · 연출 (굽는 방식은 확정표 10-b)
  하지 않는 것  : 게임 로직 · 데이터 컨테이너 · 배선 (그건 패스 ③이다)
```

## 리소스 파악

### 요약

- 원본이 호출하는 리소스를 파악한다. 원본이 부르는 리소스 폴더를 훑어 제작되어 있는 리소스 목록을 만든다.
- 화면에 나오는데 파일이 없으면 CSS 나 canvas 로 그린 것이다. 그것이 그릴 목록이다.
- Client 지식으로 그리는 코드를 짚어 그릴 목록으로 정리한다.
- 이 목록의 전 항목을 굽혀야 끝으로 센다. 단색 박스로 남긴 항목은 미완성이다.

### 설계

```bash
grep -oE "(assets|img|res)/[A-Za-z0-9_./-]+\.(png|jpg|webp|mp4|webm|mp3|ogg)" 원본.html scripts/**/*.js | sort -u
```

```bash
grep -n "background:linear-gradient\|box-shadow\|clip-path" 원본.html   # CSS 로 그리는 것
grep -n "fillRect\|arc(\|createLinearGradient\|shadowBlur" 원본.html     # canvas 로 그리는 것
```

## 아트 재제작

### 요약

- 아트를 재제작한다면 손으로 그리지 말고 규격에 맞춘다.
- 원본 에셋을 못 쓰는 게임(상용·저작권)에서도 원본 스프라이트의 규격은 잴 수 있다.
- 이유: 손으로 다시 그리면 결과가 회차마다 흔들리고, 크기·주소·컷 수만 세는 채점기는 전부 통과시킨다.
- 사례: 「실루엣·팔레트를 맞춘 재제작」으로 통과시켰으나 실측 IoU 평균 50.6%, 색 수 19색 → 7색이었다.
- 먼저 몇 단까지 뜰지 정한다. 존재 → 규격 → 형태·색 → 픽셀 배치 순이다. 사다리와 각 단이 닫는 것은 [공통절차 - 원본에서 값 캐기](공통절차%20-%20원본에서%20값%20캐기.md) 「자산 단계」가 정본이다.

### 설계

| 단계 | 무엇 | 어떻게 |
|---|---|---|
| 1 | 규격을 잰다 | 아틀라스 이미지 파일을 내려받아 컷마다 실루엣 마스크(불투명/투명) · 팔레트(색 + 비중) · 알파 단계(색과 별개의 축) · 채움률 · 고유색 수 · (4단이면) 픽셀·알파 인덱스맵을 뽑는다. 기본은 파일에서 뽑는 것이다. 캔버스로 뽑으면 저알파 RGB 가 왜곡된다 (함정: [브라우저 캔버스로 읽은 원본 그림의 색 왜곡](함정%20-%20아트%20굽기.md#브라우저%20캔버스로%20읽은%20원본%20그림의%20색%20왜곡)) |
| 2 | 규격을 데이터로 둔다 | 굽는 입력이므로 에디터 전용 자리에 둔다(빌드에 안 들어간다). 학습 산출물 `06` 에 출처와 재는 방법을 적는다 |
| 3 | 규격을 목표로 굽는다 | 마스크대로 채우고 팔레트 비중대로 면적을 나눈다 |
| 4 | 채점기가 기계로 잰다 | 픽셀 일치율(주 지표) · 실루엣 IoU · 팔레트 거리 · 색 수 비 |
| 5 | 합격선을 확정표에 숫자로 | 「픽셀 일치 ≥ N%」 형태로 |

- 규격 파일은 굽을 때마다 읽는 것이 기본이다. 이유: 정적 변수로 캐시하면 다시 재서 넣어도 옛 값으로 굽는다.
- 컷 크기가 아트 표와 다르면 대개 표가 틀린 것이다. 기본은 굽기 전에 알리는 것이다. 이유: 표를 사람이 확정했다면 어느 쪽을 따를지는 사람이 정한다 ([원칙 R12](원칙.md#R12)).

## 어디까지 맞추나

### 요약

- 「어디까지 맞추나」는 담당자가 정하지 않는다.
- 「형태는 맞추되 픽셀은 우리 것」은 작은 스프라이트에서 성립하지 않는다. 16×16 에서는 픽셀 배치가 곧 형태라, 실루엣·팔레트가 맞아도 픽셀 일치가 13~34% 에 머문다.
- 사례: 담당자가 임의로 선을 긋고 자기 지표(IoU·팔레트) 100% 로 완료를 보고했다.

### 규칙

#강제 [원칙 R11](원칙.md#R11) 아래 표의 둘째 행: 픽셀 배치까지 맞출지는 사람이 정한다.

#강제 [원칙 R8](원칙.md#R8) 재제작 합격선은 확정표의 숫자이고, 자기 지표 100% 는 완료의 근거가 아니다.

#강제 [원칙 R12](원칙.md#R12) 측정이 사람 확정과 다르면 알리고 확정을 따른다 (함정: [사람이 없애라 한 버튼 둘레 띠를 측정으로 되살린 일](함정%20-%20사람%20권리%20안전.md#사람이%20없애라%20한%20버튼%20둘레%20띠를%20측정으로%20되살린%20일)).

### 설계

| 무엇 | 누가 정하나 |
|---|---|
| 실루엣·팔레트·컷 수·fps 를 실측해 맞춘다 | 담당자. 어느 경우에나 한다 |
| 픽셀 배치까지 맞추나 | 사람. 저작권·정책 문제다. 착수 질문으로 묻고 확정표에 적는다 |

- 사람이 「픽셀까지」로 정하면 규격에 픽셀 인덱스맵을 넣고 그대로 굽는다. 그때는 재제작이 아니므로 의도된 차이 목록에서 그 줄을 지운다.
- R12 의 반영 자리는 결과물(프리팹) 또는 굽는 입력 데이터(규격)가 기본이고, 회귀 검사가 지킨다.
- 기본은 그 예외를 프리팹이나 규격 데이터에 두는 것이다. 이유: 굽는 코드에 에셋 이름 목록으로 넣으면 되돌리거나 다른 에셋에 적용할 때 코드를 고쳐야 한다 ([PD - 대원칙](PD%20-%20대원칙.md) 「속 품질」). 사례: 버튼 둘레 반투명 띠를 빌더의 이름 목록(`NoOuterHalo`)으로 걷어, 되돌리거나 다른 에셋에 적용하려면 코드를 고쳐야 했다.

## 플랫폼에 담기

### 요약

- 제작된 것과 제작할 것 모두 텍스처 사이즈를 플랫폼에 맞춘다 (ResourceRule 「해상도 정책」).
- 임포트 설정(Pivot·PPU·압축·mip)은 생성기 안에서 거는 것이 기본이다. 이유: 구운 뒤 손으로 걸면 빠진다.

## 프리팹 굽기

### 요약

- 기본은 화면 하나를 열기 전에 전수 대조표(UIUX 「화면 하나를 전수 대조표로 연다」)를 만드는 것이다. 표가 먼저이고 코드 수정은 그 뒤다.
- 굽는 방식은 확정표 10-b 를 따른다.
- 색은 원본 `:root` 변수를 그대로 쓰는 것이 기본이다. 이유: 하드코딩한 색은 원본 변수와의 연결이 끊긴다.

### 규칙

#강제 [원칙 R22](원칙.md#R22) 「프리팹이 주인」이면 있는 프리팹을 빌더로 다시 굽지 않는다.

### 설계

- 원본 DOM 의 배치 관계를 옮기는 것이 기본이다. 절대 y 대신 flex 를 옮긴다 (PrefabRule 「계층」). 주의: 원본 구조를 1:1 로 베끼는 것과는 다르다. 구조 설계는 [원칙 R2](원칙.md#R2) 를 따른다.
- 「프리팹이 주인」(기본)이면 빌더는 없는 프리팹만 초안으로 굽고 있는 것은 건너뛴다. 이후 수정은 프리팹을 열어 고친다 (PrefabRule 「프리팹이 주인일 때」).
- 「빌더가 주인」이면 빌더를 고쳐 다시 굽는다.
- 보이는 조정값(위치·크기·색·알파·연출 속도·타이밍)의 기본 자리는 프리팹 직렬화 필드다. 기본값은 원본 값, 출처는 `[Tooltip]` 이나 주석. 이유: 코드 상수로 두면 다듬을 때 프리팹만 고쳐서는 바뀌지 않는다.

## 연출 붙이기

### 요약

- 정적 캡처에는 `animation` 과 `:hover` 가 안 찍힌다. 그래서 화면을 열 때 원본 CSS 에서 먼저 훑는 것이 기본이다.
- 방향·속도를 원본에서 확인한다. 드리프트 배율·타일링 방향·왕복 여부까지 본다.
- 접기 연출은 높이로 접는 것이 기본이다. 이유: 자식을 `SetActive(false)` 로 끄면 내용 높이를 못 재서 한 프레임 튀고 형제 패널도 같이 튄다.
- 시간축 기본은 `Time.unscaledDeltaTime` 이다. 이유: 전투가 멈춘 동안에도 돌아야 한다. 원본에서 정지와 함께 멈추는 연출이면 scaled 시간이 맞다.

### 설계

| 원본 | 우리 |
|---|---|
| 등속 회전 | 회전 컴포넌트 (`degreesPerSecond`, 음수 = 시계 방향) |
| 사인파 맥동 | 맥동 컴포넌트 |
| `animation: … steps(1,end)` | 계단 점멸. 사인파로 대체하면 다른 연출이다 |
| `:hover{transform:rotate()}` | 호버 회전 + 색 전이 |
| 등속 이동 | 드리프트 (`unitsPerSecond` · `range` · `pingPong`) |
| `grid-template-rows: 0fr↔1fr` | 높이 접기. 자식을 끄지 않는다 |
| `cubic-bezier()` | 같은 이징. `SmoothStep` 으로 대충 맞추면 궤적이 다르다 |

## 유니티를 돌려 확인한다

### 요약

- 정본은 [PD - 실행 단계](PD%20-%20실행%20단계.md) 「유니티는 스스로 돌린다」.
- 에디터 작업의 기본은 에디터 다리(`Tools/unity-batch.sh`)이고, 재생 확인도 `PLAYMODE=1` 로 다리에서 돌린다.
- 재생 검사기는 `Application.runInBackground = true` 를 켜는 것이 기본이다 (함정: [포커스 없는 에디터 재생의 throttle](함정%20-%20도구%20러너.md#포커스%20없는%20에디터%20재생의%20throttle)).
- 정지 프리뷰는 `Update` 가 안 돈다. 애니메이션이 붙은 상태는 끝 상태를 세워 두는 것이 기본이다. 이유: t=0 이 찍혀 기능이 없다고 오판한다.

### 규칙

#강제 [원칙 R16](원칙.md#R16) 실행과 정지를 사람에게 맡기지 않고 직접 한다.

### 설계

```
재생 멈춤 → 굽기(초안 빌더 또는 기존 프리팹 수정 저장) → 로그 읽기(경고 0 확인)
→ Preview 하네스로 캡처와 같은 해상도로 굽는다 → 픽셀 측정
→ PLAYMODE=1 Tools/unity-batch.sh … → 거동 확인 → 재생 멈춤
```

## 패스 ③이 배선할 자리

### 요약

- ③이 값을 넣을 수 있게 자리와 통로를 만드는 것이 ②의 절반이다.
- 자리가 없으면 ③에서 프리팹을 다시 뜯는다.
- ②를 닫을 때 ③에게 무엇을 어디에 넣으면 되는지 원장에 적어 넘기는 것이 기본이다.

### 설계

| 비워 둘 자리 | 어떻게 |
|---|---|
| 데이터 종속 아트 | 프리팹에 굽는 대신 `[SerializeField] Image` 만 두고 프리팹 값은 폴백으로만 |
| 주입 API | ①에서 받은 `SetData(...)` 시그니처대로 필드를 다 만든다. 안 쓰는 필드가 있으면 계약이 틀린 것 |
| 연출 파라미터 | 속도·위상·색·범위를 `[SerializeField]` 로 노출하고 런타임 재설정 메서드를 둔다. 상수로 굽는 대신 노출 |
| 상태 전이 | 접힘/펼침·활성/비활성을 메서드 하나로 바꿀 수 있게 (`SetExpanded(bool, instant)`) |
| 장식과 내용물 | 별개 필드가 기본. 하나로 두면 ③의 런타임 주입이 장식을 덮는다 |
| 월드 프리팹의 스프라이트 | 스프라이트는 비워 두고 계층·`SpriteRenderer`·정렬 순서·머티리얼까지만 |

## 정적 캡처로 안 잡히는 것

### 요약

- Play Mode 에서 확인한다.
- 판정 항목은 [UIUX](UIUX.md) 「판정 항목」 표를 쓴다. 사본은 여기 두지 않고 링크한다. 이유: 두 곳에 두면 한쪽만 고쳐진다.

### 설계

```csharp
// 살아 움직이는 것들의 스프라이트 이름을 찍는다 — 같은 이름만 나오면 모양을 안 옮긴 것이다
foreach (Transform t in entityRoot) Log(t.GetComponentInChildren<Image>().sprite.name);
```

## 점수를 믿기 전에

### 요약

- 헤드리스 캡처는 색 프로파일 때문에 더 밝게 나올 수 있다. 점수가 낮으면 원본 에셋과 직접 대조한다.
- 글자·숫자·라벨은 DOM/JS 문자열에서 확인하는 것이 기본이다. 픽셀로 읽는 것보다 정확하다.
- 주의: 애니메이션의 어두운 구간이 찍힌 캡처는 정색으로 오인하기 쉽다.
- 폰트 차이는 허용 오차다. 폰트에 없는 글리프를 쓰는 것은 버그다.
- 영상 프레임·보유 재화·선택 상태가 다르면 그 구간 점수는 무의미하다. 결함을 찾기 전에 상태 정합 체크리스트(공통절차 「A/B 측정」)부터 채운다.

## 완료 체크리스트

### 요약

- 한 줄이라도 「미확인」이면 완료가 아니다.

### 규칙

#강제 [원칙 R23](원칙.md#R23) 아래에 「미확인」이 한 줄이라도 있으면 완료라고 말하지 않고 남은 목록을 낸다.

#강제 [원칙 R6](원칙.md#R6) 첫 줄의 못 잰 항목은 통과가 아니라 `미측정(사유)` 다.

### 설계

- [ ] 미측정 항목 0. 못 잰 것은 `미측정(사유)` 로 적고 재측정 대기에 등록했다
- [ ] 내 권한 밖 파일을 건드리지 않았다 ([PD - 실행 단계](PD%20-%20실행%20단계.md) 「역할 기동 규약」 권한표 · [원칙 R17](원칙.md#R17))
- [ ] 화면마다 전수 대조표(UIUX 「화면 하나를 전수 대조표로 연다」)를 만들었고 빈 칸이 0이다
- [ ] 「그려야 할 목록」의 전 항목을 굽혔다 (단색 박스 0)
- [ ] 구운 시트마다 쓰는 곳이 한 줄 적혀 있다. 상태별 시트는 상태를 실제로 전이시켜 그림이 갈리는지 재생에서 봤다 (함정: [만든 것을 옮긴 것으로 센 이관율 분자](함정%20-%20판정%20보고.md#만든%20것을%20옮긴%20것으로%20센%20이관율%20분자) · [상태별 시트를 구웠지만 뷰가 한 장만 그림](함정%20-%20아트%20굽기.md#상태별%20시트를%20구웠지만%20뷰가%20한%20장만%20그림))
- [ ] 굽는 코드의 갈래와 표의 행을 양방향으로 맞췄다. 표에만 있으면 자리표시자가 나가고, 갈래에만 있으면 한 번도 안 불린다 (함정: [개체만 세고 행동은 안 센 분모](함정%20-%20판정%20보고.md#개체만%20세고%20행동은%20안%20센%20분모))
- [ ] 시트를 굽는 코드가 그릴 칸 수와 그릴 위치를 같은 stride 로 계산하고, 순환하는 칸에 완전 투명 프레임이 없는지 굽는 도구가 검사한다 (함정: [칸 수와 자리 보폭이 달라 빈 시트 꼬리](함정%20-%20아트%20굽기.md#칸%20수와%20자리%20보폭이%20달라%20빈%20시트%20꼬리))
- [ ] 알파를 색과 다른 축으로 쟀다. 팔레트 키에 알파를 섞지 않고 알파 단계 표를 따로 둔다 (함정: [색 키에서 빠진 알파 축](함정%20-%20아트%20굽기.md#색%20키에서%20빠진%20알파%20축))
  - [ ] 투명 판정은 알파 0 하나다. 실루엣·색 배치·알파 배치가 같은 기준을 쓴다
  - [ ] 채점기도 알파를 본다. 이유: RGB 만 재면 반투명 그림자가 불투명이어도 만점이 나온다
  - [ ] 어두운 오버레이의 알파 역산은 방향이 반대다 (함정: [어두운 오버레이 알파 역산 방향 착오](함정%20-%20아트%20굽기.md#어두운%20오버레이%20알파%20역산%20방향%20착오), `Fx.md` 「색공간」)
- [ ] 마지막에 화면 단면으로 원본과 댔다. 스프라이트가 같아도 알파·색공간·블렌딩·늘리기로 화면은 다를 수 있다 (함정: [원본만 재고 우리 화면은 안 잰 대조](함정%20-%20검사기%20설계.md#원본만%20재고%20우리%20화면은%20안%20잰%20대조))
- [ ] 늘리기와 키우기를 갈랐다. 덤프의 `frame`·`sx/sy`·`w/h` 를 같이 보고 `w == frame × sx` 면 정수배 확대, 아니면 9슬라이스다 (함정: [덤프에 원리적으로 없는 값을 공식으로 메운 함정](함정%20-%20원본%20관측.md#덤프에%20원리적으로%20없는%20값을%20공식으로%20메운%20함정))
  - [ ] 인셋은 호출부의 인자다. 9슬라이스 생성자 이름으로 번들을 훑어 호출부를 인자와 함께 전수로 꺼내 표의 행으로 싣는다. 공식이나 그림에서 추정하지 않는다 (함정: [그림에서 추정한 9슬라이스 인셋](함정%20-%20원본%20관측.md#그림에서%20추정한%209슬라이스%20인셋)). 소스에 없는 텍스처는 9슬라이스가 아니다
  - [ ] 같은 그림을 자리마다 다른 인셋으로 쓰면 행을 나눴다. 이유: 엔진의 인셋은 스프라이트 에셋에 붙는다
- [ ] 임포트 설정이 생성기 안에서 걸린다 · 모바일은 4의 배수
- [ ] 확정표 10-b 가 「프리팹이 주인」이면 빌더를 다시 돌려도 기존 프리팹이 안 바뀐다. 「빌더가 주인」이면 프리팹이 빌더로 재생성된다
- [ ] 보이는 조정값이 프리팹 필드에 있다. 코드 상수로 박힌 위치·크기·색·연출 수치 0 · 에셋 이름으로 갈리는 코드 분기 0 ([PD - 대원칙](PD%20-%20대원칙.md) 「속 품질」)
- [ ] 굽기·저장 후 콘솔 경고 0 (스프라이트 미발견 · NRE 포함)
- [ ] 데이터 종속 아트가 프리팹에 구워져 있지 않다
- [ ] 양방향 에셋 감사 3종이 0건이다 (ResourceRule 「어드레서블 등록은 양방향으로 감사한다」)
- [ ] `animation` · `:hover` 를 원본 CSS 에서 훑어 전부 옮겼다. 엔진 게임이면 `05` 「UI 연출」 표의 창마다 펄스·호버·디머가 우리 창에 같은 식으로 있다
- [ ] 아트를 재제작했으면 「원본 참고 시트 vs 우리 시트」 대조 시트를 만들어(Assets 밖) 사람이 한 번 봤다. 이유: 그림의 질은 숫자로 안 나온다
- [ ] 그리기 파라미터(선 굵기·blur·알파·합성)가 전수표로 원본과 짝지어져 있다
- [ ] Play Mode 에서 UIUX 「판정 항목」 표 전 항목을 확인했다 (「정적 캡처로 안 잡히는 것」)
- [ ] 글자 제외 점수가 합격선 이상이고, 낮은 구간은 원인을 갈래로 나눠 적었다
- [ ] ③이 배선할 자리를 비워 뒀다 (「패스 ③이 배선할 자리」). 데이터 종속 아트를 굽지 않았고 장식/내용물이 별개 필드다
- [ ] 원장(`HtmlToUnity_작업내역_<게임명>.md`)에 수행 내용과 회고를 적었다
- [ ] Transfer_Programmer 에게 ③(배선)을 넘겼다. PD 콜은 ③이 끝난 뒤 Programmer 쪽에서 한다
