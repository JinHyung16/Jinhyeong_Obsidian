# 검증 도구

상위: [Transfer_Programmer](Transfer_Programmer.md)

## 도구 두 갈래

### 요약

- 만드는 도구는 두 갈래다. 구성하는 도구는 남기고 재는 도구는 남기지 않는다.
- 기본 생명주기는 아래 표다.

### 설계

| 갈래 | 무엇 | 어디에 | 이관이 끝나면 |
|---|---|---|---|
| 구성하는 도구 | 프리팹 빌더 · 스프라이트 굽기 · 임포트 설정 · 리소스 등록 · 플랫폼 설정 | 공용은 공용 `Editor/`, 그 게임 전용은 게임 폴더의 `Editor/` | 남긴다. 없으면 사람이 인스펙터로 해야 한다 |
| 재는 도구 | 채점기 · 플로우 검사 · 배선 검사 · 재생 검사 · 렌더 캡처 | 유니티 프로젝트 밖 (`Tools/Verify/`) | 통째로 지운다 |

## 검증 산출물 자리

### 요약

- 검증 산출물을 유니티 프로젝트 안에 만들지 않는다. 기본 자리는 프로젝트 밖이다.
- 이유: 채점기·정답지 에셋이 섞이면 개발자가 아닌 사람은 커밋 여부를 판단할 수 없다.
- 정답지는 감추지 않고 읽히는 기록으로 둔다.
- 벡터가 수십 개를 넘거나 같은 것을 3회차 이상 다시 재면 손 대조보다 검사 코드를 만드는 편이 낫다.

### 설계

| 무엇 | 어디 |
|---|---|
| 정답지 (입력 → 기대 출력) | `07_기대값.md`. md 표 (규격은 `분석로직.md`) |
| 원본 쪽 실측 | 브라우저 콘솔 |
| 유니티 쪽 실측 | 임시 로그 → 표에 옮기고 지운다 |
| 대조 결과 | 원장에 `N/N` 숫자 |

검사 산출물을 엔진의 임시 폴더에 쓰지 않는다.

- 엔진은 시작할 때 임시 폴더(`Temp/`)를 비운다.
- 그래서 산출물의 기본 자리는 재는 도구와 같은 자리(`Tools/Verify/out/`)다.
- 러너도 배치 로그를 에디터 다시 열기 전에 그 자리로 복사한다.
- 사례: 재생 검사가 임시 폴더에 뜬 사건 프레임 6장과 로그가 러너의 다시 열기로 지워졌다.

검증 소스가 어느 어셈블리로 컴파일되는지 확인한다.

- 재는 도구를 실행할 때만 들여놓으면, 폴더 이름이 엔진의 에디터 폴더 규칙에 맞지 않아 런타임 어셈블리로 컴파일된다.
- 그러면 게임 폴더의 에디터 코드(빌더·규격 데이터)를 참조할 수 없다.

| 증상 | 실제 원인 |
|---|---|
| 다리 응답이 「메서드를 못 찾았다」뿐이다 | 컴파일 에러가 다리 응답에 안 실린다. 엔진 로그를 본다 |
| 검사기가 빌더의 타입을 못 본다 | 어셈블리 경계다. 참조보다 데이터를 직접 읽는 편이 낫다 |

이쪽이 옳다. 재는 도구가 결과물에 의존하지 않아야 서로 지워도 온전하다.

## 재는 도구 정리

### 요약

- 재는 도구는 이관이 끝나면 지운다. 「이관이 끝나면」이지 「회차마다」가 아니다.
- 기본 순서는 마지막 회차에 전 검사를 한 번 통과시킨 뒤 지우는 것이다.
- 「미측정」·「재측정 대기」 칸이 비었는지 같이 본다. 남아 있으면 다시 만들어 잰다.
- 지운 사실과 마지막 통과 숫자를 원장에 적는다.
- 사례: 회차마다 `Tools/Verify/` 를 비워 같은 120줄을 한 세션에 세 번 다시 쓰고 매번 검사기 버그를 만들었다 (함정: [검사 분모를 지금 보이는 화면에 맡긴 검사기](함정%20-%20판정%20보고.md#검사%20분모를%20지금%20보이는%20화면에%20맡긴%20검사기) · [초기화 완료 전에 화면을 바꾸는 검사](함정%20-%20검사기%20설계.md#초기화%20완료%20전에%20화면을%20바꾸는%20검사)).

### 설계

| 무엇 | 언제 지우나 | 이유 |
|---|---|---|
| 회차용 검사기 (그 회차의 갈래만 재는 것) | 그 회차 끝에 | 다음 회차에 안 쓴다 |
| 게임별 하네스(예: 프로브 베이스 클래스) · 회귀 검사 | 이관이 끝날 때 | 회차마다 쓴다. 지우면 매번 다시 쓰고 새 버그를 만든다 |
| 산출물 (`Tools/Verify/out/` 의 로그·보고서) | 회차마다 비운다 | 다음 실행이 덮어쓴다. 저장소에 남기지 않는다 |

- 하네스에는 읽는 곳이 있어야 한다. 기본은 회귀 검사 하나를 같이 두는 것이다 (함정: [만든 것을 옮긴 것으로 센 이관율 분자](함정%20-%20판정%20보고.md#만든%20것을%20옮긴%20것으로%20센%20이관율%20분자)).
- 하네스에 넣는 것은 한 번 데인 함정이 기본이다. 포커스 없는 재생 throttle · 구독 전에 화면 바꾸기 · 정지 중에 재기 · 실시간으로 걸어가다 죽기가 그것이다. 편의 함수 모음이 아니다.

## 공용 자리

### 요약

- 공용 도구 자리에 게임 전용을 남기지 않는다.
- 게임 전용 도구의 기본 자리는 게임 폴더의 `Editor/` 다.
- 이유: 공용 자리에 있으면 다음 게임 담당자가 지워도 되는지 판단할 수 없다.
- 두 번째 게임이 그대로 쓰게 되면 공용으로 올린다 ([GameFramework](GameFramework.md)).
- 주의: 옮겨서 다시 구우면 픽셀이 달라질 수 있다. 라이브러리마다 안티에일리어싱이 다르다. 렌더 판정을 다시 재서 통과를 확인한다.

## 검증용 진입점

### 요약

- 게임 코드에 검증용 진입점을 두지 않는다.
- 기본은 `DebugSetXxx` 같은 문을 뚫는 대신 기존 주입 지점으로 세우는 것이다.
- 이유: 결과물에 치트가 남고 검증이 실제 경로를 안 지난다.
- 도구는 러너(`Tools/unity-batch.sh`) 실행 전용이 기본이다. 에디터 메뉴는 따로 만들 필요가 없다. 이유: 사람이 메뉴를 누를 일이 없다 ([원칙 R16](원칙.md#R16)).

### 설계

| 무엇을 세우나 | 어디로 |
|---|---|
| 무작위 | 주입식 RNG |
| 데이터 | 텍스트 주입 경로 |
| 시간 | 틱 함수 인자 |
