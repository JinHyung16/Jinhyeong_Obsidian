# 문서 쓰는 법

Dev_Unreal 노트의 형식을 정한다. 노트를 새로 쓰거나 고칠 때 편다.

노트는 두 종류뿐이다. 규칙과 독스다. 성격이 같으면 구조도 같아야 한다.

## 노트 두 종류

| 성격 | 무엇 | 구조 |
|---|---|---|
| 규칙 | 지켜야 할 것 | 번호 붙은 규칙 목록 |
| 독스 | 만드는 법 | 설명 - 핵심 아이디어 - 코드 - 사용 방법 |

## 규칙 노트 구조

규칙1) 첫 줄에 이 노트가 무엇을 정하는지 한두 문장으로 적는다.

규칙2) 본문은 `규칙N)` 로 시작하는 한 줄이다. 번호는 1부터 이어 붙인다.

규칙3) 규칙 하나는 한 가지만 말한다. 두 가지를 말해야 하면 규칙을 나눈다.

규칙4) 규칙에는 이유를 붙인다. 이유가 없으면 나중에 아무도 안 지킨다.

규칙5) 규칙을 지운 자리는 번호를 비우지 않는다. 뒤 번호를 당겨 다시 매긴다.

## 독스 노트 구조

독스는 아래 차례를 지킨다. 순서를 바꾸지 않는다.

```
# 독스 - 이름

한두 문장 설명. 이 노트가 무엇이고 언제 펴는지.

## 핵심 아이디어
왜 이렇게 만드는지. 표와 그림으로.

## 구조
파일과 클래스가 어떻게 나뉘는지.

## 전체 코드
파일마다 토글 하나. 안에 전체 코드.

## 사용 방법
에디터에서 뭘 누르고 코드에서 뭘 부르는지.

## 함정
겪어 본 것만. 안 겪은 것은 적지 않는다.
```

## 코드 토글

코드는 직접 붙여 넣지 않는다. 표시만 남기고 도구가 채운다.

```
<!-- code: Source/RollBall/Skill/RollBallSkillGraph.h -->
<!-- /code -->
```

채우는 도구는 이 볼트의 `90 도구/sync_wiki_code.py` 다. 코드를 고친 뒤 돌린다.

```bash
python "90 도구/sync_wiki_code.py"
```

이유: 노트에 코드를 손으로 붙이면 코드를 고칠 때마다 노트가 낡는다. 낡은 코드가 붙은 노트는 안 보는 것만 못하다.

## 표기

규칙1) 이모지, 장식 기호, 느낌표를 쓰지 않는다.

규칙2) 굵게와 인용 블록을 쓰지 않는다. 쓰는 것은 제목, 표, 목록, 코드 블록, 백틱이다.

규칙3) 문장은 짧게 쓴다. 한 문장에 한 가지만 담는다.

규칙4) 어려운 말 대신 쉬운 말을 쓴다. 영어를 그대로 옮긴 어색한 말도 쓰지 않는다.

규칙5) 판정할 수 있게 쓴다. 많이 빨라졌다가 아니라 43ms 에서 26ms 로 적는다.

규칙6) 겁주지 않고 인과로 쓴다. 하면 안 된다가 아니라 하면 무엇이 어긋나는지 적는다.

## 이름과 링크

규칙1) 노트 이름은 볼트 안에서 유일하다. 링크가 폴더 없이 이름으로 가리킨다.

규칙2) 독스 노트 이름은 `독스 - 주제`, 규칙 노트 이름은 `규칙 - 주제` 로 시작한다.

규칙3) 링크는 `[표시](노트%20이름.md)` 로 쓴다. 공백은 `%20` 이다.

규칙4) 앵커를 쓰지 않는다. 절을 가리키려면 링크 뒤에 절 이름을 적는다.

규칙5) 없는 노트를 가리키지 않는다.

## 프론트매터

모든 노트는 첫 줄부터 프론트매터로 시작한다.

```
---
분류: <시작|기초|장르|UI|기능|규칙>
성격: <독스|규칙>
tags:
  - devunreal
  - <분류와 같은 값>
---
```

## 고칠 때

규칙1) 노트에는 지금 맞는 내용만 둔다. 무엇이 틀렸었는지는 적지 않는다. 옛 내용은 git 이 가진다.

규칙2) 한 사실은 한 노트에만 둔다. 다른 노트에서는 링크로 가리킨다.

규칙3) 두 노트가 어긋나면 바로 한쪽을 고친다. 목록으로 쌓지 않는다.
