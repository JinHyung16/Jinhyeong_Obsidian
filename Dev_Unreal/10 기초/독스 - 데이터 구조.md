# 독스 - 데이터 구조

언리얼에서 기획 수치를 어디에 적고 게임이 어떻게 읽는지 정리한다. 새 표를 만들거나 세이브를 손볼 때 편다.

## 핵심 아이디어

### 세 자리로 나눈다

| 자리 | 무엇 | 언리얼에서 |
|---|---|---|
| 적는 곳 | 사람이 고치는 값 | CSV 파일 |
| 굽는 곳 | 검사하고 변환 | DataTable 에셋으로 가져오기 |
| 읽는 곳 | 게임이 보는 값 | 런타임 그래프, 읽기 전용 |

읽는 곳에서 값을 고치면 그건 데이터가 아니라 세이브다. 둘을 섞으면 다음 빌드에서 값이 사라진다.

### 표 하나에 모든 것을 담지 않는다

스킬 트리를 예로 든다. 한 표에 다 담으면 아래가 막힌다.

| 담고 싶은 것 | 한 표로 하면 |
|---|---|
| 같은 스킬을 여러 자리에 놓기 | 정의를 복사해야 한다. 값 하나 고치려면 수십 행을 고친다 |
| 자리마다 따로 사기 | 한 자리를 사면 같은 이름이 전부 켜진다 |
| 두 자리를 선으로 잇기 | 어느 쪽 자리인지 가리킬 방법이 없다 |

그래서 표를 셋으로 나눈다.

```
정의   이 노드가 무엇을 주는가          체력 +1, 150골드, 최대 1레벨
 ^
배치   그 정의를 격자 어디에 놓았는가    #12 체력 @ (0, 3)
       #47 체력 @ (2, 6)
연결   어느 배치와 어느 배치를 잇는가    #12 - #13
```

정의는 하나, 배치는 여럿이다. 배치가 정의를 가리킨다.

### 저장하는 것과 계산하는 것

저장한다.

- 배치의 칸 좌표
- 어느 정의를 쓰는가
- 어느 배치와 이어지는가

저장하지 않는다. 계산한다.

- 두 노드 사이 거리. 좌표를 빼면 나온다
- 화면 픽셀 좌표. 줌과 이동이 만든다
- 부모가 누구인가. 이웃 목록이 이미 안다
- 선이 꺾이는 자리. 두 좌표와 방향으로 나온다

같은 사실을 두 곳에 저장하면 둘이 어긋난다. 어느 쪽이 맞는지는 사람만 기억한다.

### 세이브 키는 배치 번호다

| 키로 쓸 것 | 무슨 일이 나나 |
|---|---|
| 배열 순번 | 중간에 노드를 하나 끼우면 뒤가 전부 밀린다 |
| 정의 이름 | 같은 정의가 여러 자리에 있으면 한 자리를 사도 전부 켜진다 |
| 배치 번호 | 안전하다. 표를 고쳐도 남의 세이브가 안 밀린다 |

배치 번호는 한 번 정하면 바꾸지 않는다. 새 노드는 뒤 번호를 붙인다.

## 구조

### 행 구조체

DataTable 한 장은 `FTableRowBase` 를 상속한 구조체 하나를 쓴다.

```cpp
USTRUCT(BlueprintType)
struct FRollBallSkillPlacementRow : public FTableRowBase
{
    GENERATED_BODY()

    UPROPERTY(EditAnywhere, BlueprintReadOnly, Category = "배치")
    int32 PlacementId = 0;
};
```

CSV 첫 칸은 행 이름이다. 나머지 칸 이름은 `UPROPERTY` 이름과 글자까지 같아야 한다.

### 이름 짓기

| 값이 무엇이냐 | 이름 |
|---|---|
| 다른 표의 행을 가리킨다 | `대상RowName` |
| 파일이나 주소를 가리킨다 | `대상Path` |
| 종류를 나타내는 낱말이다 | `이름Type` |

`Code`, `Data`, `Value` 는 쓰지 않는다. 그 값이 무엇인지 하나도 말하지 않는다.

### 세이브

`USaveGame` 을 상속한 클래스 하나에 계정 상태를 전부 담는다. 읽고 쓰는 것은 `UGameplayStatics` 셋이다.

```cpp
UGameplayStatics::SaveGameToSlot(SaveData, SlotName, 0);
UGameplayStatics::LoadGameFromSlot(SlotName, 0);
UGameplayStatics::DeleteGameInSlot(SlotName, 0);
```

파일은 `Saved/SaveGames/<슬롯이름>.sav` 에 생긴다.

### 어디에 들고 있나

| 살아남는 범위 | 클래스 |
|---|---|
| 게임을 켜는 동안 계속 | `UGameInstance` |
| 레벨 하나 도는 동안 | `AGameModeBase` |
| 액터 하나 | 그 액터 |

계정, 골드, 스킬 레벨은 레벨을 넘나들어야 하므로 `UGameInstance` 에 둔다.

## 사용 방법

### CSV 를 DataTable 로 가져오기

1. 콘텐츠 브라우저에 CSV 를 끌어다 놓는다
2. 물어보는 창에서 행 구조체를 고른다
3. 값을 고친 뒤에는 에셋 우클릭 - Reimport

### 가져오기가 실패할 때

| 증상 | 원인 |
|---|---|
| 칸이 통째로 비었다 | CSV 칸 이름과 `UPROPERTY` 이름이 다르다 |
| 숫자가 0 이다 | 칸에 숫자가 아닌 것이 섞였다 |
| 열거형이 첫 값으로 들어갔다 | 이름이 열거형 값과 다르다. 대소문자도 본다 |
| 한글이 깨졌다 | CSV 가 UTF-8 이 아니다 |

### 읽기

```cpp
static const FString Context(TEXT("RollBallSkillGraph"));

const FRollBallSkillDefRow* Row =
    DefinitionTable->FindRow<FRollBallSkillDefRow>(RowName, Context, false);
```

마지막 인자가 `false` 면 행이 없어도 경고를 찍지 않는다. 없는 것을 직접 처리할 때 쓴다.

전체를 도는 것은 `GetAllRows` 다.

```cpp
TArray<FRollBallSkillPlacementRow*> Rows;
PlacementTable->GetAllRows(Context, Rows);
```

### 검사

문자열로 다른 표를 가리키는 값은 틀려도 가져오기가 통과한다. 그래서 만들 때 직접 검사한다.

| 무엇 | 검사 |
|---|---|
| 배치 | 가리키는 정의가 실제로 있는가 |
| 배치 | 시작점이 정확히 하나인가 |
| 배치 | 두 노드가 같은 칸에 겹치지 않는가 |
| 연결 | 양쪽 배치가 실제로 있는가 |
| 연결 | 자기 자신을 잇지 않는가 |
| 연결 | 같은 쌍이 두 번 있지 않은가 |

첫 오류에서 멈추지 않는다. 전부 모아 한 번에 찍는다. 하나 고치고 다시 돌리기를 반복하면 검사를 안 보게 된다.

## 함정

### 표를 손으로 만들면 좌표가 어긋난다

노드 80개의 좌표와 연결 번호를 손으로 적으면 반드시 틀린다. 겹친 칸과 끊어진 연결은 눈으로 안 보인다.

방향은 만드는 스크립트를 두는 것이다. `Tools/gen_skill_tables.py` 가 CSV 세 장을 만들고, 저장 직전에 위 검사를 돌린다.

### 열거형 키 맵은 uint8 이어야 한다

`TMap<열거형, float>` 을 `UPROPERTY` 로 쓰려면 열거형이 `uint8` 을 상속해야 한다.

```cpp
UENUM(BlueprintType)
enum class ERollBallSkillStat : uint8
```

안 그러면 빌드가 아니라 UHT 가 먼저 막는다.

### 상한은 데이터가 아니라 코드가 건다

체력 최대 7 같은 값을 CSV 에만 적으면, 노드를 하나 더 놓는 순간 8 이 된다.

값을 합친 뒤 코드에서 한 번 자른다. 그 자리가 한 곳뿐이면 어긋날 수 없다.

```cpp
case ERollBallSkillStat::MaxHealth: return FMath::Clamp(Amount, 1.0f, 7.0f);
```
