# 양식 - 아트 생성기

`build_<대상>.py` 아트 생성기 파일 하나의 뼈대와 블록 순서를 정하는 틀이다. 새 생성기를 짜거나 기존 생성기를 고칠 때, 생성 뒤 판정할 때 편다.

[역할 - 아트](역할%20-%20아트.md) 의 "임포트 규격" · "산출물은 숫자로 판정한다"의 양식이다.
그림은 게임마다 다르다. 뼈대는 같다 — 규격표 → 프리미티브 → 후처리 → 저장 → meta.
블록 순서는 그대로 두는 것이 기본이다. 이유: 순서가 다른 생성기는 다음 게임에서 복붙이 안 된다.

## 파일 하나의 순서

```python
[예시] build_<대상>.py
# ── 0. 헤더: 무엇을 만드나 · 규격 출처(스펙 아트 규격 절) · 사고 메모
# ── 1. 상수 블록 (규격표에서 온다. 즉석 값 없이)
DST        = "<Assets/_Art/…>"     # 출력 폴더. 파일명 규칙은 역할 - 아트 "에셋 이름"

S          = 4                      # 슈퍼샘플. 곡선을 S배로 그리고 마지막에 줄인다
PPU        = 32
OUTLINE_PX = 1                      # 실루엣 팽창 두께 — 그리는 외곽선은 없다
LIT_BANDS  = ((0, 26, 1.16), (26, 44, 1.0), (44, 64, 0.82))   # 명암 3단 (y 구간, 배율)
PALETTE    = {...}                  # 이름 → RGBA. 색은 여기만
# ── 2. 프리미티브 (게임 무관. 킷 후보)
def layer(w=W, h=H): ...            # 투명 캔버스 S배
def ell(d, cx, cy, rx, ry, color): ...
def rrect(d, x0, y0, x1, y1, r, color): ...
def poly(d, pts, color): ...
def line(d, x0, y0, x1, y1, w, color): ...
# ── 3. 후처리 (게임 무관. 순서도 고정)
def fin(src):     ...  # 실루엣 팽창 → 외곽. 레이어마다 따로 건다 (한 번에 씌우면 팔다리가 묻힌다)
def stack(layers): ... # 레이어 합성. 가까운 부위는 같은 레이어에 (나누면 이음새 선이 생긴다)
def lit(img):     ...  # LIT_BANDS 로 명암 3단
def ground(...):  ...  # 접지 그림자. 탑다운·쿼터뷰면 필수 — 없으면 떠 보인다
def render(shape, hollow): ...  # 이펙트용 3겹: 글로우 → 어두운 외곽 → 밝은 안쪽선
# ── 4. 데이터 정의 — 함수 사이에 두지 않는다 (함정 45: 구간 교체가 데이터를 지운다)
DOGS   = { 'shiba': {...}, ... }
ALIENS = { 'grunt': {...}, ... }
# ── 5. 그리기 — draw_<대상>(cfg, phase, bob, face)  방향·프레임은 인자로
def draw_dog(cfg, phase, bob, face='down'): ...
# ── 6. 저장 — 파일명은 키 규칙으로 조립한다. 손으로 적지 않는다
def save(img, kind, name, action, frame): ...   # f"{kind}_{name}_{action}{frame}.png" + ground() 여기서 일괄
# ── 7. 진입
if __name__ == '__main__':
    for name, cfg in DOGS.items():
        for face in ('down', 'up', 'side'):
            for i, (bob, phase) in enumerate(WALK): save(draw_dog(cfg, phase, bob, face), 'dog', name, f'{face}_walk', i)
```

4번 블록 주석의 함정 45 는 [함정 45](함정%20-%20작업%20방식.md) 다.

## 기본값과 이유

| 기본 | 왜 |
|---|---|
| 상수는 규격표(스펙 아트 규격 절)에서 가져오고, 값 옆에 어느 행인지 주석 | 즉석 값은 다음 게임에서 근거를 잃는다 |
| 외곽선은 그리지 않고 `fin()` 이 실루엣을 팽창시킨다 | 두께가 항상 일정. 레이어별로 걸어야 부위 분리선이 생긴다 |
| 걷기는 몸통 상하 이동이 있고, 4프레임이면 포즈가 4개 | 1 · 3번이 같으면 포즈는 셋. 바운스가 없으면 미끄러진다 |
| 접지 그림자는 `save()` 에서 이름으로 일괄 | 호출부가 방향별로 여럿이라 한 곳만 빠지면 그 방향만 떠 보인다 |
| 이펙트는 흰색으로만 | 색은 데이터가 런타임에 틴트한다 |
| 반경 있는 연출은 판정 크기 그대로 | 부풀리면 사거리를 오인한다 |
| 데이터 정의(`DOGS` `ALIENS`)는 파일 위쪽 한 블록 | 함수 구간 교체가 데이터를 같이 지운 사고가 있었다 |
| 치환은 파일로 쓴 스크립트로 한다. 따옴표가 들어가면 인라인 `python -c` 를 쓰지 않는다 | 셸이 끊어 깨진 코드를 뿌린 사고가 있었다 |
| 마지막 줄 `[<스크립트>] N장` | 다음 단계(`build_meta.py`)가 이 개수로 대조한다 |

## 그 다음 — `build_meta.py`

생성기 다음에는 `build_meta.py` 를 이어 돌린다. 이유: `.meta` 가 없으면 GUID 가 새로 잡혀 프리팹 참조가 끊긴다.

```
python _DataExporter/tools/build_<대상>.py   →   python _DataExporter/tools/build_meta.py
```

- GUID 는 경로 md5 로 고정한다.
- `build_meta.py` 는 `.meta` 를 통째로 덮어쓴다. 그래서 9슬라이스 경계(`spriteBorder`)가 있는 UI 폴더는 대상에서 뺀다.
- 피벗은 접두어로 정한다 (`dog_` `alien_` → 발밑). 새 종류를 만들면 `FOOT_PIVOT_PREFIX` 에 한 줄.

## 판정 — 생성 직후가 아니라 플레이 캡처에서

[역할 - 아트](역할%20-%20아트.md) "셀 수 있는 것 넷" — 외곽선 비중 · 실루엣 폭 굴곡 · 접지 그림자 픽셀 · 명암 단수.
기본은 [단계 5 - 클라](단계%205%20-%20클라.md) 첫 실측 캡처가 나온 뒤 레퍼와 같은 방법으로 재는 것이다. 이유: 생성기 출력 PNG 는 게임 화면이 아니라서, 그것만 보고 "됐다"고 하면 실제 화면에서의 모습을 판정하지 못한다.
