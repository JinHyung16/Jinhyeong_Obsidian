# 함정 - 작업 방식

편집 범위·외부 확인·질문·병렬 분담·분석 재료처럼 일하는 방식이 틀려 데이터를 잃거나 잘못 보고하거나 작업을 되돌린 사고다. 파일 구간을 통째로 바꿀 때, 외부 패키지를 확인할 때, 사람에게 묻거나 작업을 나눌 때, 분석을 맡길 때 편다.

### 구간 일괄 교체가 그 안의 데이터 정의를 지운다
번호: 함정 45
- 증상: 함수 구간을 갈아 끼웠더니 그 사이에 있던 설정 딕셔너리·상수 표가 같이 사라졌다.
- 원인: "함수 A 부터 함수 B 직전까지"를 통째로 갈아 끼우며, 그 사이에 함수만 있는 줄 알았다.
- 방향: 기본은 구간을 교체하기 전에 그 구간 안에 무엇이 있는지 먼저 출력해 보는 것이다. 그리고 생성기·데이터가 사는 폴더는 git 추적 안에 둔다 — 추적 밖이면 실수 한 번이 곧 소실이다. [원칙](Dev_Unity%20원칙.md)
- 관련: [양식 - 아트 생성기](양식%20-%20아트%20생성기.md)

[사고] 캐릭터 그리기 함수 셋을 교체하면서 그 사이에 있던 적 설정 딕셔너리를 같이 지웠다. git 추적 밖이라 되돌릴 수 없어, 남아 있던 스프라이트에서 색·크기·눈 수를 역산해 복원했다. 같은 세션에서 산출물 목록(`SETS`)도 같은 방식으로 한 번 더 날렸다.

### 외부 패키지를 태그 대신 커밋 해시로 확인한다
번호: 함정 54
- 증상: 외부 패키지가 깨졌다고 판단했는데 아니었다.
- 원인: 태그는 다른 커밋으로 옮겨질 수 있다. 해시로 고정해 확인하면 태그가 옮겨진 뒤에도 옛 커밋을 잰다.
- 방향: 기본은 릴리스 페이지, README 설치 URL, 태그 이름 순서로 확인하는 것이다. 결과가 이상하면 보고 전에 릴리스 페이지를 다시 본다. [원칙](Dev_Unity%20원칙.md)
- 관련: [규약 - 패키지](규약%20-%20패키지.md)

[사고] 태그를 고친 커밋으로 옮기는 사이 옛 커밋을 재서 "패키지가 깨졌다"고 잘못 보고했다.

### 판단이 다른 질문 둘을 한 번에 물었다
번호: 함정 61
- 증상: 승낙을 받았는데 원하지 않은 작업이 됐다.
- 원인: 질문 둘을 한 문단에 묶으면 짧은 승낙이 어느 쪽에 대한 답인지 알 수 없다.
- 방향: 기본은 판단 축이 다르면 질문을 나누는 것이다. [원칙](Dev_Unity%20원칙.md)
- 관련: [역할 - PD](역할%20-%20PD.md)

[사고] 두 가지를 묶어 묻고 한 줄 승낙을 둘 다에 대한 답으로 읽었다. 하나만 원한 것이라 나머지를 되돌렸다.

### 파트별로 이음매까지 나눠 동시에 구현했다
번호: 함정 63
- 증상: 병렬 구현 뒤 연결 부분에서만 버그가 난다.
- 원인: 각 파트가 자기 영역만 보면 파트 사이의 연결에는 담당자가 없다. 버그는 대부분 연결에서 난다.
- 방향: 기본은 병렬을 분석 단계에서만 하고, 구현은 계약(스키마, 바인딩)을 먼저 정한 뒤에 겹치는 것이다.
- 관련: [역할 - PD](역할%20-%20PD.md) 트랙 절 · [단계 1 - 설계](단계%201%20-%20설계.md)

[사고] 동시에 구현한 뒤 난 버그가 전부 초기화 순서, 로드 순서, 삭제 잔재 같은 연결 문제였다.

### 재료 없이 분석하거나 출처를 확인하지 않았다
번호: 함정 64
- 증상: 분석 결과가 일반론이거나 다른 게임 이야기다.
- 원인: 분석하는 쪽은 레퍼런스를 직접 플레이할 수 없다. 재료가 없으면 일반론이 나오고, 출처를 안 보면 다른 게임을 분석한다.
- 방향: 기본은 재료를 확인한 것만 넘기고, 제목·개발사·플랫폼·출시 연도로 출처를 먼저 검증하는 것이다.
- 관련: [레퍼런스 해부](레퍼런스%20해부.md) · [함정 65](함정%20-%20판단%20검증.md)

[사고] 텍스트만 주고 분석을 시켰더니 절반이 일반론이었고, 웹 검색이 이름이 같은 다른 게임 문서를 가져왔다.
