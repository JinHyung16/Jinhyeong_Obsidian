# 함정 - 에셋 반입

에셋을 넣거나 옮기거나 지우거나 바꿀 때 임포트 설정·주소·참조·표현 전제가 따라오지 않아 조용히 깨진 사고다. 외부 팩을 반입할 때, 에셋을 이동·삭제·교체할 때, 3D 에서 2D 로 옮길 때, 넣은 그림이 안 보이거나 이상할 때 편다.

## 들여올 때

### 에셋 팩의 데모 스크립트
번호: 함정 11
- 증상: 에셋을 넣었더니 오브젝트가 멋대로 사라지거나 버그가 난다.
- 원인: 팩 프리팹 전수에 "키 입력 시 자기 Destroy" 데모 스크립트가 붙어 있었다. 반입했으면 플레이 중 키 하나에 풀 소속 오브젝트가 증발했다.
- 방향: 기본은 반입 절차(인벤토리 → 참조 감사 → 스크립트 판정 → 제거 → 주소 → 검증)를 순서대로 밟는 것이다. 아트 프리팹 스크립트 0 규칙으로 상시 검출할 수 있다.
- 관련: [역할 - 아트](역할%20-%20아트.md) 반입 절차 절 · [규약 - 프리팹](규약%20-%20프리팹.md) 아트 프리팹에는 스크립트 0개 절

### 루프 꺼진 클립
번호: 함정 16
- 증상: 걷다가 다리가 멈춘다. 애니가 마지막 프레임에 굳는다. 컨트롤러·파라미터·코드는 전부 정상이라 엉뚱한 곳을 뒤지게 된다.
- 원인: 에셋 팩 클립은 `Loop Time` 이 꺼진 채 오는 경우가 많다. 0.5초짜리 런 클립이 한 번 돌고 마지막 프레임에 굳었다.
- 방향: 기본은 반입 체크리스트에 "이동·대기 클립 isLooping" 항목을 두는 것이다. 검출은 `normalizedTime` 이 1을 넘어 계속 증가하는지 본다.
- 관련: [역할 - 아트](역할%20-%20아트.md) 반입 절차 절

### 에셋을 넣는 것과 쓸 수 있게 들어오는 것은 다르다
번호: 함정 51
- 증상: 넣은 이미지가 코드에서 null 로 온다.
- 원인: 파일을 프로젝트에 복사하면 들어간 것 같지만, 엔진이 그것을 무엇으로 읽었는지는 별개다. 임포트 설정이 기본값이면 그림은 그냥 텍스처이고, 스프라이트를 요구하는 코드에는 null 로 온다.
- 방향: 기본은 에셋을 만드는 도구가 .meta 도 같이 만드는 것이다. 손으로 넣었으면 임포트 타입을 확인한다. 안 보이는 그림은 그리기보다 로드를 먼저 의심한다 — 로드 실패는 대개 로그에 이미 적혀 있다.
  - .meta 를 일괄 생성하는 도구는 기존 설정을 통째로 덮어쓴다. 9슬라이스 경계·피벗처럼 손으로 맞춘 값이 있는 폴더는 대상에서 빼고, 새로 굽는 폴더만 콕 집어 넣는다.
- 관련: [양식 - 아트 생성기](양식%20-%20아트%20생성기.md) · [함정 50](함정%20-%20UI%20표시.md) · [함정 43](함정%20-%20판단%20검증.md)

[사고] 아이콘 27장을 굽고 Resources 에 넣었는데 화면에 하나도 안 떴다. `textureType` 이 Default(0) 로 들어와 `Resources.Load<Sprite>` 가 전부 null 이었다. 로그에는 경고가 27줄 찍혀 있었지만 "그림이 안 보인다"만 보고 그리기 코드를 먼저 뒤졌다.

## 옮기고 지우고 바꿀 때

### 하드코딩 경로 + 에셋 이동
번호: 함정 13
- 증상: 폴더 옮긴 뒤 빌더가 사본을 만든다. 참조가 이상하다.
- 원인: 빌더가 옛 경로에 폴더를 새로 만들고 프리팹을 새 GUID 로 복제했다. Addressable 이 사본을 가리키고 원본은 고아가 되는 조용한 분기다. 이동 자체는 에디터 안이라면 GUID 가 보존되어 무해하다.
- 방향: 기본은 빌더가 기존 산출물을 검색해 폴더를 따라가게 하는 것이다. 프리팹 재생성은 덮어쓰기(GUID 유지)로 한다. 삭제할 때는 Addressable 고아 엔트리를 같이 청소한다.
- 관련: [함정 20](함정%20-%20에셋%20반입.md) · [함정 21](함정%20-%20에셋%20반입.md)

### 지운 에셋·스크립트의 잔재가 저장을 막는다
번호: 함정 20
- 증상: 삭제한 스크립트·에셋 때문에 프리팹 저장이 거부된다. 빌더가 조용히 실패해, 로그를 안 보면 성공처럼 보인다.
- 원인: 참조하던 스크립트나 중첩 프리팹을 지우면 그걸 물고 있던 프리팹은 missing 상태로 남고, 엔진이 그 상태의 프리팹 저장을 거부한다.
- 방향: 기본은 에셋을 지우는 작업의 완료 조건에 참조처 청소를 포함하는 것이다. 빌더는 저장 전에 missing 컴포넌트·깨진 중첩 인스턴스를 제거하는 단계를 둔다.
- 관련: [함정 13](함정%20-%20에셋%20반입.md) · [규약 - 프리팹](규약%20-%20프리팹.md)

### 주소 중복 — 옛 에셋과 새 에셋이 같은 키를 문다
번호: 함정 21
- 증상: 같은 주소로 두 에셋이 등록돼 어느 쪽이 로드될지 모른다. 되는 날과 안 되는 날이 갈린다.
- 원인: 교체 작업에서 새 에셋을 같은 주소로 등록하고 옛 등록을 지우지 않았다.
- 방향: 기본은 교체를 "등록 → 옛 항목 제거" 한 세트로 하는 것이다. 빌드 뒤 주소 중복 검사를 돌린다 (주소별 개수를 세어 2 이상이면 실패).
- 관련: [함정 13](함정%20-%20에셋%20반입.md) · [역할 - 아트](역할%20-%20아트.md) 폴더링 절 · 로드 등록 절

## 3D 에서 2D 로 옮길 때

### 3D 시절 색 보정이 2D 스프라이트에서 형체를 지운다
번호: 함정 27
- 증상: 3D 때 쓰던 색 보정이 2D 에서 형체를 지운다. 특수 개체가 검은 실루엣이 되어 무엇인지 알아볼 수 없다.
- 원인: 특수 개체를 "어둡게 곱해서" 구분하던 관례를 색을 이미 가진 스프라이트에 그대로 썼다. 흰 모델을 전제한 값이었다.
- 방향: 기본은 2D 전환 시 곱연산 틴트 값을 전부 재검토하는 것이다. 스프라이트는 어둡게가 아니라 밝게·뜨겁게 물들여야 형태가 남는다.
- 관련: [역할 - 아트](역할%20-%20아트.md)

### 타일맵 스위즐은 위치만 바꾼다 — 스프라이트는 안 눕는다
번호: 함정 28
- 증상: 타일맵이 줄무늬로 보이고 타일 사이로 배경이 비친다. 증상이 "타일 색 변형이 이상하다"로 읽혀 해시·색·셀 크기를 차례로 의심하느라 시간을 버렸다.
- 원인: 월드가 XZ 평면이라 Grid 의 셀 스위즐을 XZY 로 두고 타일을 깔았더니, 위치는 XZ 로 갔는데 타일 스프라이트는 여전히 세로로 선 채였다. 비스듬한 카메라에서 줄지어 선 카드처럼 보이고 그 틈으로 배경이 비쳤다.
- 방향: 기본은 스위즐이 셀 좌표 → 로컬 위치 변환만 건드린다는 것을 전제로, 스프라이트를 눕히려면 Grid 트랜스폼을 회전시키는 것이다. 회전하면 셀 축과 월드 축의 부호가 어긋나므로 타일을 놓는 쪽에서 부호를 맞춘다. 검출은 화면 픽셀을 세로로 훑어 배경색이 주기적으로 나타나는지 보는 것이다. 주기가 셀 크기의 화면 투영값과 같으면 "덮이지 않은 틈"이지 색 문제가 아니다.
- 관련: [규약 - 뷰](규약%20-%20뷰.md)
