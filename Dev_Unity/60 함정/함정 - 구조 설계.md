# 함정 - 구조 설계

판정·조건·규약을 한 곳에 모으지 않고 흩거나 문서로만 두어, 빠진 자리나 어긋난 순간이 조용히 남은 사고다. 같은 판정을 여러 경로가 쓸 때, 퇴화 입력을 처리할 때, 등록과 실행 조건을 나눌 때, 규약을 새로 정할 때 편다.

### 같은 판정을 여러 자리에 흩어 두면 검사를 안 한 자리가 남는다
번호: 함정 47
- 증상: 절차 생성물이 서로 겹쳐 찍힌다. 고쳐도 다른 자리에서 재발한다.
- 원인: 무언가를 놓기 전에 "이 자리가 비었나"를 확인해야 하는데, 놓는 코드가 여러 군데라 그중 일부에만 검사가 붙었다. 검사가 붙은 자리만 보고 "막았다"고 판단했다.
- 방향: 기본은 판정을 함수 하나로 모으고, 놓는 경로를 세어 전부 그 함수를 거치는지 확인하는 것이다. "몇 군데에서 만드나"를 먼저 답할 수 없으면 아직 고칠 준비가 안 된 것이다.
- 관련: [함정 29](함정%20-%20전투%20규칙.md) · [함정 39](함정%20-%20전투%20규칙.md)

[사고] 절차 생성 트리에서 노드를 만드는 자리가 넷이었다(성단 중심 · 성단 잎 · 길 · 가지 끝). 겹침을 막는 검사를 둘에만 붙였고, 남은 둘이 "거리 0" 겹침을 냈다. 한 곳을 고칠 때마다 다른 곳이 같은 증상을 다시 냈고, 그때마다 원인을 새로 찾았다.

### "값을 못 구하는 경우"를 "처리할 필요 없는 경우"로 셈
번호: 함정 48
- 증상: 퇴화 입력(길이 0 · 방향 없음)에서 조용히 아무 일도 안 일어난다.
- 원인: 방향·거리·비율 같은 것을 구하다 0 으로 나눌 상황이 오면 `return` 으로 빠져나갔다. 그런데 그 자리는 대개 가장 처리가 필요한 자리다 — 값이 퇴화했다는 것 자체가 이상 상황이다.
- 방향: 기본은 퇴화 입력에서 빠져나가기 전에 "지금 안 하면 무엇이 잘못되나"를 한 줄로 답하는 것이다. 답이 "아무 일도 안 일어난다"가 아니면 기본 방향·기본값을 정해 하던 일을 마친다.
- 관련: [함정 47](함정%20-%20구조%20설계.md)

[사고] "길 위에 노드를 비켜 세우는" 함수가 길이가 0 인 길에서 방향을 못 구해 그냥 빠져나갔다. 그 결과 노드가 비키지 못하고 기존 노드 위에 그대로 앉았다. 길이가 0 인 길은 양 끝이 이미 같은 자리라는 뜻이라, 정확히 비켜서야 하는 경우였다.

### 조건을 두 곳에 나눠 걸면 둘이 어긋난 순간을 아무도 못 잡는다
번호: 함정 49
- 증상: 요청을 넣어도 하네스가 반응 없이 시간만 초과한다. 아무 에러도 없이 그냥 아무 일도 안 일어난다.
- 원인: "이럴 때만 등록한다"와 "등록됐으면 이럴 때만 실행한다"를 따로 두어, 등록 시점의 상태와 실행 시점의 상태가 어긋나는 판이 생겼다.
- 방향: 기본은 등록은 항상 하고, 빠지는 판단은 실행되는 함수 안에서 하는 것이다. 조건이 한 곳에만 있으면 어긋날 자리가 없다.
- 관련: [양식 - 하네스](양식%20-%20하네스.md) · [함정 25](함정%20-%20에디터%20자동화.md) · [함정 26](함정%20-%20에디터%20자동화.md)

[사고] 검증 하네스가 요청 감시를 "플레이 중이 아닐 때만" 등록했다. 도메인 리로드가 다른 하네스의 플레이 종료와 겹친 판에서 감시자가 아예 안 붙었고, 그 뒤로 요청 파일을 넣어도 조용히 시간만 초과했다. 하네스가 죽었다는 사실을 알려 주는 것이 아무것도 없었다.

### 규약 문서만 있고 베이스 클래스가 없다
번호: 함정 66
- 증상: 규약이 있는데 구현이 제각각이다.
- 원인: 문서로만 정한 규약은 지켜지지 않는다. 구현하는 사람이 자기 방식대로 만든다.
- 방향: 기본은 규약을 상속으로 강제하는 것이다. 문서보다 베이스 클래스가 먼저다.
- 관련: [규약 - UI](규약%20-%20UI.md)

[사고] UI 규약이 문서에만 있어 첫 화면이 Awake 에서 화면 전부를 코드로 그렸고, 프리팹은 빈 껍데기였다.
