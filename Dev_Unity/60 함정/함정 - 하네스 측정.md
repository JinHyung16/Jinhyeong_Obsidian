# 함정 - 하네스 측정

게임이 아니라 하네스·측정 방식이 틀려 "0"이나 엉뚱한 수치가 게임 결함처럼 보고된 사고다. 하네스를 짜거나 고칠 때, 측정 결과로 수치·코드를 고치기 전에, 결과 숫자가 이상할 때 편다.

## 측정이 무효인 줄 모름

### timeScale=0 게이트 위에서 잰 실측
번호: 함정 4
- 증상: 하네스가 0 만 보고한다. "피해 전부 0"이 정상 결과처럼 보고됐고, 동기 실행 항목 하나만 값이 나와 더 헷갈렸다.
- 원인: 시작 화면 게이트가 `timeScale=0` 으로 잡고 있는 줄 모르고 측정했다.
- 방향: 기본은 하네스에 워치독을 두는 것이다 — 경과 프레임·게임 시간을 병기하고, 안 흐르면 "무효"로 보고한다.
- 관련: [역할 - 클라](역할%20-%20클라.md) · [역할 - PD](역할%20-%20PD.md)

### 측정이 도는 동안 스크립트를 고치면 그 측정이 통째로 날아간다
번호: 함정 38
- 증상: 예상 종료 시각이 지나도 리포트가 없다. 14분짜리 측정이 통째로 버려진다. 남는 흔적은 오래된 `.active` 파일 하나뿐이라 원인도 안 보인다.
- 원인: 플레이 측정을 백그라운드로 돌려놓고 그 시간에 다른 코드를 편집했다. 에디터가 포커스를 얻는 순간 컴파일 → 도메인 리로드가 나고, 하네스의 정적 상태가 사라져 리포트가 영영 안 나온다. 함정 33 과 같은 뿌리(도메인 리로드)지만 이쪽은 "내가 스스로 유발한다"는 점이 다르다.
- 방향: 기본은 측정이 도는 동안 에디터가 읽는 파일(.cs/에셋)을 건드리지 않는 것이다. 그 시간에는 문서·데이터 생성기·파이썬 아트처럼 유니티 밖 작업만 한다. 검출은 예상 종료 시각이 지나도 리포트가 없고 `.active` 의 시각이 런 시작 때 그대로면 죽은 것으로 보는 것이다.
- 관련: [함정 33](함정%20-%20에디터%20자동화.md) · [양식 - 하네스](양식%20-%20하네스.md)

### 촬영이 결과 표시보다 먼저 일어난다
번호: 함정 53
- 증상: 결과 화면 캡처가 기대와 다르다. 이전 화면이 들어간다.
- 원인: 판정하려고 찍은 캡처가 화면 전환보다 앞서 찍혔다.
- 방향: 기본은 캡처 파일명에 시점을 넣고, 판정 대상이 표시된 뒤에 찍는 것이다. 값이 이상하면 수치보다 촬영 시점을 먼저 본다.
- 관련: [함정 43](함정%20-%20판단%20검증.md)

[사고] 결과 화면 딤이 안 먹는다고 알파를 올렸는데, 실제로는 런 종료 전에 찍어 결과 화면을 한 번도 본 적이 없었다.

## 하네스가 게임을 다르게 돌림

### 하네스가 트리거의 원천을 끈다
번호: 함정 18
- 증상: 하네스에선 0킬인데 손으로 하면 된다. 하네스 결과(0킬)가 게임의 결함처럼 보인다.
- 원인: 이동을 직접 조종하려고 `PlayerController` 를 껐더니 그 안의 자동공격이 같이 죽어 OnAttack 트리거 스킬이 전부 침묵했다.
- 방향: 기본은 컴포넌트를 끄지 않고 입력원만 바꿔 끼우는 것이다 (`IInputProvider` 주입). 하네스 첫 표본에 킬이 0 이면 하네스부터 의심한다.
- 관련: [규약 - 플랫폼](규약%20-%20플랫폼.md) · [함정 22](함정%20-%20비동기%20로드.md)

### 자동 조작이 회피를 안 하면 밸런스 실측 전체가 무효다
번호: 함정 34
- 증상: 라운드별 HP% 표에서 곡선이 계단처럼 뚝 끊긴다. 그 수치로 라운드 곡선을 낮추면 실제 플레이어에겐 한없이 쉬운 게임이 된다.
- 원인: 하네스 플레이어가 "가장 가까운 아이템으로 직진"만 했다. 경험치 젬은 적 시체 위에 떨어지므로, 그 조작은 매번 적 무리 한가운데로 걸어 들어가는 것이었다. 주울 게 없으면 제자리에 섰다.
- 방향: 기본은 자동 조작에 그 장르의 기본 생존 행동을 넣는 것이다. 뱀서류라면 목표 방향 + 근접 적 반발 벡터의 합성이면 충분하다. 정지는 곧 죽음이라 목표가 없어도 움직인다. 검출은 곡선이 계단처럼 끊기면 데이터를 만지기 전에 조작이 그 상황에서 무엇을 하는지 먼저 보는 것이다.
- 관련: [양식 - 하네스](양식%20-%20하네스.md) · [장르 문법 - 서바이버](장르%20문법%20-%20서바이버.md)

[사고] 같은 데이터에서 회피 없이는 라운드 5(275초) 사망, 회피를 넣으니 12라운드 완주였다. 회피 유무가 곡선 절반을 갈랐다.

### 하네스가 옛 콘텐츠 id 를 하드코딩한다
번호: 함정 52
- 증상: 게임은 멀쩡한데 하네스만 0 을 보고한다.
- 원인: 시스템을 바꿔 콘텐츠 id 가 달라졌는데 하네스는 옛 id 를 들고 있었다.
- 방향: 기본은 하네스가 참조하는 id 를 한곳에 모으는 것이다. id 를 바꾸는 작업의 완료 조건에 하네스 갱신을 넣는다.
- 관련: [양식 - 하네스](양식%20-%20하네스.md)

[사고] 스킬 체계를 바꾼 뒤 하네스가 옛 스킬 id 로 장착해 킬 0 이 나왔다.

## 리포트가 원인을 가르지 못함

### 리포트에 진단 항목이 없다
번호: 함정 55
- 증상: 결과 숫자 하나로 원인을 못 찾는다.
- 원인: "킬 0" 같은 결과 숫자 하나로는 원인이 여러 갈래다. 스폰, 부착, 팀 판정, 테이블 로드 중 어디인지 모른다.
- 방향: 기본은 리포트에 판정에 필요한 상태를 같이 찍는 것이다.
- 관련: [단계 1 - 설계](단계%201%20-%20설계.md) 진단 항목 · [단계 5 - 클라](단계%205%20-%20클라.md) · [함정 36](함정%20-%20데이터%20설계.md)

[사고] 결과 숫자만 보고 원인을 세 번 잘못 짚었다. 진단 항목을 넣자 한 번에 잡혔다.

### 경로 검증과 밸런스를 한 측정에 섞는다
번호: 함정 56
- 증상: 결과 숫자 하나로 원인을 못 찾는다. 킬 0 이 피해 경로 문제인지 밸런스 문제인지 갈리지 않는다.
- 원인: "피해가 들어가는가"와 "버틸 수 있는가"는 다른 질문인데, 죽을 수 있는 상태로 경로를 재서 일찍 죽어 결과가 비었다.
- 방향: 기본은 경로 검증은 무적으로, 밸런스는 별도 시나리오로 재는 것이다. 리포트에 어느 쪽인지 적는다.
- 관련: [역할 - 클라](역할%20-%20클라.md) · [단계 1 - 설계](단계%201%20-%20설계.md)

[사고] 시작 3초에 죽어 킬 0 이 나왔고, 피해 경로 문제인지 밸런스 문제인지 판단할 수 없었다.
