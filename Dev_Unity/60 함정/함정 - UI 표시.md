# 함정 - UI 표시

UI 가 그려질 전제(글리프·스프라이트·9슬라이스 경계·기준 해상도)를 확인하지 않아 조용히 빈칸이 되거나 뭉개지거나 크기가 어긋난 사고다. 폰트·게이지·패널 스프라이트를 넣을 때, 기준 해상도를 바꿀 때, UI 가 캡처에서 이상하게 보일 때 편다.

### CJK 글리프 없는 기본 폰트
번호: 함정 10
- 증상: 글자가 □□□ 로 뜬다.
- 원인: TMP 기본 폰트(라틴)만 믿고 한글을 넣었다.
- 방향: 기본은 CJK 를 Dynamic 폰트 에셋으로 만들고 TMP Settings 기본으로 지정하는 것이다. 검증은 스크린샷으로 한다.
- 관련: [역할 - 아트](역할%20-%20아트.md) 폰트 · [단계 4 - UI](단계%204%20-%20UI.md)

### Filled 이미지에 스프라이트 없음
번호: 함정 12
- 증상: 게이지(fillAmount)가 안 그려진다. 조용히 빈칸이다.
- 원인: `Image.type=Filled` + `fillAmount` 는 스프라이트가 있어야 그려진다.
- 방향: 기본은 코드 생성 UI 에도 절차 생성 흰 스프라이트라도 꽂는 것이다.
- 관련: [규약 - UI](규약%20-%20UI.md)

### 받은 리소스의 9슬라이스 경계를 확인 없이 믿는다
번호: 함정 50
- 증상: 9슬라이스가 안 먹고 모서리가 알약처럼 뭉갠다.
- 원인: `.meta` 에 `spriteBorder` 가 들어 있으면 맞게 잡혀 있다고 여겼다. 경계는 아트를 그린 사람이 아니라 임포트 설정을 만진 사람이 넣은 값이고, 자주 대충 들어가 있다 — 흔한 것이 "스프라이트 절반"이다. 경계가 스프라이트 절반이면 늘어나는 가운데가 없다. 9슬라이스를 걸어도 크기 고정 그림처럼 동작하고, 작은 위젯에서는 모서리끼리 겹쳐 알약이 된다.
- 방향: 기본은 경계를 재는 것이다. 알파를 훑어 가운데를 지나는 서로 같은 줄의 최대 구간을 찾으면 그 구간이 곧 늘어나도 되는 자리이고, 그 바깥이 경계다 (아래 식).
  - 원·아이콘처럼 늘리면 안 되는 모양은 9슬라이스 대상이 아니다. 가운데가 늘어나 원이 캡슐이 된다.
  - 경계 두께는 코드에 상수로 적지 않고 스프라이트에서 읽는다. 상수로 두면 임포트 설정을 고쳤을 때 조용히 어긋난다.
  - meta 를 고쳤다고 반영된 것이 아니다. 리임포트가 돌아야 바뀐다. 굽는 자리에서 실제 값을 로그로 찍어 두면 "고쳤는데 왜 그대로냐"를 추측하지 않아도 된다.
- 관련: [단계 4 - UI](단계%204%20-%20UI.md) · [양식 - UI 프리팹](양식%20-%20UI%20프리팹.md) · [함정 51](함정%20-%20에셋%20반입.md)

```
가로 경계 = 가운데 열과 같은 열이 이어지는 구간의 시작 / (폭 − 끝)
세로 경계 = 같은 방식으로 행에 대해
```

[사고] 128px 스프라이트에 경계가 63px 로 잡혀 있었다(실제 모서리는 15px). 가운데가 2px 라 늘어나지 않았고, 높이 44px 버튼에서 모서리 반지름이 63px 가 됐다. 그걸 배율을 6~12배로 올려 가렸는데, 그건 모서리 아트를 1/8 로 우겨넣는 것이라 곡률이 뭉개진다.

### 기준 해상도를 바꾸고 크기 표는 그대로 뒀다
번호: 함정 62
- 증상: 해상도를 바꿨더니 UI 크기가 전부 어긋났다.
- 원인: 글자와 여백 크기는 기준 해상도에 대한 픽셀값이다. 기준만 바꾸면 상대 크기가 전부 바뀐다.
- 방향: 기본은 기준 해상도를 바꾸는 작업에 크기 표 갱신을 포함하는 것이다. 크기 값은 한 곳에 둔다.
- 관련: [규약 - UI](규약%20-%20UI.md) 텍스트 크기 절 · [규약 - 플랫폼](규약%20-%20플랫폼.md)

[사고] 기준 해상도를 세로형에서 가로형으로 바꾸고 표를 그대로 둬 글자가 약 2.7배로 커졌다.
