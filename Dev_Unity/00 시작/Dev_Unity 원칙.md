# Dev_Unity 원칙

이 폴더의 노트는 대부분 방향이다. 기본값과 이유를 주고, 에이전트가 기획서 · 장르 · 규모를 보고 더 나은 선택을 고른다.
여기 있는 것만 판단 대상이 아니다. 어기면 결과가 거짓이 되거나, 되돌릴 수 없거나, 사람이 정한 것을 뒤집는다.

다른 노트는 원칙 문장을 반복하지 않고 `[원칙 D1](Dev_Unity%20원칙.md)` 처럼 링크한다.

## 방향을 쓰는 법

- 방향 노트의 기본값은 출발점이다. 더 나은 선택이 보이면 고른다.
- 기본값에서 벗어났으면 스펙 추정 절에 한 행으로 남긴다: 무엇을 · 왜 · 틀리면 되돌리는 비용. 사람에게 되묻지 않고 진행한다 ([개발 러너](개발%20러너.md) 빈칸을 채우는 순서).
- 멈추고 사람에게 묻는 경우는 둘이다. 원칙끼리 부딪힐 때, 원칙을 지키면 결과가 분명히 나빠질 때.
- 노트끼리 기본값이 어긋나면 더 구체적인 노트(양식 > 규약 > 역할 > 러너)를 따르고, 어긋남을 큐에 한 줄 남긴다.

## 판정

### D1
완료는 돌려서 잰 것만이다. "구현했다 · 호출했다 · 파일이 있다"는 완료가 아니다. 미측정은 통과가 아니고, 못 잰 것은 `미측정(사유)` 로 적는다.

### D2
지어내지 않는다. 출처 없는 값을 사실처럼 쓰지 않는다. 빈칸을 추정으로 채우는 것은 되지만, 추정은 추정으로 표시하고 출처와 되돌림 비용을 남긴다.

### D3
사람이 확정한 것은 에이전트의 판단이나 측정보다 위다. 측정이 확정과 다르면 알리고 확정을 따른다.

## 보고

### D4
보고는 사실대로 한다. "완료"는 조건이 전부 참일 때만 말하고, 아니면 남은 목록을 낸다. 실패를 조용히 넘기지 않는다. 기록은 덮어쓰지 않고 정정을 남긴다.

## 되돌릴 수 없는 것

### D5
프로젝트 진입 파일이 보호 경로로 적은 곳은 명시적 요청 없이 건드리지 않는다. git 밖에 있는 폴더의 구간을 통째로 바꾸기 전에는 그 안에 무엇이 있는지 먼저 본다.

### D6
이 프로젝트가 아닌 저장소(사람의 프레임워크 · 패키지 저장소 포함)는 클론 · 브랜치 · 커밋 · 파일 수정을 하지 않는다. 그쪽 작업이 필요하면 사람에게 요청하고, 기다리는 일은 큐 대기 절에 둔다. 공개 릴리스 페이지와 README 를 보는 것은 D7 확인에 한해 된다.

### D7
외부 패키지 버전은 릴리스 페이지 → README Install 절의 URL → 태그 이름 순서로 확인한다. 커밋 해시로 고정하거나 해시로 확인하지 않는다. 버전 올리기 · 새 태그를 에이전트가 제안하지 않는다. 결과가 이상하면 보고하기 전에 릴리스 페이지를 다시 본다.

### D8
git 커밋 · 브랜치 · 푸시는 사람이 시킨 범위만 한다.

### D9
프로세스는 이 프로젝트의 것으로 가려낸 PID 로만 끈다. 이름으로 일괄 종료하지 않는다. 사람이 쓰는 에디터를 저장 없이 끄지 않는다.

## 우선순위

### D10
프로젝트 진입 파일(`CLAUDE.md` 등)이 이 볼트와 어긋나면 진입 파일이 우선한다. 어긋남은 보고에 적는다.
