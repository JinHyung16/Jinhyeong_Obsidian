# 규약 - 뷰

뷰 · 카메라 · 좌표계 · 정렬의 기본 구조를 정하는 노트다. 착수 질문에서 뷰를 확정할 때, 스폰 · 정렬 · 카메라 · 월드 UI 를 만들기 전에 편다.

## 이 노트가 정하는 것과 확정표가 채우는 것

게임 종류를 모르는 트렁크다. 이 노트는 모양을 정하고, 값은 [확정표 2] 가 채운다 ([역할 - PD](역할%20-%20PD.md) 착수 질문 13행 절). 뷰는 취향이 아니라 계약이다.

| 이 노트가 정하는 모양 | 확정표가 채우는 값 |
|---|---|
| 확정할 5항목(차원 · 투영 · 각도 · 자유도 · 기준 평면) | 각 항목의 선택 |
| 화면 경계를 구하는 방법(뷰포트 역변환) | 밀어내는 거리 M · 카메라 파라미터 |
| 정렬 밴드 표의 구조 | 밴드 이름 · 값 · Y 정렬 여부 |
| 카메라 리그 계층(추적 / 흔들림 / 카메라) | 데드존 · 스무딩 · 흔들림 상한 |

## 뷰 하나가 잠그는 것

뷰를 바꾸면 아래가 전부 다시다. 그래서 착수 질문에서 코어 루프보다 먼저, 두 번째로 확정한다.

```
뷰 결정
 ├─ 좌표계      어느 평면이 "바닥"인가 (XZ? XY?) · 높이 축은 무엇인가
 ├─ 정렬        무엇이 앞에 그려지나 (Z? Y? sortingOrder? depth buffer?)
 ├─ 입력 사상   화면 좌표 → 월드 좌표 변환 규칙 (레이? 평면 교차? 그대로?)
 ├─ 스폰 경계   "화면 밖 바로 바깥"이 기하학적으로 어디인가
 ├─ 컬링/제거   무엇을 "안 보인다"고 판정하나
 ├─ 아트 규격   피벗 위치 · 스프라이트 각도 · 그림자 처리 · PPU
 └─ UI 월드앵커 HP바·피해 숫자가 월드의 어느 점을 따라가나
```

카메라를 "일단 만들고 나중에" 정하면 위 일곱을 다시 만들게 된다.

## 확정할 5항목 — "탑다운" 한 단어로는 부족하다

| # | 항목 | 선택지 | 이게 갈리면 |
|---|---|---|---|
| 1 | 차원 | 2D 스프라이트 / 3D 메시 / 2.5D(3D 월드 + 2D 캐릭터) | 정렬 방식과 아트 파이프라인 전체 |
| 2 | 투영 | Orthographic / Perspective | 원근 왜곡 · 화면 경계 계산 · 줌 의미 |
| 3 | 각도 | 탑다운(90°) / 쿼터뷰(30~60°) / 사이드(0°) / 자유 | 가시 영역 모양 · 아트 피벗 |
| 4 | 카메라 자유도 | 고정 / 추적만 / 팬·줌 / 회전까지 | 입력 계층 · 스폰 경계 재계산 주기 |
| 5 | 기준 평면 | XZ(3D 관례) / XY(2D 관례) | 모든 벡터 연산과 물리 |

5번에서 사고가 가장 많이 난다.

| 기준 평면 | 고르는 조건 |
|---|---|
| XZ | 3D 관례. 2D 게임이어도 3D 물리를 쓰려면 이쪽이 정당하다 |
| XY | 2D 관례. 3D 게임이어도 이쪽을 쓰는 구성이 정당하다 |

어느 쪽이든 정당하지만 한 프로젝트에 둘이 섞이면 평면이 섞인 자리를 아무도 잡지 못한다. 기본은 확정표에 한 줄로 적고, 그 뒤로는 "이 프로젝트의 바닥은 XZ" 같은 문장을 바꾸지 않는 규칙으로 두는 것이다.

## 뷰별 규약

### 뷰를 고르는 기준

| 뷰 | 각도 | 고르는 조건 | 가시 영역 | 정렬 기본 | 입력 |
|---|---|---|---|---|---|
| 탑다운 | 90° 수직 | 캐릭터 아트를 위에서 본 그림으로 그릴 때 | 직사각형 | 레이어 밴드 | 화면 → 바닥 1:1 |
| 유사 탑다운 | 75~85° | 캐릭터가 정면을 보는 2D. 서바이버 · 핵앤슬래시 2D | 직사각형에 가깝다 | Y 정렬 | 화면 → 바닥 |
| 쿼터뷰 / 아이소메트릭 | 30~60° 기울임 | 기울여 그린 아트를 쓸 때 | 사다리꼴 | 3D 는 depth buffer, 2D 아이소는 깊이 공식 | 바닥 평면 레이 교차 |
| 사이드뷰 | 0° 옆 | 중력 · 점프가 게임 문법일 때 | 직사각형 | Z 를 레이어로만 | 화면 → 월드 |
| 2.5D | 3D 월드 + 빌보드 2D 캐릭터 | 3D 지형 위에 2D 캐릭터를 올릴 때 | 카메라에 따름 | depth buffer 와 sortingOrder 두 체계 | 바닥 평면 레이 교차 |
| 1인칭 / 3인칭 자유 카메라 | 자유 | 카메라를 플레이어가 돌릴 때 | 카메라에 따름 | depth buffer + 월드 UI 밴드 | 카메라 기준 |

아래 절이 각 뷰의 상세다.

### 탑다운 (90°, 위에서 수직)

- 가시 영역이 직사각형이다. 스폰 경계 계산이 쉬운 유일한 뷰다.
- 정렬: 겹침이 거의 없다. 2D 면 레이어 밴드(바닥 / 그림자 / 유닛 / 이펙트 / UI)로 충분하다.
- 아트: 캐릭터를 위에서 본 그림이 기본이다. 옆모습 스프라이트를 90° 탑다운에 쓰면 전부 누워 보인다. "탑다운인데 캐릭터는 정면"이면 사실 아래의 유사 탑다운이다.
- 입력: 화면 좌표 → 바닥 평면이 1:1 이다. 가장 단순하다.

### 유사 탑다운 (75~85°, 캐릭터는 정면을 보는 2D)

- 서바이버 · 핵앤슬래시 2D 의 실제 표준이다. 엄밀히는 탑다운이 아니다.
- 정렬: 기본은 Y 정렬(아래에 있을수록 앞)이다. 없으면 캐릭터가 서로를 뚫고 지나가 보인다.
- 바닥 타일은 별도 밴드로 내려 Y 정렬에서 뺀다. 넣으면 타일이 캐릭터를 가린다.
- 그림자는 발밑 타원 스프라이트가 기본이다. 이 각도에서는 실 그림자가 안 보인다.

### 쿼터뷰 / 아이소메트릭 (30~60° 기울임)

- 가시 영역이 사다리꼴이다. 이 뷰의 함정은 전부 여기서 나온다.
  - 고정 반지름 원형 링으로 스폰하면 적이 화면 위쪽에 몰린다 ([함정 9](함정%20-%20월드%20공간.md))
  - 기본 대응: 방향별로 "화면을 벗어나는 거리"를 뷰포트 역변환으로 구해 그 경계를 쓴다 (아래 화면 경계 절)
- 정렬: 3D 면 depth buffer 가 처리한다. 2D 아이소면 깊이 = f(x, y) 공식을 한 곳에 두고 전부 그것을 쓴다.
- 아트: 피벗 = 발밑. 스프라이트는 이미 기울여 그린 것이 기본이다. billboard 로 세우면 각도가 안 맞는다.
- 입력: 화면 → 바닥 평면 레이 교차. "마우스 위치 그대로"는 틀린다.

### 사이드뷰 (0°, 옆에서)

- 중력 · 점프가 게임 문법이 된다. 물리를 하나로 통일한다 ([장르 문법 - 액션](장르%20문법%20-%20액션.md)).
- 정렬: Z 는 레이어로만 쓴다. 배경 패럴랙스는 별도 축이다.
- 카메라 추적에 데드존(카메라가 안 따라오는 사각형)과 룩어헤드가 필요하다. 플레이어를 화면 정중앙에 고정하면 진행 방향이 안 보인다.

### 2.5D (3D 월드 + 빌보드 2D 캐릭터)

- 함정이 가장 많은 뷰다. 정렬이 depth buffer 와 sortingOrder 두 체계로 갈린다.
- 반투명 스프라이트는 depth 를 안 쓴다. 그래서 3D 지형과의 앞뒤가 깨진다. 아래 둘 중 하나를 정한다.

| 선택 | 방법 | 대가 |
|---|---|---|
| 불투명 컷아웃 | 캐릭터를 alpha clip 으로 그려 depth buffer 에 태운다 | 반투명 가장자리를 쓸 수 없다 |
| 수동 렌더 순서 | 반투명을 유지하고 렌더 순서를 직접 관리한다 | 지형과의 앞뒤를 코드가 책임진다 |

- 빌보드 회전축도 정한다. 구현은 한 곳에만 둔다.

| 회전축 | 결과 |
|---|---|
| Y 축만 회전 | 기울임이 유지된다 |
| 카메라를 완전히 마주봄 | 항상 정면으로 보인다 |

### 1인칭 / 3인칭 자유 카메라

- 카메라 충돌(벽 뚫림) · FOV · 감도를 스펙 항목으로 둔다. "적당히"는 판정할 수 없다.
- UI 는 월드 스페이스와 스크린 스페이스가 섞인다. 밴드 설계에 월드 UI 밴드를 하나 더 둔다.
- 멀미(모션 시크니스)는 성능이 아니라 설계 문제다. 카메라 가속 · 흔들림에 상한을 스펙으로 둔다.

## 화면 경계는 계산이 아니라 실측이다

스폰 · 컬링 · UI 여백이 전부 이 경계 위에 선다. 기본은 추측한 반지름을 상수로 두지 않고 아래 방법으로 구하는 것이다.

### 구하는 법 — 뷰포트 역변환

```
[예시] 원리 (뷰 종류 불문)
1. 뷰포트 좌표(0..1)의 네 모서리 + 필요한 방향들을 잡는다
2. 카메라에서 그 방향으로 바닥 평면과 교차시킨다 (Orthographic 도 동일)
3. 나온 월드 점들이 화면에 보이는 바닥 영역이다
4. 스폰은 그 영역을 바깥으로 M 유닛 밀어낸 테두리에서 한다
```

- 기본은 카메라 파라미터가 바뀔 때만 다시 계산하는 것이다. 매 프레임 할 일이 아니다. 줌 · 화면 회전 · 해상도 변경 시 무효화하고 재계산하는 훅을 둔다.
- 경계를 시각화하는 디버그 그리기를 처음부터 넣는다. 눈으로 보지 않은 경계는 틀려도 알아채지 못한다. [역할 - PD](역할%20-%20PD.md) 게이트 절의 G9 증거물이 이 그림이다.

### 화면 밖 제거는 화면 밖 AND 거리 초과

| 판정 | 결과 |
|---|---|
| 거리 단독 | 먼 쪽(화면 위)에 보이는 것을 눈앞에서 지운다 |
| 화면 밖 단독 | 카메라가 되돌아왔을 때 있어야 할 것이 없다 |
| 화면 밖 AND 거리 초과 | 기본. 둘 다 만족할 때만 회수한다 |

## 좌표계 규약 — 한 프로젝트에 하나

기본은 확정표에서 정한 기준 평면을 유틸 한 곳으로 모으는 것이다. 이유: 각자 `new Vector3(x, 0, z)` 를 직접 쓰기 시작하면 평면이 섞이는 것을 아무도 못 잡는다.

```
[예시] XZ 평면 프로젝트의 규약
- 월드 위치       : Vector3 (y 는 높이, 게임플레이 로직은 y 를 보지 않는다)
- 게임플레이 좌표 : Vector2 (x, z) — 거리·방향·판정은 전부 여기서
- 변환은 유틸에서만: ToPlane(Vector3) / ToWorld(Vector2, height)
- 회전            : 바닥 평면 위의 각도 하나(도). 쿼터니언은 표현용으로만
```

- 충돌 · 거리 판정은 평면에서 한다. 높이 축을 섞으면 계단 · 경사에서 사거리가 달라진다.
- 물리 엔진 대신 자작 판정을 쓰면 판정 도형을 평면 2D 도형으로 정의한다 (원 vs OBB 등). 3D 콜라이더와 자작 판정이 공존하면 어느 쪽이 진실인지부터 정한다.

## 정렬 — "무엇이 앞에 그려지나"를 한 곳에서 정한다

정렬 규칙이 코드 여러 곳에 흩어지면 새 오브젝트 종류가 생길 때마다 앞뒤가 깨진다. 기본은 밴드 표 하나를 정렬의 유일한 출처로 두는 것이다.

```
[예시] 밴드 테이블 — 이 표가 정렬의 유일한 출처
밴드         범위          Y정렬   내용
Ground       -1000         X       바닥 타일 · 데칼
Shadow        -500         X       발밑 그림자
Unit             0         O       플레이어 · 적 · NPC
Projectile     100         O       투사체 · 드랍
FxOver         500         X       상위 이펙트 · 피격 연출
WorldUI       1000         X       HP바 · 피해 숫자
```

- Y 정렬 대상과 비대상을 표에 적는다. 섞으면 그림자가 캐릭터 위로 올라온다.
- 밴드 값은 상수 클래스 하나에 모은다. 매직 넘버로 흩어지면 두 종류가 같은 값을 쓰게 된다.
- 3D 는 depth buffer 가 정렬하지만 반투명 · 파티클 · UI 에는 여전히 수동 밴드가 필요하다.

## 카메라 리그 — 추적 · 흔들림 · 줌은 따로 산다

한 컴포넌트가 추적도 하고 흔들기도 하면 흔들림이 추적 위치를 덮어써서 카메라가 튄다. 기본은 계층을 나누는 것이다.

```
[예시] 계층
CameraRig            추적 (타깃 따라감, 데드존·스무딩·경계 클램프)
└ ShakeOffset        흔들림 (로컬 오프셋만. 리그 위치를 안 건드린다)
  └ Camera           투영·FOV·줌
```

- 스무딩의 시간 기준을 정한다. 기본은 일시정지 중 카메라가 멈추는 쪽이다.

| 시간 기준 | 일시정지(timeScale 0) 중 |
|---|---|
| `deltaTime` | 카메라도 멈춘다 |
| `unscaledDeltaTime` | 카메라가 계속 움직인다 |

- 맵 경계 클램프는 가시 영역 크기를 알아야 한다. 위 화면 경계 계산과 같은 출처를 쓴다.
- 흔들림 상한을 스펙으로 받는다. "타격감"이라는 말로 상한 없이 흔들면 멀미가 난다.

## 월드 → UI — 피해 숫자 · HP바

- 카메라 각도를 확정한 뒤에 붙인다. 각도가 바뀌면 앵커 오프셋이 전부 어긋난다.
- 월드 좌표 → 스크린 좌표 변환은 카메라 뒤에 있는 점을 걸러낸다. 뒤로 가면 좌표가 뒤집힌다.
- 대량 표시(피해 숫자)는 풀링 + 상한이 전제다. 상한 도달 시 동작(가장 오래된 것 회수)을 스펙으로 받는다.
- 빌보드가 필요한 월드 UI 는 회전 규칙을 카메라 리그와 같은 규칙으로 둔다 (위 2.5D 절).

## 완료 체크리스트

- [ ] 확정표 2행의 5항목(차원 · 투영 · 각도 · 자유도 · 기준 평면)이 전부 한 줄로 적혀 있다
- [ ] 기준 평면 변환이 유틸 한 곳에만 있다 (직접 `Vector3` 조립 grep → 유틸 밖 0건)
- [ ] 화면 경계를 뷰포트 역변환으로 구하고, 디버그로 그려서 눈으로 봤다
- [ ] 스폰이 그 경계 기준이다 (고정 반지름 상수 0건)
- [ ] 제거 판정이 "화면 밖 AND 거리 초과"다
- [ ] 정렬 밴드 표가 있고 상수가 한 곳에 모여 있다
- [ ] 카메라 리그에서 추적 · 흔들림 · 줌이 분리돼 있다
- [ ] 확정 카메라 각도에서 찍은 실제 플레이 스크린샷이 스펙 QA 절에 있다 (씬뷰 확인은 확인이 아니다)

## 함정 요약

상세는 [함정 색인 - 개발](함정%20색인%20-%20개발.md).

| 증상 | 원인 |
|---|---|
| 적이 화면 위쪽에만 몰림 | 기울인 카메라 + 원형 스폰 링 |
| 캐릭터가 서로를 뚫고 지나가 보임 | Y 정렬 없음 (유사 탑다운) |
| 바닥 타일이 캐릭터를 가림 | 타일이 Y 정렬 대상에 포함됨 |
| 눈앞의 적이 갑자기 사라짐 | 거리 단독 제거 판정 |
| 스프라이트가 다 누워 보임 | 옆모습 아트를 90° 탑다운에 사용 |
| 캐릭터가 3D 지형에 파묻히거나 뜸 | 2.5D 반투명 스프라이트 + depth buffer |
| 카메라가 미세하게 튐 | 추적과 흔들림이 같은 트랜스폼을 씀 |
| 일시정지인데 카메라가 움직임 | 스무딩이 `deltaTime` 대신 `unscaledDeltaTime` (또는 반대) |
