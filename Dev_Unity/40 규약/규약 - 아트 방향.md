# 규약 - 아트 방향

리소스가 퀄이 낮거나, 게임과 안 어울리거나, 플레이를 방해하는 것을 막는 판단 기준이다. 아트 양산을 시작하기 전, 새 출처(에셋 팩 · 생성기 · 이미지 생성)의 리소스를 들이기 전, 캡처가 어색한데 이유를 못 댈 때 편다.
게임 종류를 모르는 트렁크다. 이 노트는 무엇을 정하고 어떻게 재는지를 정하고, 값은 [확정표 12] 와 스펙 아트 규격 절이 채운다.

기술 규격(이름 · 임포트 · 반입 절차 · 캐릭터 한 장의 숫자 판정 4종)은 [역할 - 아트](역할%20-%20아트.md), 생성기 뼈대는 [양식 - 아트 생성기](양식%20-%20아트%20생성기.md) 에 있다. 이 노트는 그 위에서 "이 그림이 이 게임에 맞나"를 다룬다.

## 세 가지 실패는 검사가 다르다

| 실패 | 겉으로 보이는 것 | 보는 단위 | 절 |
|---|---|---|---|
| 플레이를 방해한다 | 적 · 위험 · 보상이 배경에 묻힌다. 이펙트가 플레이어를 가린다 | 실제 플레이 캡처 | 가독성 |
| 게임과 안 어울린다 | 한 장씩은 괜찮은데 모아 놓으면 따로 논다 | 같은 종류를 나란히 놓은 라인업 | 일관성 |
| 퀄이 낮다 | 테두리 헤일로 · 뭉개짐 · 흐림 · 애니 튐 | 에셋 한 장 + 캡처 확대 | 품질 하한 |

기본 우선순위는 가독성 > 일관성 > 품질 하한이다. 이유: 예쁜데 안 보이면 게임이 안 되고, 선명한데 따로 놀면 제품으로 안 보이고, 둘 다 맞으면 결함은 부분 수정으로 끝난다.

## 순서 — 양산 전에 방향부터 굳힌다

1. 방향 표를 채운다 (아래 절). 출처는 기획서의 톤 · 세계관 · 타깃과 레퍼런스 실측이다. 사람에게 받을 재료 형식은 [레퍼런스 해부](레퍼런스%20해부.md) 아트 재료 절. 빈칸은 스펙 추정 절에 적는다
2. 스타일 프레임 1장을 만든다. 실제 게임 해상도로 배경 + 플레이어 + 적 2~3종 + 이펙트 1개 + HUD 를 한 화면에 놓은 캡처다. 양산 전에는 이 한 장만 판정하고, 사람 확인도 이 한 장에 모은다
3. 라인업을 만든다. 같은 종류(캐릭터 전부 · 아이콘 전부 · 이펙트 전부)를 한 장에 같은 배율로 나란히 놓는다
4. 가독성 · 일관성 · 품질 하한을 스타일 프레임과 라인업에서 잰다
5. 통과한 뒤 양산한다. 새 에셋은 라인업에 끼워 넣어 판정한다

이유: 스타일은 양산 뒤에 바꾸면 전량 재작업이다. 한 장씩 보면 대부분 괜찮아 보이고, 어색함은 섞였을 때 드러난다.
다른 선택이 나은 조건: 슬라이스 초반의 프록시 단계에서는 2 · 3을 건너뛰고 가독성의 색 예약만 지킨다. 프록시는 곧 버리지만 위계 색은 코드와 데이터가 먼저 쓴다.

## 만드는 수단 — 표현 방식을 고를 때 같이 정한다

에이전트가 직접 그릴 수 있는 범위와 외부 수단이 필요한 범위가 다르다. 표현 방식을 정할 때 수단을 같이 정하는 것이 기본이다. 이유: 수단이 못 내는 품질을 방향 표에 적으면 판정이 매번 미달로 끝난다.

| 표현 | 기본 수단 | 에이전트의 몫 |
|---|---|---|
| 도트 · 단순 벡터 · 이펙트 · UI 조각 · 절차 도형 | 생성기 스크립트 ([양식 - 아트 생성기](양식%20-%20아트%20생성기.md)) | 직접 만들고 판정한다 |
| 일러스트 · 페인팅 · 사실적 3D | 외부 에셋 팩 · 이미지 생성 도구 · 사람 작업 | 방향 표 기준으로 맞추고(팔레트 매핑 · 리샘플 · 외곽선 재처리) 판정한다 |

- 외부 수단 결과도 아래 일관성 절의 출처 하나로 취급한다
- 수단이 확정표 12행과 안 맞으면 스펙 추정 절에 적고, 스타일 프레임과 함께 사람 확인 목록에 올린다

## 방향 표 — 스펙 아트 규격 절에 들어가는 항목

| 항목 | 정하는 것 | 재는 법 |
|---|---|---|
| 톤 키워드 | 원하는 인상 3개 + 피할 인상 2개 | 판정할 때 캡처를 보고 키워드마다 맞음/어긋남을 적는다. 숫자가 아니므로 사람 확인 목록으로 보낸다 |
| 표현 방식 | 도트 · 벡터 · 페인팅 · 3D 렌더 중 하나 | 출처별로 섞였는지 라인업에서 본다 |
| 텍셀 밀도 | 화면 1px 당 텍스처 px. 한 화면 안에서 같은 값 | 캡처 속 크기 ÷ 원본 크기. 도트는 정수 배율 |
| 팔레트 | 전체 색 수 상한 · 역할별 예약 색 | 팔레트 밖 색 픽셀 비율 |
| 광원 | 방향 하나 (예: 좌상단) | 명암 단이 밝은 쪽이 어디인지 에셋마다 |
| 외곽선 | 유무 · 두께 px · 색 규칙(검정 / 어두운 동색) | 두께 편차 · 외곽 픽셀 비중 ([역할 - 아트](역할%20-%20아트.md) 셀 수 있는 것 넷 절) |
| 명암 단수 | 몇 단 | 실제로 쓰인 명도 단계 수 |
| 형태 언어 | 역할별 실루엣 규칙 [예시] 아군 둥근 형태 · 적 뾰족한 형태 | 단색 실루엣만으로 역할이 갈리나 |
| 디테일 밀도 | 화면 표시 크기별로 넣을 디테일 한도 [예시] 화면 24px 이하는 눈 · 무늬 생략 | 실제 표시 크기로 줄였을 때 디테일이 노이즈가 되나 |
| 채도 · 명도 대역 | 배경은 낮게, 상호작용 대상은 높게 | 역할별 평균 채도 · 명도 |

- 값은 레퍼런스에서 잰 것이 기본이다 ([레퍼런스 해부](레퍼런스%20해부.md) art.tsv). 레퍼런스가 없으면 스타일 프레임이 기준 역할을 하고, 그 값을 스펙에 적는다
- 한 게임의 값은 스펙에만 둔다. 이 노트에는 모양만 둔다

## 가독성 — 플레이를 방해하지 않는가

### 가독 위계

기본 위계는 플레이어 > 위험(적 공격 · 투사체 · 장판) > 적 > 보상 · 상호작용 대상 > 배경 · 장식이다.
위에 있을수록 명도 대비 · 채도 · 움직임 중 적어도 둘이 더 크다. 장르가 위계를 바꾸면 장르 노트에 적는다 ([장르 문법 지도](장르%20문법%20지도.md)).

### 역할 색 예약

- 위험 신호 색과 보상 색을 먼저 예약하고, 배경 · 장식에서는 쓰지 않는다. 이유: 배경에 같은 색이 있으면 위험이 배경으로 읽힌다
- 색만으로 구분하지 않는다. 아군 / 적 / 위험은 형태나 명도로도 갈리게 한다. 이유: 색각 차이가 있는 사람과 작은 화면에서는 색이 먼저 무너진다
- 이펙트 색을 데이터가 틴트한다면 틴트 값도 이 예약을 따른다 ([양식 - 아트 생성기](양식%20-%20아트%20생성기.md))

### 재는 법

| 검사 | 방법 | 통과 기준 |
|---|---|---|
| 흑백 | 캡처를 그레이스케일로 바꾼다 | 위계 순서가 그대로 읽힌다 |
| 실루엣 | 역할별 대표 에셋을 단색으로 채운다 | 형태만으로 역할이 갈린다 |
| 축소 | 실제 기기 표시 크기로 줄인다 (모바일이면 기기 화면 크기) | 역할 식별이 된다 |
| 배경 대비 | 오브젝트 픽셀 평균 휘도 vs 주변 배경 평균 휘도 | 스펙에 적은 하한 이상. 기준은 레퍼런스에서 같은 방법으로 잰다 |
| 최대 밀도 | 적 · 이펙트가 가장 많은 순간의 캡처로 위 넷을 다시 | 플레이어와 위험 신호가 가려지지 않는다 |

- 판정은 배경이 가장 밝은 곳과 가장 어두운 곳 두 캡처에서 한다 ([역할 - 아트](역할%20-%20아트.md) 판정은 화면에서 한다 절)
- 최대 밀도 캡처는 하네스로 찍는다 ([양식 - 하네스](양식%20-%20하네스.md)). 손으로 찍으면 한가한 순간만 남는다

## 일관성 — 게임과 어울리는가

### 라인업으로 세는 것

| 항목 | 세는 법 | 어긋났을 때 흔한 원인 |
|---|---|---|
| 텍셀 밀도 편차 | 에셋별 화면 배율의 최대 ÷ 최소 | 출처마다 원본 해상도가 다르다 |
| 팔레트 이탈 | 에셋별 팔레트 밖 색 픽셀 비율 | 에셋 팩 원본 색을 그대로 씀 |
| 외곽선 | 두께 · 색 규칙이 표와 같은가 | 출처마다 선 규칙이 다르다 |
| 광원 방향 | 밝은 쪽이 같은가 | 에셋 팩마다 광원이 다르다 |
| 명암 단수 | 표와 같은가 | 생성기 파라미터와 외부 에셋이 다르다 |
| 각도 · 원근 | [규약 - 뷰](규약%20-%20뷰.md) 의 각도와 같은가 | 옆모습 에셋을 탑다운에 씀 |
| 표현 방식 | 한 방식인가 | 도트 옆에 벡터 일러스트 |

### 출처가 섞일 때

- 기본은 출처 하나를 기준으로 정하고, 나머지를 그 기준으로 맞추는 것이다: 팔레트 매핑 · 정수 배율 리샘플 · 외곽선 재처리 · 명암 재양자화
- 맞춰도 표현 방식이 다르면(도트와 페인팅) 섞지 않는 편이 낫다. 이유: 변환으로는 형태 언어가 안 맞는다
- 이미지 생성 결과도 하나의 출처다. 같은 프롬프트라도 장마다 광원 · 선 · 팔레트가 흔들리므로 라인업 검사를 똑같이 거친다
- UI 와 월드는 같은 팔레트와 같은 모서리 · 선 규칙을 쓰는 것이 기본이다. 다르게 가려면 방향 표에 이유를 적는다

### 의도한 예외

보스만 다른 톤, 특정 이벤트만 다른 팔레트처럼 일부러 튀게 하는 것은 방향 표에 예외 행으로 적는다. 적혀 있지 않은 튀는 에셋은 이탈로 센다.

## 품질 하한 — 그림 자체의 결함

| 결함 | 재는 법 | 흔한 원인 |
|---|---|---|
| 가장자리 헤일로 (흰 · 검은 테두리) | 알파 경계 픽셀의 색이 주변과 튀는가 | 투명 영역 RGB 가 흰색 · 검정 · 알파 블리딩 없음 |
| 뭉개짐 · 계단 | 도트인데 표시 배율이 정수가 아닌가 · 필터 모드 | 비정수 스케일 · 도트에 Bilinear |
| 흐림 | 캡처 속 크기 > 원본 크기인가 | Max Size 가 작다 · PPU 불일치 · UI 에 mip |
| 밴딩 · 압축 얼룩 | 그라디언트 영역을 원본 PNG 와 캡처로 비교 | 압축 포맷 · 그라디언트를 저비트로 |
| 잘림 | 이미지 가장자리 1px 에 불투명 픽셀이 있나 | 캔버스가 좁다 · 트림이 과하다 |
| 애니 튐 | 프레임 간 피벗 이동량 · 실루엣 면적 변화 | 프레임마다 기준점이 다르다 |
| 프록시 잔존 | 프록시 목록과 최종 에셋 목록 대조 | 교체를 잊었다 |
| 글자를 이미지에 구움 | 이미지 속 텍스트 유무 | 다국어 · 폰트 교체가 막힌다 |

- 헤일로 · 흐림 · 뭉개짐은 에디터 씬 뷰에서 잘 안 보인다. 판정은 실제 해상도 캡처를 확대해서 한다
- 임포트 설정 기본값은 [역할 - 아트](역할%20-%20아트.md) 임포트 규격 절

## 판정과 기록

스펙 아트 규격 절 아래에 판정 표를 둔다.

```
[예시] 스펙 아트 규격 절 — 판정 표
| 검사 | 대상 | 기준(출처) | 측정값 | 판정 |
|---|---|---|---|---|
| 흑백 위계 | 스타일 프레임 | 위계 순서 유지 | 유지 | 통과 |
| 배경 대비 | 적 3종 · 밝은 배경 | 레퍼 실측 하한 | 미측정 | 미측정 |
| 팔레트 이탈 | 캐릭터 라인업 | 5% 이하(추정 #7) | 2.1% | 통과 |
```

- 미측정은 통과가 아니다 ([원칙 D1](Dev_Unity%20원칙.md))
- 숫자로 못 재는 것(톤 키워드 맞음/어긋남)은 사람 확인 목록으로 보내고, 스타일 프레임과 라인업 캡처를 보고에 붙인다. 진행은 멈추지 않는다 ([개발 러너](개발%20러너.md) 빈칸을 채우는 순서 절)
- 어긋난 항목은 한 번에 하나씩 고치고 다시 잰다. 되돌림 한도는 [단계 3 - 아트](단계%203%20-%20아트.md) 막혔을 때 절
- 반복되는 결함은 함정 노트로 일반화한다 ([문서 쓰는 법](문서%20쓰는%20법.md) 새 함정을 더할 때 절)

## 완료 체크리스트

- [ ] 방향 표의 모든 항목에 값 또는 추정 번호가 있다
- [ ] 스타일 프레임 1장이 실제 해상도 캡처로 있다
- [ ] 종류별 라인업이 있다
- [ ] 가독성 다섯 검사 · 일관성 표 · 품질 하한 표에 미측정이 없다
- [ ] 예외로 튀게 한 에셋은 방향 표 예외 행에 있다
- [ ] 톤 키워드 판정이 사람 확인 목록에 올라가 있다
