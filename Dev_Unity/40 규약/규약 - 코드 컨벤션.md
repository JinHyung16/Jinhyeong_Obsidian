# 규약 - 코드 컨벤션

킷 코드와 새 코드가 같은 모양이 되게 하는 C# · Unity 코딩 컨벤션이다. 코드를 쓰거나 리뷰할 때, 새 시스템 폴더를 열 때 편다.

킷을 복사한 프로젝트는 이 규칙을 그대로 쓰는 것이 기본이다. 이 노트가 원본이고, 프로젝트마다 다른 것은 접두어뿐이다.

## 접두어

| 항목 | 규칙 |
|---|---|
| namespace | `<접두어>_<시스템>` · 하위는 `.` (`[예시]` `Jinhyeong_UI.Framework`) |
| 접두어 | 프로젝트당 하나. 프로젝트 진입 파일이 정한다. 킷 복사 직후 일괄 치환 — 폴더명은 안 바뀐다 |
| 전역 namespace | 쓰지 않는다. 모든 `.cs` 가 namespace 안에 |

## 폴더 = namespace 1:1

```
Assets/Scripts/<시스템>/Runtime/*.cs   → <접두어>_<시스템>
Assets/Scripts/<시스템>/Editor/*.cs    → <접두어>_<시스템>.Editor
Assets/Scripts/<시스템>/<하위>/*.cs    → <접두어>_<시스템>.<하위>
```

새 시스템은 `Runtime/` · `Editor/` 로 시작한다. 역할이 갈리면 하위 폴더 — 하위 폴더가 곧 하위 namespace 다.

## 네이밍 (.NET / Unity 표준)

| 대상 | 규칙 | 예 |
|---|---|---|
| 타입 · 메서드 · 프로퍼티 · public 필드 · const · `static readonly` | `PascalCase` | `PrefabPath` |
| private 필드 | `_camelCase` | `_applySide` |
| 로컬 · 매개변수 | `camelCase` | `applySide` |
| enum 타입 | `E` 접두 + `PascalCase` 멤버 | `EPartSlot.Head` (패키지 enum 은 패키지 규칙 — `WindowType.Popup`) |
| 인터페이스 | `I` 접두 | `IInputProvider` |
| 프리팹 경로 상수 | 그 클래스의 `private const string PrefabPath` 하나 | 두 곳에 두면 하나는 썩는다 |

## 파일

- 한 파일 = 한 타입. 작은 enum · 내부 struct 만 동거.
- MonoBehaviour 라이프사이클(`Awake` `Start` `Update` `OnEnable` …)은 `private` 이 기본이다. 이유: 킷의 `BaseBehaviour` 가 `OnEnabled()` 같은 훅을 주므로, public 으로 노출하지 않고 그 훅을 오버라이드한다.
- UI 는 `Awake` · `OnEnable` 에 논리를 두지 않고 `OnOpening()` 에서 채우고 `OnClose()` 에서 비운다. [규약 - UI](규약%20-%20UI.md)

## 코드

- `var` 는 우변에서 타입이 즉시 보일 때만 쓴다. 안 보이면 명시한다.
- Unity 오브젝트 null 비교는 `== null` / `!= null`. 이유: `?.` `??` 는 lifetime 체크를 우회한다.
- `if` 는 조건과 본문을 다른 줄에 둔다(한 줄 `if` 를 쓰지 않는다). 중괄호는 본문이 두 줄 이상일 때.
- 머티리얼은 에셋으로 두고 런타임에 `new Material` 을 만들지 않는다. 색 변형은 `MaterialPropertyBlock`.
- 런타임 `AddComponent` 는 쓰지 않는다. 이유: 루트 프리팹의 컴포넌트 구성은 빌더가 고정한다.
- 전역 상수 · 기본값은 `<접두어>_Common.CommonConfig` 한 곳에 둔다. 파일 안에 수치를 박지 않는다. 모양은 [양식 - CommonConfig](양식%20-%20CommonConfig.md).
- `Debug.Log` 는 스팸이 되지 않게 둔다. `LogWarning` / `LogError` 는 실제 에러에만. 조회 실패는 한 번만 경고.
- 이벤트는 건 곳에서 푼다. `-= / +=` 로 멱등 등록.

## 데이터

- 콘텐츠를 늘릴 때 C# 을 고치지 않는 것이 기본이다. SSOT 는 `Assets/` 밖(`_DataExporter/GameData/`), 굽기 산출물은 읽기 전용.
- 게임 코드는 JSON 을 직접 읽지 않고 종류마다 Registry 하나를 거친다.
- 노드 · 원자는 어트리뷰트로 자기 타입을 신고한다 (`[BTNode(...)]`). switch 를 손으로 늘리지 않는다.

## 비동기 — UniTask

- `async void` 는 쓰지 않는다. 반환은 `UniTask` / `UniTaskVoid`. 던져 놓는 자리(부트 · 버튼 핸들러)에서만 `.Forget()`.
- 로드 결과를 쓰는 코드는 로드가 끝난 뒤에 돌게 한다 — `await` 로 잇거나 준비됨 게이트를 둔다. [함정 19](함정%20-%20비동기%20로드.md) · [함정 22](함정%20-%20비동기%20로드.md)
- 같은 로드를 두 번 부르면 같은 Task 를 돌려준다 (멱등 `LoadAsync`, 완료 태스크 캐시). [함정 15](함정%20-%20비동기%20로드.md)
- 창이 닫히면 그 창이 띄운 비동기는 취소한다 — `OnClose()` 에서 `CancellationTokenSource.Cancel()`. 이유: 안 하면 닫힌 창에 결과가 쓰인다.
- 도메인 리로드 뒤 정적 캐시는 비어 있다. 그래서 정적 캐시는 리셋 진입점을 갖는다.

## 에디터 스크립트

- 에디터 코드는 `<시스템>/Editor/` 폴더 · `<접두어>_<시스템>.Editor` namespace. 이유: 런타임 어셈블리에 `UnityEditor` 참조가 새면 빌드가 깨진다.
- `MenuItem` 루트는 프로젝트 하나로 — `"<접두어>/<시스템>/<동작>"`. 이유: 흩어 두면 메뉴가 늘 때마다 못 찾는다.
- 자동화 진입점은 인자 없는 public static 메서드 하나 — 배치모드 `-executeMethod` 와 `Temp/editor.task` 가 같은 것을 부른다.
  새 태스크는 `EditorTaskRunner` 의 표에 이름 한 줄로 등록한다. [양식 - 하네스](양식%20-%20하네스.md)
- 에디터 스크립트도 SerializedObject 로 값을 묶는다. 이유: 리플렉션으로 private 필드에 직접 쓰면 프리팹이 dirty 표시 없이 저장을 건너뛴다.

## 실패 시 동작 — 셋 중 하나로 정해 놓는다

| 상황 | 하는 일 | 왜 |
|---|---|---|
| 데이터 조회 실패 (없는 id) | 한 번만 경고 + 기본값. 매 프레임 로그는 남기지 않는다 | 게임은 계속 돌아야 한다. 스팸은 진짜 에러를 묻는다 |
| 계약 위반 (미등록 키 · 없는 프리팹 · 미구현 노드) | `Debug.Assert` / `throw` — 즉시, 시끄럽게 | 조용한 폴백은 한참 뒤에 터진다 ([함정 2](함정%20-%20런타임%20배선.md) · [함정 13](함정%20-%20에셋%20반입.md) · [함정 21](함정%20-%20에셋%20반입.md)) |
| 하네스 안에서의 이상 | 결과 대신 "무효" 를 리포트에 | 멈춘 게임의 "피해 0"이 정상처럼 보인 사고가 있었다 |

`try/catch` 로 삼키지 않는 것이 기본이다. 잡을 거면 로그에 무엇이 안 됐는지와 다음 행동을 적는다.

## 어셈블리 · 테스트 — 지금의 결정

- 게임 쪽은 asmdef 를 나누지 않는다. 단일 `Assembly-CSharp` (+Editor). 이유: 프레임워크는 패키지가 자기 asmdef 를 들고 오고 `autoReferenced` 라 자동으로 참조된다. 게임이 asmdef 를 만들면 그 참조가 끊긴다.
- Unity Test Framework 는 기본으로 쓰지 않는다. 검증은 요청 파일 하네스([역할 - 클라](역할%20-%20클라.md) · [양식 - 하네스](양식%20-%20하네스.md))다 — 리포트 숫자가 회귀 테이블이다.
  유닛 테스트가 필요해지는 자리(순수 계산 · 파서)가 생기면 그때 EditMode 만 여는 편이 낫다.

## 텍스트 — 코드에 노출 문자열을 두지 않는다

- 화면에 보이는 글자(스킬명 · 설명 · 버튼 · 배너)는 데이터에서 온다. C# 리터럴로 한글을 적지 않는다 — 검색해서 0건이 기준이다.
- 데이터에는 `id`(기능명 · 영문)와 `displayName`(노출명 · 세계관어)을 분리한다. 이유: 노출명이 바뀌어도 id 는 안 바뀐다.
- 다국어는 지금 하지 않는다. 대신 위 둘을 지키면 나중에 `displayName` 열만 언어별로 는다.
- 폰트는 글리프를 세어서 확인한다([역할 - 아트](역할%20-%20아트.md)). CJK 가 네모로 나오는 것은 폰트 문제지 텍스트 문제가 아니다.

## git

- 커밋 메시지 `<종류>: <한 줄>` — `feat` `fix` `data` `art` `doc` `chore`. 이유: 종류를 가르면 히스토리가 읽힌다.
- 한 커밋 = 큐 항목 하나. 항목이 끝나 큐에서 지운 시점이 커밋 시점이다.
- 추적 범위는 프로젝트가 정한다. `*.csproj` `*.sln` `Library/` `Temp/` 는 무시. `_DataExporter/` 처럼 git 밖에 둔 것은 왜 밖에 두었는지를 진입 파일의 보호 경로 절에 적는다 — 잃어도 되는 것이 아니라 잃으면 안 되는 것이라 적는 것이다.

## 프로젝트와의 관계

이 노트가 원본이다. 프로젝트 진입 파일은 사본을 두지 않고 이 노트 링크만 든다. 이유: 두 곳에 두면 어긋나고, 어긋날 때마다 어느 쪽이 맞는지 따져야 한다.
프로젝트마다 다른 접두어는 진입 파일이 정한다. `[예시]` 이 프로젝트는 `Jinhyeong_`.
