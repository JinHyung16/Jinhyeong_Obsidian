# 규약 - 패키지

게임 프레임워크를 복사하지 않고 UPM 패키지로 받는 규약이다. 새 프로젝트에 프레임워크를 넣을 때, 패키지 버전을 고를 때, 무엇을 패키지에서 받고 무엇을 게임이 만들지 가를 때 편다.

정본은 `Unity_GameFramework` 다. 기본은 코드를 스킬 폴더에 복사해 두지 않고 UPM 으로 받는 것이다.
이유: 복사본은 원본과 금방 갈라지고, 새 프로젝트마다 접두어를 치환해야 한다.
UPM 으로 받으면 `Library/PackageCache` 에 읽기 전용으로 들어와 드리프트가 불가능하고, 버전이 태그로 고정된다.

## 두 패키지

| 패키지 | 저장소 | 무엇을 준다 |
|---|---|---|
| `com.jinhyung.gameframework` | `JinHyung16/Unity_GameFramework` | UIFramework — 창 수명 · 깊이 · 풀링 · 재활용 스크롤 / DataLoader — xlsx · csv · js · ts · py → JSON → C# 컨테이너 |
| `com.translation.unity` | `JinHyung16/Unity_Localization` | 번역 번들 로드 · 조회. 게임 DB 와 분리된 언어별 JSON |

의존은 `package.json` 이 들고 있어 따라온다 — addressables · newtonsoft-json · ugui. UniTask 는 어느 쪽도 안 쓴다.

## 버전을 고르는 순서

순서와 금지 항목은 [원칙 D7](Dev_Unity%20원칙.md) 이다. 여기는 요약과 예시만.

1. 릴리스 페이지를 먼저 본다 (`https://github.com/JinHyung16/<저장소>/releases`). 없으면 태그 목록.
2. README 의 Install 절에 적힌 URL 을 그대로 쓴다. 경로를 짐작하지 않는다.
3. 태그 이름으로 받는다. 커밋 해시로 고정하지 않는다.
4. 게임 시작 시점의 태그로 박아 둔다. 개발 중 올리는 것은 큐 항목으로 따로 두고, 버전 올리기를 임의로 제안하지 않는다. 이유: 저절로 올라가면 어느 날 갑자기 깨진다.

결과가 이상하면 보고하기 전에 릴리스 페이지를 다시 본다. [함정 54](함정%20-%20작업%20방식.md)

```json
[예시] Packages/manifest.json — 태그는 릴리스 페이지에서 확인한 값으로
"com.jinhyung.gameframework": "https://github.com/JinHyung16/Unity_GameFramework.git?path=/Packages/com.jinhyung.gameframework#v0.0.1",
"com.translation.unity":      "https://github.com/JinHyung16/Unity_Localization.git?path=/Packages/com.translation.unity#v0.0.2"
```

설치 확인은 컴파일이다 — 넣고 `Temp/editor.task` ← `refresh`, 에러 0.
에러가 나면 다음 작업으로 넘어가지 않고 그 자리에서 멈추는 것이 기본이다. 이유: 패키지가 컴파일되지 않은 채 쌓은 작업은 전부 그 위에서 다시 확인해야 한다.

## 패키지가 주는 것 / 게임이 만드는 것

| 축 | 패키지 | 게임 |
|---|---|---|
| 창 | `BaseWindow` · `BaseManagement` · 깊이 배정 · Resources 로드 | 창 클래스 · 프리팹 · `AddWindows()` 등록 |
| 조각 | `BaseComponent` · `PrefabAuto` · 풀 · `RecyclableScrollView` | 조각 클래스 · 프리팹 |
| 데이터 | 변환 파이프라인 · `DataManager` · 컨테이너 4종 | 원본 표 · 컨테이너 클래스 · 스키마 |
| 번역 | 번들 로드 · 조회 | 번역 CSV · 언어 목록 |
| 없는 것 | SafeArea · Panel 계층 · 프리팹 빌더 헬퍼 | 게임 쪽에 둔다 ([양식 - UI 프리팹](양식%20-%20UI%20프리팹.md) "프레임워크에 없는 것" 절) |

## 게임 쪽에 남는 것 — 패키지가 아니다

`CommonConfig`([양식 - CommonConfig](양식%20-%20CommonConfig.md)) · 아트 생성기([양식 - 아트 생성기](양식%20-%20아트%20생성기.md)) · 검증 하네스([양식 - 하네스](양식%20-%20하네스.md)) ·
충돌 · AI · 스킬 시스템처럼 그 게임 고유의 시스템. 모양은 규약 노트가 정하고, 값은 확정표가 채운다.
