# 규약 - 데이터

데이터를 어디에 적고, 어떻게 굽고, 런타임이 어떻게 읽는지의 모양을 정하는 노트다. 데이터 테이블을 설계하거나 굽기 · Registry · 세이브를 손볼 때 편다.
게임 종류를 모르는 트렁크다. 이 노트는 갈림길과 모양을 정하고, 실제 값은 [확정표 5] 가 채운다.

- 합격 조건: 콘텐츠 1개 추가에 C# 수정 0 (게이트 G7, 게이트 정의는 [역할 - PD](역할%20-%20PD.md) 게이트 절)

## 파이프라인 세 토막과 경계

```
[SSOT]            [굽기]                    [런타임]
사람이 적는 곳  →  검증 + 변환 + 코드생성  →  읽기 전용 Registry
Assets/ 바깥       실패하면 아무것도 안 씀    게임 코드는 여기만 본다
```

기본은 세 토막이 서로의 경계를 넘지 않는 것이다.

| 토막 | 방향 |
|---|---|
| SSOT | 손으로 고치는 곳은 여기 하나다. 이유: 굽기 산출물을 손으로 고치면 다음 굽기에 날아간다 |
| 굽기 | 검증이 실패하면 산출물을 쓰지 않는다. 이유: 반쯤 갱신된 출력이 제일 나쁘다 |
| 런타임 | 읽기 전용이다. 이유: 런타임이 데이터를 고치면 그건 세이브지 데이터가 아니다 |

기본은 SSOT 를 `Assets/` 바깥에 두는 것이다. 이유: 안에 두면 `.meta` 가 붙고 빌드에 딸려 가고, 사람이 에디터에서 실수로 고친다.

## 확정표 5행이 정하는 세 갈래

### 1. SSOT 를 어디에 적나

| 선택 | 맞는 때 | 대가 |
|---|---|---|
| 로컬 코드/JSON 트리 | 개발자 1~2명 · 조합형 데이터 · 버전관리 필요 | 비개발자가 못 고친다 |
| 스프레드시트(구글/엑셀) | 기획자가 따로 있음 · 평면 테이블 | 동기화 절차 · 인증 · 오프라인 |
| ScriptableObject | 에디터에서 눈으로 보며 튜닝 · 참조 연결이 잦음 | 대량 편집 · diff 가 어렵다 |

- 기본은 한 곳만 고르는 것이다. 이유: 두 곳에 진실이 있으면 둘은 어긋난다.
- "일단 SO 로 하고 나중에 시트로"는 같은 파이프라인을 두 번 만들게 된다. 처음에 정해 두면 한 번으로 끝난다.

### 2. 평면형인가 조합형인가

이 노트에서 가장 무게가 큰 갈림길이다.

| | 평면형 | 조합형(모듈 조립) |
|---|---|---|
| 모양 | 콘텐츠 1개 = 행 1개, 컬럼이 전부 | 콘텐츠 1개 = 모듈 참조 + 슬롯 채우기 |
| 맞는 때 | 축이 적고 서로 독립 (아이템 · 적 스탯) | 축이 여럿이고 곱으로 늘어난다 (스킬 · 카드 · 효과) |
| 콘텐츠 10종 | 행 10개 | 모듈 6개 + 조합 10개 |
| 콘텐츠 100종 | 행 100개 (복붙이 쌓인다) | 모듈 12개 + 조합 100개 |
| 위험 | 같은 값이 수십 행에 복제됨 | 조립 규칙이 복잡해짐 → 빌드 검증이 필요 |

- "종류를 늘리기 전에 축을 늘린다"([역할 - 기획](역할%20-%20기획.md))의 데이터 쪽 얼굴이 조합형이다.
- 축이 3개 이상이면 조합형이 거의 언제나 맞다. 축이 적고 서로 독립이면 평면형이 낫다.

### 3. 무엇으로 굽나 / 어디로 나가나

기본은 패키지 `com.jinhyung.gameframework` 의 DataLoader 다([규약 - 패키지](규약%20-%20패키지.md)). 이유: 굽기를 새로 짜면 검증 · 코드생성 · 로드를 다시 만들게 된다.

| | 값 |
|---|---|
| 원본 포맷 | `.xlsx` · `.csv` · `.js` · `.ts` · `.py` (js/ts 는 Node, py 는 Python 필요) |
| 실행 | 에디터 메뉴 `Tools/GameData/Data Generate` (단축 `%g`) · 설정 창 `Tools/GameData/Settings` |
| 설정 파일 | `_DataExporter/config.json` 의 `Paths` — 아래 기본값을 여기서 바꾼다 |
| 원본 → JSON | `_DataExporter/GameData` → `Assets/GameData` |
| 생성 코드 | `Assets/Scripts/GameData/Generated` · `Containers` · `GameEnum.cs` · `GameRoot.Generated.cs` |
| 런타임 로드 | Addressables 라벨 `game_data` — `Tools/GameData/Setup Addressables` 를 한 번 돌려야 한다 |
| 조회 | `DataManager.Instance.InitializeAsync()` → `GetContainer<T>()`. 컨테이너는 `Dictionary` · `DictionaryGroup` · `List` 중 하나 |

- C# enum 을 같이 생성한다(`EnumCollector`). 이유: 데이터의 종류 키가 코드에 문자열로 흩어지는 것을 막는다.
- `GameRoot.Generated.cs` 는 게임 쪽에 생성된다(`Game_Core.GameRoot.Instance` + 컨테이너 접근자). 패키지에 있는 파일이 아니다.
- 조합형이 필요하면(아래) 원본을 전처리해 표로 만든 뒤 이 파이프라인에 먹이는 것이 기본이다. 이유: 굽기가 두 벌이 되면 검증도 두 벌이 된다.

## 조합형 설계 — 모듈 · 슬롯 · 토큰

조합형을 고른 경우의 모양이다. 평면형이면 이 절을 건너뛴다.

```
[예시] 트리
GameData/
  _enums.js            enum SSOT ('_' 접두사 = 스캔 제외)
  modules/
    visual/  <이름>    연출 리소스 키 + 색
    stat/    <이름>    수치 + 레벨 곡선
    launch/  <이름>    동작 방식 (형제 노드 목록 + 슬롯)
    buff/    <이름>    idTable — 런타임이 숫자 id 로 조회
  contents/  <id>_<이름>   모듈 조합 + 슬롯 채우기
```

파일 경로(확장자 제외) = 모듈 ID. 폴더가 곧 종류다.

### 슬롯 — 모듈이 뚫어 둔 구멍

모듈은 자기 노드 목록을 내놓고 `{ slot: '이름' }` 으로 구멍을 남긴다. 콘텐츠가 그 자리에 노드를 꽂으면 빌드 타임에 교체된다.

- 안 채운 필수 슬롯 → 빌드 실패
- 모듈이 선언 안 한 슬롯을 채움(오타) → 빌드 실패
- `optional: true` 슬롯은 안 채워도 통과

### 토큰 — 값은 모듈에서 끌어온다

`@stat.<키>` / `@visual.<키>` 는 콘텐츠가 참조한 모듈 값으로 빌드 타임에 치환된다. 런타임 해석이 전혀 없다. 없는 키를 쓰면 빌드가 깨진다.

- 모듈을 복제하지 않고 하나만 다르게 하려면 `overrides` 로 그 값만 덮는다.
- 기본은 런타임 문자열 해석을 만들지 않는 것이다. 이유: 오타가 런타임까지 살아남고, 파싱 비용이 핫패스에 들어온다.

### id 참조 — 숫자 대신 경로

`#<종류>/<경로>` 로 쓰면 빌드 타임에 그 모듈의 `id` 로 치환된다.

```
[예시] { type: 'DebuffOnHit', params: { DebuffId: '#debuff/burn' } }   →  DebuffId: 2001
```

기본은 콘텐츠 파일에 숫자 id 를 직접 적지 않는 것이다. 이유: 손으로 적은 id 의 오타는 런타임까지 산다.

## id 대역 — 종류마다 천 단위, 파생은 수식으로

id 를 손으로 고르면 언젠가 두 종류가 같은 숫자를 쓴다. 기본은 대역표를 확정표 5행 부속으로 먼저 적는 것이다.

```
[예시] 대역표
1000~1999  (예약)              5000~5999  적
2000~2999  스킬 = 파츠(같은 id)  7000~7999  라운드
4000~4999  파츠 옵션 (파생)      8000~8999  시너지
```

- 종류당 천 단위. 한 종류가 천을 넘으면 그건 종류가 아니라 축이다 — 데이터를 다시 본다.
- 파생 id 는 수식으로 정한다. [예시] 옵션 `4000 + (파츠id-2000)*10 + 특성번호`. 이유: 손으로 안 적으니 겹칠 수 없고, 역산이 된다.
- 굽기가 대역 밖 id 와 종류 간 충돌을 검사한다(아래 표에 추가). 이유: 검사가 없으면 대역표는 문서일 뿐이다.
- 노출명은 id 와 분리한다 — `id` 는 영문 기능명, `displayName` 은 세계관어([규약 - 코드 컨벤션](규약%20-%20코드%20컨벤션.md) 텍스트 절).

## 굽기의 본체는 검증

통과 못 하면 아무것도 쓰지 않는 것이 기본이다. 굽기 스크립트가 잡아야 하는 것:

| 검사 | 안 잡으면 |
|---|---|
| 미구현 원자 사용 | enum 에만 있고 C# 구현이 없는 타입 → "조용한 무동작" |
| 죽은 참조 | A 가 없는 B 를 가리킴 → "등록은 됐는데 안 나온다" |
| id 중복 | 뒤엣것이 앞엣것을 덮어씀. 어느 쪽이 이길지 아무도 모른다 |
| enum 오타 | 문자열 타입 필드의 오타 |
| 필수 필드 누락 / 타입 불일치 | 런타임 파싱에서 조용히 기본값 |
| 구조 규칙 위반 | 조합형의 순서 · 개수 제약 (예: 종결 노드가 2개, 종결 뒤에 노드가 남음) |
| bool 열에 숫자 | `1` 이 조용히 `false` 가 된다 ([함정 36](함정%20-%20데이터%20설계.md)) |
| id 대역 밖 · 종류 간 충돌 | 두 종류가 같은 숫자를 쓰면 조인이 엉뚱한 행을 집는다 |

- 검증 실패 = 종료 코드 비0 + 산출물 미갱신. 이유: 경고만 찍고 진행하면 그 경고는 읽히지 않는다.
- 검증 리포트는 로드 등급의 증거물이다([역할 - PD](역할%20-%20PD.md) 미측정은 통과가 아니다 절). 게이트 G3 가 이것을 본다.
- 에디터 쪽 검증기도 따로 둔다. 이유: 굽기를 안 돌리고 에셋만 옮긴 경우를 잡는다.

## 런타임 — Registry 하나가 창구다

기본은 게임 코드가 JSON 을 직접 읽지 않고, 종류마다 Registry 를 두어 거기만 보는 것이다.

```
[예시] 규약
- 로드는 최초 1회 (정적 캐시). 이후 조회는 딕셔너리 히트
- 조회 실패는 한 번만 경고하고 null/기본값 (매 프레임 로그 스팸은 피한다)
- id → 데이터 외에, 자주 쓰는 축은 미리 인덱싱해 둔다 (타입별 목록 등)
- 런타임에 내용을 수정하지 않는다. 진행 상태는 세이브 쪽에 산다
- 씬 리로드에서 다시 로드하지 않아도 되게 정적으로 두되, 리셋 진입점은 만든다
```

- Registry 가 곧 화면의 출처다. 도감 · 목록 UI 는 Registry 를 그대로 나열하면 된다. UI 가 따로 배열을 하드코딩하고 있으면 그 화면은 콘텐츠를 추가해도 늘어나지 않는다.
- 하네스가 참조하는 콘텐츠 id 는 한곳에 모아 둔다([함정 52](함정%20-%20하네스%20측정.md)).

## 세이브 — 데이터와 다른 것

| | 데이터 (이 노트) | 세이브 |
|---|---|---|
| 진실 | SSOT 파일 | 플레이어 기기(또는 서버) |
| 수명 | 빌드에 박힘 | 플레이 중 계속 변함 |
| 버전 | 빌드가 곧 버전 | 버전 필드 + 마이그레이션 필요 |

- 세이브에 콘텐츠 id 를 저장할 때는 그 id 가 사라질 수 있다고 본다. 로드 시 죽은 id 를 걸러낸다.
- 세이브 스키마에는 처음부터 버전 필드를 넣는다([규약 - 플랫폼](규약%20-%20플랫폼.md)). 나중에 넣으면 필드 없는 옛 세이브를 따로 다루게 된다.
- 데이터 밸런스를 바꿨을 때 기존 세이브가 깨지는지를 콘텐츠 추가 절차의 체크 항목으로 넣는다.

## 완료 체크리스트

- [ ] SSOT 위치가 한 곳이고 `Assets/` 바깥이다 (또는 이유가 확정표에 있다)
- [ ] 굽기가 검증 실패 시 산출물을 안 쓴다 (실제로 깨뜨려서 확인했다)
- [ ] enum 이 자동 생성되고, 미구현 원자 차단 목록이 유지된다
- [ ] 죽은 참조 · id 중복 · 타입 불일치를 굽기가 잡는다
- [ ] 게임 코드에 JSON 직접 읽는 곳이 0곳 (Registry 경유)
- [ ] 콘텐츠 1개를 실제로 추가해 봤고 C# 수정이 0이었다 (게이트 G7)
- [ ] 목록형 UI 가 Registry 를 나열한다 (하드코딩 배열 0)
- [ ] 세이브에 버전 필드가 있다

## 자주 보는 증상

| 증상 | 원인 |
|---|---|
| 데이터를 고쳤는데 게임이 그대로 | 굽기를 안 돌림 · 산출물이 갱신 실패했는데 조용히 넘어감 |
| 등록은 됐는데 화면에 안 나옴 | 죽은 참조 · UI 가 하드코딩 배열을 봄 |
| 콘텐츠가 있는데 아무 일도 안 함 | enum 에만 추가하고 C# 원자 미구현 |
| 값이 항상 기본값 | bool 열의 숫자 · 컬럼명 오타 · 타입 불일치를 파서가 삼킴 |
| 밸런스를 바꾸니 기존 세이브가 깨짐 | 세이브가 데이터 인덱스를 저장 (id 를 저장해야 한다) |
| 하네스만 0을 보고 | 하네스가 옛 콘텐츠 id 를 하드코딩 |
| 두 사람이 다른 값을 봄 | SSOT 가 둘 (시트와 SO 병행 등) |
