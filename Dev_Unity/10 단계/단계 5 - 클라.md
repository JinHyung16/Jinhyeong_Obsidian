# 단계 5 - 클라

하네스 → 골격 → 루프 → 연결 → 실측. 계약·데이터·프리팹이 나온 뒤 코드를 짜고 코어 루프를 실측으로 돌릴 때 편다.
하네스가 1번이다. 기준만 정해 놓으면 아무도 안 잰다. 이 단계의 완료는 "구현했다"가 아니라 리포트 파일이 생긴 것이다.

| 칸 | 내용 |
|---|---|
| 받는 것 | 스펙 계약 절, 하네스 절 · `Assets/GameData/*.json`(Addressables 라벨 `game_data`) · `Assets/_Art/Prefabs/**`(스크립트 0) · `Assets/_Art/Prefabs/UI/*.prefab` · 큐 |
| 읽을 노트 | [역할 - 클라](역할%20-%20클라.md) · [양식 - 하네스](양식%20-%20하네스.md) · [함정 색인 - 개발](함정%20색인%20-%20개발.md) · [규약 - 뷰](규약%20-%20뷰.md) · [규약 - 최적화](규약%20-%20최적화.md) |
| 내는 것 | 코드 · `Temp/runloop.report`(god) + `runloop_*.png` · 컴파일 로그 · G7 증거(콘텐츠 1개 추가 diff) |
| 게이트 | G2 에러 0·신규 경고 0 · G4 루프 1바퀴 실측 · G7 콘텐츠 1개 추가에 C# 수정 0 |

## 하는 일

읽을 노트에서 볼 곳:

- [역할 - 클라](역할%20-%20클라.md) 전체
- [양식 - 하네스](양식%20-%20하네스.md) 전체
- [함정 색인 - 개발](함정%20색인%20-%20개발.md) 색인
- [규약 - 뷰](규약%20-%20뷰.md) 좌표계·스폰 경계
- [규약 - 최적화](규약%20-%20최적화.md) "처음부터 넣는 것"

1. 하네스를 먼저 만든다 — 스펙 하네스 절 시나리오 그대로. 요청 파일 → 플레이 진입 → 리포트 + 캡처 → 종료.
   워치독(경과 프레임·게임 시간)이 없으면 "무효"를 보고한다. 멈춘 게임의 "피해 0"이 정상처럼 보인 사고가 있다
2. 에디터 경로를 확정한다. 브리지가 붙었으면 A(룩 판정 가능), 아니면 B(배치모드, 로직만).
   눈으로 봐야 하는 항목은 A 가 없으면 미측정으로 남긴다. 배치모드로 "보인다"를 보고하지 않는다
3. 골격 — `GameInitialize` 순서 · `GameFlow` 상태 · Registry 로드. 부트 순서의 출처는 한 곳에 둔다
4. 코어 루프를 화살표 순서대로. 큐 위에서부터. 항목 하나 = 실측 하나. 완료된 항목은 큐에서 지운다
5. 프리팹에 컴포넌트를 연결한다. 바인딩 계약의 필드명으로. 기본은 아트 프리팹에 스크립트를 추가하지 않고, 런타임 `AddComponent` 도 쓰지 않는 것이다.
   루트 프리팹의 컴포넌트 구성은 고정해 둔다 ([예시] `Skill_Root` 류)
6. 컴파일 0. 도메인 리로드가 끝난 뒤(`isCompiling=false`) 하네스를 돌린다. 도는 동안에는 코드를 건드리지 않는다
7. G7 을 실제로 해 본다 — 콘텐츠 1개를 데이터로 추가 → 굽기 → 로드. C# diff 가 0 이어야 통과다

## 막혔을 때

| 상황 | 하는 일 |
|---|---|
| 리포트가 "킬 0" | 원인이 열 갈래다. 추측으로 고치기보다 진단 항목(스폰 수·부착 스킬·팀·테이블 로드)을 리포트에 더하고 다시 돌린다 |
| 에디터가 안 떠 있다 | 분리 프로세스로 띄우고 프로젝트 경로로 확인한다. 다른 프로젝트 인스턴스를 우리 것으로 착각한 사고가 있다 |
| 브리지 없음 | B 로 간다. 룩 항목은 미측정으로 표시하고 [단계 6 - QA](단계%206%20-%20QA.md) 에서 다시 잰다. 무엇이 막혔는지 리포트에 적는다 |
| 같은 게이트 3회 실패 | 그 지점에서 원인과 시도 3회를 보고하고 종료한다 (실패 정지) |

## 자주 틀리는 것

[함정 색인 - 개발](함정%20색인%20-%20개발.md) 에서 이 단계가 자주 걸리는 것이다.

- "생성됨" 이벤트만 구독하고 현재 값을 안 본다 → 이미 생성된 뒤 구독한 쪽은 영영 못 받는다 ([함정 31](함정%20-%20런타임%20배선.md))
- 팀 검사를 호출처마다 흩어 둔다 → 새 경로마다 아군 오사 재발. `TakeDamage` 입구 한 곳에 둔다 ([함정 39](함정%20-%20전투%20규칙.md))
- 비동기 `Start` 가 앞의 결과를 지운다 ([함정 19](함정%20-%20비동기%20로드.md))
- 풀 재사용 시 상태가 남는다 · 이벤트 중복 구독 ([함정 7](함정%20-%20풀링%20수명.md) · [함정 8](함정%20-%20풀링%20수명.md))
- 하네스가 옛 콘텐츠 id 를 하드코딩한다 → 게임은 멀쩡한데 하네스만 0. id 는 한곳에 둔다
- 새로 고침 직후 플레이 진입 → 도메인 리로드가 자동화를 먹는다 ([함정 33](함정%20-%20에디터%20자동화.md))
