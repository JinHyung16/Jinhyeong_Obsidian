# 단계 3 - 아트

규격 → 프록시 → 생성 → 반입. 확정표 12행과 계약 절 에셋 목록이 나온 뒤, 아트 규격을 정하고 스프라이트·FX·UI 조각을 들일 때 편다.
아트가 없어도 개발은 계속 간다. 프록시가 먼저 규격을 채우고 진짜 아트는 그 규격으로 스왑된다. 판정은 눈보다 숫자로 한다.

| 칸 | 내용 |
|---|---|
| 받는 것 | 스펙 확정표 절 12행 · `_Ref/<게임>/art.tsv` · `view.tsv`(비율·피벗) · 스펙 계약 절 에셋 목록 |
| 읽을 노트 | [역할 - 아트](역할%20-%20아트.md) · [규약 - 아트 방향](규약%20-%20아트%20방향.md) · [양식 - 아트 생성기](양식%20-%20아트%20생성기.md) · [규약 - 뷰](규약%20-%20뷰.md) · [규약 - 프리팹](규약%20-%20프리팹.md) |
| 내는 것 | 스펙 아트 규격 절(방향 표 · 판정 표) · 스타일 프레임 캡처 · 종류별 라인업 · `Assets/_Art/Sprites/**` `Assets/_Art/FX/**` `Assets/_Art/UI/**` + `.meta` · `Assets/_Art/Prefabs/**`(스크립트 0) · 어드레서블 감사 리포트 |
| 게이트 | 스크립트 0 · Missing Script 0 · 양방향 감사 미등록 0/미사용 0/중복 0 · 규격표 미측정 0(추정 허용) · 아트 방향 판정 표(가독성 · 일관성 · 품질 하한) 미측정 0 |

## 하는 일

읽을 노트에서 볼 곳:

- [규약 - 아트 방향](규약%20-%20아트%20방향.md) 전체 (순서 · 방향 표 · 가독성 · 일관성 · 품질 하한)
- [역할 - 아트](역할%20-%20아트.md) 전체 (반입 절차 6단계 · 숫자 판정 4종 포함)
- [양식 - 아트 생성기](양식%20-%20아트%20생성기.md) 전체
- [규약 - 뷰](규약%20-%20뷰.md) 피벗·정렬
- [규약 - 프리팹](규약%20-%20프리팹.md) 전체

1. 규격표를 쓴다 → 스펙 아트 규격 절. 이 값들이 없으면 그림을 다시 그리게 된다

   출처의 `art.tsv` 행 이름은 [레퍼런스 해부](레퍼런스%20해부.md) art.tsv 고정 행 절과 같다. 행이 `미측정`이면 다음 출처로 내려간다.

   | 항목 | 출처 순서 |
   |---|---|
   | PPU · 캔버스 크기 | `art.tsv` 스프라이트 캔버스 · 도트 배율 → [규약 - 뷰](규약%20-%20뷰.md) 뷰별 기본값 |
   | 피벗 (부위별) | `view.tsv` → 장르 노트 |
   | 애니 프레임 수 · fps | `art.tsv` 애니 프레임 수 → 걷기 4 · 대기 2 · 연출은 수명에 맞춰 |
   | 외곽선 | `art.tsv` 외곽선 비중 · 외곽선 두께 → 비중 25% 이하 |
   | 명암 · 광원 | `art.tsv` 명암 단수 · 광원 방향 → 3단 · 위 |
   | 팔레트 폭 | `art.tsv` 캐릭터 팔레트 폭 · 캡처 팔레트 폭 |
   | 배경 톤 | `art.tsv` 배경 채도 · 배경 명도 · 전경-배경 명도차 |
   | 형태 | `art.tsv` 실루엣 폭 굴곡 · 변동 |
   | 접지 그림자 | `art.tsv` 접지 그림자 → 탑다운·쿼터뷰면 넣는다 |
   | 이펙트 | `art.tsv` 잉크 비중 · 이펙트 채움률. 색은 흰색으로만 그리고 데이터가 런타임에 틴트한다 |
   | UI 조각 | `art.tsv` 9슬라이스 경계 |

   우리 캡처 · 스프라이트도 같은 측정기로 재서 레퍼 `art.tsv` 옆에 놓고 판정한다.

2. 프록시를 먼저 낸다. 단색 프리미티브·생성 스프라이트. 규격은 진짜와 동일하게 — 피벗·스케일·어드레스 키.
   프록시로 [단계 5 - 클라](단계%205%20-%20클라.md) G4 를 통과시키고, 아트는 그 뒤 병렬로 간다
3. 생성기를 돌린다. `python _DataExporter/tools/build_<대상>.py` — 파라미터는 규격표에서 가져오고 즉석 값은 쓰지 않는 게 기본이다.
   외곽선은 그리지 않고 실루엣을 팽창시킨다 (두께가 항상 일정). 부위는 레이어로 나눠 각각 만든다
4. 생성 뒤에는 `build_meta.py` 를 돌린다. 이유: `.meta` 가 없으면 GUID 가 새로 잡혀 참조가 끊긴다. GUID 는 경로 md5 로 고정된다
5. 반입 절차 6단계 ([역할 - 아트](역할%20-%20아트.md)) — 임포트 규격 · 압축 포맷 · 폰트 글리프는 세어서 확인한다
6. 어드레서블 양방향 감사 — 데이터가 부르는 키 ↔ 등록된 키. 미등록·미사용·중복 각 0
7. 숫자 판정 4종을 캡처에서 잰다 (단계 5 첫 실측 캡처가 나온 뒤 재판정) — 외곽선 비중 · 실루엣 폭 굴곡 · 접지 그림자 픽셀 · 명암 단수.
   레퍼 캡처와 같은 방법으로 재서 표로 남긴다. "잘 나온 것 같다"는 판정이 아니다

## 막혔을 때

| 상황 | 하는 일 |
|---|---|
| `art.tsv` 가 미측정 | 규격표에 [규약 - 뷰](규약%20-%20뷰.md)·장르 노트 기본값을 넣고 스펙 추정 절에 적는다. 비용: "해당 종류 전량 재생성 (생성기라 스크립트 재실행)" |
| 레퍼런스 스타일이 두 갈래 (네온 / 만화) | 모양이 처리를 정한다 — 큰 단일 실루엣은 속 비움, 작은 조각 여럿은 속 채움. 둘 다 만들기보다 하나로 간다 |
| 캡처 판정이 레퍼와 어긋남 | 4종 중 어느 값이 벗어났는지 표로 → 생성기 파라미터 1개만 고쳐 재생성. 3회 한도 |

## 자주 틀리는 것

- "그렸다"를 "보인다"로 센다. 스프라이트 시트가 아니라 플레이 캡처로 판정한다 ([함정 43](함정%20-%20판단%20검증.md))
- 반경 있는 연출을 눈에 띄게 하려고 키운다. 크기가 곧 사거리다 — 반경 없는 장식만 키운다
- 구간을 통째로 교체하며 그 사이의 데이터 정의를 지운다 ([함정 45](함정%20-%20작업%20방식.md)). `_DataExporter/` 는 git 밖이다
- 폰트 글리프를 안 세고 넘어간다 — CJK 가 네모로 나온다 ([함정 10](함정%20-%20UI%20표시.md))
