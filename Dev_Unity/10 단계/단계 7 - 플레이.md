# 단계 7 - 플레이

플레이 가능: 봉인 → 보고. QA 가 끝나고 큐에 슬라이스 밖 항목만 남았을 때, 파이프라인을 닫으며 편다.
여기서 멈추는 것은 HOLD 가 아니라 종료다. 사람이 하는 일은 하나 — 하네스가 우회한 것(실제 입력·손맛)을 켜서 해 보는 것. 그 절차를 세 줄로 넘긴다.

| 칸 | 내용 |
|---|---|
| 받는 것 | 스펙 QA 절, 추정 절 · 큐 · 캡처 세트 · 회귀 기준표 |
| 읽을 노트 | [역할 - PD](역할%20-%20PD.md) |
| 내는 것 | 기록 `<오늘>` · 스펙 추정 절(비용순 정렬본) · `README.md` 현황 절 · 최종 보고 |
| 게이트 | 큐의 미완료 = "슬라이스 밖" 항목뿐 · 기록 4칸 존재 · 스펙 추정 절 모든 행에 비용 있음 |

## 하는 일

읽을 노트에서 볼 곳:

- [역할 - PD](역할%20-%20PD.md) 원장 절
- 프로젝트 진입 파일의 보고 규칙 절

1. 큐를 확인한다. 슬라이스 항목이 남아 있으면 이 단계가 아니다 — [단계 5 - 클라](단계%205%20-%20클라.md) 로. 남은 것은 "슬라이스 밖"과 QA "미달·3회"뿐이어야 한다
2. 스펙 추정 절을 비용순으로 정렬한다. 사람이 볼 것은 이 표 하나다. 맨 위 5행이 "틀리면 가장 아픈 가정"이다
3. 실행 절차 세 줄. 어떻게 켜고(씬·엔트리) · 어떻게 조작하고(키) · 무엇을 보면 되는지(첫 30초에 일어나야 할 것)
4. 사람 확인 체크리스트 — 하네스가 우회한 것만. 실제 키 입력 · 조작 반응 지연 · 화면 전이 체감. 항목마다 "이러면 정상 / 이러면 이상"
5. 기록 봉인 → 기록 `<오늘>`. 확정 / 산출 / 실측 / 발견 4칸. 완료 항목을 큐에서 지운 것을 여기서 확인한다
6. README 현황 절 갱신 — 실측치 3줄 + 안 잡힌 것
7. 최종 보고. 순서는 아래가 기본이다
   1. 실행 절차 3줄
   2. QA 위반 0 / 미달 N (행 이름)
   3. 추정 상위 5행
   4. 사람 확인 체크리스트
   5. 큐에 남은 것 (슬라이스 밖)
   6. "완료" — 단, QA 미달이 있으면 "완료" 대신 남은 것을 적는다

## 막혔을 때

이 단계엔 빈칸이 없다. 앞 단계가 다 채웠다. 채워지지 않은 것이 있으면 그 단계로 돌아가기보다
"미측정 · 어느 단계에서 왜"를 보고에 적는다. 이유: 여기서 되돌리면 파이프라인이 끝나지 않는다.

## 자주 틀리는 것

- "완료"를 쓰고 싶어서 미달을 보고에서 뺀다. 미달은 위에, 완료는 아래
- 추정을 정렬 없이 넘긴다. 40행을 사람이 다 읽지 않는다 — 비용순 상위 5행이 검토의 전부다
- 사람 확인 체크리스트에 하네스가 이미 잰 것을 넣는다. 사람은 하네스가 못 하는 것만 한다
