# 단계 2 - 데이터

계약 → SSOT 모듈 → 굽기. 스펙 계약 절의 스키마가 나온 뒤 콘텐츠를 데이터로 넣을 때 편다.
기본은 콘텐츠를 C# 수정 없이 넣는 것이다. 이 단계의 산출물은 파일과 검증 리포트뿐이고, 검증을 통과하지 못하면 산출물을 쓰지 않는다.

| 칸 | 내용 |
|---|---|
| 받는 것 | 스펙 계약 절 스키마 · `_Ref/<게임>/curve_*.tsv` · `design.tsv` 의 `adopt=채택` 행 |
| 읽을 노트 | [규약 - 데이터](규약%20-%20데이터.md) · [규약 - 패키지](규약%20-%20패키지.md) · [역할 - 기획](역할%20-%20기획.md) |
| 내는 것 | `_DataExporter/GameData/**`(원본) · `Assets/GameData/*.json` · `Assets/Scripts/GameData/{Generated,Containers,GameEnum.cs,GameRoot.Generated.cs}` · 굽기 로그 · `Temp/editor.task.log`(validate) |
| 게이트 | G3 죽은 참조 0 · 미구현 원자 0 · id 중복 0 · bool 열에 숫자 0 |

## 하는 일

읽을 노트에서 볼 곳:

- [규약 - 데이터](규약%20-%20데이터.md) 전체
- [규약 - 패키지](규약%20-%20패키지.md) 전체
- [역할 - 기획](역할%20-%20기획.md) 수치는 데이터 파일에, 규칙은 표로 절 · 밸런스 방법론 절 · 두 분류 축의 충돌 확인 절

1. 스키마를 `config.json` 에 등록한다. 새 콘텐츠 종류면 `Modules` 에 이름을 더하고 출력 경로를 확인한다.
   기존 종류면 그대로 둔다
2. `_enums.js` 를 먼저 채운다. 스키마의 enum 목록이 여기 있어야 굽기가 오타를 잡는다.
   런타임이 아직 처리 못 하는 원자는 `UnimplementedNodes` 에 넣어 빌드에서 막는다. 이유: 데이터로 쓰면 조용히 무동작이다
3. 모듈 파일을 쓴다. 한 폴더 = 한 콘텐츠. 공유는 발사 방식처럼 "재사용이 본질"인 것만 둔다.
   id 는 대역 규칙으로, 참조는 이름으로(`@stat.Damage` 처럼 토큰) 적는 게 기본이다. 숫자를 손으로 적지 않는다
4. 곡선을 굽는다. `curve_*.tsv` 를 `Tables/<축>/` 모듈로. TSV 행이 곧 모듈 행이라서 사람이 옮겨 적는 구간이 없게 한다
5. 두 분류 축 충돌을 표로 확인한다. 부위 × 계열처럼 두 축이 있으면 교차표를 만들어 도달 불가능한 조합이 없는지 본다 ([함정 32](함정%20-%20데이터%20설계.md))
6. `cd _DataExporter && node export.js` — 종료 코드가 0 이 아니면 산출물이 갱신되지 않았다. 로그의 첫 오류부터 본다
7. `Temp/editor.task` ← `validate`. 굽기를 안 돌리고 에셋만 옮긴 경우를 에디터 쪽 검증기가 잡는다

## 막혔을 때

| 상황 | 하는 일 |
|---|---|
| 곡선 TSV 가 `미측정` | 장르 노트 값 → 없으면 선형 기본값으로 채우고 스펙 추정 절에 적는다. 비용: "단계 6 밸런스 실측 후 재조정" |
| 스키마에 없는 필드가 필요 | 계약 변경이다. 스펙 계약 절을 고치고 [단계 1 - 설계](단계%201%20-%20설계.md) 게이트(G0-b)를 다시 본다. 기본은 조용히 추가하지 않는 것이다 ([함정 1](함정%20-%20런타임%20배선.md)) |
| 굽기 검증 실패 | 3회까지 고친다. 4회째면 그 오류를 그대로 보고하고 종료한다 (실패 정지, HOLD 아님) |

## 자주 틀리는 것

- 굽기 산출물(`Assets/GameData/*.json`)을 손으로 고친다. 다음 굽기에 날아간다
- 경고만 찍고 진행한다. 경고는 안 읽힌다 — 검증 실패는 종료 코드로 낸다
- 파일 이름을 바꾼 직후 첫 실행에서 옛 어셈블리가 새 JSON 을 읽는다. 도메인 리로드 뒤 다시 잰다
- 대소문자만 다른 폴더 이름으로 개명한다. 윈도우가 같은 폴더로 본다 — 해체하고 다시 만든다
